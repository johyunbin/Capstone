# 연구 방향 카톡 요약 (복붙용)

---

## 버전 1: 전체 요약 (길이 주의)

얘들아 연구 방향 정리해봤어. 상세 문서는 깃에 올렸고 핵심만 공유할게.

**큰 그림**
Exqutor 논문이 "벡터 카디널리티를 정확히 추정하면 실행 계획이 좋아진다"까지 보여줬잖아. 우리는 그 다음 질문을 파는 거야:
→ "정확한 카디널리티로 구체적으로 뭘 더 잘할 수 있는가?"

**핵심 아이디어 (재현 아이디어 발전)**
재현이 말했던 "많이 retrieval → 적게 retrieval 순서" 아이디어를 학술적으로 확장하면, 다중 조건 VAQ에서의 "필터 순서 최적화" 문제가 돼. 실무에서 벡터 검색에 날짜/카테고리/가격 등 여러 필터가 붙는데, 어떤 필터를 먼저 적용하느냐에 따라 성능이 수배 차이남. 이 순서를 올바르게 결정하려면 각 필터의 선택도를 정확히 알아야 하고, 그게 바로 Exqutor가 해결한 문제.

**실험 3단계**
1단계: pgvector에서 선택도별 현황 파악 (선택도 sweep + EXPLAIN ANALYZE)
2단계: 다중 필터 쿼리에서 필터 순서를 pg_hint_plan으로 강제 변경하며 비교 (핵심)
3단계: 논문이 안 다룬 변수 1~2개 추가 (top-k, 고차원, pgvector 0.8.0 등)

**논문과의 차별점**
- 논문은 필터 1개(태그)만 테스트 → 우리는 다중 필터 조합
- 논문은 필터 순서 최적화 안 다룸 → 우리의 핵심 실험
- 논문은 range query만 → 우리는 top-k도 확장
- 논문 시점 pgvector 0.7.x → 0.8.0 비교도 가능

**토의 필요한 것**
1. 연구실 서버 쓸 수 있는지 (세은이 확인 중?)
2. 누가 먼저 Exqutor 코드 clone해서 빌드 테스트할지
3. 3단계 확장을 top-k vs pgvector 0.8.0 비교 중 뭘 우선할지
4. 이 방향으로 연구제안서(4/2 마감) 쓰는 거 괜찮은지

## 버전 2: 짧은 버전

얘들아 연구 방향 정리했어.

재현이 말했던 "많이 retrieval → 적게 retrieval" 아이디어를 발전시켜서:
→ "다중 조건 VAQ에서 필터 적용 순서 최적화"를 핵심 주제로 잡았어

Exqutor가 카디널리티를 정확하게 추정한 다음, 그걸로 필터 순서를 최적화하면 추가 성능 향상이 가능한지를 실험하는 거야.

실험:
1. 선택도 sweep으로 baseline 측정
2. pg_hint_plan으로 필터 순서 강제 변경하며 비교 (핵심)
3. top-k, 고차원 등 논문이 안 다룬 조건 확장

논문이 필터 1개+range query만 했는데, 우리는 다중 필터+필터 순서+top-k까지 확장하는 거라 차별점 충분해.

상세 문서 깃에 올렸으니 한번 봐줘. 괜찮으면 이 방향으로 4/2 연구제안서 쓸게.
