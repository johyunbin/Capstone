## §1. Tier 1 — 알고리즘 충실도

### 1.1 RANDOM20 low-sel 측정 (`rq1/random20_low_sel.py`)

#### 정의 및 절차
- DEEP 1M, 100 query × 5 seed × {bernoulli, stratified} × {KM20, RANDOM20} = 4,000 측정
- TARGET_SELS = [0.010, 0.050]
- Phase 1 (KM20): 기존 stratum_id 유지 → BERN/STRAT 측정
- Phase 2 (RANDOM20): SQL `setseed(0.42)` → `UPDATE SET stratum_id = floor(random()*20)` → 측정 → 복원
- Q-error: `max(plan_rows / true_card, true_card / plan_rows)` — `q_error_hook` (log regex) 사용

#### 검증 항목

| 항목 | 검증 | 결과 |
|---|---|---|
| Q-error 정의 | line 80 `max(pr/tc, tc/pr)` | ✓ 표준 정의 |
| Paired test | bern + strat 둘 다 same seed 사용 (line 112-113) | ✓ paired |
| Wilcoxon 검정 | line 121 `alternative='less'` (STRAT < BERN 단측) | ✓ 가설 일치 |
| RANDOM20 reproducibility | `setseed(0.42)` 고정 | ✓ deterministic |
| Restore 보장 | `km20_backup` 컬럼 backup → DROP | ✓ 안전 |
| Bootstrap CI | `np.random.default_rng(42)` 고정 + 10,000 resample (line 194-195) | ✓ 표준 |

#### 우려 사항 (소형)
- line 124 `diff = (mb - ms) / mb * 100` — **median 기반** 차이. mean-of-ratios 가 아닌 ratio-of-medians. 둘은 다르며 후자는 이상치에 robust 하지만 평균 행동 추적은 약화. 전 RQ1 narrative 가 median 기반임을 명시 필요.
- line 207 `mannwhitneyu(km_diffs, rd_diffs, alternative='greater')` — KM20 의 diff_pct > RANDOM20 의 diff_pct 가설. 5 vs 5 sample 에서 power 낮음. 결과는 "KM20 - RANDOM20 = +X%p" 형태로 보고됨 → narrative 에서 직접 인용시 n=5 한계 명시 필요.

### 1.2 SIFT mid-sel 측정 (`rq1/sift_mid_sel_measurement.py`)

#### 정의
- SIFT 1.5M, sel=[0.10, 0.30], 100 query × 5 seed × 3 mode (bernoulli + km20 + random20)
- **Numpy estimator** (PG 외부, 캐시 기반)
- N_STRATA=20, CACHE_PER_CLUSTER=500 → 총 ~10K 캐시
- Q-error: `max(est/true_card, true_card/est)` (line 170)

#### 핵심 발견 — Bernoulli 의 sampling 기반

```python
# line 138-146 (bernoulli_estimate)
total_rows = sum(sizes.values())  # = 1.5M (전체)
flat = np.concatenate([samples[sid] for sid in range(N_STRATA)], axis=0)  # ≤10K (캐시)
n = flat.shape[0]
s = min(int(budget), n)  # 385
idxs = rng.choice(n, size=s, replace=False)  # ≤10K 에서 385 샘플
sub = flat[idxs]
hits = int((d < D).sum())
return hits * (total_rows / s)  # HT estimator 가중치 = 1.5M / 385
```

**의도와 실제의 격차**:
- HT 가중치 N/s = 1.5M / 385 ≈ 3,896 — 전체 모집단 가정
- 그러나 실제 샘플은 캐시 (≤10K) 에서 추출 — **stratified pre-sampling 이 disguised**
- 캐시 자체가 stratified 균등 (각 클러스터 500) 이므로 실제 BERN 보다 분산이 작음
- 따라서 **BERN 의 절대 q-error 가 실제 PG bernoulli 보다 낙관적으로 측정**될 가능성

⚠️ **단**, KM20 측정도 동일 캐시 사용 → 상대 비교는 보존됨. 절대 q-error 인용 시 caveat 필요.

#### Stratified estimator 검증

```python
# line 122-134 (stratified_estimate)
weight = sizes.get(sid, 0) / s_i  # N_i / s_i (HT)
est += hits * weight
```
- ✓ Horvitz-Thompson 표준 (N_i × p̂_i)
- s_i = max(min(int(s_i), n_cache), 1) — 클러스터 캐시가 작은 경우 s_i 가 잘릴 수 있음 (소형 클러스터 undersampling)

### 1.4 RQ1 단조성 검정 (`local_analysis/rq1_gradient_monotonicity.py`)

#### Methodology

| 항목 | 결과 |
|---|---|
| Per-seed Spearman | `for seed in groupby` → 각 seed 의 cell 들에 대해 ρ(sel, diff%) 계산 → mean ± 95% bootstrap CI (5,000 resample, rng=42) |
| Mann-Kendall trend | seed-mean sequence (sel 오름차순) → S statistic + z + p_two_sided |
| Pooled Spearman | seed-mean 으로 ρ(sel, mean) 계산 |

#### 검증

| 검사 | 결과 |
|---|---|
| MK 연속성 보정 | line 156-159 표준 (S>0 → S-1, S<0 → S+1) | ✓ |
| Bootstrap reproducibility | `default_rng(42)` 고정 | ✓ |
| Per-seed n_seeds 정확 | seeds 0.1-0.5 에 대해 4-5 cell 사용 (s=0.50 의 seed 0.42 는 단일 cell 이라 자동 제외) | ✓ |

#### 데이터 source 격차 ⚠️

`gradient_monotonicity.md` 의 DEEP-KM20 cells:
- s=0.01, 0.05 ← `random20_low_sel_summary.json` (SQL D_target, 4/15)

### 2.3 q_error 의 두 정의 (q_error vs q_error_hook)

| 정의 | source | 의미 |
|---|---|---|
| `q_error` | `plan["Plan Rows"]` (EXPLAIN ANALYZE) | planner 가 본 estimate (cap, smoothing 등 PG 내부 보정 후) |
| `q_error_hook` | `Estimated cardinality for range query on table {tbl}: {val}` (log regex) | sampling estimator 의 raw output |

`random20_strat_all_sel.parquet` 의 `q_error` 가 3,750 인 데 비해 `q_error_hook` 은 1.125 — 둘이 7,000 배 차이. 가능 원인:
1. PG 의 `sampling_method='stratified'` 경로에서 plan_rows 가 estimator output 을 무시하고 default cap 적용
2. Stratified estimator 가 hook 으로 raw value 를 emit 하지만 planner 는 무시
3. q_error 컬럼은 mode 별로 의미가 다름 — 비교 분석 시 q_error_hook 만 사용해야 함

→ 신 측정의 narrative table 들은 모두 q_error_hook 기반 ✓ 그러나 publication 시 q_error vs q_error_hook 차이 명시 권고.

## §3. Tier 3 — 통계 검정 정확성

### 3.1 DEEP-KM20 per-seed Spearman 재현

| 항목 | 보고 | 검증 |
|---|---|---|
| mean ρ | −0.680 | ✓ (rq1_gradient_monotonicity_test.json) |
| 95% CI | [−0.800, −0.440] | ✓ tight CI = 5 seed 의 ρ 값이 비슷함 (보고 rhos 비공개지만 분산 < 0.13) |
| n_seeds | 5 | ✓ (seeds 0.1–0.5, 4 cell 각각) |

⚠️ **CI 가 0 을 제외하므로 H1-G (gradient) 가 per-seed 기준으로 통계적 유의** — 그러나:

- 4 cell 만으로 ρ 계산 (s=0.50 제외) → ρ 가능값 한정
- bootstrap 5000 이지만 underlying n=5 ρ values → CI 은 단일 measurement 의 분산이 아닌 seed 간 분산

### 3.2 Mann-Kendall pooled

| 항목 | 보고 | 평가 |
|---|---|---|
| DEEP-KM20 S | −6 | n=5 cell 에서 가능값 ±10 |
| z | −1.225 | continuity 보정 후 |
| p (two-sided) | 0.2207 | **유의 X** (p > 0.05) |

→ pooled (cell-mean) 단조성은 통계적으로 약함. Per-seed 와 pooled 결과의 격차는 cell-mean 의 noise (특히 s=0.05 vs s=0.10 의 비단조 anomaly) 가 원인.

### 4.3 Cross-source 단조성

§1.4 에 기술. Phase 6 SQL 기반 5 cell vs Phase 7 numpy 5 cell 의 차이가 narrative 의 단조성 주장의 robustness 결정. **현재 narrative (gradient = Level 2) 는 SQL 기반에서만 성립**.

대안 narrative:
- "Bernoulli 와 KM20 의 비교는 sampling-population 의 정의 (PG sampling extension 의 actual implementation vs 단순 캐시 기반 simulation) 에 민감하다. PG sampling 기준으로는 gradient 가 negative monotone (sel↓ → KM20 advantage↑); numpy simulation 기준으로는 gradient 가 약함 (mean ρ ≈ 0 ± noise)."
- 만약 SQL 기반 결과를 신뢰하면 → 본 narrative 유지 + numpy 격차를 "estimator implementation 차이로 future work" 로 이관
