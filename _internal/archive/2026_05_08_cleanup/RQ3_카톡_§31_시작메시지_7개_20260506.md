## #8 — F. MiniBatch K-means (★★★ 1순위)

```
[실험 #8 시작] HH:MM

실험명: F. MiniBatch K-means (Sculley 2010)
RQ: RQ3 (분포 모를 때 어떤 방식?)
예상 시간: ~1h (DEEP fetch 5m + SIFT fetch 7m + 학습 30s × 2 + 측정 30m)

[기획 의도]
- KM20 oracle 은 production 환경에서 매번 full K-means 학습 부담 큼
- MiniBatch K-means 는 1~5% sample 만으로 학습 → 시간 1/20~1/100 단축
- "production-ready 솔루션은 무엇?" 의 직접 답변
- RQ재정립 plan 의 Limitation 1 (KM20 = oracle, production X) 해소

[측정 목표 + 가설]
- H3-F: MiniBatch K-means 가 KM20 oracle 의 75% 이상 recovery 달성
- 정량: 1% 학습 (DEEP 1M → 10K rows, ~수초) 으로 oracle 수준 근접
- 좁은 sel (s=0.01) 에서도 recovery_rate ≥ 0.7

[기대치]
- recovery_rate 75~95%
- KM oracle 과 paired Wilcoxon p > 0.05 (구별 안 됨)
- inertia 가 oracle 의 1.05~1.10 배

[측정 조건]
- DEEP 1M + SIFT 1.5M, 5 sel × 5 seed × 100 query
- sample_size 385, K=20, learn_frac 1%

- JL lemma 는 거리만 보존, cluster 구조 반영 X

[기대치]
- recovery_rate 10~40%
- 좁은 sel 에서 RANDOM20 보다 약간 우수 또는 비슷
- bucket 분포 max/min 5배 이상 (argmax 가 high-norm dim 편향)
- DEEP/SIFT 차이 작음 (distribution-agnostic)

- PCA 2D 의 explained variance 가 결정 (DEEP 96d → 2d 5~15% 추정)
- MiniBatch (75~95%) 보다 낮으나 Random Projection (10~40%) 보다 높음

- recovery_rate 20~60%
- bucket 분포 균형 (quantile 분할 → max/min < 2)
- DEEP vs SIFT 차이 발생 가능 (PCA 효율 데이터셋 의존)
- 좁은 sel (s=0.01) 에서 KM 과 격차 큼

[측정 조건]
- DEEP 1M + SIFT 1.5M, 5 sel × 5 seed × 100 query
- sample_size 385, K=20, p=10 (1024×1024 grid), learn_frac 1%

```
[실험 #6 시작] HH:MM

[기획 의도]
- cosine LSH 는 학습 없이 유사도 보존하는 정통 hash 방법

[측정 목표 + 가설]
- H3-A: LSH 의 recovery_rate 는 30~60%
- Random Projection 보다 +10~20%p 우수 (multi-bit 효과)
- cosine 유사도 보존 정도가 cluster 구조 반영의 proxy

[기대치]
- recovery_rate 30~60%
- bucket 분포 imbalance (max/min 2~5배): mod 20 collision 영향
- DEEP/SIFT 차이 작음 (distribution-agnostic)

[측정 조건]
