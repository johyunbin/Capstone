## 사용법

각 실험은 **2 단계**로 진행:

1. **시작 프롬프트** (실험 진행 전에 복붙)
   - [동기] [확인] [예상] 3축으로 컨텍스트 명확화
   - Claude 가 스크립트 작성 / 측정 가이드 / 예상 결과 안내

2. **완료 프롬프트** (실험 끝난 후 복붙)
   - 측정 결과 + 핵심 수치를 알려줌
   - Claude 가 **간단 브리핑 + 동기/가설/예상/실제 4단계 + 상세 설명** 출력 (보고서/발표용)

## 공통 — 실험 완료 후 브리핑 + 상세 설명 요청

```
[실험 #X 완료]

실험명: ___
측정 결과 위치: experiments/results/...
핵심 수치 (직접 본 것):
  - ...
  - ...

다음 형식으로 정리해줘 (★ 동기·가설·예상·실제 4단계 명시 필수):

1. 한 줄 요약 (트윗 길이 — 누가 봐도 결과를 알 수 있게)

2. 간단 브리핑 (3~5줄)
   - 무엇을 측정했는가
   - 핵심 결과 한 줄

3. ★ 동기·가설·예상·실제 (4단계, 핵심)

   (a) 동기 — 왜 이 실험을 시작했나
       · 어떤 의문 또는 문제에서 출발했나
       · 어떤 선행 결과 또는 이론이 동기를 부여했나
       · 박세은님 의문 / 선행 RQ 결과 / Exqutor 한계 등과의 연결

   (b) 확인하고자 한 것 — 가설 또는 질문
       · 정량적으로 무엇을 측정하려 했나
       · 가설 H?: ...

   (c) 예상 결과 — 진행 전 기대값
       · 가설이 맞다면 어떤 수치 또는 방향으로 나올까?
       · 선행 이론·실험에 비추어 어느 정도일까?

   (d) 실제 결과 — 측정값
       · 핵심 수치 (mean ± std, p-value, CI)
       · 가설 확인 vs 반증?
       · 예상과 일치/불일치 — 일치면 "왜 그런지", 불일치면 "왜 어긋났는지"

4. 상세 설명 (처음 보는 사람도 이해 가능 — 친절한 학술 산문 톤)
   - 배경 (왜 이 실험이 필요했나, 어떤 의문이 있었나)
   - 방법론 (구체적으로 무엇을 어떻게 측정했나, 용어 풀어서)
   - 결과 (수치 + 통계적 유의성 + 비교 표)
   - 의의 (이 결과가 RQ 와 어떻게 연결되며, 다음 단계로 어떻게 이어지나)

5. 발표/보고서 narrative 보강 포인트
   - 발표 슬라이드 / 보고서 어디에 녹일 것인가
   - 박세은님 의문 5가지 중 어느 것을 강화하나
     · Normal vs Skew BERN 직접 비교 부재
     · Exqutor 결함 ↔ q-error 인과 chain
     · KM ≈ 인덱스 비판
     · 사전 계산 비용 비판
     · iff → 필요조건 표현

6. 다음 실험 연결 (선택)
   - 이 결과를 받아서 다음 실험은 무엇을 보강해야 하나

(선택) Cohen's d 효과 크기 + BH-FDR 다중 비교 보정 + 시각화 (PNG) 까지 함께 산출

raw 데이터 경로: ___
관련 설계안: plans/RQ재정립_20260505_2122.md

```
RQ1 보강 실험 — SIFT × SYSTEM(block) baseline 측정 진행.

[동기]
- 박세은 팀장이 "Normal vs Skew BERN baseline 직접 비교 부재" 의문 제기.

[측정 조건]
- 데이터셋: SIFT 1.5M
- 샘플링 모드: TABLESAMPLE SYSTEM (block 단위)
- selectivity: 1%, 5%, 10%, 30%, 50% (5 점)
- seed: 5 / query: 100 / sample_size: 385

[기존 자료]

- SIFT BERNOULLI: experiments/results/rq1_motivation/phase7_sift_bern.parquet
- 측정 인프라: experiments/code/rq1/

[예상 결과]

2. vector.c 의 sample 배분 weight 수정 (~50줄):

3. GUC 추가: vector.allocation_method = 'proportional' | 'neyman'

[기존 자료]
- KM20 Proportional: experiments/results/rq1_motivation/phase6_strat_km20_native.parquet

### #5 — RQ3: C. Random Projection (~2h)

```
RQ3 — C. Random Projection 구현 + 측정 진행.

[동기]
- 분포 모를 때 가장 단순한 distribution-agnostic 방법.
- Johnson-Lindenstrauss lemma (1984): 랜덤 단위벡터 사영이 거리를 ε 이내로 보존.
- 7-way 비교의 "최단순 하한선" 역할 — 다른 방법들이 이보다 나음을 보이는 baseline.
- RQ2 의 KM20 oracle 을 분포 정보 없이 얼마나 회수하는가의 출발점.

[확인하려는 것]
- H3-C: 1D 랜덤 사영으로 KM20 의 일부 (10~40%) 를 회수할 수 있는가?
- recovery_rate = (C − RANDOM20) / (KM20 − RANDOM20)

[예상 결과]
- recovery_rate 10~40%
- 1D 사영으로는 다차원 구조 포착 한계 → RANDOM20 과 큰 차이 없을 수도
- "최단순 방법도 RANDOM20 보다는 낫다" 정도 입증되면 충분.

[측정 조건]
- 데이터셋: DEEP 1M, SIFT 1.5M
- selectivity 5점 × 5seed × 100query
- 비교: RANDOM20 ≤ C ≤ KM20 예상

[구현]
1. Python ~50줄:
   - r = np.random.randn(d), r /= np.linalg.norm(r)
   - 각 행에 대해 v · r 계산
   - K=20 quantile 로 stratum_id 할당
2. DB UPDATE: SET stratum_id = 새 값
3. 기존 KM20 측정 파이프라인 재활용

측정 시작 도와줘.
```
