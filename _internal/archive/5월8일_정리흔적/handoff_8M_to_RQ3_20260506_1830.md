## 2. ★ 측정 운영 가이드 — 병렬 vs 순차

### 2.1 병렬 가능 여부 — 세부 분석

| 차원 | 병렬 가능 | 근거 |
|------|----------|------|
| PG connection | ✅ 가능 | read-only, max_connections 충분, fresh conn per cluster 패턴 |
| numpy compute | ✅ 가능 | process 별 독립 BLAS, CPU 분할 |
| 메모리 | ⚠️ 주의 | 측정 1 process ≈ 500MB (cache 0.4GB + numpy buffer). 서버 RAM 32GB+ 면 4 process OK |
| Disk I/O (cluster cache fetch) | ⚠️ 중복 | 같은 dataset 을 여러 process 가 fetch 하면 같은 데이터 중복 (PG buffer cache 가 완화) |
| vector.c 누수 | ✅ 무관 | Python 시뮬레이션이라 vector.c 패치 안 씀 |

### 2.2 권장 운영 시나리오

#### 시나리오 A — Dataset 분할 병렬 (★ 권장)

```
Process 1: DEEP 만 측정 (모든 mode 순차)
Process 2: SIFT 만 측정 (모든 mode 순차)
```

**장점**:
- cache fetch 가 dataset 별 1회 (각 process 가 자기 dataset 만 fetch)
- 메모리 ≈ 1GB, CPU 분할 효율적
- 시간 ≈ DEEP + SIFT 의 max ≈ DEEP 시간 ≈ 절반

**실행**:
```bash
# Terminal 1
cd /mnt/hdd0/home/capstone2026/cache
nohup python3 -u rq3/measure_offline.py --datasets DEEP --out-prefix rq3_offline_deep \
  > logs/measure_offline_deep.log 2>&1 &

# Terminal 2 (동시)
nohup python3 -u rq3/measure_offline.py --datasets SIFT --out-prefix rq3_offline_sift \
  > logs/measure_offline_sift.log 2>&1 &

# 완료 후 합치기
python3 -c "
import pandas as pd
d = pd.read_parquet('cache/rq1/rq3_offline_deep.parquet')
s = pd.read_parquet('cache/rq1/rq3_offline_sift.parquet')
pd.concat([d, s]).to_parquet('cache/rq1/rq3_offline.parquet', index=False)
"
```

#### 시나리오 B — Mode 분할 병렬 (비권장)

```
Process 1: measure_offline.py (offline 알고리즘들)
Process 2: kde_pilot.py (online)
Process 3: distance_shell.py (online)
```

**단점**:
- 같은 dataset 의 cache 를 3번 fetch (중복)
- 메모리 ≈ 1.5GB
- PG buffer cache 가 완화하지만, cold cache 일 때 첫 fetch 가 ~1분 추가

**적용 가능**: cache 가 이미 PG buffer 에 올라온 상태 (warm), 또는 시간 매우 부족할 때.

#### 시나리오 C — 완전 순차 (안전)

```
Process 1: DEEP+SIFT 모든 mode 순차 측정
```

**장점**: 가장 단순. 시간 ≈ 모든 mode 합산.

**적용**: 메모리 부족 또는 다른 작업 동시 진행 시.

## 4. 측정 결과 → Recovery Rate 분석

### 4.1 분석 흐름

```python
import pandas as pd
import numpy as np
from experiments.code.local_analysis.recovery_rate import (
    recovery_rate, paired_wilcoxon_with_bh_fdr,
)

# 1. 측정 결과 로드
offline = pd.read_parquet("cache/rq1/rq3_offline.parquet")
# kde = pd.read_parquet("cache/rq1/rq3_kde_pilot.parquet")
# all_methods = pd.concat([offline, kde, ...])

# 2. cell 별 mean q_error 집계
agg = offline.groupby(["dataset", "mode", "selectivity"])["q_error"].mean().reset_index()

# 3. recovery_rate 계산 (각 mode vs km20 / random20)
pivot = agg.pivot(index=["dataset", "selectivity"], columns="mode", values="q_error")
for method in ["minibatch", "random_proj", "hilbert"]:
    pivot[f"rr_{method}"] = pivot.apply(
        lambda r: recovery_rate(r[method], r["random20"], r["km20"])[0], axis=1
    )

# 4. paired Wilcoxon + BH-FDR (BERN 대비 / KM20 대비)
results_bern = paired_wilcoxon_with_bh_fdr(
    offline, compare_pairs=[("minibatch", "bernoulli"), ("hilbert", "bernoulli"), ...]
)
```

## 6. 주의 사항 — 함정 회피

### 6.1 cache fetch 의 메모리 누수

PG vector::real[] cast 의 누적 누수 → **cluster 마다 fresh connection** (`with psycopg.connect(...) as c:`) 사용. 이미 모든 wrapper 가 이 패턴 적용됨.

### 6.2 sklearn PCA RuntimeWarning

Hilbert 의 PCA fit/transform 시 toy 또는 단일-cluster 데이터에서 RuntimeWarning (divide by zero) 가능. 실제 1M 데이터에선 안 발생. measure_offline.py 가 `warnings.catch_warnings` 로 suppress.

### 6.3 stratum_id_hilbert 컬럼 추가 X

Hilbert/MiniBatch/RandProj 등은 in-memory 만. DB 에 새 컬럼 안 만듦. 측정 시 cache 에서 직접 stratify.

### 6.4 caffeinate 휴면 방지

```bash
pgrep -lf caffeinate || nohup caffeinate -dimsu >/dev/null 2>&1 & disown
```

서버는 항시 작동 상태이므로 무관.
