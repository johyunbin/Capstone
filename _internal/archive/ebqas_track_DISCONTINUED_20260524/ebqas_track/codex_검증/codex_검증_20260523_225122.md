## 2. 축별 정밀 정리 (verbatim carry)

### 2.1 (a) 수학 정확성 — concern (0.86)

**Codex 핵심 finding 3건 verbatim**:

1. Beta-Binomial posterior `Beta(α+s, β+n-s)`와 posterior mean 가중평균 표현은 맞습니다. 근거: 제안서 line 212, line 383, Bayes Rules Ch.3.
2. B1 MSE, EB MSE, EB<B1 조건도 Bernoulli approximation·fixed n·unbiased current sample 조건에서는 맞습니다. 단 "대략"이 아니라 해당 가정 아래 정확한 대수 조건입니다.
3. `n_EB ≈ n_B1 - κ`는 heuristic입니다. without replacement, finite population correction, optional stopping, prior bias가 들어가면 그대로 보장되지 않습니다.

**Codex 정정 권고 3건 verbatim**:

1. 수식 앞에 가정: Binomial approximation, fixed n, unbiased Bernoulli sample, relevant prior, optional stopping 제외를 명시.
2. "current-query posterior conjugacy"와 "history에서 α,β를 만드는 empirical pseudo-count update"를 분리해 쓰기.
3. 제안서 수식의 `=======`, `# N p_hat` 같은 렌더링 깨짐을 활성화 전 정정.

**본 트랙 적용 노트**: 권고 3은 사용자 제공 verbatim 본문(정본 anchor §5·§6) — 렌더링 깨짐은 카톡 paste 시 코드블록 인코딩 손실. 활성화 시 LaTeX 수식 정제 작업 별도. 권고 1·2는 정본 anchor 머리말 §환각·정합성 점검에 추가 가능.

### 2.2 (b) ★ 안전장치 충분성 — fail (0.91)

**Codex 핵심 finding 3건 verbatim**:

1. mismatch reset이 실제로 B1으로 수렴하지 않습니다. 의사코드는 mismatch 때 `κ *= γ` 후 곧바로 `κ ← ρ·κ + w`를 적용합니다. 기본값 `ρ=0.95, γ=0.5, w=10`이면 반복 mismatch에서도 κ는 0으로 가지 않고 약 `10/(1-0.475)=19.0` 근방으로 수렴합니다. 근거: 의사코드 line 227, 235, 257.
2. "B1 수준 fallback"은 문장으로만 있고, explicit mode switch가 없습니다. group key 부적절·prior drift·hyperparam 오류 시 안전 보장은 아직 spec 수준에서도 미증명입니다.
3. `L = max(L, 1/(10N))` floor는 overflow 방지에는 필요할 수 있으나, early stopping 판단에 쓰이면 posterior risk를 과소평가할 수 있습니다.

**Codex 정정 권고 3건 verbatim**:

1. mismatch N회 이상이면 `prior_mode=no_history`, `κ=0 또는 2`, `early_stop=False`로 B1 cap까지 샘플링하는 명시적 fallback 추가.
2. mismatch가 발생한 query에서는 `w` update를 skip하거나 별도 낮은 `w_mismatch`를 사용.
3. `Q_post` 계산의 numerical floor는 logging용과 stop decision용을 분리.

**본 트랙 적용 노트**: 본 finding은 spec 수준에서도 알고리즘 동작 반례 — `κ ← ρ·κ + w`의 fixed point가 `w/(1−ρ) ≈ 19`이므로 mismatch가 반복돼도 κ가 0에 가까워지지 않아 prior 영향이 잔존. 정본 anchor §10.4·의사코드 §4.2 mismatch reset 식을 활성화 시 explicit mode switch로 재설계 필수. 본 보고서는 활성화 전 spec patch의 최우선 항목으로 carry.

### 2.3 (c) paired 비교 통제 — concern (0.82)

**Codex 핵심 finding 3건 verbatim**:

1. 4-way matched 구조와 동일 `seed/query_set/trial_idx/query_idx` 통제는 잘 잡혀 있습니다. 근거: 실험 A spec line 250.
2. CaseB가 `method_name`을 필요로 하는데, 실험 A의 "CaseB"가 어느 method의 CaseB인지 고정되어 있지 않습니다. 비교 baseline이 흔들릴 수 있습니다. 근거: measure_paper_exact.py line 1087.
3. Cliff's δ는 독립 표본 효과크기로 쓰이는 경우가 많아 paired 설계와 약간 어긋납니다. paired delta 분포에는 matched rank-biserial 또는 sign-based effect size가 더 직접적입니다.

**Codex 정정 권고 3건 verbatim**:

1. CaseB comparator를 `strong-13 aggregate`, 특정 대표 method, 또는 CaseC dual-Bernoulli 중 무엇으로 둘지 사전 고정.
2. output을 query-level row로 저장해 `cell, trial_idx, query_idx` join invariant를 테스트.
3. Wilcoxon + paired bootstrap CI + matched rank-biserial/sign delta로 통계축 정리.

**본 트랙 적용 노트**: 권고 1은 활성화 시 사용자 결정 영역 — 본 EB-QAS 트랙에서는 v14 CaseC dual-Bernoulli 통제군이 메인 트랙 paused이므로 strong-13 aggregate 또는 대표 method 중 사전 고정 권고. 권고 3의 matched rank-biserial은 실험 A spec §4.2의 통계량 리스트에 추가.

### 2.4 (d) leakage 방지 — concern (0.84)

**Codex 핵심 finding 3건 verbatim**:

1. 현재 query true cardinality는 실행 후에만 prior update, current sample double counting 금지, 전체 평균 selectivity prior 금지 규칙은 명확합니다. 근거: 실험 A spec line 272, 의사코드 line 281.
2. 다만 `threshold_bucket`을 "dataset별 quantile"로 만들거나 예시 group을 `sel=0.001`로 표기하는 부분은 위험합니다. 실제 optimizer가 모르는 target selectivity label을 group key에 넣으면 leakage입니다.
3. `Q-error`는 true cardinality 이후에만 계산 가능하므로, current query의 stop/update에 절대 쓰이지 않는다는 assert가 필요합니다.

**Codex 정정 권고 3건 verbatim**:

1. group key는 query text, threshold D, template, predicate signature만으로 생성. target `sel` label 사용 금지.
2. quantile bucket을 쓰려면 train-only threshold distribution인지, 아니면 단순 log-scale D bucket인지 명시.
3. prequential evaluation으로 보고: query t 평가는 t-1까지의 history만 사용.

**본 트랙 적용 노트**: 본 trakhc 실험 B outline §1.3의 “Group 1: DEEP × sel=0.001 × Q1” 식 표기는 benchmark 분석 label이며 runtime group key가 아니다. 활성화 시 명시 — 표기 분리(benchmark label vs runtime group key) 필요. threshold_bucket은 단순 log-scale D bucket으로 명시하거나 train-only quantile 명시. assert는 measure_ebqas 구현 시 unit test.
