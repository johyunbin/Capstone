- 발표 자료 제출 마감 관리 → 제출물지침

### Phase 1: 슬라이드 구조 설계 (10분)

발표 유형에 맞는 슬라이드 구조를 설계한다.

- [ ] 샘플 PPT 구조 분석 (섹션 수, 슬라이드 수, 시간 배분)
- [ ] 아래 기본 구조를 발표 유형에 맞게 조정

**중간발표 기본 구조 (10~12슬라이드):**

| # | 슬라이드 | 시간 | 핵심 메시지 |
|---|----------|------|-------------|
| 1 | 표지 | — | 팀명(속도는벡터), 주제, 팀원 4명 |
| 2 | 연구 배경 | 1.5분 | VAQ 문제 정의 + pgvector 한계 |
| 3 | 관련 연구 | 1.5분 | Exqutor, VBASE, DuckDB 비교 |
| 4 | 본 논문 핵심 | 2분 | ECQO + Adaptive Sampling 요약 |
| 5 | 연구 방법론 | 2분 | Cascaded Vector Similarity Decomposition |
| 6 | 실험 설계 | 2분 | 데이터셋, 지표, 비교축 |
| 7 | 현재 진행 상황 | 1분 | 환경 구축, 예비 실험 |
| 8-9 | 중간 결과 | 2분 | 있으면 차트/표, 없으면 예비 분석 |
| 10 | 향후 계획 | 1분 | 남은 실험 + 일정 |
| 11 | 참고문헌 | — | 주요 논문 5~10편 |
| 12 | Q&A | — | 예상 질문 대비 |

**최종발표 추가 슬라이드:**
- 전체 실험 결과 (3~5슬라이드 추가)
- 결론 + 기여 (1슬라이드)
- 한계 + 향후 연구 (1슬라이드)

**전시회 포스터 (A0/A1 기준):**
- 제목 + 팀 정보
- 배경·동기
- 방법론 다이어그램
- 핵심 실험 결과 (차트 2~3개)
- 결론 + QR코드(GitHub)

- [ ] 슬라이드 구조 확정 → md 파일로 저장

출력 파일: `submission/발표/{유형}_슬라이드구조.md`

### Phase 2: 슬라이드 내용 작성 (20분)

각 슬라이드의 실제 내용을 작성한다.

- [ ] plans/ 최신 설계안에서 연구 방법론 내용 추출
- [ ] reference/analysis/ 시리즈 분석에서 관련 연구 내용 추출
- [ ] 각 슬라이드별 핵심 메시지 1개 + 보조 포인트 2~3개 작성

작성 규칙:
- 슬라이드 1장 = 핵심 메시지 1개 (텍스트 5줄 이하)
- 차트/표/다이어그램이 필요한 슬라이드 식별 + 데이터 소스 명시
- 전문 용어 첫 등장 시 한영 병기

- [ ] 실험 결과 시각화 계획 (차트 유형 + 데이터)
  - 성능 비교: 막대 그래프 (QPS, latency)
  - 선택도별 변화: 라인 차트
  - 실행 계획 비교: 표
- [ ] 다이어그램 필요 부분 목록화
  - 시스템 아키텍처 (Exqutor 구조)
  - Cascade Decomposition 흐름도
  - 실험 파이프라인

출력 파일: `submission/발표/{유형}_슬라이드내용.md`

### Phase 3: 발표 스크립트 (10분)

슬라이드별 발표 대본을 작성한다.

- [ ] 전체 발표 시간 확인 (Phase 0에서 결정)
- [ ] 슬라이드별 시간 배분 (Phase 1 표 기준)
- [ ] 각 슬라이드에 30초~1.5분 분량의 대본 작성

스크립트 형식:
```markdown
## 슬라이드 N: {제목} ({시간})

{대본 텍스트}

**강조 포인트**: {청중이 반드시 기억해야 할 1가지}
**전환 멘트**: {다음 슬라이드로 넘어가는 연결 문장}
```

- [ ] 전체 분량 검증: 대본 글자수 ÷ 분당 300자 = 예상 시간
- [ ] 시간 초과 시 내용 축약 조정

출력 파일: `submission/발표/{유형}_발표스크립트.md`

### Phase 4: 포스터/팜플렛 (전시회 시) (15분)

전시회 발표인 경우에만 실행한다. 중간/최종 발표이면 건너뛴다.

- [ ] 전시회 여부 확인 (Phase 0 결과)
- [ ] 포스터 크기 결정 (A0 841×1189mm / A1 594×841mm)
- [ ] templates/samples/포스터/ 샘플 구조 분석
- [ ] 레이아웃 설계:
  - 상단: 제목 + 팀 정보 + 학교 로고
  - 좌측: 배경 + 방법론
  - 중앙: 핵심 결과 차트
  - 우측: 결론 + 참고문헌
  - 하단: QR코드(GitHub) + 팀원 연락처
- [ ] 포스터 텍스트는 슬라이드 내용의 50% 이하로 압축
- [ ] 팜플렛: A4 3단 접지 기준, 포스터 핵심만 재배치

출력 파일: `submission/발표/전시회_포스터레이아웃.md`

### Phase 5: 리허설 체크리스트 + Q&A 준비 (5분)

- [ ] 리허설 체크리스트:
  - [ ] 발표 시간이 제한 시간 이내인가?
  - [ ] 슬라이드 전환이 자연스러운가? (전환 멘트 확인)
  - [ ] 차트/표가 멀리서도 읽히는 크기인가?
  - [ ] 백업 슬라이드 준비했는가? (상세 데이터, 추가 실험)
  - [ ] 발표자 노트가 슬라이드에 포함되었는가?
  - [ ] 팀원 역할 분담 (발표자, 질의응답, 시연)

- [ ] Q&A 예상 질문 + 답변 준비 (최소 10개)

예상 질문 카테고리:
1. **방법론**: Cascade Decomposition의 구체적 작동 원리
2. **실험 설계**: 왜 이 데이터셋/지표를 선택했는가
3. **결과 해석**: 성능 차이의 원인은?
4. **한계**: 어떤 상황에서 효과가 없는가
5. **비교**: 기존 방법(pgvector, VBASE) 대비 장단점
6. **확장성**: 대규모 데이터셋에서의 성능
7. **실용성**: 실제 서비스 적용 시 고려사항

출력 파일: `submission/발표/{유형}_리허설체크리스트.md`
