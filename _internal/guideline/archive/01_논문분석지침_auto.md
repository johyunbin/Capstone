# 논문분석지침 (AUTO)

> 대상: Capstone 프로젝트 | 모드: 자동 실행 (전권 위임)
> 마지막 실행: (미실행)

## 논문분석지침의 범위

**IS (이 지침이 하는 것):**
- research/papers/ 원논문 PDF 읽고 총정리 md 작성 → research/summaries/
- 시리즈 분석(그룹 비교/통합) md 작성 → research/analysis/
- 논문 번호 부여 규칙 관리: summaries `[0]`~`[N]`, analysis `(01)`~`(NN)`
- 분석 품질 체크리스트 검증 (배경/기법/실험/한계/데이터셋/메트릭)
- 논문 간 관계 매핑 (인용, 대조, 확장, Exqutor와의 연결고리)

**IS NOT (이 지침이 하지 않는 것 → 담당 지침):**
- md → PDF 변환 실행 → 문서생성지침
- PDF 폰트 검증, 파일 무결성 → 점검지침
- 실험 재현, 벤치마크 실행 → 실험지침
- 미팅용 심층분석 가공 → 미팅지침 (논문분석 결과를 기반으로 가공)
- 제출물 양식 작성 → 제출물지침

## Phase 구성

### Phase 0: 인벤토리 + 번호 확인 (2분)

현재 논문 분석 현황을 파악한다.

- [ ] research/papers/ 원논문 수 카운트
- [ ] research/summaries/ 총정리 md 수 카운트 + 현재 최대 번호 확인
- [ ] research/analysis/ 시리즈 분석 수 카운트 + 현재 최대 번호 확인
- [ ] 미분석 논문 식별 (papers에는 있지만 summaries에 없는 논문)

인벤토리 수집:
```bash
cd ~/Capstone
echo "papers: $(ls research/papers/*.pdf 2>/dev/null | wc -l)"
echo "summaries md: $(ls research/summaries/*.md 2>/dev/null | wc -l)"
echo "analysis md: $(ls research/analysis/*.md 2>/dev/null | wc -l)"

# 현재 최대 번호
echo "summaries 최대번호: $(ls research/summaries/*.md | sed -E 's/.*\[([0-9]+)\].*/\1/' | sort -n | tail -1)"
echo "analysis 최대번호: $(ls research/analysis/*.md | sed -E 's/.*\(([0-9]+)\).*/\1/' | sort -n | tail -1)"
```

다음 할당 번호:
- summaries: `[현재최대+1]` (현재 [0]~[81] → 다음 [82])
- analysis: `(현재최대+1)` (현재 (01)~(12) → 다음 (13))

### Phase 1: 대상 논문 선택 + 읽기 (10분)

- [ ] 사용자가 지정한 논문 확인, 없으면 미분석 논문 중 우선순위 제안
- [ ] 원논문 PDF 읽기 (research/papers/ 또는 사용자 제공 경로)
- [ ] 핵심 구조 파악: 제목, 저자, 출처, 연도, 주제 분류

우선순위 기준 (사용자 미지정 시):
1. Exqutor 직접 인용 논문 (본 논문 레퍼런스)
2. VAQ/벡터 DB 최적화 관련 논문
3. 벤치마크/실험 방법론 논문
4. 기타 관련 논문

### Phase 2: 총정리 md 작성 (15분)

한국어 학술 산문 스타일로 총정리 문서를 작성한다.

- [ ] 파일명 결정: `[번호] 논문제목_키워드 총정리.md`
- [ ] 저장 경로: `research/summaries/`
- [ ] 필수 섹션 모두 포함

#### 필수 문서 구조

```markdown
# [논문 제목] 총정리

**논문 제목:** [원제]
**저자:** [저자 목록]
**출처:** [학회/저널/arXiv]
**발행 연월:** [YYYY년 MM월]

---

## 요약

### 연구 문제
(배경 맥락 → 기존 접근의 한계 → 이 논문이 해결하려는 문제)

### 핵심 기술 과제
(구체적 기술 과제 서술)

### 본 논문의 접근법
(제안 기법을 번호 매겨 설명: O1, O2...)

### 주요 기여 및 성과
(정량 결과 포함)

---

## 상세 분석

### 실험 설계
- 데이터셋: (이름, 크기, 차원, 특성)
- 하드웨어: (CPU, RAM, GPU, 스토리지)
- 비교 대상(baseline): (시스템/알고리즘 목록)
- 핵심 메트릭: (Recall@k, QPS, latency 등)

### 실험 결과
(표/수치 기반 결과 서술)

### 한계점 및 미해결 문제
(저자 인정 한계 + 리뷰어 관점 한계)

---

## Exqutor와의 연결고리
(본 논문이 Exqutor 연구와 어떻게 관련되는지)

## 핵심 용어 정리

| 용어 | 정의 |
|------|------|
| ... | ... |
```

#### 작성 규칙

- **한국어 학술 산문** 선호, bullet 나열 지양
- 배경 맥락 → 핵심 아이디어 → 번호 매긴 기법 → 후속 질문
- 데이터셋, 하드웨어 스펙, baseline, 핵심 메트릭 — **반드시 포함**
- 피상적 요약 지양. 실험 조건과 한계까지 다룰 것
- Exqutor 본 논문과의 관계 반드시 서술

### Phase 3: 시리즈 분석 작성 (선택, 그룹 분석 시) (20분)

여러 총정리를 종합한 비교/통합 분석. 사용자가 요청하거나 관련 논문 3편 이상 축적 시 수행.

- [ ] 대상 총정리 선정 (공통 주제/기법으로 묶이는 논문들)
- [ ] 파일명 결정: `(번호) 제목.md`
- [ ] 저장 경로: `research/analysis/`

시리즈 분석 유형:
- **상세분석**: 개별 논문 심층 비교 (예: `(09) [1] AnalyticDB-V_미팅준비_심층분석.md`)
- **통합요약**: 그룹 전체 종합 (예: `(04) 레퍼런스6편_통합요약.md`)

시리즈 구조:
```markdown
# [시리즈 제목]

## 분석 대상
- [번호1] 논문제목1
- [번호2] 논문제목2
...

## 공통 문제 인식
## 접근법 비교
| 논문 | 핵심 기법 | 장점 | 한계 |
|------|----------|------|------|
...

## 실험 조건 비교
## 종합 시사점
## Exqutor 연구에의 함의
```

### Phase 4: 품질 체크 + PDF 변환 요청 (3분)

작성된 md 문서의 품질을 체크리스트로 검증한다.

- [ ] 품질 체크리스트 전항목 통과 확인

#### 품질 체크리스트

| # | 항목 | 확인 |
|---|------|------|
| 1 | 배경/문제 정의가 구체적인가 | ☐ |
| 2 | 제안 기법이 번호 매겨 설명되었는가 | ☐ |
| 3 | 실험 설계(데이터셋/HW/baseline/메트릭) 모두 기재 | ☐ |
| 4 | 정량적 실험 결과가 포함되었는가 | ☐ |
| 5 | 한계점/미해결 문제가 서술되었는가 | ☐ |
| 6 | Exqutor와의 연결고리가 서술되었는가 | ☐ |
| 7 | 핵심 용어 표가 포함되었는가 | ☐ |
| 8 | 파일명이 규칙에 맞는가 (`[N] 제목 총정리.md`) | ☐ |
| 9 | 한국어 학술 산문 스타일인가 (bullet 나열 지양) | ☐ |

- [ ] PDF 변환 실행: `python3 scripts/md2pdf.py research/summaries/[파일명].md`
- [ ] 변환 결과 확인 (동일 디렉토리에 .pdf 생성)

**주의**: PDF 변환은 Chrome CDP 방식만 사용. fpdf2 사용 금지.
