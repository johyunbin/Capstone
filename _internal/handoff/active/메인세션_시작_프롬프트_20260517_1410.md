## 3. 작업 방식 — plan-first 병렬 에이전트 2단계

handoff v34 §8 의 방식을 따른다.

1. **1단계 plan** — 병렬 에이전트로 작업 A~J 의 상세 plan 을 ExitPlanMode 수준으로 매우 상세하게 작성한다(어떤 파일, 어떤 명령, 어떤 검증).
2. **취합** — 메인 세션이 에이전트 plan 산출물을 직접 읽고 취합한다. 작업 간 의존성(A → B/C/I)을 정리하고 순서를 확정한다.
3. **2단계 implement** — 취합한 plan 으로 다시 병렬 에이전트로 구현한다.
4. **검증** — 메인 세션이 에이전트 결과를 반드시 직접 확인한다(parquet 재계산·파일 존재·로그 점검). 에이전트 산출물을 검증 없이 신뢰하지 않는다.

순서 권장 — A 먼저 단독 실행 → 결론에 따라 B·C 측정 launch(background) + D 모니터링 → 측정 도는 동안 E·F·G·H 정리 작업 병렬 → 측정 완료 후 I·J.
