## 1. 본 연구 framing (불변 — 가장 먼저 내재화)

본 연구는 Exqutor 논문(arXiv:2512.09695v2) 재현이 아니다. 카디널리티 추정 파이프라인에서 **표본 선택(sample selection) 단계 하나**의 개입(무작위 Bernoulli → 분포 인지 stratification)이 추정 오차(Q-error)에 미치는 영향을 전 변인에 걸쳐 검증한 완전 실험 — 3-way matched B1(기존)·CaseA(완전 대체, 음성 대조군)·CaseB(결합, 산술평균). 발표물은 코드명(B1/CaseA/CaseB)·"영역" 필러·영어 메타 라벨·수식 노출 금지.

## 2. 「엔진 적용 검증」 실험이란 (불변 전제)

오프라인 1508측정은 결합(CaseB)이 Q-error를 **89.1%에서** 줄임을 입증했으나 Q-error는 **중간 지표**다. 본래 목적 — *정확한 추정 → 더 나은 실행 계획 → 더 빠른 쿼리*(Exqutor 핵심 주장) — 의 고리를 오프라인 실험은 닫지 않았다. 이 실험은 **검증된 추정치를 실제 PostgreSQL에 주입**해 "추정치 → 실행 계획 → end-to-end latency"를 닫는다. 엔진(서버 PostgreSQL) 고정, **카디널리티 추정치만 유일 변인**. 4조건:

| 조건 | 의미 | GUC (§4.1) |
|---|---|---|
| 기본 엔진 | 플래너 default selectivity (개입 없음) | `vector.disable_estimation=on` |
| 베이스라인 | 논문 무작위 Bernoulli 추정 est_B1 | `vector.injected_card=<est_B1>` |
| 결합 | 우리 결합 추정 est_CaseB = (est_b1+est_method)/2 | `vector.injected_card=<est_CaseB>` |
| 오라클 | 참 카디널리티 true_card (이론적 상한) | `vector.injected_card=<true_card>` |

측정 사슬: Q-error(오프라인 기검증) → 실행 계획 변화 → end-to-end latency. 6/11 최종 보고서에 반영(5/26 deck·5/28 포스터엔 미반영, 일정상).

### 4.1 주입 메커니즘 (구현·검증 완료)

Exqutor `vector.c`(서버 `/mnt/hdd0/home/capstone2026/Exqutor/PostgreSQL/pgvector/pgvector/src/vector.c`)에 GUC 2개 패치:
- **`vector.injected_card`** (real, default −1.0): ≥0이면 `estimate_cardinality_with_sampling()` 호출을 건너뛰고 그 값을 `estimated_sample_rows`로 써서 base-relation `rel->rows`에 주입.

### 4.4 EXPLAIN ANALYZE 충돌 (Phase 1 설계에 직결)

EXPLAIN ANALYZE는 Exqutor 2-pass(탐지→재플랜→재실행) 하에서 **우리 쿼리가 아닌 Exqutor 내부 SPI 쿼리의 플랜**을 반환한다(injected_card=-1 → 샘플링 쿼리 `Sample Scan`, injected_card 주입 → `exqutor_qerror` 조회 플랜). 따라서:
- **latency 측정 = 실쿼리를 직접 실행하고 client-side wall-clock timing**(EXPLAIN ANALYZE 금지). 2-pass 오버헤드 포함된 정직한 값.
- **플랜 트리 캡처**(부차 분석 — 플랜 변화 카탈로그용)는 별도 방법 필요 — `auto_explain` 테스트 권장(Phase 1).
