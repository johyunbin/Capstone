## 1. 본 연구 framing (불변 — 가장 먼저 내재화)

본 연구는 Exqutor 논문(arXiv:2512.09695v2) 재현이 아니다. 카디널리티 추정 파이프라인에서 **표본 선택(sample selection) 단계 하나**의 개입(무작위 Bernoulli → 분포 인지 stratification)이 추정 오차(Q-error)에 미치는 영향을 전 변인에 걸쳐 검증한 완전 실험 — 3-way matched B1(기존)·CaseA(완전 대체, 음성 대조군)·CaseB(결합, 산술평균). 발표물은 코드명(B1/CaseA/CaseB)·"영역" 필러·영어 메타 라벨·수식 노출 금지.

## 2. 「엔진 적용 검증」 실험이란 (불변 전제)

오프라인 1508측정은 결합(CaseB)이 Q-error 를 89.1%에서 줄임을 입증했으나 Q-error 는 **중간 지표**다. 본래 목적 — *정확한 추정 → 더 나은 실행 계획 → 더 빠른 쿼리* — 의 고리를 오프라인 실험은 닫지 않았다. 이 실험은 **검증된 추정치를 실제 PostgreSQL 에 주입**해 "추정치 → 실행 계획 → end-to-end latency"를 닫는다. 엔진(서버 PG 55435) 고정, **카디널리티 추정치만 유일 변인**. 4조건:

| 조건 | 의미 | 주입 (정정된 메커니즘 — §4) |
|---|---|---|
| 기본 엔진(baseline) | 플래너 default selectivity | `SET vector.disable_estimation=on` |
| 베이스라인(B1) | 논문 무작위 Bernoulli 추정 est_B1 | `SET vector.injected_card=<est_B1>` |
| 결합(CaseB) | 결합 추정 (est_b1+est_method)/2 | `SET vector.injected_card=<est_CaseB>` |
| 오라클(oracle) | 참 카디널리티 true_card | `SET vector.injected_card=<true_card>` |

측정 사슬: Q-error(오프라인 기검증) → 실행 계획 변화 → end-to-end latency. 6/11 최종 보고서 반영(5/26 deck·5/28 포스터엔 미반영, 일정상).

## 4. ★★ 정정된 주입 메커니즘 — 다음 세션이 반드시 흡수할 핵심

직전 handoff(0054) §4.1 은 "주입 작동 검증 ✅"라 했으나, 그 검증은 **Exqutor 로그에 주입값이 찍힌 것**만 확인했을 뿐 **플랜에 반영되는지·언제 발동하는지**를 확인하지 않았다. 본 세션 recon 이 이를 정밀 규명했다.

### 4.1 Exqutor 주입은 실행 시점 2-pass다 (vector.c 정독으로 확정)
- Exqutor 는 **planner_hook + ExecutorRun_hook** 2단. planner 는 pass-1(기본 selectivity) 플랜만 만든다. `ExecutorRun` 시점에 `check_for_vector_search`가 벡터 술어를 탐지·카디널리티 확정 → **재plan(pass-2)** → 재실행.
- `vector.injected_card`(≥0)는 `check_for_vector_search`(vector.c L666)에서만 읽힌다 → **오직 실행 시점**. 순수 `EXPLAIN`(실행 안 함)은 영원히 pass-1 기본 플랜만 본다 — recon 에서 injected_card 3값 EXPLAIN 이 byte-identical 확인.
- ⇒ **latency 는 실쿼리 직접 실행 + `time.perf_counter()`** (2-pass 오버헤드 포함 정직값). **플랜은 `auto_explain`** 으로 캡처(실행 후 `queryDesc->plannedstmt`가 pass-2 플랜).

### 4.2 ★ 주입은 벡터 테이블이 pass-1 에서 SeqScan 될 때만 발동
- `check_for_vector_search`(vector.c L643-694)는 **SeqScan 분기**에서만 `injected_card`를 쓴다. partsupp 가 pkey **IndexScan**(nested-loop inner)으로 접근되면 주입을 건너뛴다.
- sf1 q3 join 은 partsupp 를 pkey IndexScan → **주입 skip**(recon 실측). sf10 q3 join 은 partsupp 를 Parallel Seq Scan → **주입 발동**(probe 실측 — injection_fired=True 전 조건).
- ⇒ harness 는 측정마다 Exqutor 의 `LOG: Estimated cardinality for range query on table X: <v>`를 포착해 **`injection_fired` 플래그**를 기록한다. false 면 그 측정은 기본 selectivity 플랜이라 **무효** — analyze 가 `MISS`로 표시·경고.
- ⇒ Phase 0 prescan 의 go/no-go 게이트에 직결: sf10/sf100 코어 쿼리에서 injection_fired 가 안 뜨는 쿼리는 코어 매트릭스에서 빼거나 강제 SeqScan 방안 필요.

### 4.3 GUC·세션·테이블 (recon 확정)
- `shared_preload_libraries`가 비어 있다 → **모든 세션이 첫 statement 로 `LOAD 'vector'`** 를 해야 GUC(`vector.injected_card`·`vector.disable_estimation`·`vector.update_sample_size`)가 보인다. plan capture 세션은 `LOAD 'auto_explain'`을 **`LOAD 'vector'`보다 먼저** (훅 체인 순서 — 안 그러면 2-pass 시 auto_explain 이 pass-2 플랜을 못 잡음).
- 모든 측정 세션 `SET vector.update_sample_size=off`(적응형 갱신 차단) + `SET plan_cache_mode=force_custom_plan`.
- 서버 테이블은 전부 `<name>_<sf>` suffix: `partsupp_deep_10`·`customer_10`·`lineitem_10`… → harness 는 세션마다 **임시 VIEW**(`partsupp_deep` + base 7종)를 만들어 VAQ 템플릿을 무수정 실행. (문자열 치환은 q8·q9 가 `nation`을 컬럼 alias 로도 써서 위험 — 임시 VIEW 가 정답.)
- 벡터 테이블: DEEP=`partsupp_deep_<sf>`(96d)·SIFT=`partsupp_sift_<sf>`(128)·SSN=`partsupp_fb_<sf>`(256). HNSW 인덱스 보유(`deep_hnsw_10` 등).
