## 1. 본 연구 framing (불변 — 가장 먼저 내재화)

본 연구는 Exqutor 논문 재현이 아니다. sample selection 단계 개입이 cardinality 추정 Q-error 에 미치는 영향을, 전 데이터셋(DEEP/SIFT/SSN/WIKI/YFCC + concat) + 전 조작 변인(selectivity 0.001/0.01/0.10 · method 16종 · single/multi/concat · scale 1/10/100 · strata K 10/20/30)에 걸쳐 검증하는 완전 실험이다.

측정 3-way: **B1**(대조군 — paper §V-B Bernoulli random sampling) / **CaseA**(실험군·완전 대체 — est=est_method) / **CaseB**(실험군·결합 — est=(est_b1+est_method)/2 산술평균). 16 method = 8 paradigm 대표. AdaptiveState 식 1-6 은 paper 그대로, 개입은 sample selection 단계 하나.

## 5. 결합 규칙 proxy 분석 — 산술평균 우위 (REPORT v13 robustness 용)

CaseB = (est_b1 + est_method)/2 산술평균 외 대안 검토. 1508 JSON 의 standalone B1·CaseA estimates 로 8종 결합 규칙 후처리 비교(`proxy_ensemble_compare.py`, 1220 JSON 시점 실행):

- **산술평균이 capped Q-error 최저** — 기하·조화·가중·min·max 7종 전부 94~100% 측정에서 산술평균보다 나쁨.
- 기하평균: 두 추정기가 **둘 다 과소추정** 경향이라 더 아래로 당기면 악화 + Bernoulli 0-hit 시 `√(0·x)=0` zero-collapse(inf율 1.3%→6.1%, 특히 low sel 치명적).
- 결합 규칙은 AdaptiveState 식 1-6 피드백 루프 안에 있어 충실한 "CaseB-규칙X" 후측정은 불가(서버 재측정 필요) — 단 루프는 나쁜 규칙을 증폭만 하므로 proxy 결론(산술평균)이 뒤집히지 않는다. 재측정 불필요.
- → REPORT v13 에 "7종 대안 검토 → 산술평균이 robust(과소추정+zero-collapse 메커니즘)" 수록.

## 6. 캠페인 N-tuning saga (향후 측정 캠페인 교훈)

sf100 대용량 NPY(A1-SSN 256d 82GB · A9-concat 224d 71GB) 측정에서 메모리 문제 2회:
- **N=8**: `fetch_all_vectors_safe` 가 `np.load`(82GB) + `all_vecs_raw[order]` fancy-index 복사(82GB) → proc 당 peak ~164GB. 8 procs = ~1.3TB ≫ 1TB RAM → OOM/스왑 → 35분/batch.
- **N=4**: 여전히 4×164=656GB+ peak → swap 101GB thrash(so ~900MB/s) → batch 6.5→18분 악화.
- **N=2**: peak ~330GB → 스왑 없음, 안정. 완주.
- 교훈: sf100(특히 256d/224d) 측정은 **proc 당 peak ~2×NPY 크기**, 병렬도는 `N × 2 × NPY < RAM·0.7` 로 잡을 것. launch 스크립트 백업: 서버 `cache/rq3/launch_3way_campaign_5_17.sh.bak_n8_5_17`·`.bak_n4_5_17`.
- 서버 메모리 사건: N=8 구간에 다른 연구실 사용자 코드가 OOM 으로 영향받음 → N=4 전환으로 해소. 향후 sf100 캠페인은 시작부터 N 보수적으로.
