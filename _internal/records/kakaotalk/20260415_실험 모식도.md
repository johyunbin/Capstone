## 실험 타임라인

```
Phase 1~2  │  8개 skewness 지표 × 6 selectivity
(RQ1)      │  → 전부 |상관|< 0.2 → "글로벌 지표로는 쏠림 포착 불가"
           │  → data-side partition 필요성 정당화
           │
Phase 3    │  Exqutor design constraint 5종 발견
           │  → "왜 Exqutor가 이런 구조인지" 학술적 기여
           │
Phase 4    │  Pivot A: block → row sampling 교체
(개선 1)   │  → +3.8~9.6% 개선 (4구간 p<0.001)
           │
Phase 5    │  로컬 skewness 지표 4종 추가 → 역시 무상관
           │  → data-side partition 방향 재확인
           │
Phase 6    │  Pivot C: KM20 stratified sampling 구현
(개선 2)   │  → s=0.500에서 +1.64% (5-seed CI [1.25, 2.02])
           │
   ★ 현재  │  RANDOM20 Control Experiment (오늘 완료)
           │  → "쏠림이 원인임을 증명"하는 대조 실험
```

## ★ RANDOM20 대조 실험 결과 (오늘)

```
실험 설계:
  같은 stratified sampling 코드를 두 가지 partition으로 비교

  KM20 partition          RANDOM20 partition
  ┌─────────────┐         ┌─────────────┐
  │ k-means로    │         │ 무작위로     │
  │ 공간 구조    │         │ 20개 그룹   │
  │ 반영한 20개  │  vs     │ (공간 구조  │
  │ 클러스터     │         │  무시)       │
  └─────────────┘         └─────────────┘

결과 — Selectivity Gradient:

  query 범위    │  KM20 (공간 인식)  │  RANDOM20 (무작위)  │  차이
  ─────────────┼───────────────────┼────────────────────┼──────────
  넓은 (s=0.5) │     +1.64%        │     +2.20%         │  ~0
  중간 (s=0.05)│     +1.85%        │     +0.79%         │  +1.1%p
  좁은 (s=0.01)│   ★ +8.93%        │   ★ -10.67%        │  +19.6%p
  ─────────────┴───────────────────┴────────────────────┴──────────

해석:
  ┌────────────────────────────────────────────────────┐
  │  넓은 범위: 데이터가 전체에 퍼짐                      │
  │  → 아무렇게나 나눠도 OK → 공간 인식 불필요            │
  │                                                    │
  │  좁은 범위: 데이터가 특정 영역에 집중                  │
  │  → 그 영역을 정확히 알아야 함 → 공간 인식 필수        │
  │  → 무작위로 나누면 오히려 악화 (-10.67%)              │
  └────────────────────────────────────────────────────┘
  = 교수님의 "쏠림 → 성능 저하 → 개선" 실험적 확인
```
