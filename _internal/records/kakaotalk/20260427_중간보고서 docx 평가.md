## [수정 1] ECQO 동사 — "추정"이 아니라 "정확 계산" (High)

**원문 (¶2)**:
> "Exqutor 라는 시스템은 이 한계를 해결하기 위해 ECQO(Exact Cardinality Query Optimization)과 Adaptive Sampling 을 이용해서 카디널리티를 **추정한다**."

ECQO 는 이름 그대로 Exact 이므로 추정이 아니라 인덱스 기반 정확 계산. 추정은 Adaptive Sampling 만 해당. 4/25 피드백 1번이 부분만 반영됨.

**제안 수정**:
> "Exqutor 는 이 한계를 인덱스 유무에 따라 두 경로로 해결한다. 인덱스가 있을 때는 ECQO(Exact Cardinality Query Optimization)로 HNSW range query 를 실제로 한 번 실행하여 정확한 카디널리티를 얻고(오버헤드 1.88ms), 인덱스가 없을 때는 Adaptive Sampling 으로 모멘텀 기반 동적 샘플링을 통해 카디널리티를 근사한다."

## [수정 2] Adaptive Sampling 편향의 두 메커니즘 분리 (Mid)

**원문 (¶3)**:
> "Adaptive Sampling 과정에서 모든 데이터가 골고루 포집되지 않고 특정 영역의 데이터만 과대 표집되는 편향이 생긴다. 특히 고차원 벡터 데이터가 특정 구역에 모여있는 경우 (skewness) 추정 정확도가 급락한다."

우리 finding 은 두 개의 별도 메커니즘:
- **(a) Block sampling bias** — `TABLESAMPLE SYSTEM` 이 block 단위(8KB 페이지) 추출이라 row 단위 균일성을 깸 → RQ2-1 로 sanitize
- **(b) Skewed cluster underrepresentation** — 무작위 균일 샘플이 skewed cluster 분포를 대표하지 못해 small-cluster 비례 배분이 무너짐 → RQ2-2 로 sanitize

두 개를 묶어 "편향이 생긴다"고 하면 RQ2-1 / RQ2-2 분리가 흐릿해진다.

**제안 수정**:
> "Adaptive Sampling 의 정확도 저하는 두 별도 메커니즘에서 발생한다. 첫째, `TABLESAMPLE SYSTEM` 의 block 단위 추출이 row 단위 균일성을 깨뜨려 block sampling bias 를 발생시킨다. 둘째, 무작위 균일 샘플이 skewed cluster 분포를 대표하지 못해 small cluster 의 비례 배분이 무너진다. 두 메커니즘은 RQ2-1(BERN sanitize)과 RQ2-2(stratified sampling)로 각각 직교 측정된다."

## [수정 3] hook 우회 부작용 — "정확도 급락"이 아니라 design constraint (Mid)

**원문 (¶4)**:
> "단일 테이블에서 이 기능을 강제로 키기 위해 조건문을 수정하는 경우 다중 테이블을 가정하고 쓰인 코드와 충돌하면서 정확도가 급락한다."

v2 보고서의 정확한 발견:
- hook 우회 시 base relation 이 PostgreSQL `Sample Scan` 으로 plan-tree 가 교체됨
- 단일 테이블 시나리오에서는 outer query 결과 자체가 sample 안 부분 카운트로 격하 (true=100,000 query 에서 `SELECT count(*)` 가 32 반환)
- 추가로 q-error inf 발산 / sample_size NaN 발산 / Adaptive update path SIGSEGV 등 5가지 design constraint 발견

즉 "정확도 급락"이 아니라 outer query 의 의미가 깨지고 update path 가 발산한다.

**제안 수정**:
> "단일 테이블에서 이 조건을 우회하면(`table_count >= 1`로 한 줄 수정) base relation 이 PostgreSQL `Sample Scan` 으로 plan-tree 가 교체되어, outer query 결과 자체가 sample 안 부분 카운트로 격하된다(true=100,000 query 에서 `SELECT count(*)` 가 32 반환). 이외에 q-error inf 발산, sample_size NaN 발산, Adaptive update path SIGSEGV 등 다섯 가지 design constraint 가 발견되었으며, 이는 Adaptive Sampling 의 update path 가 multi-table only design intent 위에 만들어진 결과다."
