## 회의 흐름 (시간순)

### 20:12 — 사용자(조현빈) 흐름 정리 시도
RQ1/RQ2/RQ3 의 이해를 정리하면서 1번에서 "쿼리에 따라 결과가 다르게 나올 수 있는가"를 물었으나, 쿼리만으로는 추론 불가하다는 결론. 2번은 block→row 변경과 KM20 두 단계로 분리, 3번은 분포 모를 때 3 패러다임(Offline/Online/Weight)으로 정리.

### 20:15 — 익스큐터 결함과 q-error 상관 관계 의문
> *"Exqutor 의 하자(결함)와 쿼리를 보고 q-error 를 상관 짓는 것은 연관성이 떨어지지 않는가?"*

논의 결과: 결함 분석은 정성적, q-error 측정은 정량적으로 차원이 다르나, **인과 chain 으로 연결**되어 있음 — 결함 분석이 어떤 변경(intervention)을 할지 결정하고, q-error 가 그 변경의 효과를 측정. narrative 에서 이 chain 을 명시해야 자연스러움.

### 20:17 — 멀티테이블 검증 필요성 제기
> *"Exqutor 와 연관 지으려면 멀티테이블 환경에서 검증을 통해 단일 → 멀티 개선이 이루어지는지 검증 절차가 필요하지 않은가?"*

논의 결과: 비판이 정당하나 멀티테이블 검증은 KM20 의 stratum_id 가 join 후에도 의미를 유지하는지의 이론적 문제부터 다시 풀어야 하는 새 연구 분량. 캡스톤 범위 외. 두 갈래:
- (A) **연구 positioning 재정의** — Exqutor 가 미작동하는 단일테이블 영역에 대한 새 솔루션, 멀티는 future work
- (B) Toy 검증 추가 — 1~2일 정성 분석

→ **(A) 채택**.

### 20:20 — 추가 실험 결정 및 단일→멀티 framing
박세은이 보강 실험 방향 정리:
- 페이지 방식(SYSTEM)과 랜덤 방식(BERNOULLI)을 normal/skew 에서 비교 — 2x2 디자인
- "단일 테이블 카디널리티 예측이 정확해야 멀티에서도 정확" — 단일 정확성을 멀티 정확성의 *필요조건*으로 framing (iff 아님)

이 시점에서 K=20 채택 근거 질문 → Phase 6 Step 3' 에서 K=10 vs K=20 직접 비교 결과 K=20 이 selectivity 0.10 까지 추가 유의 신호 확보. K=50 이상은 sample_size=385 기준 stratum 당 표본이 7~8 개 이하로 떨어져 추정 분산이 폭증.

### 20:35 — 분포 알 때 추가 방법 (RQ2 보강)
> *"한 가지 정도 더 고안해서, 이렇게 하면 성능이 더 좋아질 것 같다 — 분포 알고 있을 때 성능 개선 방식?"*

3 후보 검토 후 **Neyman Allocation** 채택:
- n_i ∝ N_i × σ_i (분산 비례 배분)
- variance-optimal (Neyman 1934)
- 통계학 정통, KM20 위에서 자연스러운 다음 단계
- 구현 ~4시간, 추가 +1~3% 기대

### 20:39 — 인덱스 비판 + 사전 계산 비용 비판
박세은 비판 두 가지:
1. *"인덱스가 없을 때 KM 을 사용하는데, 이 클러스터가 사실상 인덱스를 만드는 것이라 전제 조건 위배 아닌가?"*
2. *"클러스터링 사전 계산 시간이 길면 빠른 쿼리 응답 요구와 충돌, 비효율적이지 않은가?"*

**답변 정리**:
1. KM cluster 라벨 ≠ 인덱스 — HNSW 는 검색 가속용, KM 라벨은 옵티마이저 단계 추정 정확도용. 메모리 1/1000 (4MB vs 수GB). 다만 정당한 비판이라 **Limitation 섹션에 명시**.
2. 사전 계산은 one-time cost (HNSW 빌드와 같은 layer). 쿼리 응답 시점은 stratum lookup O(1). DEEP 1M 1.2초. INSERT 빈번 OLTP 는 본 연구 범위 외 — RQ3 의 F (MiniBatch) 가 부담 1/20~1/100 수준 완화.

→ 두 비판이 정확히 RQ3 의 motivation 강화. "한계 → 다음 단계" 흐름.

### 20:46 — 전체 정리 + 보완 요청
조현빈이 RQ1/RQ2/RQ3 흐름 정리. 박세은 검토:
- "iff" 표현 → "필요조건"으로 정정
- RQ1 메시지 단순화 위험 (skew 정량 + Exqutor 결함 두 축 명시)
- RQ3-2 표현 정확화 ("데이터셋 변하는 상태" → "쿼리 시점 동적 적응")
- Neyman Allocation 추가 결정사항 누락 → 반영
- 누락: RQ3 7가지 방법 명시 / Recovery Rate metric / Limitation 섹션

### 20:54 — Anti-Neyman ablation + Exqutor 대비 효과 약함 지적
박세은이 두 가지 추가:
1. *"네이만 추출을 분산 크기에 반비례할수록 많이 가져가는 방식도 테스트해보면 어때?"*
   → Anti-Neyman 은 variance-suboptimal 이지만 **3-way ablation** (Proportional / Neyman / Anti-Neyman) 으로 묶으면 narrative 강화. "왜 분산 비례가 옳은가" 의 직관 그림.
2. *"Exqutor 에서는 분포 알 때 성능 개선이 많이 되었는데, 지금 2번 실험에서는 그 결과가 약하다"*
   → 단일 테이블 baseline 이 이미 q_error 1.06 수준이라 절대 개선 폭의 상한이 작음. 강화 방안:
     - Selectivity Gradient 강조 (s=1% 에서 격차 19.6%p)
     - Cross-Dataset 비교 (Skew → 효과 2배+)
     - Two-Level Decomposition narrative
     - Sample size sensitivity 추가 실험

### 21:09 — RQ 재정의 제안 (★ 핵심 결정)
박세은이 새 RQ 구조 제안:

```
RQ1. 기존 방식이 skew 상황에서 얼마나 나쁜가?
     → block/row 샘플링을 normal/skew 에 적용해 성능 차이 비교

RQ2. 분포 아는 상황에서 어떤 방식이 최적인가?
     → Neyman 추출 등 성능 더 좋은 방식 찾기

RQ3. 분포 모르는 상황에서 어떤 방식이 최적인가?
     → 후보 방식 7-way 테스트
```

→ **전원 합의**. 박세은이 제기한 "Normal vs Skew 비교 부재" 의문이 RQ1 로 직접 흡수되며, "분포 알 때 vs 모를 때" trade-off 가 RQ2 ↔ RQ3 로 자연스럽게 매핑됨.
