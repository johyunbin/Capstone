# 주간보고지침 (MANUAL)

> 사람이 직접 수행하거나 Claude에게 개별 요청할 때 참조

## 언제 실행하나?

- **매주 금요일** 또는 주말에 이번 주 작업을 정리할 때
- 교수님/자문위원 미팅 전 진행 현황을 파악할 때
- "이번 주 뭐 했지?", "주간보고 만들어줘" 요청 시
- 팀원에게 주간 진행 공유가 필요할 때

## 트리거 키워드

`주간`, `보고`, `이번 주`, `작업일지`, `주간보고`, `weekly`

## 단계별 가이드

### Step 1: 이번 주 커밋 확인

```bash
cd ~/Capstone
git log --since="1 week ago" --oneline --no-merges
```

커밋 메시지에서 핵심 작업을 파악한다. 접두사로 분류:
- `feat:` — 새 기능/문서
- `sync:` — 동기화/정리
- `fix:` — 수정
- `docs:` — 문서 업데이트

### Step 2: 문서 변경 확인

```bash
cd ~/Capstone
git log --since="1 week ago" --name-only --pretty=format:"" -- research/ | sort -u
```

새로 추가된 분석 문서, 수정된 문서를 파악한다.

### Step 3: 분석 진행률 확인

```bash
cd ~/Capstone/research
echo "총정리: $(ls summaries/*.md 2>/dev/null | wc -l) / 82"
echo "시리즈: $(ls analysis/*.md 2>/dev/null | wc -l)"
echo "원논문: $(ls papers/*.pdf 2>/dev/null | wc -l)"
```

### Step 4: 회의록 확인

```bash
ls ~/Capstone/records/meetings/ | tail -5
```

이번 주 회의록이 있으면 핵심 결정사항을 1~2줄로 요약한다.

### Step 5: 노션 동기화

1. **Study Archive DB** — 새 분석 문서가 등록되었는지 확인
2. **캡스톤 일정 DB** — 완료된 마감이 "완료" 상태인지 확인
3. 미반영이면 직접 업데이트하거나 Claude에게 요청

### Step 6: 다음 주 계획

CLAUDE.md의 핵심 일정표에서 다음 마감을 확인하고:
- 우선순위 작업 나열
- 팀원 역할 분담 (4인 팀)
- 블로커가 있으면 기술

### Step 7: 리포트 저장

`records/weekly/주간보고_YYYY-MM-DD.md` 파일로 저장.
형식은 `주간보고지침_auto.md`의 Phase 4 리포트 형식을 따른다.

## 자주 하는 실수

| 실수 | 올바른 방법 |
|------|------------|
| git log 기간을 안 지정해서 전체 이력 출력 | `--since="1 week ago"` 필수 |
| 커밋만 보고 문서 변경을 빠뜨림 | `-- research/` 경로 필터 사용 |
| 노션 동기화를 건너뜀 | Study Archive + 일정 DB 둘 다 확인 |
| 다음 주 계획 없이 보고만 작성 | 반드시 다음 주 계획까지 포함 |
| 팀원 역할 분담 누락 | 4인 팀 기준으로 분담 명시 |

## 관련 지침

| 지침 | 연동 관계 |
|------|----------|
| 미팅지침 | 회의록을 주간보고에서 참조 (미팅 → 주간보고) |
| 점검지침 | 문서 현황 수치를 주간보고에서 활용 가능 |
| 제출물지침 | 마감 일정을 주간보고의 "다음 주 계획"에 반영 |
| 논문분석지침 | 분석 진행률을 주간보고에 포함 |
