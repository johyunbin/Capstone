## 연구설계지침의 범위

**IS (이 지침이 하는 것):**
- 연구 방향 기획안 작성 및 갱신 (plans/연구_기획안_YYYYMMDD_HHMMSS.md)
- 연구 설계안 작성 및 버전 관리 (plans/연구_설계안_YYYYMMDD_HHMMSS.md)
- 실험 설계서: 데이터셋 선정, 평가 지표, 비교축, 대조군 설정
- Cascaded Vector Similarity Decomposition 방법론 상세 설계
- 자문위원/교수님 피드백 반영하여 설계 수정
- 연구 질문(RQ) 정의 + 가설 설정 + 기대 결과 명시
- 설계 확정 시 CLAUDE.md "현재 단계" 업데이트 + 실험지침 연동

**IS NOT (이 지침이 하지 않는 것 → 담당 지침):**
- 실험 실행 (환경 구축, 벤치마크 실행, EXPLAIN ANALYZE) → 실험지침
- 논문 분석 문서 작성 → 논문분석지침 (설계 근거로 "참조"만 함)
- 설계안 md→PDF 변환 → 문서생성지침
- 설계안을 미팅에서 발표/브리핑 → 미팅지침
- 발표 슬라이드에 방법론 배치 → 발표지침

### Phase 1: 연구 질문 정의 (10분)

- [ ] 연구 질문(RQ) 작성 (3개 이내)

RQ 작성 기준:

예시 구조:
```
RQ1: Exqutor의 ECQO가 선택도(selectivity) 변화에 따라
     pgvector 대비 어느 구간에서 가장 큰 성능 이점을 보이는가?
RQ2: Adaptive Sampling의 모멘텀 파라미터가 카디널리티 추정

RQ3: pre-filter / post-filter / hybrid 전략 간 성능 분기점이

```

### Phase 2: 실험 설계서 작성 (20분)

실험의 모든 변수와 조건을 명세한다.

- [ ] 데이터셋 선정 + 선정 이유

| 규모 | 데이터셋 | 차원 | 크기 | 선정 이유 |
|------|----------|------|------|-----------|
| Small | SIFT1M | 128 | 1M | 표준 벤치마크, 재현성 |
| Small | GloVe-100 | 100 | 1.2M | 텍스트 임베딩 대표 |
| Medium | Deep10M | 96 | 10M | 스케일 테스트 |
| Medium | GIST1M | 960 | 1M | 고차원 성능 확인 |
| Large | Deep1B | 96 | 1B | 하드웨어 허용 시 |

- [ ] 평가 지표 정의

| 지표 | 정의 | 측정 방법 |
|------|------|-----------|
| Recall@k | 정확 k-NN 대비 반환 비율 | brute-force vs 인덱스 결과 비교 |
| QPS | 초당 쿼리 처리량 | 1000회 반복 측정, warm-up 제외 |
| Latency p50/p99 | 중위/99퍼센타일 응답 시간 | 동일 1000회 측정 |
| 비용 추정 오차 | EXPLAIN 추정 vs 실제 rows 차이 | EXPLAIN ANALYZE 비교 |

- [ ] 비교축 설계

| 축 | 값 |
|-----|-----|
| 선택도 sweep | 0.1%, 1%, 10%, 50%, 90% |
| 필터 유형 | label(등호), range(범위), compound(복합) |
| 필터 전략 | pre-filter, post-filter, hybrid |
| 인덱스 유형 | IVFFlat, HNSW, 없음(brute-force) |

- [ ] 대조군 설정

| 시스템 | 역할 | 비고 |
|--------|------|------|
| pgvector (vanilla) | baseline | 고정 카디널리티 추정 (33.3%) |
| pgvector + Exqutor | treatment | ECQO/Adaptive Sampling 적용 |
| VBASE | 비교군 | 고정 50% 추정 |
| DuckDB | 비교군 | 100% 추정 |

- [ ] 하드웨어/소프트웨어 스펙 명시
  - CPU/RAM/SSD 스펙
  - PostgreSQL 버전 + pgvector 버전
  - Exqutor 패치 커밋 해시
  - DuckDB 버전
  - Python / NumPy / FAISS 버전

### Phase 3: 방법론 상세화 — Cascade Decomposition (15분)

3단계 실험의 세부 설계를 확정한다.

- [ ] 최신 설계안에서 Cascade Decomposition 현황 읽기
- [ ] 각 단계별 입력/처리/출력/성공 기준 작성

**1단계: 병목 프로파일링**
- 입력: vanilla pgvector + 5개 선택도 × 3개 필터 유형 쿼리
- 처리: EXPLAIN ANALYZE로 실행 계획 수집, 카디널리티 추정 오차 측정
- 출력: 선택도별 오차율 테이블, 병목 구간 식별
- 성공 기준: 선택도 구간별 오차 패턴 도출 (예: 낮은 선택도에서 과대추정)

**2단계: Exqutor 기법 적용**
- 입력: 1단계에서 식별된 병목 쿼리 + Exqutor 패치 적용 pgvector
- 처리: ECQO(인덱스 있을 때) + Adaptive Sampling(인덱스 없을 때) 실행
- 출력: 동일 쿼리의 실행 계획 비교 (before/after), 성능 지표 측정
- 성공 기준: 카디널리티 추정 오차 50% 이상 감소

**3단계: 성능 비교 분석**
- 입력: 2단계 결과 + VBASE/DuckDB 동일 쿼리 결과
- 처리: 시스템 간 QPS/latency/recall 비교, 선택도별 성능 곡선
- 출력: 비교 차트, 통계 검정 (유의미한 차이 확인)
- 성공 기준: 논문 주장(pgvector 1000×, VBASE 10000×) 재현 또는 차이 분석

- [ ] 단계 간 의존성 명시: 1→2→3 순차 필수
- [ ] 각 단계 예상 소요 시간 산정
