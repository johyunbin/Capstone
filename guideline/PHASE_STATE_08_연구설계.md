## Phase 1 결과: 연구 질문 정의 (확정)

> 기존 RQ4(Exqutor 비교)를 RQ3에 흡수 → **3개로 압축** (RQ-단계 1:1 대응, 캡스톤 규모 적합)

### RQ1 — 병목 프로파일링 (→ 1단계)

- **질문**: VAQ에서 플래닝 시간이 전체 지연의 유의미한 비중을 차지하는가? 선택도에 따라 어떻게 변하는가?
- **가설 H1**: 벡터 선택도가 낮을수록(< 1%) Planning Time 비율이 높아진다 (≥ 30%).
- **맞을 때**: Cascade 분해의 전제 조건 성립 → RQ2 진행
- **틀릴 때**: 플래닝은 병목이 아님 → "구조적 pre-filtering으로 실행 시간 최적화"로 재프레이밍 (설계안 IX장 대안 경로)

### RQ2 — 분해의 효과 (→ 2단계)

- **질문**: 벡터 유사도 조건을 느슨→엄격 두 단계로 분해하면 플래닝 시간이 감소하는가?
- **가설 H2**: Cascade 분해 시 Planning Time이 단일 조건 대비 ≥ 20% 감소한다.
- **맞을 때**: 핵심 기여 확보 → RQ3에서 총 비용 분석
- **틀릴 때**: 분해가 오히려 플래닝을 복잡하게 함 → 분해 전략 자체를 재검토

### RQ3 — 총 비용 + Exqutor 비교 (→ 3단계)

- **질문**: Cascade의 총 비용(플래닝 + 실행 + 캐싱)은 단일 검색 및 Exqutor ECQO 대비 어떠한가?
- **가설 H3**: 캐싱이 두 번 검색 오버헤드를 상쇄하여 end-to-end latency가 단일 검색 대비 개선되며, Exqutor와는 상호보완적이다.
- **맞을 때**: Cascade + ECQO 병용 시너지 확인 → 실용적 기여
- **틀릴 때**: 총 비용 악화 → Cascade는 특정 조건에서만 유효, 조건 범위를 결론으로 제시

### 변경 사항

- 기존 RQ4(Exqutor 비교) → RQ3에 흡수 (ECQO를 대조군으로 포함)
- 가설에 수치 기준 명시 (30%, 20%)
- 각 RQ에 실패 시 대안 경로 정의

## Phase 2 결과: 실험 설계서 (필수 6항목)

### ① 데이터셋
- **TPC-H VAQ (SF1)**: 관계형 테이블 + VAQ 8개 쿼리 (Exqutor GitHub 활용)
- **SIFT1M (128d, L2)**: 기본 벡터 데이터, `part`/`orders`에 embedding 컬럼 추가
- **확장용**: sentence-transformers(768d), OpenAI(1536d) — 3-C 고차원 실험
- **선택도 제어**: D 조절 → 0.01%~90% 8단계 sweep, 각 D 값 사전 측정

### ② 평가지표 (7개)
- Planning Time / Execution Time / Total Latency (ms) — `EXPLAIN (ANALYZE, TIMING, FORMAT JSON)`
- Planning Ratio (%) — Planning/Total×100, RQ1 핵심
- Q-error — max(추정/실제, 실제/추정)
- Plan Choice — Index Scan / Seq Scan / 조인 방식
- 캐싱 오버헤드 — CTE 실체화 비용
- **프로토콜**: 5회 반복, 워밍업 1회 제외, 최대값 제거, 3회 평균. 유의미 기준: 총 비용 10%+

### ③ 비교축 (5축)
- 선택도 8단계 / 필터 복잡도 4단계 / ECQO 유무 4전략 / 캐싱 전략 3가지 / 분해 임계값 4조합
- **축소**: Phase 2a(16개, 핵심만) → Phase 2b(24~36개, 유의미한 것 확장)

### ④ 대조군
- Baseline (pgvector 33.3% 고정) / ECQO only / Cascade only / ECQO+Cascade
- ECQO 오버헤드(1~2ms)와 Cascade 오버헤드 모두 Total Latency에 포함 → 공정 비교

### ⑤ HW/SW 스펙
- SW: PostgreSQL 16(패치), pgvector 0.7.x+0.8.0, pg_hint_plan, Python 3.10+
- HW: 옵션 A(연구실 서버, 확인 중) / 옵션 B(개인 머신, SF1 즉시 가능)
- PG 설정: shared_buffers 25%, work_mem 256MB, jit off

### ⑥ 실험절차
- 0단계(환경 구축, 4/1~14) → 1단계(병목 프로파일링, 4/14~28) → 2단계(Cascade 핵심, 4/28~5/15) → 3단계(확장, 5/15~25)
- 각 단위: pg_stat 리셋 → 워밍업 1회 → 본 측정 4회 → 최대값 제거 → 3회 평균
- 실패 대안: Planning≤10% → pre-filtering 재프레이밍 / 분해 효과 없음 → 비용 모델 전환 / Exqutor 빌드 실패 → Baseline vs Cascade 축소

## Phase 3 결과: 방법론 상세화 — Cascade Decomposition

### 1단계: 병목 프로파일링 (RQ1 → H1)

- **입력**: vanilla pgvector + TPC-H VAQ 8쿼리 + SIFT1M(128d)
- **독립변수**: 선택도 8단계 × 필터 복잡도 4단계
- **처리**: `EXPLAIN (ANALYZE, TIMING, BUFFERS, FORMAT JSON)` — 5회 반복, 워밍업 1회 제외, 최대값 제거, 3회 평균
- **출력**: Planning Ratio 곡선, Q-error 곡선, crossover point, 필터별 Planning Time 증가율
- **성공 기준**: Planning Ratio ≥ 30% 구간 존재 → H1 지지
- **실패 대안**: Planning < 10% → "구조적 pre-filtering" 재프레이밍
- **소요**: 4/14~4/28 (2주)

### 2단계: Cascade 핵심 실험 (RQ2 → H2)

- **입력**: 1단계 결과 + Exqutor 패치 적용 pgvector
- **Phase 2a**: 분해 임계값 4 × ECQO 유무 4 = 16조합 (필터 없음, CTE 고정)
- **Phase 2b**: 유의미한 분해 2~3개 × 필터 4 × 캐싱 3 = 24~36조합
- **출력**: 분해 최적점 그래프, 트레이드오프 곡선, ECQO vs Cascade 비교표
- **성공 기준**: Planning ≥ 20% 감소 또는 Total Latency ≥ 10% 개선
- **실패 대안**: 분해 효과 없음 → 비용 모델 전환
- **소요**: Phase 2a 4/28~5/5 (1주), Phase 2b 5/5~5/15 (1.5주)
- **Phase 2a→2b 전환**: 총 비용 10%+ 차이 조합만 선별
- **핵심 판별**: ECQO+Cascade 시너지 여부 (합산 > 개별 합?)

### 3단계: 확장 + Exqutor 비교 (RQ3 → H3)

- **입력**: 2단계 최적 조합 + 확장 데이터셋
- **확장 우선순위**: 3-D(pgvector 0.8.0) > 3-A(top-k) > 3-C(고차원)
- **출력**: 조건별 가이드라인, 확장 결과, 총 비용 breakdown
- **성공 기준**: 캐싱이 오버헤드 상쇄, Exqutor와 상호보완 확인
- **실패 대안**: "특정 조건에서만 유효"를 결론으로 제시
- **소요**: 5/15~5/25 (1.5주)

### 단계 간 의존성

```
1단계 → [Planning ≥20%] → 2단계 원래 프레이밍
     → [Planning <10%] → 2단계 재프레이밍 (pre-filtering)
2단계 → Phase 2a(16) → [10%+ 차이 선별] → Phase 2b(24~36)
3단계 → 2단계 최적 조합 기반 변수 1개씩 추가
순차 필수: 1→2→3
```
