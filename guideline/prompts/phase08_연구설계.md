# Phase 8: 연구설계지침 제작 프롬프트

## 지침 개요

**연구설계 = 연구 방향 수립 + 실험 설계서 작성 + 버전 관리.** 무엇을 연구하고,
어떻게 실험할지를 설계한다. 설계가 확정되면 실험지침에 넘긴다.

## IS / IS NOT

**IS:**
- 연구 방향 기획안 작성 (plans/연구_기획안_*.md)
- 연구 설계안 작성 및 버전 관리 (plans/연구_설계안_*.md)
- 실험 설계서: 데이터셋 선정, 평가 지표, 비교축, 대조군 설정
- Cascade Decomposition 등 방법론 상세 설계
- 자문위원/교수님 피드백 반영하여 설계 수정
- 설계안 확정 → 실험지침 연동

**IS NOT:**
- 실험 실행 (환경 구축, 벤치마크 실행) → 실험지침
- 논문 분석 → 논문분석지침 (설계 근거로 "참조"만)
- 설계안 PDF 변환 → 문서생성지침
- 설계안을 미팅에서 발표 → 미팅지침

## 읽어야 할 프로젝트 파일

1. `CLAUDE.md` — 실험 설계 초안, Exqutor 핵심 요약, 현재 단계
2. `plans/` — 기존 기획안/설계안 전체
3. `submission/1차 자문내역서*.pdf` — 자문위원 피드백
4. `research/summaries/[0] Exqutor*.md` — 본 논문 총정리
5. `research/analysis/(01)~(02)` — Exqutor 상세/통합 분석

## Phase 구성 가이드

### Phase 0: 현재 설계 상태 파악 (3분)
- plans/ 내 최신 설계안 확인
- CLAUDE.md "현재 단계" 확인
- 미반영 피드백 있는지 확인 (자문내역서, 미팅 회의록)

### Phase 1: 연구 질문 정의 (10분)
- 핵심 연구 질문 (RQ) 명확화
- 가설 설정
- 기대 결과

### Phase 2: 실험 설계서 작성 (20분)
**필수 항목:**
- 데이터셋 선정 (이유 포함)
- 평가 지표 정의 (Recall@k, QPS, latency, 비용 추정 오차)
- 비교축 설계 (선택도 sweep, 필터 유형, 전략)
- 대조군 설정 (pgvector baseline, VBASE, DuckDB)
- Exqutor 적용 전/후 비교 설계
- 하드웨어/소프트웨어 스펙 명시

### Phase 3: 방법론 상세화 (15분)
- Cascade Decomposition 단계별 설계
- 1단계: 병목 프로파일링
- 2단계: Exqutor 기법 적용
- 3단계: 성능 비교 분석
- 각 단계의 입력/출력/성공 기준

### Phase 4: 피드백 반영 + 버전 관리 (5분)
- 자문위원/교수님 피드백 항목별 반영 여부 체크
- 설계안 새 버전 저장: `plans/연구_설계안_YYYYMMDD_HHMMSS.md`
- 이전 버전과 diff 요약

### Phase 5: 확정 + 연동 (3분)
- 설계 확정 시 CLAUDE.md "현재 단계" 업데이트
- 실험지침에 전달할 핵심 파라미터 요약
- 메모리 업데이트

## 완료 조건
- 설계안 md 파일 plans/에 저장
- 연구 질문 + 실험 설계서 필수 항목 전부 포함
- PDF 변환 요청 (문서생성지침)
