# 9대 지침 공통 포맷

## 분류 체계

| # | 지침명 | Phase | 핵심 범위 |
|---|--------|-------|-----------|
| 0 | 점검지침 | 0 | 문서 무결성, PDF 폰트, 파일 규칙, 사이트 공지 |
| 1 | 논문분석지침 | 1 | paper → 총정리/시리즈, 논문 번호 관리 |
| 2 | 실험지침 | 2 | 환경 구축 → 실험 실행 → 결과 분석 → 시각화 |
| 3 | 제출물지침 | 3 | 양식 + 마감 관리 + 일정 3곳 동기화 |
| 4 | 문서생성지침 | 4 | md→PDF 파이프라인, 폰트/레이아웃 규칙 |
| 5 | 주간보고지침 | 5 | git log 종합 + 노션 동기화 + 팀 진행 추적 |
| 6 | 미팅지침 | 6 | 브리핑 제작 + 카톡→회의록 + 후속 과제 |
| 7 | 발표지침 | 7 | PPT + 포스터 + 스크립트 + 리허설 |
| 8 | 연구설계지침 | 8 | 기획안/설계안 버전 관리 + 실험 설계서 |

## 3파일 세트 구조

각 지침은 반드시 3파일로 구성:

### 1. `{지침명}_auto.md` — 자동 실행 (전권 위임)

```markdown
# {지침명} (AUTO)

> 대상: Capstone 프로젝트 | 모드: 자동 실행 (전권 위임)
> 마지막 실행: (미실행)

## {지침명}의 범위

**IS (이 지침이 하는 것):**
- ...

**IS NOT (이 지침이 하지 않는 것 → 담당 지침):**
- ...

---

## Phase 구성

### Phase 0: {제목} ({예상 시간})
- [ ] 체크리스트 항목
- [ ] ...

### Phase 1: {제목} ({예상 시간})
- [ ] ...

---

## 완료 조건
- [ ] 전체 Phase 완료
- [ ] 결과 요약 출력
```

### 2. `{지침명}_manual.md` — 수동 가이드 (사람이 참조)

```markdown
# {지침명} (MANUAL)

> 사람이 직접 수행하거나 Claude에게 개별 요청할 때 참조

## 언제 실행하나?
- 트리거 조건 설명

## 단계별 가이드
### Step 1: ...
### Step 2: ...

## 자주 하는 실수
- ...

## 관련 지침
- {다른 지침명}: {연동 관계}
```

### 3. `{지침명}_실행.sh` — bash 오케스트레이터

```bash
#!/bin/bash
# {지침명} 자동 실행 스크립트
# 사용법: cd ~/Capstone && ./guideline/{지침명}_실행.sh

set -euo pipefail
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
PROJECT_ROOT="$(cd "$SCRIPT_DIR/.." && pwd)"
LOG_FILE="${PROJECT_ROOT}/{지침명}.log"

echo "=== {지침명} 시작: $(date) ===" | tee "$LOG_FILE"

# Claude Code 세션 실행
claude --print "{지침명}_auto.md 읽고 전체 Phase 실행" \
  2>&1 | tee -a "$LOG_FILE"

echo "=== {지침명} 완료: $(date) ===" | tee -a "$LOG_FILE"
```

## 작성 규칙

### 토큰 제한
- **각 파일 300줄(약 10,000토큰) 이하** — Claude Code Read 도구 한계
- 초과 시 Phase를 분리하거나 세부 내용을 간결하게

### IS / IS NOT 경계
- 모든 지침은 IS(하는 것)와 IS NOT(안 하는 것 → 담당 지침)을 명시
- 지침 간 역할이 절대 겹치지 않아야 함
- IS NOT에는 반드시 "→ {담당 지침명}" 표기

### Phase 설계 원칙
- Phase 0은 항상 "환경 확인 + 인벤토리"
- 각 Phase에 예상 시간 표기
- 체크리스트는 `- [ ]` 형식 (실행 시 체크 가능)
- Phase 간 의존성이 있으면 순서 고정, 없으면 병렬 가능 표기

### 프로젝트 컨텍스트 참조
- CLAUDE.md의 디렉토리 구조, 일정, 문서 규칙을 반드시 반영
- 기존 스킬(`.claude/skills/`)의 내용을 지침에 흡수 — 중복 방지
- 실제 프로젝트 파일/폴더명을 사용 (추상적 placeholder 금지)

### 연동 관계

```
점검 ←── 논문분석 (3종 완성도 검증)
점검 ←── 문서생성 (PDF 폰트 검증)
점검 ←── 제출물 (마감 체크)
논문분석 ──→ 문서생성 (md→PDF 변환 위임)
실험 ──→ 문서생성 (결과 보고서 PDF 변환)
실험 ←── 연구설계 (실험 설계서 기반)
제출물 ←── 발표 (PPT/포스터도 제출물)
미팅 ──→ 주간보고 (회의록 → 주간 종합)
연구설계 ──→ 미팅 (설계안 → 브리핑 자료)
```
