# 지침 부트스트랩

> 새 프로젝트에서 guideline/ 지침 체계를 처음부터 만드는 범용 워크플로.
> 이 파일을 참고해서 5단계를 순서대로 실행하면 됨.

---

## 전체 흐름

```
Step 0: 브레인스토밍 — 프로젝트 분석 → 지침 목록 도출
Step 1: 공통포맷.md + phaseNN 프롬프트 파일 생성
Step 2: Phase 0 지침 제작 (최초 1회, 포맷 기준점)
Step 3: Phase 1~N 반복 제작 (자동탐색 프롬프트 1개로 반복)
Step 4: 참조 검증 + CLAUDE.md 통합
```

**핵심 원칙:**
- 매 Phase 사이에 `/clear` (컨텍스트 초기화) — 지침 1개당 컨텍스트 100% 확보
- 각 파일 10,000 토큰(약 300줄) 이하 — Claude Code Read 도구 한계
- 번호 접두사 `NN_` 필수 — `ls` 정렬 시 논리적 순서 보장

---

## Step 0: 브레인스토밍

Claude에게 아래 프롬프트를 붙여넣는다.

```
이 프로젝트의 코드베이스, CLAUDE.md, README.md를 읽고
운영에 필요한 지침 카테고리를 브레인스토밍해줘.

요구사항:
1. 프로젝트 특성(언어, 프레임워크, 도메인)을 먼저 파악
2. 아래 6대 축으로 분류하되, 해당 없으면 생략
   A. 코드 품질 (린트, 리뷰, 리팩터링, 테스트)
   B. 기능 관리 (기획, 설계, 구현, 배포)
   C. 도메인 특화 (해당 프로젝트 고유 업무)
   D. 데이터/분석 (데이터 파이프라인, 실험, 시각화)
   E. 인프라/운영 (CI/CD, 모니터링, 보안, 백업)
   F. 보고/메타 (문서, 회의, 일정, 온보딩)
3. 각 지침에 대해:
   - 이름 (한글 2~4글자)
   - 한 줄 범위 설명
   - IS 3개 / IS NOT 3개 (경계 명확화, IS NOT에 "→ 담당 지침" 표기)
   - 트리거 키워드 2개 ("{이름} 자동", "{이름} 수동")
4. 지침 간 연동 관계 다이어그램 (A → B 형태)
5. 총 지침 수 7~25개 (프로젝트 규모에 비례)

출력 형식:
| # | 이름 | 축 | 범위 | 트리거 |
|---|------|-----|------|--------|
| 00 | 점검 | A | 정적 분석+테스트+문서 | "점검 자동/수동" |
| 01 | ... | ... | ... | ... |

+ 연동 관계:
점검 → 리팩토링 (거대함수 발견 → 분할)
설계 → 구현 (설계서 기반)
...
```

**결과물**: 지침 목록 테이블 + 연동 관계 → Step 1에서 사용.

→ `/clear`

---

## Step 1: 공통포맷 + Phase 프롬프트 파일 생성

```
위 브레인스토밍 결과를 바탕으로 guideline/prompts/ 폴더에 파일들을 만들어줘:

1. guideline/prompts/공통포맷.md
   - 분류 체계 테이블 (브레인스토밍 결과 그대로)
   - 3파일 세트 구조 (NN_{이름}지침_auto.md / NN_{이름}지침_manual.md / NN_{이름}_실행.sh)
   - IS/IS NOT 전체 목록
   - 연동 관계 다이어그램
   - auto.md / manual.md / .sh 포맷 템플릿

2. guideline/prompts/phase00_{이름}.md ~ phaseNN_{이름}.md
   각 파일에 포함:
   - 지침 개요 (한 줄)
   - IS / IS NOT
   - 읽어야 할 프로젝트 파일 목록
   - Phase 구성 가이드 (Phase 0은 항상 "환경 확인 + 인벤토리")
   - 환경별 범위 (해당 시)
   - 완료 조건

3. guideline/prompts/phaseNN_CLAUDE_MD_통합.md (마지막 번호)
   CLAUDE.md에 트리거 테이블 + 오케스트레이터 + 디렉토리 구조 반영 프롬프트

규칙:
- 각 파일 300줄(10,000 토큰) 이하
- 공통포맷.md가 300줄 초과 시 연동 관계를 공통포맷_부록.md로 분리
- 파일명의 지침 이름은 한글 (예: phase00_점검.md, phase01_테스트.md)
```

→ `/clear`

---

## Step 2: Phase 0 제작 (최초 1회)

이 Phase만 전용 프롬프트를 사용한다. 이후 Phase의 포맷 기준점이 됨.

```
guideline/prompts/공통포맷.md를 읽고 전체 포맷 규칙을 파악해.
그 다음 guideline/prompts/phase00_{이름}.md를 읽고
해당 지침의 3파일 세트를 만들어줘:
- guideline/00_{이름}지침_auto.md
- guideline/00_{이름}지침_manual.md
- guideline/00_{이름}_실행.sh

프로젝트 코드를 충분히 읽고 IS/IS NOT 범위에 맞게 Phase를 구성해.
각 파일 10,000 토큰(약 300줄) 이하.
```

→ `/clear`

---

## Step 3: Phase 1~N 반복 (자동탐색 — 매번 동일 프롬프트)

아래 프롬프트를 `/clear` 사이에 반복 붙여넣기한다.
Claude가 자동으로 다음 미생성 Phase를 찾아 실행한다.

```
guideline/prompts/ 폴더에서 아직 지침이 안 만들어진 다음 Phase를 자동으로 찾아서 실행해줘.
1. guideline/ 폴더의 기존 *지침_auto.md 파일 목록 확인
2. guideline/prompts/phase00~NN 중 아직 생성 안 된 가장 낮은 번호 식별
3. guideline/prompts/공통포맷.md + 해당 phaseNN 파일 읽기
4. guideline/00_{첫번째지침}지침_auto.md 포맷 참고해서 3파일 세트 생성
각 파일 10,000 토큰(약 300줄) 이하.
```

→ `/clear` → 같은 프롬프트 반복 → 모든 Phase 완료 시 "미생성 Phase 없음" 출력

---

## Step 4: 참조 검증 + CLAUDE.md 통합

### 4-1. 참조 검증

```
guideline/ 전체에서 참조 무결성을 검증해줘.
1. *.sh 내부의 파일 경로가 실제 파일과 일치하는지
2. *_auto.md, *_manual.md에서 다른 지침/PHASE_STATE를 참조할 때 이름이 맞는지
3. 번호 없는 옛 파일명 잔존 여부 Grep 확인
4. 불일치 있으면 수정
```

→ 잔존 0건 확인 후 `/clear`

### 4-2. CLAUDE.md 통합

```
guideline/prompts/phaseNN_CLAUDE_MD_통합.md를 읽고 실행해줘.
```

## 파일명 규칙

```
guideline/
├── prompts/                           # 제작 프롬프트 (원본, 수정하지 않음)
│   ├── 공통포맷.md
│   ├── phase00_{이름}.md
│   ├── phase01_{이름}.md
│   ├── ...
│   └── phaseNN_CLAUDE_MD_통합.md
├── 00_{이름}지침_auto.md              # ← "지침" 접미사 포함
├── 00_{이름}지침_manual.md
├── 00_{이름}_실행.sh                  # ← "지침" 없음
├── 01_{이름}지침_auto.md
├── 01_{이름}_실행.sh
├── ...
├── PHASE_STATE_00_{이름}.md           # 실행 상태 (런타임 생성)
└── PHASE_STATE_NN_{이름}.md
```

**핵심 패턴:**
- `.md` 파일: `{NN}_{이름}지침_{auto|manual}.md` — "지침" 포함
- `.sh` 파일: `{NN}_{이름}_실행.sh` — "지침" 미포함
- `PHASE_STATE`: `PHASE_STATE_{NN}_{이름}.md`
- 번호는 `prompts/phaseNN`과 일치 (00~NN)

## 3파일 세트 템플릿

### auto.md

```markdown
# {이름}지침 (AUTO)

> 대상: {프로젝트명} | 모드: 자동 실행 (전권 위임)
> 마지막 실행: —

## 실행 방법
### A. bash 오케스트레이터 (추천)
./guideline/NN_{이름}_실행.sh

### B. Claude Code 대화형
"{이름} 자동" 입력

## {이름}지침의 범위
**{이름} = {한줄 정의}.**

**IS (이 지침이 하는 것):**
- ...

**IS NOT (이 지침이 하지 않는 것 → 담당 지침):**
- ... → {담당 지침명}

## 환경별 실행 범위
| 환경 | Phase 범위 | 비고 |
|------|-----------|------|

## Phase 구성
### Phase 0: 환경 확인 + 인벤토리 (N분)
- [ ] 체크리스트 항목
- [ ] PHASE_STATE_{NN}_{이름}.md 생성

### Phase 1: {제목} (N분)
- [ ] ...

## 완료 조건
- [ ] 전체 Phase 완료
- [ ] PHASE_STATE_{NN}_{이름}.md 최종 업데이트
```

### manual.md

```markdown
# {이름}지침 (MANUAL)

> 모드: 수동 (Phase별 정지, 사용자 확인 후 진행)

## 사용법
1. "{이름} 수동" 입력
2. Phase 0 실행 → 결과 보고 → 정지
3. /clear 후 "Phase N 이어가줘"
4. PHASE_STATE_{NN}_{이름}.md 읽고 다음 Phase 자동 속행

## Phase 체크리스트
### Phase 0: 환경 확인 + 인벤토리
- [ ] 체크리스트 (상세 스크립트: NN_{이름}지침_auto.md 참조)
> ✅ Phase 0 완료 — 정지. /clear 후 "Phase 1 이어가줘"

### Phase 1: ...
> ✅ Phase 1 완료 — 정지.

## 관련 지침
- {지침명}: {연동 관계}
```

### 실행.sh — Phase별 독립 세션 (권장)

```bash
#!/bin/bash
# [NN] {이름}_실행.sh — Phase별 독립 claude 세션
# 사용: cd ~/{프로젝트} && ./guideline/NN_{이름}_실행.sh

set -euo pipefail
cd ~/{프로젝트}

LOG="guideline/NN_{이름}.log"
STATE="guideline/PHASE_STATE_NN_{이름}.md"
echo "=== {이름} 시작: $(date) ===" | tee "$LOG"

PHASES=(0 1 2 3)
PHASE_NAMES=(
  "환경 확인 + 인벤토리"
  "..."
  "..."
  "..."
)

TOOLS="Bash,Read,Write,Edit,Glob,Grep"

for i in "${!PHASES[@]}"; do
  P="${PHASES[$i]}"
  NAME="${PHASE_NAMES[$i]}"
  echo "── Phase $P: $NAME ──" | tee -a "$LOG"

  claude -p "{프로젝트명} {이름} Phase $P ($NAME) 실행.
guideline/NN_{이름}지침_auto.md 읽고 Phase $P 체크리스트 수행.
상태파일: $STATE — 결과 기록.
완료 후 결과를 테이블로 요약." \
    --allowedTools "$TOOLS" \
    --permission-mode "bypassPermissions" \
    2>&1 | tee -a "$LOG"

  echo "Phase $P 완료 ✓ — $(date)" | tee -a "$LOG"
done

echo "=== {이름} 전체 완료: $(date) ===" | tee -a "$LOG"
```

**왜 Phase별 독립 세션인가:**
- 지침 1개가 7 Phase면 컨텍스트가 분산됨
- 독립 세션 = Phase당 100% 컨텍스트 → 더 정확한 작업
- 실패 시 해당 Phase만 재실행 가능

## 작성 규칙 요약

| 규칙 | 내용 |
|------|------|
| 토큰 제한 | 각 파일 300줄(10,000 토큰) 이하 |
| IS/IS NOT | 모든 지침에 필수, IS NOT에 "→ 담당 지침" 표기 |
| Phase 0 | 항상 "환경 확인 + 인벤토리" |
| Phase 예상 시간 | 각 Phase 제목에 (N분) 표기 |
| 체크리스트 | `- [ ]` 형식 |
| 프로젝트 참조 | 실제 파일/폴더명 사용, placeholder 금지 |
| 연동 | 지침 간 역할 중복 금지, IS NOT으로 명시 |
| 카테고리 | A~F 축 그룹핑 권장 (7개 이상일 때 가독성) |

---

## 실전 팁

1. **Phase 수는 프롬프트에서 결정** — phase 프롬프트에 Phase 구성을 적어두면 Claude가 그대로 만듬
2. **Phase 0은 전 지침 공통** — 환경 판별 + 인벤토리 + PHASE_STATE 생성
3. **공통포맷.md가 레퍼런스** — 매 Phase 제작 시 반드시 같이 읽혀야 포맷 일관성 유지
4. **번호 리팩토링은 나중에** — 먼저 전부 만들고, 마지막에 한꺼번에 번호 접두사 부여해도 됨
5. **PHASE_STATE는 런타임 생성** — 지침 제작 시엔 빈 파일 안 만들어도 됨 (실행 시 자동 생성)
6. **manual은 auto의 축약판** — 상세 스크립트는 auto 참조, manual은 체크리스트 + 정지점만

---

## 총 작업량

```
브레인스토밍 1회 + 공통포맷/프롬프트 1회 + Phase 0 1회
+ Phase 1~N 반복 (N-1회) + 검증/통합 1회
= N+4 세션 (N = 지침 수)
```

예: 지침 10개 → 14세션, 25개 → 29세션
