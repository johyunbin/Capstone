# 지침 시스템 부트스트랩 가이드

> 새 프로젝트에서 guideline/ 지침 체계를 처음부터 만드는 범용 워크플로.
> 이 파일 하나를 프로젝트 루트에 복사하고 따라가면 됨.

---

## 전체 흐름

```
Step 0:   브레인스토밍 (지침 목록 도출)
Step 1:   공통포맷.md + phaseNN 프롬프트 파일 생성
Step 2:   Phase 0 지침 제작 (최초 1회)
Step 3:   Phase 1~N 반복 제작 (복붙 1개로 반복)
Step 3.5: 참조 검증 (파일명·경로 무결성 확인)
Step 4:   CLAUDE.md 통합 업데이트
```

---

## Step 0: 브레인스토밍

새 프로젝트에서 Claude에게 아래 프롬프트를 붙여넣는다.

```
이 프로젝트의 코드베이스, CLAUDE.md, README.md를 읽고
운영에 필요한 지침 카테고리를 브레인스토밍해줘.

요구사항:
1. 프로젝트 특성(언어, 프레임워크, 도메인)을 먼저 파악
2. 아래 6대 축으로 분류하되, 프로젝트에 해당 없으면 생략
   - 코드 품질 (린트, 리뷰, 리팩터링, 테스트)
   - 기능 관리 (기획, 설계, 구현, 배포)
   - 도메인 특화 (해당 프로젝트 고유 업무)
   - 데이터/분석 (데이터 파이프라인, 실험, 시각화)
   - 인프라/운영 (CI/CD, 모니터링, 보안, 백업)
   - 보고/메타 (문서, 회의, 일정, 온보딩)
3. 각 지침에 대해:
   - 이름 (한글, 2~4글자 + "지침")
   - 한 줄 범위 설명
   - IS 3개 / IS NOT 3개 (경계 명확화)
   - 트리거 키워드 3개
4. 지침 간 연동 관계 다이어그램 (A → B 형태)
5. 총 지침 수는 7~25개 사이 (프로젝트 규모에 비례)

출력 형식:
| # | 지침명 | 축 | 핵심 범위 | 트리거 키워드 |
|---|--------|-----|-----------|--------------|
| 0 | 점검지침 | 메타 | 파일 무결성, 상태 점검 | "점검", "헬스", "상태" |
| 1 | ... | ... | ... | ... |

+ 연동 관계:
점검 ←── 테스트 (결과 검증)
설계 ──→ 구현 (설계서 기반)
...
```

**결과물**: 지침 목록 테이블 + 연동 관계 → 이것을 Step 1에서 사용.

---

## Step 1: 공통포맷 + Phase 프롬프트 파일 생성

브레인스토밍 결과가 나오면 아래 프롬프트를 붙여넣는다.

```
위 브레인스토밍 결과를 바탕으로 guideline/prompts/ 폴더에 다음 파일들을 만들어줘:

1. guideline/prompts/공통포맷.md
   아래 템플릿을 이 프로젝트에 맞게 채워서 생성:
   - 분류 체계 테이블 (위 브레인스토밍 결과)
   - 3파일 세트 구조 (auto.md / manual.md / .sh)
   - 작성 규칙 (토큰 제한, IS/IS NOT, Phase 설계 원칙)
   - 연동 관계 다이어그램
   - CLAUDE.md 트리거 키워드 테이블

2. guideline/prompts/phase00_{지침명}.md ~ phaseNN_{지침명}.md
   각 지침별 제작 프롬프트 파일. 각 파일에 포함:
   - 지침 개요 (한 줄)
   - IS / IS NOT
   - 읽어야 할 프로젝트 파일 목록
   - Phase 구성 가이드 (Phase 0은 항상 "환경 확인 + 인벤토리")
   - 완료 조건

3. guideline/prompts/phaseNN_CLAUDE_MD_통합.md (마지막 번호)
   CLAUDE.md에 지침 트리거 테이블 + 디렉토리 구조 반영 프롬프트

⚠️ 각 파일 300줄(10000 토큰) 이하.
⚠️ 파일명의 지침명은 한글로 (예: phase00_점검.md, phase01_테스트.md).
⚠️ 공통포맷.md가 300줄 초과할 것 같으면 분류 체계 테이블 + 3파일 세트 구조 + 작성 규칙만 남기고,
   연동 관계/트리거 키워드는 별도 파일(공통포맷_부록.md)로 분리해.
```

→ 완료 확인 후 `/clear`

---

## Step 2: Phase 0 제작 (최초 1회)

```
guideline/prompts/공통포맷.md를 읽고 전체 포맷 규칙을 파악해.
그 다음 guideline/prompts/phase00_{지침명}.md를 읽고
해당 지침의 3파일 세트를 만들어줘:
- guideline/00_{지침명}_auto.md
- guideline/00_{지침명}_manual.md
- guideline/00_{지침명}_실행.sh

프로젝트 코드를 충분히 읽고 IS/IS NOT 범위에 맞게 Phase를 구성해.
⚠️ 각 파일 10000 토큰 이하.
```

→ 완료 확인 후 `/clear`

---

## Step 3: Phase 1~N 반복 (매번 동일 프롬프트)

아래 프롬프트를 `/clear` 사이에 반복 붙여넣기한다.
Claude가 자동으로 다음 미생성 Phase를 찾아 실행한다.

```
guideline/prompts/ 폴더에서 아직 지침이 안 만들어진 다음 Phase를 자동으로 찾아서 실행해줘.
1. guideline/ 폴더의 기존 *지침_auto.md 파일 목록 확인
2. guideline/prompts/phase00~NN 중 아직 생성 안 된 가장 낮은 번호 식별
3. guideline/prompts/공통포맷.md + 해당 phaseNN 파일 읽기
4. guideline/00_{첫번째지침}_auto.md 포맷 참고해서 3파일 세트 생성
⚠️ 각 파일 10000 토큰 이하.
```

→ 완료 → `/clear` → 같은 프롬프트 붙여넣기 → 반복

모든 Phase가 완료되면 Claude가 "미생성 Phase 없음"이라고 알려준다.

---

## Step 3.5: 참조 검증 (모든 Phase 완료 후)

CLAUDE.md 통합 전에 파일명 참조가 깨진 곳이 없는지 확인한다.

```
guideline/ 전체에서 참조 무결성을 검증해줘.
1. guideline/*.sh 내부의 파일 경로가 실제 파일과 일치하는지
2. guideline/*_auto.md, *_manual.md에서 다른 지침을 참조할 때 이름이 맞는지
3. 옛 파일명(번호 없는 이름 등) 잔존 여부 Grep 확인
4. 불일치 있으면 수정
```

→ 잔존 0건 확인 후 `/clear`

## Step 4: CLAUDE.md 통합

```
guideline/prompts/phaseNN_CLAUDE_MD_통합.md를 읽고 실행해줘.
```

## 3파일 세트 템플릿

### auto.md

```markdown
# {지침명} (AUTO)

> 대상: {프로젝트명} | 모드: 자동 실행 (전권 위임)
> 마지막 실행: (미실행)

## {지침명}의 범위

**IS (이 지침이 하는 것):**
- ...

**IS NOT (이 지침이 하지 않는 것 → 담당 지침):**
- ... → {담당 지침명}

---

## Phase 구성

### Phase 0: {제목} ({예상 시간})
- [ ] 체크리스트 항목

### Phase 1: {제목} ({예상 시간})
- [ ] ...

---

## 완료 조건
- [ ] 전체 Phase 완료
- [ ] 결과 요약 출력
- [ ] `> 마지막 실행:` 라인에 현재 날짜+시각 업데이트
```

### manual.md

```markdown
# {지침명} (MANUAL)

> 사람이 직접 수행하거나 Claude에게 개별 요청할 때 참조

## 언제 실행하나?
- 트리거 조건

## 단계별 가이드
### Step 1: ...
### Step 2: ...

## 자주 하는 실수
| 실수 | 해결 |
|------|------|

## 관련 지침
- {지침명}: {연동 ��계}
```

### 실행.sh

```bash
#!/bin/bash
# {지침명} 자동 실행 스크립트
# 사용법: cd ~/{프로젝트} && ./guideline/NN_{지침명}_실행.sh

set -euo pipefail
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
PROJECT_ROOT="$(cd "$SCRIPT_DIR/.." && pwd)"
LOG_FILE="${PROJECT_ROOT}/NN_{지침명}.log"

echo "=== {지침명} 시작: $(date) ===" | tee "$LOG_FILE"

claude --print "guideline/NN_{지침명}_auto.md 읽고 전체 Phase 실행" \
  2>&1 | tee -a "$LOG_FILE"

echo "=== {지침명} 완료: $(date) ===" | tee -a "$LOG_FILE"
```

## 파일명 규칙

```
guideline/
├── prompts/                        # 제작 프롬프트 (원본, 수정하지 않음)
│   ├── 공통포맷.md
│   ├── phase00_{지침명}.md
│   ├── phase01_{지침명}.md
│   ├── ...
│   └── phaseNN_CLAUDE_MD_통합.md
├── 00_{지침명}_auto.md             # 번호 접두사 + 지침명
├── 00_{지침명}_manual.md
├── 00_{지침명}_실행.sh
├── 01_{지침명}_auto.md
├── ...
└── NN_{지침명}_실행.sh
```

- 번호는 prompts/phaseNN과 일치 (00~NN)
- ls 정렬 시 논리적 순서 보장
- 지침명은 한글 2~4글자 + "지침" (예: 점검지침, 테스트지침)

---

## 작성 규칙 요약

| 규칙 | 내용 |
|------|------|
| 토큰 제한 | 각 파일 300줄(10000 토큰) 이하 |
| IS/IS NOT | 모든 지침에 필수, IS NOT에 "→ 담당 지침" 표기 |
| Phase 0 | 항상 "환경 확인 + 인벤토리" |
| Phase 예상 시간 | 각 Phase에 표기 |
| 체크리스트 | `- [ ]` 형식 |
| 프로젝트 참조 | 실제 파일/폴더명 사용, placeholder 금지 |
| 연동 | 지침 간 역할 중복 금지 |
