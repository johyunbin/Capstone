# 연구설계지침 (MANUAL)

> 사람이 직접 수행하거나 Claude에게 개별 요청할 때 참조

## 언제 실행하나?

- 학기 초 **연구 방향을 처음 잡을 때** (기획안 작성)
- 교수님/자문위원 미팅 후 **피드백을 설계에 반영할 때**
- 실험 시작 전 **실험 설계서를 확정할 때**
- 연구 방향을 **수정하거나 피벗할 때**
- "설계", "기획", "연구 방향", "실험 설계", "RQ" 키워드로 Claude에게 요청

## 단계별 가이드

### Step 1: 현재 상태 확인

먼저 기존 설계안이 어디까지 진행되었는지 확인한다.

```bash
ls -lt ~/Capstone/plans/
```

- 최신 설계안(`연구_설계안_*.md`)과 기획안(`연구_기획안_*.md`) 확인
- CLAUDE.md "현재 단계" 섹션 읽기
- 미반영 피드백 유무 확인 (자문내역서, 회의록)

### Step 2: 연구 질문 정의

연구의 핵심 질문을 3개 이내로 명확하게 정의한다.

좋은 RQ의 조건:
- **구체적**: "성능이 좋아지는가?" ✗ → "선택도 0.1%에서 QPS가 몇 배 향상되는가?" ✓
- **검증 가능**: 실험으로 답할 수 있는 형태
- **범위 한정**: 학기 내 수행 가능한 범위

각 RQ에 반드시:
- 가설(H) 설정: "~할 것이다"
- 기대 결과: 가설이 맞을 때 / 틀릴 때 각각

### Step 3: 실험 설계서 작성

**필수 6개 항목** — 하나라도 빠지면 설계 미완성:

1. **데이터셋**: 무엇을, 왜 선택했는지
2. **평가 지표**: Recall@k, QPS, latency(p50/p99), 비용 추정 오차
3. **비교축**: 선택도 sweep, 필터 유형, 필터 전략, 인덱스 유형
4. **대조군**: pgvector(baseline), VBASE, DuckDB + Exqutor 적용 전/후
5. **하드웨어/소프트웨어 스펙**: 재현을 위한 정확한 버전 명시
6. **실험 절차**: 단계별 실행 순서와 성공 기준

### Step 4: 방법론 상세화

Cascade Decomposition 3단계를 구체적으로 설계한다.

| 단계 | 목적 | 입력 | 출력 |
|------|------|------|------|
| 1단계 | 병목 프로파일링 | vanilla pgvector 쿼리 | 선택도별 오차율 |
| 2단계 | Exqutor 적용 | 병목 쿼리 + 패치 | before/after 비교 |
| 3단계 | 시스템 비교 | 전 시스템 결과 | 비교 차트 + 통계 |

각 단계마다 "성공 기준"을 명시해야 다음 단계로 진행 가능.

### Step 5: 피드백 반영

자문위원/교수님 피드백을 설계에 반영한다.

체크리스트 형태로 관리:
```markdown
| 피드백 | 소스 | 반영 여부 | 반영 위치 |
|--------|------|-----------|-----------|
| 데이터셋 근거 | 박성원 자문위원 | ✅ | Step 3 데이터셋 |
```

### Step 6: 버전 관리 + 저장

설계안을 타임스탬프 포함 파일명으로 저장한다.

- 파일명: `plans/연구_설계안_YYYYMMDD_HHMMSS.md`
- 상단에 변경 이력(이전 버전 대비 diff 요약) 기록
- PDF 변환은 문서생성지침에 요청

## 자주 하는 실수

| 실수 | 해결 |
|------|------|
| RQ가 너무 광범위 | 선택도·데이터셋·시스템 등 변수를 한정 |
| 대조군 미설정 | baseline 없이는 비교 불가 — 반드시 vanilla pgvector 포함 |
| 하드웨어 스펙 누락 | 재현 불가능한 실험 = 무의미, 반드시 명시 |
| 피드백 구두 반영 | 반영 체크리스트에 기록해야 추적 가능 |
| 설계안 덮어쓰기 | 타임스탬프 파일명으로 버전 분리 |
| 설계만 하고 전환 안 함 | 설계 확정 후 반드시 실험지침 연동 |
| 성공 기준 없는 단계 | "이 단계는 언제 끝나는가?" 답할 수 없으면 미완성 |

## 관련 지침

- **실험지침**: 설계 확정 후 실험 실행을 넘기는 대상 — 핵심 파라미터 요약 전달
- **논문분석지침**: 설계 근거가 되는 논문 분석 참조 (역방향)
- **문서생성지침**: 설계안 md→PDF 변환 위임
- **미팅지침**: 설계안을 미팅 브리핑 자료로 활용
- **발표지침**: 방법론 슬라이드 내용의 소스
- **제출물지침**: 연구제안서·수행계획서에 설계 내용 반영
