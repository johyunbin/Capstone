## 변경 배경

중간발표(4/30) 후 박세은 팀장이 두 가지 보강 사안을 제기하였다.

(가) **Normal vs Skew 데이터셋의 직접 비교 부재**: 중간발표 시점까지는 KM20 층화와 BERN baseline 의 비교에 집중하였으며, 데이터 분포 자체가 random sampling 정확도에 미치는 영향을 정량화하는 직접 비교가 빠져 있었다. 박세은이 제안한 연구 동기 ("normal 분포에서 잘 되던 random sampling 이 skew 분포에서는 이렇게나 안 나오더라") 를 살리기 위해서는 이 비교가 RQ1 의 핵심 실험으로 격상되어야 한다.

(나) **분포 인식 샘플링의 추가 강화 가능성**: Proportional Allocation 만으로는 분포 정보의 잠재력을 완전히 활용하지 못한다. Neyman Allocation (variance-optimal, Neyman 1934) 을 RQ2 의 추가 후보로 도입한다.

추가로 회의 중 제기된 두 비판 — (다) "KM cluster 가 사실상 인덱스이지 않은가" 와 (라) "사전 계산 비용이 크면 빠른 응답 요구와 충돌하지 않는가" — 는 본 연구의 positioning 을 명확히 하는 계기가 되었다. 본 연구는 Exqutor 가 다루지 않는 단일 테이블 영역에 대한 분포 정보의 가치 정량화 연구로 재정의된다.

## 새 연구 질문

### RQ1. 기존 random sampling 이 skew 데이터셋에서 얼마나 부정확한가?

**가설 H1**: skew 데이터일수록 random sampling 의 q-error 가 악화되며, block 단위가 row 단위보다 편향이 더 심하다.

**설계**: 2x2 factorial (Block vs Row × Normal vs Skew)

| 데이터셋 | SYSTEM (block 단위) | BERNOULLI (row 단위) |
|---|---|---|
| DEEP 1M (HHI 0.0527, normal-ish) | ✅ 측정 완료 (`phase4_system.parquet`) | ✅ 측정 완료 (`phase4_bernoulli.parquet`) |
| SIFT 1.5M (HHI 0.0578, skew) | **❌ 추가 측정 필요** | ✅ 측정 완료 (`phase7_sift_bern.parquet`) |

**측정 항목**: q-error mean/median + paired Wilcoxon p-value × selectivity 5점 (1%, 5%, 10%, 30%, 50%) × 5-seed × 100 query.

**기측정 결과 (DEEP 1M)**:
- SYSTEM vs BERNOULLI: BERNOULLI 가 모든 selectivity 에서 우위 +0.7~12.0%p, p<0.001.

**추가 실험**: SIFT × SYSTEM(block) baseline 측정 (~2시간).

**예상 결과**: SIFT 의 SYSTEM(block) baseline 이 DEEP 보다 절대적으로 부정확하며, SIFT 안에서 SYSTEM 과 BERNOULLI 의 격차가 DEEP 보다 클 것이다 (skew 가 block 편향을 증폭).

### RQ2. 분포를 아는 상황에서 어떤 샘플링 방식이 최적인가?

**가설 H2**: KM20 + Proportional 위에 Neyman Allocation 을 적용하면 추가 분산 감소를 얻을 수 있다. Anti-Neyman 은 Proportional 보다 나쁘다 (분산 비례 배분의 정당성).

**기준 baseline**: BERNOULLI (RQ1 의 row-level baseline)

**비교 후보 (3-way ablation)**:

| 방법 | 메커니즘 | 이론적 정당성 | 기대 성능 |
|---|---|---|---|
| **(a) Proportional** | n_i ∝ N_i (cluster 크기 비례) | Neyman 비례 배분의 단순화 | DEEP +1.6~8.9%, SIFT +3.0~4.4% (측정 완료) |
| **(b) Neyman** | n_i ∝ N_i × σ_i (크기 × 분산) | variance-optimal, Neyman 1934 정리 | (a) + 추가 +1~3% 기대 |
| **(c) Anti-Neyman** | n_i ∝ N_i / σ_i (크기 / 분산) | variance-suboptimal, ablation 용 | (a) 보다 나쁨 예상 |

**부수 실험**: Sample size sensitivity (`s_size = 100, 385, 1000, 3000`). 표본 크기가 작을수록 KM20 의 효과가 커지는지 검증 → "저비용 환경에서의 가치" narrative 보강.

**K=20 채택 근거** (이미 확보):
- Phase 6 Step 3' 에서 K=10 vs K=20 직접 비교, K=20 이 selectivity 0.10 까지 추가 유의 신호 확보.
- K=50 이상은 sample_size=385 기준 stratum 당 표본이 7~8 개 이하로 떨어져 추정 분산이 폭증.

**구현 비용 (W1 안에 처리)**:
- Neyman: 사전에 cluster 분산 σ_i 측정 (Python ~30줄) + vector.c 의 sample 배분 weight 수정 (~50줄), ~4시간.
- Anti-Neyman: weight 부호만 변경 (~30분).
- Sample size sensitivity: 기존 측정 인프라 재활용, sample_size GUC 만 변경, ~3시간.

### RQ3. 분포를 모르는 상황에서 어떤 샘플링 방식이 최적인가?

**가설 H3**: distribution-agnostic 방법은 KM20 (oracle) 대비 유의미한 비율을 회수하면서 사전 학습 불필요 또는 극소 비용이라는 운영 이점을 제공한다.

**핵심 metric**: Recovery Rate

```
recovery_rate = (방법X − RANDOM20) / (KM20 − RANDOM20)
```

- 1.0 → KM20 oracle 수준 회수
- 0.0 → RANDOM20 (공간 인식 없음) 수준
- 음수 → RANDOM20 보다 나쁨

**분모 붕괴 경계** (사전 등록): `|KM20 − RANDOM20| ≤ 1%p` 또는 seed 간 분산의 1σ 이하인 셀에서는 Recovery Rate 를 보고하지 않고, **절대 Q-error 개선폭 (방법X − BERN)** 을 primary metric 으로 사용한다.

**설계**: 7-way 비교, 3 패러다임

#### Paradigm 1. Offline Partition (데이터셋 고정 가정, 1회 사전 계산)

| 방법 | 이론 | 기대 recovery | 구현 시간 |
|---|---|---|---|
| **C. Random Projection** | Johnson-Lindenstrauss lemma | 10~40% | ~2h |
| **A. LSH** | 거리 보존 hashing | 30~60% | ~4h |
| **E. Hilbert Curve** | space-filling curve, 30년 검증 | 20~60% | ~4h |
| **F. MiniBatch K-means** | Sculley 2010, 1~5% 학습 | 75~95% | ~1h |

#### Paradigm 2. Online Query-Adaptive (쿼리 시점 동적 적응)

| 방법 | 이론 | 기대 recovery | 구현 시간 |
|---|---|---|---|
| **G. Distance-Shell** | pilot 기반 동심원 분할 | 25~50% | ~4h |
| **B. KDE-pilot** | Silverman bandwidth + Neyman | 50~80% | ~6h |

#### Paradigm 3. Weight-based (분할 X, 가중치만)

| 방법 | 이론 | 기대 recovery | 구현 시간 |
|---|---|---|---|
| **H. Importance Sampling** | f(x)/g(x) 가중치, 2x2 factorial 측정 | 30~70% | ~6h |

**예상 순서**: RANDOM20 ≤ C ≤ {A, E, G} ≤ {B, H} ≤ F ≤ KM20

## 본 연구의 contribution

1. **RQ1: Normal vs Skew × Block vs Row 정량 비교** — 데이터 분포가 random sampling 정확도에 미치는 영향의 직접 측정.
2. **Selectivity Gradient 분석** — 좁은 쿼리(s=1%)에서 KM20 vs RANDOM20 격차 19.6%p, Exqutor 가 다루지 않은 영역.
3. **Two-Level Decomposition** — Level 1 (Proportional, K 등분 효과) 와 Level 2 (Spatial, 공간 인식) 의 분해 — 분포 정보가 가치를 만드는 메커니즘 정량화.
4. **Recovery Rate Framework** — 분포 정보 없이 oracle 의 가치를 어디까지 회수할 수 있는지의 trade-off curve.

---

## Limitation

1. **KM20 은 oracle benchmark** — production 솔루션 아님. 실제 운영 솔루션은 RQ3 의 distribution-agnostic 방법.
2. **사전 계산은 one-time cost** — HNSW 인덱스 빌드와 같은 layer (메모리 1/1000, DEEP 1M K=20 학습 1.2초). 쿼리 응답 시점은 stratum_id lookup O(1).
3. **INSERT/UPDATE 빈번한 OLTP 환경은 범위 외** — RQ3 의 F (MiniBatch) 가 부담을 1/20~1/100 수준으로 완화하나, 본격 OLTP 검증은 future work.
4. **단일 → 멀티 테이블 일반화는 future work** — 단일 테이블 정확성은 멀티 테이블 정확성의 *필요조건*이지 충분조건은 아님. 멀티 테이블에서는 join key 분포, 상관 등 추가 차원이 있어 별도 검증 필요.
