### 3. Methodology (4-5p)

- **3.1 측정 환경**
  - 서버: 165.132.140.240 (capstone2026), `/mnt/hdd0/home/capstone2026`. PG 18.0 + pgvector 0.8.1 + cmake/ninja 빌드
  - Dataset: DEEP 1M (96d, normal), SIFT 1.5M (128d, skew), DEEP 8M (96d, cross-scale)
  - Query pool: 100 query × 5 sel × 5 seed × 2-5 mode
- **3.2 RQ1 measurement design**
  - **Phase 6 (SQL D, vector.c hook, production-near)**: PG `tablesample` (BERNOULLI / SYSTEM) + vector.c hook 으로 D_target 직접 측정 → estimator 가 production env 와 일치
  - **Phase 7 (numpy D, simulation)**: Python NumPy 시뮬레이션 (≤10K row 캐시 추출 + HT weight=N=1M) → 빠른 반복 가능
  - **Methodology robustness sub-contribution motivation**: 두 환경의 동일 query pool / 동일 5 sel / 동일 5 seed 측정. 5-cell 격차를 정직 보고 (옵션 2 narrative)
- **3.3 RQ2 measurement design**
  - **5-mode**: BERN baseline / Equal (n_i = n/K) / Proportional (n_i ∝ N_i) / Neyman (n_i ∝ N_i × σ_i) / Anti-Neyman (n_i ∝ N_i / σ_i)
  - **KM20 oracle baseline**: K-means K=20, **PG 직접 query 로 DEEP 1M / 8M / SIFT 1.5M 모든 stratum_id 0-19 일치 확인** (5/7 W2 보강)
  - **σ_i 사전 계산**: sel=0.10 D_target anchor, 100 query 평균 Bernoulli SD
  - **Sample size sensitivity**: 4 ssize × 2 dataset × 5 sel = 40 cell
- **3.4 RQ3 measurement design**
  - **22 method 4 paradigm**:
    - Offline cluster: KM20 (oracle), MiniBatch K-means, MiniBatch partial_fit, HDBSCAN, GMM, BIRCH, Spectral
    - Locality: Hilbert, Z-order, Hybrid (KMeans+Hilbert)
    - Projection: Random Projection, Sparse RP, PCA-1D
    - Tree: KD-tree, Product Quantization (FAISS)
    - Online weight: KDE-pilot, Distance-Shell, Importance Sampling 4 variants
    - Quasi-random: Sobol
    - Hash: LSH
  - **8M sensitivity**: 5 method (minibatch / random_proj / hilbert / zorder / lsh) × DEEP_8M × 2 sel × 5 seed × 100 query (cross-scale 외적 타당성)
- **3.5 통계 분석**
  - paired Wilcoxon (n=500/cell) + BH-FDR 다중 비교 보정
  - Bootstrap 95% CI (2,000 resample, percentile)
  - per-seed Spearman ρ + Mann-Kendall trend test (RQ1 단조성)
  - Cohen's d (effect size) + paired CI

#### 5.2 Honest Limitations 6종 (5/8 회의 합의 narrative)

1. **L1 Single-table only** — Multi-table join 은 Exqutor main scope. 단일 정확성이 multi 의 *필요조건*, multi 일반화는 future work
2. **L2 KM20 oracle 의 production 학습 부담** — full K-means ~30분 (DEEP 1M ~0.06s 학습 자체는 짧으나 σ_i 사전 계산 + stratum_id 부여 포함). partial_fit (OLTP) + Hilbert (learning-free) 가 production replacement
3. **L3 Effect size practical small** — Hilbert d=−0.156 (negligible-small). RQ3 22 method 중 어떤 method 도 |d| > 0.8 large effect 미달. paired Wilcoxon p < 0.05 는 sample size (n=500) 효과 별도 보고. 어려운 query 에서 method routing 가치 강 (spread vs difficulty ρ=0.78)
4. **L4 numpy estimator 의 sampling-population scope** — bernoulli sampling 이 ≤10K row 캐시에서 추출되며 HT weight 만 N=1M 적용. 절대 q-error 인용 시 "numpy simulation 의 캐시 기반" 명시 필수. 상대 비교 (BERN vs KM20, method ranking) 는 보존
5. **L5 RQ1 measurement methodology robustness** (5/7 W2 발견) — Phase 6 (SQL D, vector.c hook, production-near) 와 Phase 7 (numpy D, simulation) 의 5-sel 격차. gradient 19.6%p 핵심 수치는 Phase 6 기준 인용, Phase 7 결과는 sub-contribution 으로 honest 별도 보고
6. **L6 σ_i 신호 약함의 honest 입증** — Anti-Neyman vs Proportional CI 0 제외하지만 paired Wilcoxon p > 0.5, Cohen's d < 0.1. σ_i 신호가 약해 median 수준에서만 detect, 개별 query 수준은 random 과 동치. 이 fact 자체가 RQ3 distribution-agnostic 추구의 정직 motivation

#### 5.3 Production deployment 권고

- **OLTP 환경**: MiniBatch K-means partial_fit (10ms/chunk, batch 재학습 X)
- **OLAP / 학습 비용 회피**: Hilbert Curve (learning-free, 결정론, ~수초 fit)
- **Skewed dataset (SIFT-like)**: HDBSCAN mid-sel 강
- **Hybrid 환경**: KMeans (outer) + Hilbert (inner) — 두 method 정보 직교 결합
