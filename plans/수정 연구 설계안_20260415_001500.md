## I. 본 수정본의 위치 — v3로부터의 거리

본 v4는 v3(4/3 교수님 미팅 직후 확정)를 완전히 대체하지 않는다. v3의 큰 3단계 구조 — **베이스라인 측정 → 분포 인지 sampling 개선 → 분포 무인지 sampling 확장** — 그리고 그 핵심 동기 — **Exqutor Adaptive Sampling의 skewed 환경 정확도 한계를 드러내고 개선한다** — 는 그대로 유지된다. 본 v4가 v3로부터 달라진 부분은 단 두 가지 차원에서의 정교화다.

첫째, **시나리오 좁힘**. v3는 multi-table join with vector range filter를 본선 시나리오로 가정했으나, 4/14 Phase 3(옵션 A 네이티브 검증) 과정에서 발견된 Exqutor의 네 가지 design constraint는 Exqutor의 Adaptive Sampling hook이 multi-table only로 trigger되며 단일 테이블 vector range query가 hook의 사각지대라는 사실을 정량적으로 드러냈다. v4는 이 사각지대를 본 연구의 새로운 시나리오로 격상한다. 시나리오의 실무적 정당성 — 이미지 검색, 추천 시스템, RAG의 retrieval 단계에서 단일 테이블 vector range query가 오히려 더 흔하다는 관찰 — 은 narrative §II에서 상세화한다.

둘째, **측정 도구의 교체**. v3는 Fisher γ 등의 글로벌 skewness 지표로 query를 skew 구간으로 분류하고 구간별 stratified sampling 이득을 측정한다는 계획이었다. 4/14 Phase 1(RQ1 1차 실험)에서 **글로벌 4 지표 모두 query별 q_error와 Spearman |ρ| < 0.2로 신호 부재**임이 확인되었고, 4/14 Phase 5(로컬 4 지표 후속 시도)에서도 **로컬 4 지표 모두 q_error와 |ρ| < 0.2**임이 재확인되었다. 즉 query-side feature 8지표 전수 검증 후 query-conditional layer 정의가 사전 식별 불가능하다는 결론에 도달했다. v4는 이 negative result를 motivation의 한 축으로 직접 편입하고, layer 정의를 **data-side** — 즉 데이터 자체의 partition (k-means K=20) — 으로 이전한다. 이 이전의 정량 근거는 4/14 Phase 6 Step 3'~4에서 KM20이 3 selectivity 구간에서 paired Wilcoxon p < 0.05로 BERNOULLI 대비 유의하게 우위임이 native 경로로 확인되었다는 것이다. 최강 신호는 s=0.500에서 p=4.01e-05로, Phase 4~6 전체의 최강 통계적 유의 구간이다.

이 두 정교화는 v3의 두 핵심을 모두 보존한 채 각각의 측정 정의를 4/14의 정량 데이터 위에서 단단하게 만드는 방향이며, v3에서 새로 추가되거나 폐기된 RQ는 없다. v4는 v3의 RQ 세 개를 모두 유지하고, 각 RQ의 내용을 4/14 결과에 맞게 재정의한다.

본 v4의 학술적 명제는 다음과 같이 좁고 정확하다.

> **v4 본 명제**. 본 연구는 Exqutor가 자신의 multi-table only design intent로 배제한 단일 테이블 vector range query 사각지대를, 두 단계로 분석하고 개선한다. 첫째 단계는 finding 제시다 — Hook trigger 사각지대와 plan replacement 부작용을 직접 소스 검증과 EXPLAIN ANALYZE로 정량 드러낸다. 둘째 단계는 개입 측정이다 — `TABLESAMPLE SYSTEM`의 block bias를 `TABLESAMPLE BERNOULLI` 한 줄 교체(Pivot A)로 sanitize하고, naive uniform sampling을 data-side k-means K=20 기반 stratified sampling(Pivot C)으로 sanitize한다. 두 sanitize의 정확도 이득은 직교적 ablation — SYSTEM/BERNOULLI/STRATIFIED × dataset × 선택도 — 으로 분리 측정된다. 본 연구는 이 두 단계를 4/28 중간발표(RQ1 Motivation + RQ2 Aware)와 6/11 최종보고서(+ RQ3 Agnostic)의 두 국면으로 나눠 수행한다.

## II. 시나리오 정당화 — multi-table에서 단일 테이블 사각지대로의 좁힘

v3의 multi-table join with vector range filter 시나리오는 Exqutor 원논문이 자신의 본 기여 영역으로 제시한 시나리오와 정확히 일치한다. 그러나 4/14 Phase 3의 옵션 A 네이티브 검증 시도에서 본 팀은 Exqutor의 Adaptive Sampling hook이 multi-table only로 trigger된다는 사실을 직접 소스 검증으로 확인했다. 구체적으로 `pgvector/src/vector.c` line 243의 `if (table_count > 2)` 조건이 query rangetable의 RTE_RELATION + RTE_SUBQUERY 재귀 카운트가 2 이하이면 hook을 우회하고 PG default selectivity 1/3로 fall-through되도록 설계되어 있다. 단일 테이블 vector range query — `SELECT count(*) FROM t WHERE (vec <-> q) < D` 형태 — 는 `table_count = 1`이므로 hook 진입 자체가 불가능하며, 따라서 Exqutor의 Adaptive Sampling 함수에 도달하지 못한다. 이 사실은 Exqutor 원논문 본문에 명시되지 않은 design constraint이며, 본 팀의 직접 소스 검증으로 처음 정량 확인되었다.

본 발견이 시사하는 바는 두 가지다. 첫째, Exqutor의 Adaptive Sampling은 **multi-table 시나리오에 한정된 해법**이며, 단일 테이블 vector range query는 현행 pgvector의 고정 비율 카디널리티 추정 (33.3%)으로 그대로 남아 있다. 둘째, 이 사각지대는 실무적으로 중요하다. 이미지 검색의 *주어진 사진과 유사한 사진을 찾되 거리가 임계값 이하인 것만*, 추천 시스템의 *사용자 임베딩과 유사도 ≥ θ인 아이템 개수*, RAG의 retrieval 단계의 *쿼리 임베딩과 가까운 문서 개수* 는 모두 단일 테이블 vector range query의 전형이며, 카디널리티 추정 정확도가 하위 쿼리 실행 계획 선택 (nested loop vs hash join, vector index 사용 여부)에 직접 영향을 미친다. 즉 Exqutor가 명시적으로 배제한 이 시나리오는 본 연구가 채울 수 있는 학술적 빈자리이면서 동시에 실무적으로 더 흔한 영역이다.

본 v4는 이 두 관찰을 근거로 본선 시나리오를 **단일 테이블 vector range query**로 좁힌다. 좁힘의 비용은 한 가지 — Exqutor 원논문의 multi-table 벤치마크와 직접 비교가 불가능해진다 — 이지만, 대응은 세 가지로 정당화된다. 첫째, 본 연구의 motivation 자체가 "Exqutor가 자신의 design constraint로 배제한 사각지대를 드러낸다"는 것이므로, multi-table 벤치마크와 직접 비교할 필요가 없다. 둘째, 단일 테이블 시나리오에서도 Exqutor의 hook을 `table_count >= 1`로 한 줄 수정해 우회하면 Adaptive Sampling 함수 자체의 동작을 측정 가능하며, 본 팀은 이미 Phase 4에서 이 우회 경로 위에서 Pivot A (BERNOULLI 교체)의 정량 효과를 600 paired 관측 × 4 유의 구간 (p<0.001)으로 확보했다. 셋째, 단일 테이블 시나리오의 실무적 중요성 — 위에 열거한 세 가지 — 은 본 연구의 외적 타당성을 오히려 강화한다.

한편 hook을 `>= 1`로 수정한 상태에서는 Exqutor의 또 다른 design constraint — **hook 활성 시 outer query의 plan-tree 자체가 `Sample Scan` 노드로 교체** — 가 발견되었다. 이는 Exqutor의 hook이 단순 cardinality estimation만 수행하는 것이 아니라 plan execution 자체를 sample scan으로 격하시키는 동작을 한다는 의미이며, multi-table join에서는 outer query가 join 결과를 반환하므로 부분 영향에 그치지만 단일 테이블에서는 outer query 결과 자체가 sample 안 부분 카운트로 바뀌어 의미를 잃는다. 본 v4는 이 두 번째 finding도 motivation의 한 축으로 편입하며, 본선 측정에서 q_error 계산은 plan tree의 actual_rows가 아니라 hook이 set한 plan_rows (또는 `elog`로 서버 로그에 기록된 `Estimated cardinality` 값)로부터 직접 계산한다. 이는 plan replacement 부작용을 측정 단계에서 우회하는 방법론적 선택이며, Phase 6 Step 4의 native 측정 절차로 확립되었다.

네 가지 design constraint 중 나머지 두 가지 — **q-error inf 발산** 과 **sample_size NaN 발산** — 은 Adaptive Sampling 의 update path가 단일 테이블 시나리오에서 수치적으로 불안정함을 보여주는 기술적 발견이며, 본 v4의 중간발표에서는 `vector.update_sample_size = off` GUC로 Adaptive update 경로를 차단한 채 sampling method 자체의 효과만 분리 측정하는 방식으로 회피한다. 이 회피는 Phase 4 / Phase 6의 측정에서 0 segfault로 검증되었다.

본 v4의 중간발표 슬라이드에서 네 가지 design constraint 중 어디까지를 drive하게 노출할지는 자문 결과에 따라 결정된다 (본 문서 §VII 참조). 현재 본 팀의 기본 결정은 **첫째(Hook trigger 사각지대) + 둘째(plan replacement 부작용)** 만 motivation의 새 첫 줄로 드러내고, 셋째 / 넷째 / 다섯째는 부록 또는 보고서에만 기록하는 것이다.

## III. 수정된 RQ 정의 (v4 본선)

본 v4의 RQ1/RQ2/RQ3은 v3의 큰 3단계 구조를 유지하면서 각 RQ의 측정 정의를 4/14 결과에 맞게 재정의한다.

### RQ1 — Motivation: Exqutor Adaptive Sampling의 단일 테이블 사각지대와 구조적 약점 finding

**v3 원안 (H1)**: 거리 분포의 skewness가 클수록 Exqutor Adaptive Sampling의 Q-error가 증가한다. 특히 `|γ| > 1`에서 uniform 대비 2배 이상 악화.

**v4 본선 정의**: Exqutor의 Adaptive Sampling은 단일 테이블 vector range query 시나리오에서 다음 네 가지 구조적 약점을 가진다. (i) Hook trigger 사각지대 — `table_count > 2` 조건이 단일 테이블 query를 hook 경로에서 배제, (ii) Plan replacement 부작용 — hook 우회 시 outer query의 plan-tree 교체로 outer query 결과 의미 상실, (iii) Block sampling bias — `TABLESAMPLE SYSTEM`이 Bernoulli 대비 selectivity ≥ 0.05에서 median q-error를 3.8~9.1% 더 높임, (iv) Query feature 사전 식별 불가능성 — 거리 분포의 글로벌 4 지표 및 로컬 4 지표 모두 query별 q_error와 |Spearman ρ| < 0.2로 무관. 본 네 finding은 skew-aware sampling의 개선 여지가 어디에 있는지 정량적으로 좁혀주며, RQ2/RQ3의 측정 대상을 정의한다.

**판단 기준 (v4)**: (i), (ii)는 직접 소스 검증 및 EXPLAIN ANALYZE 로그로 finding 확정 — 이미 달성. (iii)은 native Phase 4 측정에서 selectivity 4 구간 paired Wilcoxon p<0.001 — 이미 달성. (iv)는 Phase 1 + Phase 5 에서 8 지표 전수 검증 후 24 조합 모두 |ρ| < 0.2 — 이미 달성.

**진행 상태**: ~85%. 남은 작업은 **(a) 시각화 Stage 5b** (Figure 1~6, 4/16 목표)와 **(b) β 외적 타당성 확장** (Phase 7에서 sf10 8M 원본 재현 + sift 128d 확장, 4/15~16).

### RQ2 — Distribution-Aware: Data-side partition 기반 stratified sampling의 정량 효과

**v3 원안 (H2)**: 분포를 알 때 strata(EW/EF/Neyman) × K(3/5/10/20)로 Q-error 50% 감소.

**v4 본선 정의 (Pivot A + Pivot C 병합)**: 두 개의 직교적 sanitize를 직교 ablation matrix로 분리 측정한다.

- **Pivot A**: `vector.c` L889의 `TABLESAMPLE SYSTEM(%f)`을 `TABLESAMPLE BERNOULLI(%f)`로 한 줄 교체. 이는 Exqutor의 block sampling bias를 제거해 **fair baseline** 을 구축하는 도구이며, 단독 기여보다는 Pivot C의 측정 단위로 분리된다. Phase 4에서 native 600 paired × 4 유의 구간 (p<0.001) 달성 — 이미 완주.
- **Pivot C**: `vector.c`에 **data-side k-means K=20 기반 stratified sampling 분기**를 추가. `partsupp_deep_10` 의 1M subset에 `stratum_id smallint` 컬럼 + 인덱스를 미리 부여하고, `vector.sampling_method = 'stratified'` GUC 활성화 시 per-stratum `ORDER BY random() LIMIT sample_size/K` 형태의 SPI SQL로 층별 균등 sample을 추출해 HT (Horvitz-Thompson) 가중 카디널리티 추정식 `est = Σ (n_i × cnt_i / s_i)` 를 native에서 계산한다. Phase 6 Step 4에서 native 600 paired × 3 유의 구간 (s=0.050 p=0.0068, s=0.100 p=0.045, s=0.500 **p=4.01e-05**) 달성 — 이미 완주.

**판단 기준 (v4)**: Phase 6 Step 4에서 Pivot C (KM20 native)가 Pivot A (BERNOULLI native) 대비 selectivity 3 구간 이상 paired Wilcoxon p < 0.05 우위 — **달성 (s=0.050, 0.100, 0.500)**. 최강 신호 s=0.500의 p=4.01e-05는 Phase 4~6 전체의 최강 통계적 유의.

**진행 상태**: ~30%. 남은 작업은 **(a) sf10 8M 원본 재현 (Phase 7-1, 4/15~16)**, **(b) sift 128d 외적 타당성 확장 (Phase 7-2, 4/15~16)**. 본 두 작업이 완료되면 중간발표 본선 RQ2는 3 구간 유의 + 2 dataset 외적 타당성으로 마무리되며, 최종발표에서 wiki 768d 확장 + Layer sweep + 10 seed × 500 query 전면 ablation으로 γ 확장한다.

### RQ3 — Distribution-Agnostic: 1D distance KDE quantile 기반 자동 층화

**v3 원안 (H3)**: Pilot sample 기반 KDE로 분포를 추정한 후 층화. Pilot 1~5%에서 Q-error 30% 개선.

**v4 본선 정의**: query별 pilot sample (전체의 1% 수준)의 거리 값을 1D Gaussian KDE로 fit한 후, **quantile 경계**로 층화해 stratum을 자동 정의. 여기서 핵심 회피 경로는 **고차원 k-means 재학습을 하지 않는 것** — Phase 5의 negative result가 보여준 대로 query feature는 사전 식별 불가능하지만, 같은 query의 sample 된 거리 값 자체는 1D로 환원되므로 KDE가 안정적으로 동작한다. RQ2의 data-side KM20과 RQ3의 1D distance KDE는 직교적 접근 (RQ2는 데이터 자체의 partition, RQ3는 query 시점의 1D 거리 분포)이며, RQ3는 RQ2의 KM20을 대체하지 않고 RQ2가 부담하기 어려운 비용 (online k-means 재학습)을 회피하는 경량 대안을 제시한다.

**판단 기준 (v4)**: (a) RQ3의 pilot 오버헤드 포함 총 비용이 RQ2 대비 20% 이내로 증가하면서, (b) selectivity 2 구간 이상에서 BERNOULLI 대비 paired Wilcoxon p < 0.05 우위 달성. 비용-정확도 곡선으로 시각화.

**진행 상태**: **0%**. 최종보고서 국면 (W7, 5/12~5/18)에서 구현 + 측정. 중간발표에는 진입하지 않는다 (자문 요청 (b) 에 해당).

## IV. 중간발표 (4/28) 본선 범위 — β 옵션 확정

중간발표의 RQ1/RQ2 완성 범위를 **β 옵션** (sf10 8M + sift 128d 외적 타당성 1 구간 추가)으로 확정한다. γ 옵션 (wiki 768d + 전 선택도 6 구간) 은 최종발표로 이월한다. 본 범위 조정의 근거는 두 가지다. 첫째, 중간발표의 목적은 "RQ1 motivation 완성 + RQ2 본선 구현 성공 + 2 dataset 외적 타당성"까지의 내부/외부 타당성 baseline을 제시하는 것이며, 3 dataset × 6 선택도 × 10 seed × 500 query 전면 ablation은 γ 단계의 최종발표 목표이므로 중간발표 범위에는 과잉이다. 둘째, 서버 HDD 환경에서 `ORDER BY random() LIMIT 19/20` 의 per-stratum 비용이 BERN 대비 11배 더 높고, sf10 8M 전체에서 선택도 × seed × query를 풀 확장하면 예산이 기하급수적으로 증가한다. 본 β 옵션은 각 확장 축을 1 구간으로 좁혀 중간발표 데드라인 (4/28) 내에 안전하게 완료할 수 있도록 설계된다.

### IV.1 β 옵션 구체 범위

β 옵션은 중간발표 본선에 다음 4 축을 1 구간씩 추가한다.

1. **sf10 8M native 재현** (`partsupp_deep_10_phase7_8m_subset` — 본 v4 §IV.2 참조): 선택도 s=0.500 1 구간, BERN + STRAT 2 mode, 100 query × 1 seed × 1 mode = 100 측정 × 2 mode = 200 측정. 예상 소요: BERN ~680초 + STRAT ~7300초 ≈ 2h 15m (HDD, 8M 규모). 본 실험의 목적은 Phase 6 Step 4 의 1M subset 결과가 8M 원본에서 재현되는지 (즉 subset 설계 자체가 bias를 만들지 않았는지)를 확인하는 내적 타당도 강화.

2. **sift 128d 외적 타당성 확장** (`customer_sift_10` 기반 subset): 선택도 s=0.500 1 구간, BERN + STRAT 2 mode, 100 query × 1 seed × 1 mode = 100 측정 × 2 mode = 200 측정. sift 데이터셋은 pgvector 커뮤니티의 표준 benchmark 중 하나이며, 128d는 96d DEEP과 다른 차원 영역을 커버한다. 본 실험의 목적은 Pivot C의 KM20 층화 효과가 96d DEEP의 특정 데이터 특성에 국한되지 않고 128d SIFT에서도 재현되는지 외적 타당성 확인.

3. **기존 1M subset × KM20 native 측정** (Phase 6 Step 4, 이미 완주): 본 v4는 이 결과를 중간발표 본선의 내적 타당도 baseline으로 그대로 유지. selectivity 6 구간, BERN + STRAT 2 mode, 100 query × 1 seed, p=4.01e-05 (s=0.500) 최강 신호.

4. **시각화 Stage 5b** (Figure 1~6, 4/16 목표): Phase 4 SYSTEM vs BERNOULLI paired scatter (Figure 1), Phase 6 Step 4 KM20 native s=0.500 boxplot (Figure 2), Phase 6 Step 3' 4 mode 비교 (Figure 3), Phase 7 sf10 8M + sift 128d heatmap (Figure 4), Python vs Native 일치성 표 (Figure 5), Phase 5 local skew 24 조합 ρ heatmap (Figure 6, negative result 시각화).

### IV.2 안전 경로 — 옵션 B 채택

4/14 세션에서 두 가지 경로가 검토되었다. (A) 원본 `partsupp_deep_10` 8M 테이블에 `stratum_id smallint` 컬럼을 직접 추가하고 1M UPDATE를 8M UPDATE로 확장, (B) `partsupp_deep_10_phase7_8m_subset` 이라는 별도 테이블을 `CREATE TABLE AS SELECT ... FROM partsupp_deep_10` 로 복사한 후 복사본에만 stratum_id를 부여. 본 v4는 **옵션 B를 채택** 한다.

옵션 B의 근거는 세 가지다. 첫째, 원본 `partsupp_deep_10` 은 다른 팀/사용자가 사용할 가능성이 있는 공유 자산이며, `ALTER TABLE ADD COLUMN` + 8M UPDATE는 원본에 되돌릴 수 없는 변경을 남긴다. 둘째, Phase 6 Step 4의 1M subset 패턴 (`partsupp_deep_10_subset_1m` 별도 테이블) 이 이미 동일 원리로 구축되어 있어, 본 β 확장은 그 패턴의 직접 확장이다 — 설계 일관성. 셋째, 8M subset은 약 4 GB + 16 MB stratum + 수 MB 인덱스 = 대략 4.1 GB로, 서버 HDD 여유 (2 TB)에 충분히 수용 가능.

옵션 B의 실행 SQL 골격은 다음과 같다.

```sql
-- 1. 원본 복사 (stratum_id 0 placeholder)
CREATE TABLE partsupp_deep_10_phase7_8m_subset AS
SELECT ps_partkey, ps_suppkey, ps_embedding, 0::smallint AS stratum_id
FROM partsupp_deep_10;

-- 2. 인덱스 (선택도 실험 전용, HNSW는 생성 않음 — Sampling 경로 강제)
CREATE INDEX idx_phase7_8m_stratum
  ON partsupp_deep_10_phase7_8m_subset (stratum_id);

-- 3. KM20 centroid 재학습 (8M 전체에 대해 numpy mini-batch k-means, seed=42)
--    + stratum_id UPDATE (8M rows, 예상 150~200초)
--    스크립트: experiments/code/rq1/phase7_sf10_8m.py (본 v4 §V.1)

-- 4. VACUUM ANALYZE
VACUUM ANALYZE partsupp_deep_10_phase7_8m_subset;

-- 5. 측정 (BERN + STRAT s=0.500 × 100 query)
--    스크립트: experiments/code/rq1/phase7_sf10_8m.py 의 measure 부분
```

### IV.3 sift 128d 경로

`customer_sift_10` 은 현재 HNSW 인덱스 (`c_sift_hnsw` 추정)를 가지고 있어, Sampling 경로 강제를 위해서는 **HNSW 인덱스가 없는 subset** 을 별도로 생성해야 한다. 본 v4는 `customer_sift_10_phase7_noidx_subset` 이라는 이름으로 `CREATE TABLE ... ## V. 실험 파이프라인 확정 (Phase 7 β 단계)

본 §V는 4/15~16 에 조현빈이 서버에서 실행할 실험 파이프라인 세 가지를 정의한다. 로컬에서 스크립트 작성 → git push → 서버 rsync → tmux 실행 경로로 진행한다.

### V.1 Phase 7-1: `phase7_sf10_8m.py`

**목적**: Phase 6 Step 4 의 1M KM20 native 결과를 8M 원본에서 재현. 내적 타당도 강화.

**입력**: `partsupp_deep_10` (서버 Exqutor PG 55436, 8M rows, HNSW 없음), `query_pool.parquet` (100 query), `query_selectivity.parquet` (600 row, 단 s=0.500 1 구간만 사용).

**동작 단계**:
1. `partsupp_deep_10_phase7_8m_subset` 이 존재하면 재사용, 없으면 `CREATE TABLE AS` 로 8M 복사 (stratum_id 0 placeholder, 예상 5~8분).
2. 서버 `partsupp_deep_10_phase7_8m_subset` 의 ps_embedding 8M × 96 float 을 numpy array 로 로드 (약 3 GB 메모리 — 서버 64GB RAM 충분).
3. `phase6_layer_compare.build_layer_kmeans (seed=42, K=20)` 을 8M 에 대해 재호출. 새 centroid 20 × 96 + 8M stratum_id 를 얻음. Phase 6 Step 3' 의 1M 결과와는 centroid 가 다를 것이나, 이는 데이터가 달라졌기 때문이며 정상.
4. stratum_id CSV export → `COPY ... FROM stdin` 으로 8M UPDATE (예상 150~200초, 1M 대비 선형 확장).
5. `CREATE INDEX idx_phase7_8m_stratum ON ... (stratum_id); VACUUM ANALYZE`.
6. 측정: `phase6_strat_native.py` 의 측정 loop 를 s=0.500 1 구간 × 100 query × 2 mode (BERN, STRAT) 로 실행. 옵션 `--table partsupp_deep_10_phase7_8m_subset`, `--selectivity-filter 0.5`, `--n-queries 100`.
7. 산출물: `cache/rq1/phase7_8m_bern.parquet`, `cache/rq1/phase7_8m_strat.parquet`, `phase7_8m_paired.json`.

**예상 시간 (HDD)**:
- 복사 5~8분 + k-means + UPDATE + index 10~15분 = **사전 준비 ~20분**
- BERN 측정 (100 query × s=0.500, sample_size=385, 8M 스캔 일부): ~7분/query × 100 query ÷ 60 = 서버 HDD 병목에 따라 30분~2시간. 실제로는 sample_size 385 추출만 하므로 query 당 0.5~1초 수준 예상, 100 query ≈ 50~100초.
- STRAT 측정 (100 query × s=0.500 × per-stratum ORDER BY random() LIMIT 20): Phase 6 의 1M BERN 대비 STRAT 11배 느렸음 (83초 → 908초). 8M × s=0.500 STRAT 은 sample_size * 8 = 3080 per stratum, 즉 stratum 당 154 row, 이를 8M 에서 ORDER BY random() 으로 추출 → query 당 5~15초. 100 query ≈ 8~25분.
- **총 예상 1시간 30분 ~ 2시간 (준비 + 측정)**.

**성공 기준**: s=0.500 에서 STRAT 가 BERN 대비 median q_error −1% 이상 (Phase 6 Step 4 의 −1.81% 재현 허용 범위). paired Wilcoxon p < 0.05 가 이상적이나, p<0.15 선에 들어오면 β 달성으로 판단. Phase 6 Step 4 에서 100/100 paired 가 확보된 것을 감안하면 재현성 높음.

## VI. 최종발표 (5/27) 로드맵 — W5 ~ W8

본 §VI 는 중간발표 이후 4/28 ~ 5/25 의 4 주를 W5 ~ W8 로 분할해 최종발표 본선 범위를 정의한다. γ 단계 확장 + RQ3 구현 + 최종보고서 작성이 핵심.

### VI.1 W5 (4/28 ~ 5/4): 최적화 + Layer sweep + wiki 768d 검증

1. **STRAT 속도 최적화** (1 day): 현재 per-stratum `ORDER BY random() LIMIT` 의 908초/600 query 를 per-stratum `TABLESAMPLE BERNOULLI(ratio_i)` 로 교체. sample size 가 부정확해지지만 median q_error 영향은 미미할 것으로 예상. 목표: BERN 대비 11배 → 2배 이내. 검증: Phase 6 Step 4 의 3 유의 구간 재현.
2. **Layer sweep** (1 day): KM20 이외의 layer 후보 4 종 — (a) KM30 / KM40 / KM50, (b) random projection 기반 층, (c) multi-layer PCA (Python counterfactual only), (d) k-means on half precision (float16) — 의 selectivity 3 구간 기준 paired Wilcoxon 비교. 목표: KM20 유지 또는 전환 결정. 1M subset × 5 seed 로 제한.
3. **wiki 768d k-means 사전 검증** (0.5 day): `part_wiki_10` (768d) 에서 KM20 이 empty cluster 없이 학습되는지, 학습 시간이 어떻게 증가하는지 측정. empty cluster 발생 시 fall-back: **PCA 96d 축소 후 KM20** 경로.
4. **sift 128d 전면 6 sel × 3 mode native** (1 day): β 에서 확보한 sift subset 을 6 selectivity 전 구간으로 확장. 500 query 로 상승.

### VI.2 W6 (5/5 ~ 5/11): 3 dataset × 3 mode × 6 sel × 10 seed × 500 query 전면 ablation

본 주차의 핵심 결과물은 **최종보고서의 main result table**. 예산 계산: 3 dataset × 3 mode × 6 sel × 10 seed × 500 query = 270,000 측정. query 당 평균 1~2초 (HDD, STRAT 포함) = 270,000 ~ 540,000 초 = 75 ~ 150 시간. 서버 24시간 점유 불가 — **W5 의 per-stratum BERNOULLI 최적화** (11배 → 2배) 가 전제. 최적화 적용 시 총 예산 ~25 시간. 주말 분할 + 주중 야간 실행으로 수용 가능.

본 ablation 는 다음 축을 가진다.

| 축 | 값 |
|---|---|
| dataset | deep 96d / sift 128d / wiki 768d (wiki 는 W5 검증 통과 시, 실패 시 PCA 96d fallback) |
| mode | bernoulli / stratified_km20 / (선택) stratified_km_optimized |
| selectivity | 0.001, 0.010, 0.050, 0.100, 0.300, 0.500 (6 구간) |
| seed | 10 (Phase 6 의 5 → 10 으로 확대) |
| query | 500 (Phase 6 의 100 → 500 으로 확대, p-value 신뢰도 강화) |

결과 분석 + 시각화 1 차는 본 주차 말 착수.

### VI.3 W7 (5/12 ~ 5/18): RQ3 KDE-pilot Native 구현 + pilot sensitivity

1. **RQ3 KDE-pilot Python counterfactual 구현** (2 day): scipy.stats.gaussian_kde 기반, pilot 500 row (전체의 0.05%), pilot의 distance 값 분위 경계로 6 stratum 정의. 본 Python 구현은 RQ2 의 KM20 counterfactual 과 같은 estimator 로직을 재사용해 동치성 확인 후 Native 로 포팅.
2. **RQ3 Native 구현** (2 day): `vector.c` 에 `sampling_method=kde_pilot` 분기 추가 (+200 줄 예상). per-query pilot 추출 → SPI 로 1D KDE 를 PL/pgSQL 또는 C 함수로 평가 → quantile 경계 도출 → main sample 을 경계 위에서 층화 → HT 공식으로 추정. 구현 리스크는 pilot 추출의 random() 재시드 및 경계 계산의 수치 안정성.
3. **pilot 크기 sensitivity** (1 day): pilot 0.5% / 1% / 2% / 5% 에서 최종 q_error 비교.
4. **비용-정확도 곡선** (1 day): pilot overhead (추출 + KDE + 경계) 를 포함한 총 sampling cost 대비 q_error 곡선. RQ2 의 KM20 (사전 학습된 stratum 사용, overhead 0)과 직접 비교.

### VI.5 리스크 대응 (3종)

본 v4 의 로드맵은 다음 3 종 리스크에 대해 구체 대응 경로를 가진다.

**R1. 측정 시간 폭발**. W6 ablation 의 총 예산 25 시간은 per-stratum BERNOULLI 최적화 (W5) 가 전제. 최적화가 실패하면 11배 비용 → 275 시간 → **500 query → 200 query 축소** + **10 seed → 5 seed** 축소로 재조정. 축소 적용 시 약 50 시간 → 주말 + 주중 야간 분할.

**R2. wiki 768d k-means 재학습 실패**. empty cluster 발생 또는 학습 시간 > 10 분 시 fall-back: (a) PCA 96d 축소 후 KM20, 또는 (b) wiki 전체 대신 100K subset 사용. 최악의 경우 wiki 제외하고 **deep + sift 2 dataset** 으로 후퇴.

**R3. RQ3 KDE Native 구현 고차원 문제**. 본 v4 의 핵심 회피 경로는 **k-means 재학습 없이 1D distance KDE 를 quantile 경계로 활용** 하는 것 — 고차원 문제 자체를 우회. scipy.stats.gaussian_kde 는 1D 에서 매우 안정적이며, quantile 경계는 KDE 의 inverse CDF 로 직접 계산 가능. 본 경로가 실패하면 **histogram 기반 단순 층화** 로 degrade.

## VII. 자문 요청 항목 (4/15 이메일 발송)

본 v4 는 멘토 자문을 이메일 형태로 요청한다 (미팅 일정 조율 불필요). 자문 요청의 세 항목은 `direction_pivot_rationale.md §6` 의 6 항목을 본 v4 의 우선순위에 맞춰 3 항목으로 압축한 것이다.

**자문 요청 (a) — 시나리오 전환의 학술적 정당성**. v3 의 multi-table join 시나리오가 v4 의 단일 테이블 vector range query 사각지대로 전환된 것이 학술적으로 정당한지. 본 §II 의 네 가지 design constraint 가 전환의 충분 근거인지. 본 팀의 입장은 *충분 근거이며 동시에 새 학술적 빈자리*. 자문 결과에 따라 본 v4 §II 의 narrative 톤이 조정될 수 있다.

**자문 요청 (b) — Pivot A + Pivot C 병합의 기여 정당성**. Pivot A (BERNOULLI 한 줄 교체) 가 Pivot C (KM20 stratified) 와 병합된 것이 v3 합의 본선과 별개로 정당한 기여인지, 아니면 *기여 인플레이션* 으로 보일 위험이 있는지. 본 팀의 입장은 *Pivot A 는 fair baseline 구축 도구이며 동시에 sampling method ablation 의 단독 단위로 학술적 가치 보유*. Pivot A 만 단독으로는 한 줄 변경이지만 Pivot C 와 결합한 ablation matrix 의 일부로서 정당.

**자문 요청 (c) — 중간발표 슬라이드의 design constraint 노출 수위**. 본 v4 §II 에서 Motivation 의 새 첫 줄로 격상된 두 design constraint (Hook trigger 사각지대 + plan replacement 부작용) 외에, 다른 세 가지 (q_error inf / sample_size NaN / Adaptive update SIGSEGV) 를 중간발표 슬라이드에 어느 수준으로 드러낼지. 본 팀의 세 후보는 (a) 첫째·둘째만 (motivation 강화 목적, 슬라이드 1~2 장, 기술적 발견은 부록/보고서) — **기본 결정**, (b) 네 가지 모두 (정직한 보고 목적, 슬라이드 3~4 장), (c) 첫째만 (시간 제약 고려, 슬라이드 1 장). 자문 결과에 따라 확정.

본 세 자문 요청은 자문 이메일 본문 (submission/속도는벡터_자문이메일_20260415.md) 에서 구체화된다. 자문 회신이 도착한 후 본 v4 § II / §VII 이 v4.1 로 미세 조정될 수 있으며, 조정은 commit 로 이력 보존된다.

## VIII. 예상 기여 (최종)

본 v4 의 예상 기여는 v3 의 네 가지를 두 단계 (finding 제시 + 개입 측정) 로 재조직한 결과다.

**기여 1 — Exqutor 의 단일 테이블 vector range query 사각지대 finding**. 본 연구는 Exqutor 의 `vector.c` 소스 검증과 EXPLAIN ANALYZE 로그 분석을 통해 Adaptive Sampling hook 이 multi-table only 로 trigger 되는 design constraint 와, 단일 테이블 시나리오에서 plan-tree 가 Sample Scan 으로 교체되어 outer query 정확성이 깨지는 부작용을 정량 드러낸다. 이 두 finding 은 Exqutor 원논문 본문에 명시되지 않은 사실이며, 본 팀의 실험 (Phase 3) 이 처음 확인한 내용이다.

**기여 2 — Query feature 사전 식별 불가능성의 전수 검증**. 본 연구는 96d DEEP 1M subset 의 100 query 에 대해 query-side feature 8 지표 (글로벌 4 + 로컬 4) 를 전수 계산하고, q_error 와의 Spearman 상관이 24 조합 모두 |ρ| < 0.2 임을 확인해 query-conditional layer 정의가 고차원 vector dataset 에서 *사전 식별 불가능* 함을 정량 입증한다. 이 부정 결과는 향후 vector DB 의 카디널리티 추정 연구에서 query-side feature 기반 stratified sampling 을 시도하기 전에 본 결과를 우회할 대안적 접근을 설계해야 함을 시사한다.

**기여 3 — Block sampling bias 의 native 정량 검증과 한 줄 교체 해결**. 본 연구는 Exqutor 가 사용하는 `TABLESAMPLE SYSTEM` 이 Bernoulli 대비 selectivity ≥ 0.05 에서 median q_error 를 3.8~9.1% 높인다는 것을 600 paired 관측으로 확인하고, `vector.c` L889 한 줄 교체로 이 bias 를 제거한다. Phase 4 의 native 측정에서 4 selectivity 구간에서 paired Wilcoxon p < 0.001 로 Pivot A 의 효과가 확인되었다.

**기여 4 — Data-side k-means K=20 기반 stratified sampling 의 native 구현과 정량 효과**. 본 연구는 `vector.c` 에 +228 줄의 stratified sampling 분기를 추가하고, 1M subset 에 `stratum_id` 컬럼 + 인덱스를 부여해 per-stratum `ORDER BY random() LIMIT` + HT 가중 카디널리티 추정을 native 로 구현한다. Phase 6 Step 4 의 native 측정에서 3 selectivity 구간에서 paired Wilcoxon p < 0.05 로 BERNOULLI 대비 우위임이 확인되었고, 최강 신호는 s=0.500 에서 p=4.01e-05 로 Phase 4~6 전체의 최강 통계적 유의이다. 본 기여는 v3 의 원 가설 (H2) 을 native 경로 위에서 처음으로 실제 구현해 측정한 결과이며, Python counterfactual 과의 직접 일치성 검증 (summary.md §IX.4) 도 함께 확보되었다.

**기여 5 (최종발표 단계) — Distribution-agnostic KDE-pilot 의 경량 구현과 비용-정확도 trade-off**. 최종보고서 국면에서 RQ3 의 KDE-pilot 을 1D distance KDE + quantile 경계로 구현해 고차원 k-means 재학습을 회피하는 경량 대안을 제시한다. pilot 오버헤드 포함 총 비용 대비 q_error 곡선으로 RQ2 의 KM20 (사전 학습) 과 직접 비교한다.
