### 1단계: 메인 페이지 심층 분석

(a) `notion-fetch`로 메인 페이지의 전체 콘텐츠를 가져와.
   - `include_discussions: true` 옵션으로 코멘트·토론 위치도 포함.

(b) 메인 페이지의 **아이콘, 커버 이미지** 유무를 확인해. 없으면 개선 대상으로 기록.

(c) 발견한 모든 하위 페이지도 `notion-fetch`로 각각 콘텐츠를 가져와서 분석해.

(d) 다음 기준으로 콘텐츠 품질을 점검해:

**구조적 완성도** — 캡스톤에 필수적인 다음 섹션이 존재하는지:
   - 프로젝트 개요 (연구 주제, 목표, 범위)
   - 팀원 소개 (이름, 역할, GitHub 계정, 연락처)
   - 연구 배경 및 관련 연구 (Exqutor, ECQO, VAQ 등)
   - 연구 방향 (Cascaded Vector Similarity Decomposition — 벡터 유사도 범위 분할 필터링)
   - 실험 설계 (데이터셋, 메트릭, 비교 시스템, 환경 구축 계획)
   - 일정/마일스톤 (4/1 세미나 ~ 6월 최종)
   - 회의록 (교수님 미팅, 팀 회의, 자문위원 미팅)
   - 산출물 관리 (제출물, 분석 문서, 코드)
   - 참고문헌/논문 리스트 (55편, A~E 5개 카테고리)
   - 주간 진행 보고

**내용 충실도**:
   - 빈 섹션, "TODO", "작성 예정", placeholder 텍스트가 있는 곳

**일관성**:

### 2단계: 데이터베이스 정밀 점검

0단계에서 발견한 모든 데이터베이스에 대해:

(a) `notion-fetch`로 각 DB의 스키마(data source)를 가져와서 분석해.

(b) **스키마 적절성 점검**:
   - 캡스톤 일정 DB: 제목, 마감일(DATE), 상태(STATUS/SELECT), 담당자(PEOPLE), 우선순위, 카테고리 속성이 있는지
   - 회의록 DB: 날짜, 참석자, 안건, 결정사항, 후속과제 속성이 있는지
   - 논문 리스트 DB: 제목, 저자, 학회/연도, 분석상태, 카테고리(A~E), 담당자 속성이 있는지
   - 태스크/할일 DB: 제목, 상태, 담당자, 마감일, 우선순위 속성이 있는지
   - 속성 타입이 적절한지 (날짜가 텍스트로 되어있진 않은지, 상태가 체크박스 대신 SELECT/STATUS인지 등)
   - Select/Multi-select 옵션이 체계적인지 (색상 코딩, 옵션 이름 통일)

(c) **뷰(View) 활용도 점검**:
   - 각 DB에 어떤 뷰가 있는지 확인
   - 부족한 뷰 제안 (예시):
     - 일정 DB → 캘린더뷰(`CALENDAR BY "마감일"`), 타임라인뷰(`TIMELINE BY "시작일" TO "마감일"`)
     - 태스크 DB → 보드뷰(`GROUP BY "상태"`), 필터 뷰(내 담당만, 이번 주 마감 등)
     - 회의록 DB → 갤러리뷰 또는 리스트뷰(최신순 정렬)
     - 논문 DB → 보드뷰(`GROUP BY "분석상태"`), 차트뷰(카테고리별 진행률)

(d) **DB 간 관계(Relation) 점검**:
   - 태스크↔일정, 회의록↔태스크, 논문↔태스크 간 Relation 속성이 연결되어 있는지
   - 없다면 어떤 Relation을 추가하면 좋을지 제안

### 3단계: 코멘트·토론 점검

(a) 메인 페이지와 주요 하위 페이지에 대해 `notion-get-comments`를 실행해:

   - `include_resolved: true` (해결 완료 코멘트 포함)

(b) 다음을 정리해줘:
   - 미해결(unresolved) 코멘트 목록 — 내용, 위치, 작성자, 날짜
   - 오래된 미해결 코멘트 (1주 이상) 강조
   - 해결 완료됐지만 본문에 반영이 필요해 보이는 코멘트

### 5단계: 개선 제안 종합 보고서

위 1~4단계 점검 결과를 바탕으로, 다음 6개 카테고리별로 구체적인 개선 액션 리스트를 만들어줘.

**번호 체계**: 카테고리 접두어 + 일련번호로 통일 (예: FIX-1, ADD-3, VIS-2).
각 항목에 **우선순위(상/중/하)**와 **예상 소요 시간**을 표시해.

| 접두어 | 카테고리 | 설명 |
|---|---|---|
| FIX | 🔧 수정 | 오류, 오타, 잘못된 정보, 깨진 링크, 날짜 오류 등 즉시 고칠 사항 |
| FILL | 📝 보완 | 내용이 부족하거나 빈 섹션에 채울 내용 제안 (구체적 초안 포함) |
| ADD | ➕ 추가 | 없지만 있어야 할 섹션, 페이지, DB, 뷰 (구체적 스키마/구조 제안) |
| REORG | 🗂️ 구조 개선 | 페이지 계층 구조, 네비게이션, 정보 설계 개선 |
| VIS | 🎨 비주얼 | 아이콘, 커버 이미지, 콜아웃, 구분선, 색상, 토글 활용 |
| LINK | 🔗 연동 강화 | 관련 페이지 간 링크, Relation DB 연결, 백링크, 외부 연동 |

### 6단계: 실행 (내 승인 후에만)

5단계의 개선 리스트를 보여준 후, **내가 항목 번호(예: "FIX-1, ADD-2, VIS-3 실행해줘")를 지정해서 승인하면** 해당 항목만 다음 도구로 실행해:

**콘텐츠 수정/보완:**
- `notion-update-page` (command: "update_content") — 기존 콘텐츠의 특정 부분 수정
- `notion-update-page` (command: "replace_content") — 섹션 전체 교체
- `notion-update-page` (command: "update_properties") — 아이콘·커버·제목 변경

**페이지/DB 생성:**
- `notion-create-pages` — 부족한 하위 페이지 신규 생성 (parent 지정 필수)
- `notion-create-database` — 필요한 DB 신규 생성 (스키마 DDL 포함)

**DB 스키마 개선:**
- `notion-update-data-source` — 기존 DB에 컬럼 추가(ADD COLUMN), 이름 변경(RENAME COLUMN), 타입 변경(ALTER COLUMN SET)
- Relation 속성 추가 시 양방향(DUAL) 여부도 제안해줘

**뷰 추가/수정:**
- `notion-create-view` — 유용한 뷰 추가 (보드, 캘린더, 타임라인, 차트, 대시보드 등). configure DSL 포함.
- `notion-update-view` — 기존 뷰의 필터·정렬·그룹 최적화

**구조 개선:**
- `notion-move-pages` — 잘못된 위치의 페이지를 올바른 부모 아래로 이동
- `notion-duplicate-page` — 템플릿 활용을 위한 페이지 복제

**팀 협업:**
- `notion-create-comment` — 팀원에게 알림이 필요한 곳에 코멘트 작성 (멘션 포함 가능)

---

### 실행 규칙

1. 각 단계를 실행한 뒤 **발견 사항 요약**을 보여주고, 다음 단계 진행 전 나에게 확인받아줘.
2. 실제 수정·추가·삭제 작업은 **6단계에서 내가 항목별로 승인한 것만** 진행해.
3. `notion-fetch`로 콘텐츠를 수정하기 전에 반드시 현재 내용을 먼저 가져와서 정확한 old_str을 확인해.
4. DB 스키마 변경 시 기존 데이터에 영향이 있을 수 있는 경우 반드시 경고해줘.
5. 모든 텍스트는 **한국어**로 작성하되, 학술 용어는 영어 병기 가능.
6. 페이지 생성 시 아이콘은 주제에 맞는 이모지를 포함해줘.
