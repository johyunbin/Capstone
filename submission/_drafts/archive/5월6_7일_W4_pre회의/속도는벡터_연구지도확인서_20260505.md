## 1. 중간 발표(4/30) 이후 진행 사항

지난 4월 30일 인종 A428호에서 진행된 중간 발표를 통해 RQ1 (데이터 skew 정량화) 및 RQ2 (KM20 층화 샘플링) 의 일차 결과를 보고드렸습니다. 발표 직후 팀 내부 검토 및 5월 4-5일에 걸친 두 차례 회의를 통해 두 가지 보강 사안이 도출되어, 연구 질문의 구조를 재정립하기로 결정하였습니다.

### 1.1 보강 사안 (가) — Normal vs Skew 데이터셋의 직접 비교 부재

중간 발표 시점까지는 KM20 층화 샘플링과 BERN baseline 의 비교에 집중하였으며, 데이터 분포 자체가 random sampling 정확도에 미치는 영향을 정량화하는 직접 비교 실험이 빠져 있었습니다. 박세은 팀장이 제안한 연구 동기 — "normal 분포에서 잘 작동하던 random sampling 이 skew 분포에서는 이렇게나 부정확해진다" — 를 살리기 위해 이 비교를 RQ1 의 핵심 실험으로 격상하기로 하였습니다.

### 1.2 보강 사안 (나) — 분포 인식 샘플링의 추가 강화 가능성

기존 RQ2 의 KM20 층화는 Proportional Allocation (cluster 크기 비례 배분) 만을 사용하였는데, 이는 cluster 별 분산 정보를 활용하지 않습니다. 통계학적으로 정통한 Neyman Allocation (variance-optimal, Neyman 1934) 을 추가 후보로 도입하여 KM20 위에서의 추가 분산 감소 가능성을 검증합니다.

## 2. 재정립한 연구 질문

### RQ1. 기존 random sampling 이 skew 데이터셋에서 얼마나 부정확한가?

**가설 H1**: skew 데이터일수록 random sampling 의 q-error 가 악화되며, block 단위가 row 단위보다 편향이 더 심하다.

**설계** — 2x2 factorial (Block vs Row × Normal vs Skew):

| 데이터셋 | SYSTEM (block 단위) | BERNOULLI (row 단위) |
|---|---|---|
| DEEP 1M (HHI 0.0527) | 측정 완료 | 측정 완료 |
| SIFT 1.5M (HHI 0.0578) | **추가 측정 예정** | 측정 완료 |

**기측정 결과 (DEEP 1M, SYSTEM vs BERNOULLI)**: BERNOULLI 가 모든 selectivity 구간에서 우위 +0.7~12.0%p, paired Wilcoxon p<0.001.

**추가 실험**: SIFT × SYSTEM(block) baseline 측정 (~2시간). 이로써 4 cell 비교 표가 완성됩니다.

### RQ2. 분포를 아는 상황에서 어떤 샘플링 방식이 최적인가?

**기준선**: BERNOULLI (RQ1 의 row-level baseline)

**비교 후보** (3-way ablation):

(a) **KM20 + Proportional Allocation** — n_i ∝ N_i (cluster 크기 비례). 측정 완료, DEEP +1.6~8.9%, SIFT +3.0~4.4%.

(b) **KM20 + Neyman Allocation** (신규) — n_i ∝ N_i × σ_i (크기 × 분산). variance-optimal, Neyman 1934 정리. 추가 +1~3% 기대.

(c) **KM20 + Anti-Neyman** (신규, ablation) — n_i ∝ N_i / σ_i (크기 / 분산). variance-suboptimal. 분산 비례의 정당성을 ablation 으로 입증.

**부수 실험**: Sample size 민감도 분석 (sample_size = 100, 385, 1000, 3000). 표본 크기가 작을수록 KM20 의 효과가 커지는지 검증.

**K=20 채택 근거**: Phase 6 Step 3' 에서 K=10 vs K=20 직접 비교 결과 K=20 이 selectivity 0.10 까지 추가 유의 신호를 확보하였습니다. K=50 이상은 sample_size=385 기준 stratum 당 표본이 7~8 개 이하로 떨어져 추정 분산이 폭증하므로 본 연구 범위에서 제외하였습니다.

### RQ3. 분포를 모르는 상황에서 어떤 샘플링 방식이 최적인가?

**가설 H3**: distribution-agnostic 방법은 KM20 (oracle) 대비 유의미한 비율을 회수하면서 사전 학습 불필요 또는 극소 비용이라는 운영 이점을 제공한다.

**설계**: 7-way 비교, 3 패러다임

**Paradigm 1 — Offline Partition** (데이터셋 고정 가정, 1회 사전 계산):
- C. Random Projection (Johnson-Lindenstrauss lemma)
- A. LSH (Locality-Sensitive Hashing)
- E. Hilbert Curve (space-filling curve)
- F. MiniBatch K-means (Sculley 2010, 1~5% 학습)

**Paradigm 2 — Online Query-Adaptive** (쿼리 시점 동적 적응):
- G. Distance-Shell (pilot 기반)
- B. KDE-pilot (Silverman bandwidth + Neyman)

**Paradigm 3 — Weight-based** (분할 X, 가중치만):
- H. Importance Sampling (2x2 factorial 측정)

**핵심 metric — Recovery Rate**:
```
recovery_rate = (방법X − RANDOM20) / (KM20 − RANDOM20)
```
- 1.0 → KM20 oracle 수준 회수
- 0.0 → RANDOM20 수준 (공간 인식 없음)
- 음수 → RANDOM20 보다 나쁨

분모 붕괴 경계 (사전 등록): `|KM20 − RANDOM20| ≤ 1%p` 인 셀에서는 Recovery Rate 대신 절대 Q-error 개선폭을 primary metric 으로 사용.

## 4. 본 연구의 contribution

(1) **RQ1 — Normal vs Skew × Block vs Row 정량 비교**: 데이터 분포가 random sampling 정확도에 미치는 영향의 직접 측정. 이는 박세은 팀장이 제기한 연구 동기 ("normal 에서 잘되던 random 이 skew 에서는 이렇게나 안 나오더라") 의 정량 증거가 됩니다.

(2) **Selectivity Gradient 분석**: 좁은 쿼리 (s=1%) 에서 KM20 vs RANDOM20 격차가 19.6%p 에 달하며, 이는 Exqutor 원논문이 다루지 않은 영역입니다.

(3) **Two-Level Decomposition**: Level 1 (Proportional, K 등분의 표본 안정화 효과) 와 Level 2 (Spatial, 공간 구조 인식 효과) 의 분해 framework. 분포 정보가 가치를 만드는 메커니즘을 정량적으로 분해합니다.

(4) **Recovery Rate Framework (RQ3)**: 분포 정보 없이 oracle 의 가치를 어디까지 회수할 수 있는지의 trade-off curve 를 정량화합니다.

## 5. Limitation 자기 점검

본 연구의 한계와 향후 연구 방향을 다음과 같이 명시합니다.

(1) RQ2 의 KM20/Neyman 은 **oracle benchmark** 이며 production 솔루션이 아닙니다. 실제 운영 솔루션은 RQ3 의 distribution-agnostic 방법이며, 본 연구의 가치는 분포 정보의 이론적 상한과 회수율을 정량화하는 데 있습니다.

(2) 사전 계산 비용은 **one-time cost** 이며, 이는 HNSW 인덱스 빌드와 같은 layer 입니다 (DEEP 1M K=20: 1.2초, 메모리 1/1000 of HNSW). 쿼리 응답 시점은 stratum_id lookup O(1) 입니다.

(3) **INSERT/UPDATE 빈번한 OLTP 환경**은 본 연구 범위 외이며, 본 연구는 analytical workload (bulk load + 다수 쿼리) 를 가정합니다. RQ3 의 F (MiniBatch K-means) 가 이 부담을 1/20~1/100 수준으로 완화하나, 본격 OLTP 검증은 future work 입니다.

(4) **단일 → 멀티 테이블 일반화**는 future work 입니다. 단일 테이블 정확성은 멀티 테이블 정확성의 *필요조건*이지 충분조건은 아닙니다. 멀티 테이블에서는 join key 분포, 상관 등 추가 차원이 있어 별도 검증이 필요하며, 특히 KM20 의 stratum_id 가 join 후에도 의미를 유지하는지의 이론적 분석부터 다시 풀어야 합니다.
