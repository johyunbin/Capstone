## 1 페이지 핵심 요약 — 이 표만 외워도 5 분 살아남는다

### 본 연구의 4 줄 요약

1. **사각지대 (RQ1)**: Exqutor 의 Adaptive Sampling 진입 조건이 `table_count > 2` 라서 단일 테이블 검색에서는 작동하지 않는다 (이미지 검색·추천·RAG 의 핵심 형태인데도).
2. **추출 단위 보완 (RQ2-1)**: 8KB 블록 단위 추출을 행 단위 베르누이 추출로 바꿨더니 selectivity 0.5 에서 100 개 중 78 개 우세, 중앙값 9.6 % 개선 (p < 0.001).
3. **공간 인식 보완 (RQ2-2)**: k-means K=20 층화 표본을 베르누이 위에 추가했더니 1.6 ~ 4.4 % 의 추가 개선 (5-seed 95 % CI 양수 확정).
4. **인과 입증 (Two-Level)**: 같은 K=20 으로 나누되 무작위로 나누면 -10.67 % 악화, 거리 기반(k-means) 으로 나누면 +8.93 % 개선 → 공간 인식 단독 효과 +19.6 %p.

### 핵심 수치 7 개 — 발표 중 외워서 말하는 숫자

| 수치 | 의미 | 출처 |
|---|---|---|
| **9.6 %** | DEEP 1M s=0.500 에서 베르누이 추출의 Q-error 중앙값 개선 | 표 1, RQ2-1 |

### 본 연구가 *하지 않은* 것 — 솔직하게 인정

- **End-to-end query time 측정 X** — Q-error (추정 정확도) 만 측정. 실행 시간 영향은 옵티마이저의 plan 선택 메커니즘으로 간접 추론.
- **VBASE/pgvector/DuckDB 와 직접 head-to-head 비교 X** — Exqutor 코드를 직접 수정하는 형태이므로 다른 시스템 비교는 RQ3 또는 후속 연구.
- **K=20 외 K sweep X** — RQ2 에서는 K=20 고정. K sensitivity 는 W5 보충 실험 (5 월) 또는 RQ3 설계에 통합.
- **Multi-table join 시나리오 X** — 단일 테이블 사각지대로 좁힌 의도적 선택. Exqutor 의 multi-table 가정을 깨지 않음.
- **10 seed × 500 query 본격 검정력 측정 X** — W6 (5 월 12 일경) 에 BH-FDR + TOST + Cohen's d 까지 확보 예정. 현재는 5 seed × 100 query.
- **RQ3 측정 X** — 7 가지 방법 설계만 보고. 측정은 5 월 (W10 ~ W12).

# 섹터 1. 연구 동기 & 배경 (Why this research?)

> *벡터 데이터베이스가 왜 중요한지부터 묻는 가벼운 청중·심사위원 대비. 5 ~ 6 개 질문이 충분히 가능.*

### Q1.1 카디널리티 추정이 *왜* 그렇게 중요한가요? 1 % 정확도 개선이 정말 의미가 있나요?

**핵심 한 줄**: 카디널리티 한 번의 짐작이 옵티마이저의 plan 선택을 결정하고, 잘못된 plan 한 번이 실행 시간을 1 만 배까지 늘리기 때문입니다.

**표준 답변** (40 초)
> 옵티마이저는 SQL 쿼리를 실행하기 전에 "이 조건을 만족하는 행이 몇 개나 나올까" 를 미리 추정합니다. 이 추정값에 따라 인덱스 사용 여부, 조인 순서, nested loop 와 hash join 사이의 선택이 결정됩니다. 추정이 1 % 어긋나는 것 자체가 문제가 아니라, 그 어긋남이 *plan 의 categorical 한 변경* 을 일으키는 임계점 근처에서 큰 차이를 만듭니다. Exqutor 원논문이 보고한 VBASE 1 만 배 이상의 실행 시간 차이도 이런 임계점에서의 plan 변경 때문입니다. 따라서 1 % 의 정확도 개선은 임계점 근처 쿼리들이 잘못된 plan 을 고를 확률을 줄이는 의미입니다.

**디테일 보강** (3 분 분량 — 꼬리 질문 시)
> Selinger 1979 이래 카디널리티 추정은 query optimization 의 가장 큰 unsolved problem 중 하나입니다. PostgreSQL 의 ANALYZE 로 만드는 histogram 도, 다중 컬럼 상관관계나 거리 기반 조건 같은 비선형 술어에서는 정확도가 빠르게 떨어집니다. 벡터 거리 조건은 그중에서도 어려운 케이스인데, 분포가 매우 비대칭이고 선택도가 0.001 % 부터 100 % 까지 변동하기 때문입니다. 잘못된 카디널리티는 nested loop join 으로 가야 할 쿼리를 hash join 으로 보내거나, 인덱스 스캔으로 가야 할 쿼리를 sequential scan 으로 보내는 식의 plan 단위 잘못을 만들고, 그 한 번의 잘못이 OLTP 환경에서는 millisecond 가 minute 으로 변하는 일을 만듭니다. 1 만 배는 Exqutor 원논문 Table 1 의 실측치이고, "1 % 의 정확도 개선" 은 Q-error 의 중앙값 차이로, 분포 전체의 shift 를 의미합니다.

### Q1.2 임베딩이 무엇인지부터 설명해 주실 수 있나요?

**핵심 한 줄**: 의미가 가까운 두 항목이 벡터 공간에서도 가까이 놓이도록, 데이터를 96 차원이나 1024 차원의 숫자 벡터로 변환하는 절차입니다.

**표준 답변** (30 초)
> 이미지·텍스트·음성처럼 의미가 중요한 데이터는 글자 그대로 비교할 수 없습니다. "고양이" 와 "야옹이" 는 같은 의미지만 글자는 다릅니다. 그래서 이런 데이터를 *임베딩* 이라는 신경망 기반 변환을 통해 의미 거리가 보존되는 숫자 벡터로 바꿉니다. 의미가 가까운 두 항목은 벡터 공간에서도 가까이 놓이도록 학습된 변환입니다. 본 연구에서 쓴 DEEP 데이터셋은 96 차원, SIFT 는 128 차원 벡터입니다.

**디테일 보강** (2 분)
> 본 연구에서 쓴 DEEP 1M, DEEP 8M 은 SIFT-style 의 deep image feature (96 차원 float32), SIFT 1.5M 은 image keypoint descriptor (128 차원 uint8) 입니다. 모두 표준 ANN benchmark 에서 사용되는 데이터셋으로, 추가 임베딩 학습 없이 미리 만들어진 벡터를 그대로 사용했습니다. 임베딩 모델 자체는 본 연구의 변수가 아니므로 통제 변수로 두고, 분포 특성 (skewness) 만 cross-dataset 비교에 활용했습니다.

### Q1.3 VAQ (Vector-Augmented Analytical Query) 가 정확히 무엇인가요?

**핵심 한 줄**: 단순한 top-k 유사도 검색을 넘어, 벡터 거리 조건이 일반 SQL 의 조인·집계·필터와 결합된 분석 쿼리 형태를 의미합니다.

**표준 답변** (35 초)
> top-k 검색은 "가장 가까운 10 개 문서를 찾아라" 같은 단순 질의입니다. VAQ 는 거기에 SQL 의 다른 연산이 결합된 형태로, 예를 들어 "거리가 0.3 이내인 문서 중 카테고리가 '뉴스' 인 것의 개수를 카테고리별로 집계하라" 같은 쿼리입니다. 본 연구가 다루는 것은 VAQ 중에서도 *거리 임계값 D 이내의 모든 항목* 을 찾는 *range query* 형태이고, 이 형태가 RAG·추천·이상 탐지의 검색 단계에서 자주 사용됩니다.

### Q1.4 왜 Exqutor 논문을 베이스로 삼았나요? 다른 벡터 카디널리티 연구는 없나요?

**핵심 한 줄**: Exqutor (arXiv:2512.09695v2, 2025) 가 2025 년 가장 최근 발표된 시스템적 접근이고, 본 연구가 발견한 *단일 테이블 사각지대* 가 그 이후 빈자리이기 때문입니다.

**표준 답변** (40 초)
> 학습 기반 카디널리티 추정 (LearnedCard, MSCN 등) 은 일반 SQL 술어에는 좋은 결과를 내지만, 벡터 거리 조건처럼 분포가 비대칭이고 차원이 96 ~ 1024 인 술어에는 직접 적용된 사례가 적습니다. 시스템 측면에서 벡터 카디널리티를 정면으로 다룬 연구는 Exqutor 가 본격 첫 사례에 가깝고, 두 갈래 보완 (ECQO + Adaptive Sampling) 으로 1 만 배 이상의 실행 시간 개선을 보고했습니다. 본 연구는 이 보완책의 적용 범위가 *multi-table only* 라는 빈자리를 발견했고, 그 빈자리에서 코드 세 줄 보완으로 측정 가능한 개선을 만들 수 있는지를 묻는 형태입니다.

### Q1.5 "VBASE 에서 최대 1 만 배 이상" — 이 표현이 과장 아닌가요?

**핵심 한 줄**: Exqutor 원논문 Table 1 의 실측 시나리오 중 가장 큰 격차를 인용한 것이며, "최대" 가 아니라 "최대 1 만 배 이상" 으로 표현한 것은 이것이 상한이 아닌 의미입니다.

**표준 답변** (30 초)
> Exqutor 원논문의 보고 그대로 인용한 것입니다. 시나리오 (selectivity, 데이터셋, plan 분기점) 에 따라 변동이 크고, 1 만 배가 상한이 아닌 "최소 1 만 배 이상이 가능한 경우가 있다" 는 의미입니다. 회의에서 이 표현을 그대로 유지하기로 합의했습니다 (4 월 25 일 카톡 회의). 우리가 측정한 값이 아니라 원논문의 인용이라는 점은 보고서·발표 모두에 명시되어 있습니다.

# 섹터 2. Exqutor 이해 (Related Work)

> *Exqutor 의 두 보완책에 대한 깊은 질문. 시스템 백그라운드를 가진 심사위원·자문위원이 가장 좋아하는 영역.*

### Q2.1 ECQO 와 Adaptive Sampling 의 차이가 정확히 무엇인가요?

**핵심 한 줄**: ECQO 는 *인덱스가 있을 때* HNSW range query 를 한 번 실행해 정확값을 얻는 *exact* 방식이고, Adaptive Sampling 은 *인덱스가 없을 때* 표본 일부의 비율로 추산하는 *approximate* 방식입니다.

**표준 답변** (45 초)
> Exqutor 는 인덱스 유무에 따라 두 갈래 보완을 갖습니다. 인덱스가 있을 때는 ECQO — Exact Cardinality Query Optimization — 가 옵티마이저의 plan 수립 단계에서 HNSW 인덱스를 이용해 가벼운 range query 를 한 번 실제로 실행하여 정확한 카디널리티를 얻습니다. 추정이 아니라 정확값이고, 인덱스 검색이 빠르므로 오버헤드가 약 1.88 ms 정도라고 원논문이 보고합니다. 인덱스가 없을 때는 Adaptive Sampling 이 일부 행만 추출해 임계값을 만족하는 비율을 계산하고, 그 비율을 전체 행 수에 곱해 카디널리티를 추산합니다. *모멘텀 기반 동적 sample_size 조정* 이 핵심으로, 이전 쿼리 결과를 보고 sample_size 를 점진적으로 늘리거나 줄입니다. 본 연구는 후자(Adaptive Sampling) 의 적용 범위와 정확도를 다룹니다.

**디테일 보강** (1 분 30 초)
> ECQO 의 1.88 ms 오버헤드는 옵티마이저가 plan 을 만드는 비용 (parse + plan + execute 중 plan 단계만) 에 비해 무시할 수 있는 수준입니다. HNSW 의 search complexity 가 O(log N) 이라 1M 데이터셋에서 ms 단위로 끝납니다. Adaptive Sampling 의 sample_size 는 본 연구 기준 sample_size = 385 가 default 이고 (이는 Cochran 의 sample size 공식에서 95 % CI 5 %p 마진의 binomial proportion estimation 기준), 모멘텀 기반 조정은 hit rate 가 너무 작거나 너무 클 때 sample_size 를 동적으로 늘리는 식입니다. 본 연구는 update_sample_size = off (4/19 추가) 환경에서 sample_size 를 고정한 채로 측정했습니다. 이는 sample_size 변동이 두 보완 효과 측정에 교란으로 들어오는 것을 막기 위해서입니다.

---

### Q2.2 ECQO 가 그렇게 정확하면, 그냥 ECQO 만 쓰면 되지 않나요? 왜 Adaptive Sampling 이 필요한가요?

**핵심 한 줄**: ECQO 는 인덱스가 있어야만 작동하고, 모든 환경에서 인덱스가 항상 유지되지는 않기 때문입니다.

**표준 답변** (30 초)
> 인덱스가 항상 존재한다는 보장이 없습니다. 데이터 적재 직후, 동적 INSERT 가 빈번한 환경, 인덱스 미생성 컬럼, 인덱스 빌드 비용을 감당하기 어려운 시나리오에서는 인덱스가 없거나 stale 합니다. 이런 상황을 위해 Exqutor 는 두 번째 보완책으로 Adaptive Sampling 을 둡니다. 인덱스가 있을 때 ECQO 가 0.001 ms 단위로 정확값을 주고, 없을 때 Adaptive Sampling 이 ms 단위로 근사값을 주는 *2 layer fallback* 구조입니다. 우리 연구는 두 번째 layer 의 정확도와 적용 범위를 다룹니다.

---

### Q2.3 Adaptive Sampling 의 *모멘텀* 은 정확히 어떻게 동작하나요?

**핵심 한 줄**: 이전 쿼리에서 sample 의 hit rate 가 예상보다 낮으면 다음 쿼리에서 sample_size 를 늘리고, 반대로 높으면 줄이는 EWMA (exponentially weighted moving average) 형태의 피드백 조정입니다.

**표준 답변** (40 초)
> Exqutor 의 모멘텀 기반 조정은 직전 N 개 쿼리의 sample hit rate 를 EWMA 로 누적해서, 현재 쿼리의 sample_size 를 동적으로 결정합니다. hit 가 너무 적으면 (예: 1 % 미만) sample 자체를 늘려 추정 분산을 줄이고, 너무 많으면 (예: 50 % 이상) sample 을 줄여 비용을 아낍니다. 본 연구는 이 모멘텀이 RQ2 의 두 보완 효과 측정에 교란으로 들어오는 것을 막기 위해 `update_sample_size = off` GUC 로 sample_size 를 385 로 고정했습니다. 이 설정은 4 월 19 일 ultrareview 에서 추가된 default 입니다.

---

### Q2.4 Exqutor 의 hook 메커니즘은 PostgreSQL 의 어떤 부분에 들어가는 건가요?

**핵심 한 줄**: PostgreSQL 의 `clauselist_selectivity` 콜백 체인에 등록되는 extension 형태로, 옵티마이저가 카디널리티 추정을 호출할 때 자동으로 trigger 됩니다.

**표준 답변** (40 초)
> Exqutor 는 PostgreSQL extension 형태로 빌드되며, `vector` extension 의 hook 으로 `selfunc.c` 의 selectivity 추정 경로에 끼어듭니다. 옵티마이저가 vector 거리 조건을 마주칠 때마다 hook 이 호출되어, table_count 와 거리 임계값을 보고 ECQO 또는 Adaptive Sampling 을 trigger 합니다. 본 연구가 발견한 단일 테이블 사각지대는 이 hook 의 진입 조건문 (`vector.c` line 243) 이 `table_count > 2` 로 짜여 있어, 단일 테이블 쿼리는 hook 자체를 통과하지 못하고 PostgreSQL 의 default 1/3 selectivity 로 떨어진다는 점입니다.

---

### Q2.5 Exqutor 가 *왜* table_count > 2 로 조건을 짰는지 알 수 있나요?

**핵심 한 줄**: 원논문이 명시적으로 설명하지 않았으나, 코드 동작과 5 가지 design constraint 의 패턴으로 보아 *multi-table join 의 base table 카디널리티 추정* 을 첫 타깃으로 잡은 design intent 로 추정됩니다.

**표준 답변** (50 초)
> Exqutor 의 ECQO/Adaptive Sampling 은 plan 단계에서 base relation 의 selectivity 를 보정하는 메커니즘인데, 단일 테이블 쿼리에서는 base relation 이 곧 outer query 의 결과 자체입니다. 우리가 hook 을 강제로 켜 봤더니 base relation 이 PostgreSQL `Sample Scan` 으로 plan-tree 가 교체되어, 100,000 행이 나와야 할 outer query 가 sample 안의 32 행만 반환하는 형태로 *결과 자체가 격하* 됩니다. 이 부작용은 multi-table join 시나리오에서는 일어나지 않습니다 — base table 의 sample scan 결과가 join 의 부분 입력으로만 들어가고 outer query 결과는 join 결과이기 때문입니다. 즉 Exqutor 의 design intent 는 *join 의 base table 카디널리티를 sample 로 추산* 하는 데 맞춰져 있고, 단일 테이블은 그 가정 밖이라는 해석입니다. 원논문이 명시적으로 이 사실을 적지는 않았습니다.

**디테일 보강** (2 분)
> 우리가 발견한 5 가지 design constraint 가 모두 *multi-table 가정* 을 바닥에 두고 있다는 점이 일관된 증거입니다. (1) hook 진입 조건의 `table_count > 2`, (2) plan replacement 시 outer query 격하, (3) `TABLESAMPLE SYSTEM` 의 block 단위 추출 (multi-table 시 sample size 가 작아도 join 으로 보강), (4) hook_est 가 sample 안 부분 카운트를 outer 결과로 격하, (5) Adaptive update path 의 SIGSEGV (sample_size NaN 발산은 단일 테이블에서만 재현). 다섯 모두 *multi-table 에서는 우회 가능, 단일 테이블에서는 직접 노출* 되는 패턴입니다. 즉 Exqutor 의 design intent 는 multi-table 이고, 단일 테이블 사각지대는 *논문이 의도적으로 비워 둔 영역* 으로 봐도 무리 없습니다. 이 부분이 본 연구의 차별성을 만드는 빈자리입니다.

---

### Q2.6 본 연구는 Exqutor 와 협력하나요? 아니면 비판하는 입장인가요?

**핵심 한 줄**: Exqutor 의 multi-table 가정을 깨지 않으면서 그 옆에 단일 테이블 보완을 *추가* 하는 형태로, 협력적 확장입니다.

**표준 답변** (30 초)
> 본 연구의 코드 변경은 모두 Exqutor 기존 동작 경로 *옆에* 추가되도록 짜여 있어, multi-table 시나리오의 동작은 건드리지 않습니다. `table_count > 2` 조건문 한 줄을 풀어 단일 테이블에서도 보완이 활성화되도록 한 것이 첫 변경이고, 그 위에 추출 단위 변경과 층화 표본 분기 추가로 두 보완을 layered 추가합니다. Exqutor 의 design intent 를 부정하기보다 그 위에 *missing case* 를 메우는 형태이며, 협력적 확장 입장입니다.

# 섹터 3. RQ1 — 단일 테이블 사각지대

> *코드 검증 + 8 지표 무상관 + 5 가지 design constraint. RQ1 은 측정이 아니라 발견·기록.*

### Q3.1 단일 테이블 사각지대를 *어떻게* 발견했나요?

**핵심 한 줄**: Exqutor 소스 코드 (`vector.c` line 243) 의 hook 진입 조건문 `if (table_count > 2)` 를 직접 읽어 발견했고, EXPLAIN ANALYZE 로 단일 테이블 쿼리에서 hook 이 실제로 trigger 되지 않음을 검증했습니다.

**표준 답변** (45 초)
> 4 월 둘째 주에 Exqutor 의 PostgreSQL extension 소스를 처음부터 끝까지 읽어 hook 의 진입 경로를 추적했습니다. `vector.c` 의 selectivity 함수 안에서 `table_count > 2` 조건이 단일 테이블을 가로막는다는 점을 코드에서 확인했고, 단일 테이블 벡터 거리 쿼리에 EXPLAIN ANALYZE 를 돌려 옵티마이저가 default 1/3 selectivity 로 떨어지는 것을 직접 확인했습니다. 즉 코드 검증 + 실측 두 단계로 사각지대를 확인했고, 이는 Exqutor 원논문 본문에 명시되지 않은 finding 입니다.

---

### Q3.2 hook 조건문을 풀어서 강제로 켜면 어떻게 되나요?

**핵심 한 줄**: 단일 테이블에서 base relation 의 plan-tree 가 PostgreSQL `Sample Scan` 으로 교체되어, 100,000 행이 나와야 할 결과가 sample 안의 32 행으로 *외부 쿼리 의미 자체* 가 깨집니다.

**표준 답변** (45 초)
> `if (table_count >= 1)` 로 한 줄 수정하면 hook 이 단일 테이블에서도 trigger 됩니다. 그러나 hook 이 호출하는 sample-based selectivity 가 base relation 의 plan-tree 를 `Sample Scan` 으로 교체하는데, multi-table 가정에서는 join 결과로 보강되던 부분이 단일 테이블에서는 outer query 의 결과 자체가 됩니다. 결과적으로 100,000 행이 진짜 답인 쿼리에서 `SELECT count(*)` 가 32 (= sample 안 hit 수) 를 반환하는 식으로 *외부 쿼리 의미가 격하* 됩니다. 이 외에도 q-error inf 발산, sample_size NaN 발산, Adaptive update path SIGSEGV 등 5 가지 design constraint 가 발견되었고, 단순 우회로는 해결 안 된다는 결론이 나왔습니다.

---

### Q3.3 발견한 5 가지 design constraint 를 모두 말씀해 주실 수 있나요?

**핵심 한 줄**: (1) hook trigger 사각지대, (2) Sample Scan 으로의 plan-tree 격하, (3) `TABLESAMPLE SYSTEM` block 단위 편향, (4) hook_est 의 sample 안 부분 카운트 격하, (5) Adaptive update path 의 SIGSEGV — 모두 multi-table only design intent 의 패턴.

**표준 답변** (50 초)
> 다섯 가지가 있습니다. 첫째, hook 진입 조건 `table_count > 2` 가 단일 테이블 쿼리에서 hook 자체를 trigger 하지 못하는 *사각지대*. 둘째, hook 을 강제로 켰을 때 base relation 의 plan-tree 가 `Sample Scan` 으로 교체되어 외부 쿼리 결과가 *sample 안 부분 카운트로 격하*. 셋째, sample 추출이 PostgreSQL 의 `TABLESAMPLE SYSTEM` (8KB block 단위) 이라 row 단위 균일성이 깨지는 *block sampling bias*. 넷째, hook_est 가 outer query 결과를 sample 안 hit 수로 반환해 *q-error infinity 로 발산*. 다섯째, Adaptive update path 가 단일 테이블에서 sample_size NaN 발산과 *SIGSEGV crash*. 다섯 모두 multi-table only design intent 의 일관된 패턴이며, 본 연구는 이를 ECQO 의 multi-table 가정을 깨지 않으면서 단일 테이블 사각지대를 메우는 *layered 보완* 으로 해결합니다.

---

### Q3.4 사각지대 자체가 학술적 기여가 될 수 있나요? 그냥 버그 아닌가요?

**핵심 한 줄**: 단순한 버그가 아니라 multi-table only design intent 의 *체계적 결과* 이며, 학술적 기여는 *논문이 명시하지 않은 적용 범위 한계의 정량화 및 그 보완 가능성의 실증* 에 있습니다.

**표준 답변** (40 초)
> 한 줄짜리 조건문 자체는 의도적 설계였을 가능성이 높습니다 (Exqutor 의 multi-table join 시나리오 우선 가정). 그러나 이미지 검색·추천·RAG 의 *핵심 응용 형태* 가 단일 테이블 검색이라는 점에서, 이 사각지대는 학술적·실무적 의미가 있는 빈자리입니다. 본 연구의 기여는 (1) 사각지대를 코드 + 실측으로 정량화한 점, (2) 단순 우회로는 해결 안 된다는 5 가지 design constraint 를 발견한 점, (3) layered 보완 (베르누이 + 층화 표본) 으로 측정 가능한 개선을 만든 점입니다. 즉 단순 bug fix 가 아니라 *missing case 의 체계적 분석과 보완* 이 기여입니다.

---

### Q3.5 Exqutor 저자에게 이 발견을 알렸나요?

**핵심 한 줄**: 본 연구 시점에서는 알리지 않았으며, 최종 보고서 (6 월) 또는 후속 논문 작성 시 contact 예정입니다.

**표준 답변** (25 초)
> 중간 보고 시점에서는 학술적 검증과 측정 단계가 우선이라 저자에게 contact 하지 않았습니다. 본 연구가 Exqutor 의 design intent 를 깨지 않는 *layered 확장* 형태이고, 본 finding 이 multi-table 가정 위에서는 일어나지 않는 부작용을 드러냈으므로, 최종 보고서 단계에서 저자에게 finding 공유와 협력 가능성을 contact 할 계획입니다. 자문위원 (박성원 멘토) 에게는 4 월 15 일 v3 자문 이메일로 본 finding 을 공유했고, 회신에서 "단일 테이블 시나리오로 좁힌 점이 적절하다" 는 평가를 받았습니다.

---

### Q3.6 단일 테이블 검색이 정말 핵심 응용 형태인가요? 근거가 있나요?

**핵심 한 줄**: 이미지 검색·추천·RAG 의 *retrieval 단계* 가 모두 단일 테이블 거리 조건 형태이며, 이는 ANN benchmark (SIFT, DEEP, GIST) 의 표준 evaluation 형태이기도 합니다.

**표준 답변** (35 초)
> RAG (Retrieval-Augmented Generation) 의 검색 단계는 *임베딩 vector 가 저장된 단일 테이블* 에 거리 조건을 거는 형태가 표준입니다. 추천 시스템에서도 user/item embedding 단일 테이블 query 가 핵심이고, 이미지 검색은 정의상 단일 테이블 입니다. ANN-Benchmarks (Aumüller et al., 2017+) 의 표준 evaluation 도 단일 테이블 형태이며, 본 연구가 쓴 DEEP 와 SIFT 데이터셋이 그 표준입니다. 즉 *학술 benchmark 의 표준 형태이자 실무 응용의 핵심 형태* 가 단일 테이블 거리 query 이고, Exqutor 의 multi-table only 보완은 이 핵심 영역을 비워 둔 셈입니다.

# 섹터 4. RQ1 — 8 지표 전수 검증 (분포 쏠림 사전 식별 가능성)

> *통계 백그라운드 청중·자문위원의 favorite. 가장 디테일한 추궁이 들어올 수 있는 영역.*

### Q4.1 8 가지 지표가 정확히 무엇이었나요? 왜 8 개를 골랐나요?

**핵심 한 줄**: 글로벌 4 (Fisher γ, log-Fisher γ, P99/P50 tail ratio, Bowley skew) 와 로컬 4 (k-NN distance entropy, k-NN PCA EVR1, KDE modality count, NN clustering coefficient) 로, *분포 쏠림 측정의 4 가지 직교 패러다임* (모멘트, 분위수, 밀도, 그래프) 을 각각 글로벌·로컬 스코프로 적용한 것입니다.

**표준 답변** (60 초)
> 분포 쏠림을 측정하는 통계 지표는 크게 4 가지 패러다임이 있습니다. 모멘트 기반 (skewness γ), 분위수 기반 (P99/P50 같은 tail ratio), 밀도 기반 (KDE bandwidth, modality), 그래프 기반 (k-NN 구조). 각 패러다임을 글로벌 (전체 데이터 분포) 과 로컬 (쿼리 주변) 두 스코프로 적용해 8 개 지표를 만들었습니다. 글로벌은 Fisher γ, log-Fisher γ, Bowley skew (분위수 robust skewness), P99/P50 tail ratio. 로컬은 k-NN distance entropy (쿼리 k 이웃 거리의 Shannon entropy), k-NN PCA EVR1 (k 이웃 벡터의 PCA 첫 주성분 explained variance ratio), KDE modality count (커널 밀도 추정 후 mode 개수), NN clustering coefficient (k-NN 그래프의 local clustering). 이 8 지표 vs 쿼리별 Q-error 의 Spearman ρ 가 모든 조합에서 절대값 0.2 미만이었습니다. 즉 분포 쏠림을 *쿼리 단위 사전 휴리스틱* 으로 식별할 길은 닫혀 있습니다.

**디테일 보강** (3 분)
> 이 finding 의 의미는 두 갈래입니다. 첫째, RQ2 (분포를 알 때) 와 RQ3 (분포를 모를 때) 두 갈래를 모두 다뤄야 한다는 *직접 근거* 가 됩니다 — 단순 휴리스틱으로 RQ3 를 우회할 수 없으니 RQ3 의 distribution-agnostic 방법 비교가 의미 있습니다. 둘째, *데이터 분포의 쏠림이 쿼리별 추정 오차의 결정 요인이 아니다* 라는 finding 도 있습니다. 그러면 무엇이 결정 요인인가? 본 연구의 hypothesis 는 *쿼리 벡터의 위치와 클러스터 구조의 상호작용* 입니다. KM20 의 layered 효과 (s=0.5 에서 1.6 %, s=0.01 에서 8.93 %) 가 쿼리 벡터가 어떤 클러스터에 떨어지느냐에 따라 달라지는 패턴이 이를 뒷받침합니다. 다만 이 hypothesis 의 검증은 RQ3 (5 월) 의 Distance-Shell 방법 (G) 측정에서 이뤄질 예정입니다.

---

### Q4.2 |Spearman ρ| < 0.2 가 약한 상관이라는 근거는?

**핵심 한 줄**: Cohen 의 효과크기 가이드라인 (1988) 에서 |ρ| < 0.1 은 negligible, 0.1 ~ 0.3 은 small, 0.3 ~ 0.5 는 medium, 0.5 이상은 large 이며, 0.2 미만은 small 의 하단으로 *예측 모델로 활용하기 어려운 수준* 입니다.

**표준 답변** (40 초)
> Cohen (1988) 의 effect size 가이드라인을 그대로 따랐습니다. |ρ| < 0.1 은 negligible, 0.1 ~ 0.3 은 small, 0.3 ~ 0.5 는 medium, 0.5 이상은 large. 본 연구가 측정한 8 지표 모두 |ρ| < 0.2 였으니 small 의 하단입니다. 더 중요한 건 *통계적 유의성과 실용적 의미가 다르다* 는 점입니다. n = 6000 측정에서는 |ρ| = 0.05 도 통계적으로 유의하지만 (p < 0.001), 실제로 쿼리별 Q-error 를 예측하는 모델로 쓸 수 없는 수준입니다. R^2 가 4 % 미만이기 때문입니다. 그래서 본 연구는 8 지표 휴리스틱 자체를 *쿼리 단위 사전 식별 도구로 활용 불가* 라고 결론지었고, RQ2 의 *오프라인 분할* 과 RQ3 의 *분포 무인지 적응* 두 갈래로 길을 잡았습니다.

---

### Q4.3 8 지표 외 다른 지표는 시도 안 했나요? 가령 Wasserstein distance 같은?

**핵심 한 줄**: 4 패러다임 × 2 스코프 = 8 지표가 분포 쏠림 측정의 직교 공간을 cover 한다고 판단했고, Wasserstein 같은 추가 지표는 4 패러다임 중 *밀도 기반* 의 변형이라 KDE modality count + k-NN distance entropy 가 이미 그 정보를 capture 한다고 보았습니다.

**표준 답변** (40 초)
> Wasserstein distance, Kolmogorov-Smirnov, Bhattacharyya 같은 distance-based 분포 비교 지표는 모두 *두 분포의 차이* 를 재는 도구입니다. 본 연구의 검증은 *단일 분포 내부의 쏠림 측정* 이 목적이므로 prior 분포가 있어야 하는 distance 기반 지표는 직접 적용이 어렵습니다. 만약 prior 로 uniform 분포를 두면 KDE modality count 와 본질적으로 같은 정보를 잰 셈이 되고, 그래서 본 연구는 직접 modality 와 entropy 로 측정했습니다. 추가 지표 (Theil index, Gini coefficient, MIPS) 는 RQ3 의 보충 분석 (5 월) 에 포함시킬지 검토 중입니다.

---

### Q4.4 KDE modality count 가 정확히 무엇인가요? bandwidth 는 어떻게 정했나요?

**핵심 한 줄**: 쿼리 k = 50 이웃의 *거리 분포* 를 Silverman bandwidth 의 KDE 로 추정한 뒤, density 의 local maxima 를 세어 multimodality 를 정량화한 것입니다.

**표준 답변** (45 초)
> 쿼리 벡터의 k = 50 nearest neighbor 의 거리 distribution 을 KDE 로 추정한 뒤, density 의 local maxima 개수를 셉니다. Bandwidth 는 Silverman's rule of thumb (1986) 의 default 를 썼고, 1 차원 거리 분포라 차원의 저주가 없습니다. modality count = 1 이면 unimodal (분포 깔끔), > 1 이면 multimodal (쿼리 주변에 여러 클러스터). 본 hypothesis 는 multimodal 쿼리에서 Q-error 가 클 것이라는 가정이었으나, |ρ| < 0.2 로 sufficient correlation 이 없었습니다. 즉 *쿼리 단위로 multimodal 여부를 미리 알아낼 수 없거나, 알아내도 Q-error 와 직접 연결되지 않는다* 는 finding 입니다.

---

### Q4.5 8 지표 검증의 sample 은 어떻게 구성됐나요?

**핵심 한 줄**: DEEP 1M, 100 쿼리 × 6 selectivity = 600 (query, selectivity) 셀에 대해, 8 지표 × 600 = 4800 (지표, 셀) pair 의 ρ 를 산출했고, 이를 multiple comparison 보정 (BH-FDR) 후 모두 |ρ| < 0.2 였습니다.

**표준 답변** (40 초)
> DEEP 1M 의 100 개 쿼리 × 6 selectivity 구간 = 600 측정 셀에서, 각 셀의 Q-error 와 8 개 글로벌·로컬 지표의 Spearman ρ 를 산출했습니다. 8 × 600 = 4800 ρ 값에서 multiple comparison 위험을 BH-FDR (Benjamini-Hochberg) 로 통제한 결과도 모두 |ρ| < 0.2 였습니다. 8 지표가 직교 패러다임이라 일부 지표만 좋고 나머지 약한 형태가 아니라 *전수* 약한 패턴이고, 이는 *단순 휴리스틱으로 분포 쏠림을 사전 식별할 수 없다* 는 강력한 negative finding 입니다.

### Q4.6 그래도 *어떤* 지표가 가장 좋았나요?

**핵심 한 줄**: 글로벌 지표 중 P99/P50 tail ratio (|ρ| ≈ 0.18) 와 로컬 지표 중 KDE modality count (|ρ| ≈ 0.16) 가 상대적으로 가장 신호가 강했지만, 둘 다 small 효과 하단이라 모델로 활용하기 어렵습니다.

**표준 답변** (30 초)
> 차이가 작긴 하지만, 글로벌 P99/P50 tail ratio 와 로컬 KDE modality count 가 약간 더 신호가 강했습니다. 이 두 지표는 *분포의 꼬리 두께* 와 *분포의 멀티모달 정도* 를 측정하는 것으로, hypothesis 와 가장 직접 연관된 metric 이었습니다. 그러나 |ρ| 가 0.18 / 0.16 정도라 R^2 = 3 % 미만이고, 이를 사전 식별 모델로 쓰면 false positive/negative 가 너무 많아 실용성이 없습니다. 그래서 *어떤 지표가 좋다* 보다 *모든 지표가 약하다* 는 finding 이 본 연구의 결론입니다.

# 섹터 5. RQ2-1 — 베르누이 추출 (행 단위)

> *RQ2 의 첫 보완 — 코드 한 줄 교체로 9.6 % 개선. 통계 검정과 추출 단위 메커니즘이 핵심.*

### Q5.1 왜 베르누이가 시스템보다 좋다고 확신할 수 있나요?

**핵심 한 줄**: PostgreSQL 의 `TABLESAMPLE SYSTEM` 은 8KB 블록 단위 추출이라 같은 블록 안 행들의 dependency 가 추정 분산을 키우고, 베르누이는 행 단위 독립 추출이라 이론적으로 분산이 작으며, 본 연구가 100 쿼리 × 6 selectivity 측정에서 이를 paired Wilcoxon 으로 통계적으로 확인했습니다.

**표준 답변** (50 초)
> 두 갈래 근거가 있습니다. 첫째, 이론적으로 베르누이 추출은 각 행의 inclusion probability 가 독립이라 추정 variance 의 lower bound 가 작습니다. 시스템 추출은 8KB 블록 단위라 같은 블록의 행들이 dependency 를 가지고, 그 결과 same effective sample size 라도 variance 가 큽니다 (Cochran 1977). 둘째, 실측에서 DEEP 1M, 100 쿼리, 6 selectivity 구간에 paired Wilcoxon 검정을 돌려 selectivity 0.05 ~ 0.50 모든 구간에서 p < 0.001 로 베르누이 우세, selectivity 0.5 에서 100 개 중 78 개 우세, 중앙값 9.6 % 개선을 통계적으로 확인했습니다. 이론과 실측 모두 일치합니다.

---

### Q5.2 paired Wilcoxon 을 쓴 이유는? t-test 도 됐을 텐데?

**핵심 한 줄**: Q-error 분포가 lognormal 또는 heavy-tail 이라 정규성 가정이 깨지고, paired Wilcoxon 은 *분포 가정 없이 paired difference 의 median* 만 검정하는 robust 비모수 검정이라 본 연구에 적합합니다.

**표준 답변** (40 초)
> Q-error 는 추정값과 실제값의 비율이므로 분포가 lognormal 또는 heavy-tail 입니다. paired t-test 는 정규성 가정이 필요한데, lognormal 한 Q-error 에 t-test 를 그대로 쓰면 outlier 영향이 크고 false positive 위험이 있습니다. paired Wilcoxon 은 두 처리 (시스템 vs 베르누이) 의 paired difference 의 median 이 0 인지를 *분포 가정 없이* 검정하는 비모수 검정이라, lognormal Q-error 에 robust 합니다. 또한 same query 에서 두 추출 방식을 비교하므로 paired structure 가 자연스럽고, query 단위 effect (쿼리 자체의 selectivity 변동) 를 제거하는 효과가 있습니다. 즉 *robust + paired* 두 이유로 Wilcoxon 이 정답입니다.

**디테일 보강** (1 분)
> 추가로 *log-transform 후 paired t-test* 도 검토했습니다. log Q-error 가 정규성에 가까워지므로 이론상 가능합니다. 그러나 SIFT 1.5M s = 0.010 의 양자화 영역 (median Q-error 가 5 seed 모두 1.4435 로 동일) 에서 log Q-error 의 분산이 0 으로 수축해 t 통계량이 정의되지 않는 케이스가 있어, 비모수가 더 안정적이라 결론지었습니다. W6 (5/12 경) 의 본격 검정력 측정에서는 paired Wilcoxon + paired t (log) 를 모두 보고할 예정이며, 두 결과가 일관됨을 보일 계획입니다.

---

### Q5.3 100 개 쿼리가 충분합니까? sample size 가 작은 것 아닌가요?

**핵심 한 줄**: 본 보고서 시점은 5-seed × 100 쿼리 = 500 측정 단위이며, 이는 Wilcoxon 의 검정력 0.8 기준 medium effect (Cohen's d ≈ 0.5) 를 잡기에 충분한 sample size 이고, W6 (5 월 12 일경) 에 10-seed × 500 쿼리 = 5000 단위로 본격 검정력을 확보할 예정입니다.

**표준 답변** (45 초)
> Wilcoxon paired test 의 검정력 분석으로 medium effect (Cohen's d ≈ 0.5) 를 power 0.8, α = 0.05 로 잡으려면 약 50 ~ 70 paired sample 이 필요합니다. 본 연구는 query 100 × 5 seed = 500 paired sample 이라 이 기준의 약 7 ~ 10 배입니다. 따라서 selectivity 0.05 ~ 0.50 구간에서 p < 0.001 의 일관된 결과는 검정력 측면에서 robust 합니다. selectivity 0.001, 0.010 의 약한 신호는 sample size 부족이 아니라 *Q-error 자체의 정수 양자화* — true cardinality 가 작아 추정값이 0/1/2 같은 작은 정수만 나오므로 분해능이 제한 — 때문입니다. 본격 검정력 측정 (BH-FDR + TOST + Cohen's d) 은 W6 (5/12 경) 에 10-seed × 500-쿼리로 확보 예정입니다.

---

### Q5.4 selectivity 0.001, 0.010 에서 효과가 약한 게 *진짜로 효과 없는 건* 아닌가요?

**핵심 한 줄**: 효과 자체는 있을 수 있으나, true cardinality 가 1,000 ~ 10,000 행 수준에서 sample-based 추정값이 정수 양자화 (sample 안 hit 이 0, 1, 2 같은 작은 수) 로 분해능이 제한되어 통계적 유의성을 잡기 어려운 영역입니다. RQ2-2 의 KM20 효과는 이 영역에서 오히려 가장 큽니다 (s=0.010 에서 +8.93 %).

**표준 답변** (50 초)
> 두 영역 (s=0.001, s=0.010) 에서 베르누이 효과가 약한 이유는 *효과 부재* 가 아니라 *분해능 한계* 입니다. true cardinality 가 작으면 sample 안 hit 수도 작은 정수 (0, 1, 2, 3) 로 quantize 되고, 두 추출 방식의 estimated cardinality 차이도 작은 정수 단위로만 변합니다. 그래서 paired Wilcoxon 의 zero-difference tie 가 많아 검정력이 떨어집니다. 흥미롭게도 RQ2-2 의 KM20 효과는 이 영역에서 가장 큽니다 — DEEP 1M s=0.010 에서 +8.93 %, RANDOM20 -10.67 % 격차. 이는 KM20 의 stratified 추출이 small-cluster 의 sample 보장을 통해 *양자화 영역에서 0/1 분해능을 유지* 하기 때문입니다. 즉 RQ2-1 과 RQ2-2 의 효과가 *서로 다른 selectivity 영역에서 빛난다* 는 layered 구조가 본 연구의 흥미로운 finding 입니다.

---

### Q5.5 베르누이 추출이 더 비싸지 않나요? 시스템보다 느리지 않나?

**핵심 한 줄**: 베르누이는 행 단위 inclusion 결정이라 random number generator 호출이 더 많지만, 본 연구의 sample_size = 385 규모에서는 추가 오버헤드가 ms 단위 미만으로 무시할 수 있고, 추정 분산 감소로 얻는 정확도 개선이 훨씬 큽니다.

**표준 답변** (40 초)
> 이론상 베르누이는 행 단위 RNG 호출이 N 번 (전체 행 수) 발생하지만, PostgreSQL 의 `TABLESAMPLE BERNOULLI` 구현은 이를 hash-based skip 으로 최적화해 시스템 추출과 거의 같은 latency 를 보입니다. 본 연구의 측정에서 sample_size = 385 기준 두 방식의 hook latency 차이는 1 ms 미만이었습니다. 추정 분산 감소로 얻는 옵티마이저 plan 안정화 이익이 sample latency 차이를 상쇄하고 남으므로, 베르누이가 *비용 대비 이득* 측면에서도 정답입니다. 다만 sample_size 가 매우 클 때 (예: 100K 이상) 의 latency 비교는 본 연구 범위 밖이며 W5 보충 실험에서 sample_size sensitivity 로 다룰 예정입니다.

### Q5.6 표 1 의 selectivity 6 구간 (0.001/0.010/0.050/0.100/0.300/0.500) 은 어떻게 정했나요?

**핵심 한 줄**: 0.001 ~ 0.500 의 *log-uniform* 그리드로, 좁은 영역 (양자화 한계) 부터 넓은 영역 (분포 안정) 까지 cover 하면서, ANN benchmark 와 Exqutor 원논문의 측정 영역과 일치하도록 잡았습니다.

**표준 답변** (35 초)
> selectivity 가 0.001 (0.1 %) 부터 0.500 (50 %) 까지 3 orders of magnitude 변동하는데, 이를 log-uniform 6 점 (0.001, 0.010, 0.050, 0.100, 0.300, 0.500) 그리드로 cover 했습니다. 이 6 점이 *ANN benchmark 의 표준 evaluation 영역* (top-1% ~ top-50%) 과 일치하고, Exqutor 원논문의 selectivity 측정 영역 (0.01 ~ 0.50) 도 cover 합니다. SIFT 1.5M 과 DEEP 8M 은 시간 제약상 3 점 (0.500, 0.050, 0.010) 으로 좁혔으나, 핵심 selectivity 0.500 은 모든 데이터셋에서 측정해 cross-dataset 비교의 anchor 가 됩니다.

# 섹터 6. RQ2-2 — 공간 인식 층화 표본 (KM20)

> *RQ2 의 두 번째 보완 — k-means K=20 층화 표본. 여기가 본 연구의 정량적 핵심.*

### Q6.1 K = 20 은 왜 그 값으로 정했나요? K=10 이나 K=50 은 왜 안 되나요?

**핵심 한 줄**: K=10 과 K=20 두 값을 모두 측정해 K=20 이 일관되게 우세함을 phase6_layer_compare 에서 확인했고, K=20 은 sample_size 385 와 well-balanced (385/20 ≈ 19 행/stratum) 한 이유로 baseline 으로 채택했습니다. K sweep (K = 5, 10, 20, 50, 100) 은 W5 (5 월 4 일) 보충 실험에 포함됩니다.

**표준 답변** (50 초)
> phase6_layer_compare 측정에서 K=10 과 K=20 을 baseline + bernoulli + pca_decile 4 mode 와 함께 비교했습니다. K=20 이 K=10 보다 selectivity 0.100 (+2.25%), 0.300 (+0.76%), 0.500 (+0.33%) 모두 우세였고, KM20 vs KM10 cross-pair 에서 selectivity 0.100 paired Wilcoxon p = 0.0013 으로 통계적으로 KM20 우세입니다. K=50 같은 더 큰 값을 시도하지 않은 이유는, sample_size = 385 / K = 50 = 7.7 행/stratum 으로 stratum 당 sample 수가 통계적으로 너무 작아져 양자화 효과가 발현되기 때문입니다. K=20 은 385 / 20 ≈ 19 행/stratum 으로 적절한 균형점이며, 본격 K sweep (5, 10, 20, 50, 100) 은 W5 보충 실험에 포함됩니다.

**디테일 보강** (1 분 30 초)
> RQ3 (5 월) 의 F (MiniBatch K-means) 와 G (Distance-Shell) 측정에서도 K = 20 을 유지합니다. K = 20 의 stratum 크기 분포를 보면 DEEP 1M 에서 size_min 26343, size_max 81233 로 *3.08 배* 차이가 나는데, 이는 데이터 자체의 클러스터 쏠림을 반영합니다 — k-means 가 균등하게 나누지 못하는 것이 아니라 데이터 자체가 균등하지 않다는 증거입니다. SIFT 1.5M 에서는 동일 K=20 이 3.33 만 ~ 14.82 만 (4.45 배) 으로 더 큰 격차를 만들고, 이것이 SIFT 의 KM20 효과가 DEEP 의 약 두 배인 이유입니다.

### Q6.2 왜 k-means 인가요? GMM, DBSCAN, hierarchical clustering 같은 다른 분할법은 왜 안 썼나요?

**핵심 한 줄**: k-means 의 hard partition 이 *모든 행이 정확히 하나의 stratum 에 속해야* 하는 stratified sampling 의 정의에 직접 부합하고, 96d/128d 고차원에서 GMM/DBSCAN 은 차원의 저주로 안정적으로 학습되지 않으며 hierarchical 은 O(N²) 비용으로 1M 데이터에 비현실적이기 때문입니다.

**표준 답변** (50 초)
> Stratified sampling 의 정의는 모든 행이 정확히 하나의 stratum 에 *disjoint partition* 으로 속해야 합니다. k-means 의 hard partition (Voronoi 분할) 이 이 정의에 직접 부합합니다. GMM 은 soft membership 이라 stratum 경계가 모호하고, sample 추출 시 각 행의 stratum 을 결정하기 위해 추가 hard assignment 가 필요해 결국 k-means 와 비슷한 결과로 수렴합니다. DBSCAN 은 noise 와 outlier 를 별도 분류하는데, vector cardinality estimation 에서는 모든 행이 stratum 에 속해야 하므로 noise 행을 어떻게 처리할지 별도 정책이 필요합니다. Hierarchical 은 O(N²) 메모리·시간 비용으로 1M 데이터에 비현실적입니다. RQ3 (5 월) 의 7 가지 distribution-agnostic 방법에서 LSH (확률적 hard partition) 와 Hilbert curve (결정론적 hard partition) 등 다른 hard partition 패러다임을 함께 비교합니다.

### Q6.3 5-seed 가 충분합니까? 왜 10 seed 를 쓰지 않나요?

**핵심 한 줄**: t-distribution 기반 CI 산출에서 t(4, 0.975) = 2.776 인 5-seed 가 mean diff 의 표준오차를 ±55 % 마진으로 잡기에 충분하고, 본격 검정력 (10-seed × 500-쿼리 + BH-FDR + TOST + Cohen's d) 은 W6 (5/12 경) 에 확보 예정입니다.

**표준 답변** (45 초)
> 5-seed 에서 t(4, 0.975) = 2.776 으로, mean ± t × std/sqrt(5) 의 t-based CI 를 산출합니다. DEEP 1M s=0.500 KM20 의 mean = 1.6366 %, std = 0.4416 % 로 CI [+1.09, +2.18] 가 나옵니다. 이는 mean 의 표준오차 std/sqrt(5) = 0.198 % 의 약 2.78 배 마진으로, 효과의 통계적 유의성 (CI 양수 확정) 을 검증하기에 충분합니다. 다만 본격 검정력 측정 — 10-seed × 500-쿼리 + Bonferroni-Hochberg FDR multiple comparison + TOST equivalence test + Cohen's d effect size — 는 W6 (5/12 경) 보충 실험에 포함됩니다. 이는 출판급 통계 수준 확보를 위한 추가 단계이고, 현재 5-seed 에서도 효과의 *방향성* 과 *통계적 유의성* 은 robust 하게 확인됩니다.

### Q6.4 표 2 에 "단일 seed" 라고 표기된 셀들 (DEEP 1M s=0.05, s=0.01) — 정말 단일 seed 입니까?

**핵심 한 줄**: 정확하게는 5-seed 측정이 raw data 에 보존되어 있으나, 본 보고서 시점에서는 보수적으로 "단일 seed" 로 표기했습니다. raw 5-seed CI 는 s=0.05 [-0.22, +3.42], s=0.01 [+6.59, +10.95] 입니다.

**표준 답변** (40 초) — *솔직한 자체 정정 답변*
> 표 2 의 "단일 seed" 표기는 raw data 와 다소 다른 보수적 표현입니다. 실측 raw 에는 5-seed 측정이 보존되어 있고, mean diff 는 +1.85 % (s=0.05), +8.93 % (s=0.01) 로 표기와 일치하며, 5-seed t-based CI 는 [-0.22, +3.42], [+6.59, +10.95] 입니다. s=0.05 CI 는 0 을 포함해 통계적으로 유의하지 않고, s=0.01 CI 는 양수 확정으로 강한 효과입니다. 표기를 "단일 seed" 로 한 이유는 s=0.5 의 5-seed 가 "본선 anchor 측정" 으로 분리되어 있고, s=0.05/0.01 은 selectivity gradient 분석의 보충 데이터라서 *anchor 와 보충을 분리해 표시* 한 의도입니다. 본 표기는 W5 보충 실험 후 갱신되며, 발표 시 질문이 들어오면 raw 5-seed CI 를 직접 보고할 수 있습니다.

**디테일 보강** (1 분)

### Q6.5 Horvitz-Thompson 가중치 식이 정확히 어떻게 적용되나요?

**핵심 한 줄**: 각 stratum h 에서 sample size n_h, stratum 전체 size N_h 일 때, 추정 카디널리티 = sum_h (N_h × hit_h / n_h) 로, hit count 를 stratum 크기 비례로 weighted sum 합니다. Exqutor 의 hook_est 함수에 동일 식이 구현됩니다.

**표준 답변** (45 초)
> Horvitz-Thompson estimator 의 표준 형태는 각 sample 의 inclusion probability 의 역수로 가중하는 것이며, stratified sampling 에서는 stratum h 의 inclusion probability = n_h / N_h 가 됩니다. 따라서 추정값은 sum_h sum_{i in sample_h} (1 / (n_h / N_h)) × indicator(distance_i < D) = sum_h (N_h / n_h) × hit_count_h 입니다. 우리 구현 (`src/vector.c` 약 +228 라인 추가) 에서는 stratum_id 컬럼을 사전 계산해 각 행에 K=20 라벨을 붙이고, hook 호출 시 stratum 별 hit count 를 집계해 N_h / n_h 가중합으로 카디널리티를 추정합니다. 이는 *unbiased estimator* 이며, sample size 안정화 (Level 1) 와 spatial awareness (Level 2) 두 효과를 직교적으로 분리하기 위해 *비례 배분* (n_h ∝ N_h) 만 사용합니다 — Neyman optimal allocation 은 RQ3 의 H (Importance Sampling) 에서 별도 비교합니다.

### Q6.6 비례 배분 (proportional allocation) 만 쓰면, *Neyman 최적 배분* 의 분산 감소 이점은 어떻게 되나요?

**핵심 한 줄**: Neyman optimal allocation 은 stratum 별 분산 σ_h 정보가 필요한데, 본 연구는 *분포를 알 때* (RQ2) 와 *모를 때* (RQ3) 의 직교적 비교에 집중하므로, RQ2 에서는 baseline 인 비례 배분만 쓰고 Neyman 은 RQ3 의 H (Importance Sampling) 에서 비교합니다.

**표준 답변** (40 초)
> Neyman 최적 배분 (Neyman 1934) 은 분산 감소가 더 크지만 stratum 별 분산 σ_h 의 사전 지식이 필요합니다. 본 연구의 RQ2 는 *공간 분할 자체의 효과* 를 측정하는 데 집중하므로 비례 배분 (n_h ∝ N_h) 으로 통제하고, 분산 정보를 활용하는 효과는 RQ3 의 H (Importance Sampling) 에서 별도 비교합니다. H 는 importance weight 를 분산 추정값으로 조정하므로 Neyman 의 변형으로 볼 수 있고, 본 연구의 7-way 비교에서 H 만 *2×2 factorial* 로 estimator (uniform vs IS) × allocation (KM20 vs no partition) 4 조합을 모두 측정하는 이유가 여기에 있습니다.

### Q6.7 sample_size = 385 는 어디서 온 값인가요?

**핵심 한 줄**: Cochran (1977) 의 sample size formula 에서 95 % CI ±5 %p 마진의 binomial proportion estimation 기준으로 (1.96² × 0.5 × 0.5) / 0.05² ≈ 384.16 ≈ 385 로, Exqutor 의 default 값을 그대로 사용했습니다.

**표준 답변** (40 초)
> Cochran 의 *Sampling Techniques* 교과서 표준 공식: n = z² × p(1-p) / e² 에서 z = 1.96 (95 % CI), p = 0.5 (most conservative), e = 0.05 (5 % margin) → n ≈ 384.16 → 385. 이는 Exqutor 의 GUC default `vector.sample_size = 385` 와 일치하며, 본 연구는 이 default 를 그대로 사용해 *sample_size 변동 효과를 통제* 했습니다. sample_size 의 sensitivity (작거나 큰 값에서 효과가 어떻게 변하는지) 는 W5 보충 실험에 포함되며, 본 보고서 시점은 default 385 로 실험 조건을 일관되게 유지합니다.

### Q7.2 DEEP 8M 에서 KM20 효과 +1.76% 가 1M 의 +1.64% 와 거의 같은데, 의미가 있나요?

**핵심 한 줄**: 외적 타당성 (external validity) 의 핵심은 *효과의 absolute size* 가 아니라 *효과가 데이터 규모를 바꿔도 일관되게 유지되는가* 입니다. 8M (8 배 큰 데이터) 에서도 1M 과 동일한 효과 크기가 나온 것은 본 연구가 *data size-invariant property* 를 가짐을 강하게 시사합니다.

**표준 답변** (50 초)
> 외적 타당성의 학술적 의미는 *효과 크기의 절대값* 이 아니라 *효과가 다른 조건에서도 재현되는가* 입니다. 8M (8 배 큰 데이터) 에서 KM20 의 mean diff 가 1M 과 비슷한 +1.76 % 로 측정된 것은, 본 연구의 효과가 *data size-invariant* 하다는 의미입니다. 즉 sample_size = 385 가 1M 과 8M 모두에서 비례적으로 유지되어 (1M 에서 0.0385 % vs 8M 에서 0.0048 % sample fraction) 효과 크기가 일정하게 나옵니다. 또한 8M 의 95 % CI [+0.65, +2.86] 와 1M 의 [+1.09, +2.18] 가 *완전히 겹치며* CONSISTENT 판정이 나왔는데, 이는 통계적으로 두 측정이 같은 모집단의 두 sample 임을 시사합니다.

**디테일 보강** (1 분)
> 8M 에서 selectivity 0.05/0.01 의 효과가 1M 보다 작거나 noise 영역으로 들어간 것은 *별도의 limitation* 입니다 — sample_size = 385 가 8M 의 0.005 % 에 불과해 small selectivity 에서 양자화 한계에 걸리기 때문입니다. 이는 anomaly_analysis.md 에 명시적으로 기록된 limitation 이며, "sample_size 가 데이터 규모와 함께 비례적으로 늘어나야 한다" 는 후속 연구 방향을 제시합니다. 본 연구의 명확한 finding 은 *s ≥ 0.05 영역에서 효과가 data-size-invariant 하게 유지된다* 는 점입니다.

### Q7.3 SIFT 가 DEEP 보다 더 skewed 한 이유가 *데이터셋 자체의 특성* 인가요, 아니면 *임베딩 모델의 특성* 인가요?

**핵심 한 줄**: SIFT 는 image keypoint descriptor (Lowe 2004) 로 *handcrafted feature* 이고 DEEP 는 *deep learning feature* 인데, 둘의 분포 차이는 임베딩 *방식* 자체의 차이로 해석되며, 본 연구는 이를 통제 변수로 두고 *층화 표본의 효과 측정* 에 집중합니다.

**표준 답변** (45 초)
> SIFT 는 SIFT 알고리즘 (Lowe 2004) 으로 추출된 128 차원 image keypoint descriptor 로, *handcrafted feature* 입니다. 한 이미지에서 여러 keypoint 가 추출되므로 *keypoint 기반 분포* 가 형성되고, 이는 자연 이미지의 edge·corner 분포에 따라 *spatially clustered* 됩니다. DEEP 는 deep learning 으로 학습된 image feature 로, neural network 의 representation 이 *isotropic distribution* 에 가깝게 학습되는 경향이 있습니다. 즉 두 데이터셋의 분포 차이는 *임베딩 방식의 차이* 에서 옵니다. 본 연구는 이 차이를 *통제 변수* 로 두고, "두 분포 모두에서 KM20 의 효과가 양수 확정이고, 더 skewed 한 SIFT 에서 효과가 더 크다" 는 cross-dataset 일반화를 확인합니다. 임베딩 모델별 효과 비교 (BERT vs CLIP vs ResNet) 는 RQ3 또는 후속 연구의 영역입니다.

---

### Q7.4 차원이 다르면 (96d vs 128d) k-means clustering 자체의 안정성이 달라지지 않나요?

**핵심 한 줄**: k-means 는 차원이 늘어날수록 *curse of dimensionality* 로 cluster 경계가 흐려지지만, mini-batch k-means + n_iter=100 + seed 42 의 결정론적 학습으로 두 데이터셋 모두 *재현 가능한 partition* 을 얻었고, partition 의 *stability* 는 별도 측정으로 확인됩니다.

**표준 답변** (45 초)
> k-means 의 차원 효과는 잘 알려진 issue 이지만, 두 데이터셋 모두에서 *결정론적 재현 가능 partition* 을 얻었습니다. mini-batch k-means (Sculley 2010) 를 batch_size=4096, n_iter=100, seed=42 로 학습해 cluster centroid 를 고정하고, 1M / 8M / 1.5M 모든 행에 stratum_id 를 할당했습니다. partition 의 stability 는 inertia (within-cluster sum of squares) 측정으로 확인되며, DEEP 1M K=20 의 inertia_mean = 0.692, training time = 0.5 s 로 빠르고 안정적입니다. 즉 두 데이터셋 모두에서 k-means 가 동작하지 않는 영역이 아니라 *재현 가능한 baseline partition* 을 얻었고, 이를 RQ3 의 distribution-agnostic 방법들과 fair comparison 의 reference 로 사용합니다.

### Q7.5 DEEP 1M 과 8M 의 CV 가 다를 텐데, 두 데이터셋의 *underlying 분포* 는 같다고 볼 수 있나요?

**핵심 한 줄**: DEEP 8M 은 DEEP 1M 의 *upscaled version* 이 아니라 *동일 source 의 더 큰 sample* 입니다. 두 데이터셋 모두 동일한 deep learning 모델로 추출된 96 차원 feature 의 다른 sample 이며, 핵심 partition 통계 (CV, ratio) 는 sample size 무관하게 *underlying distribution 고유* 입니다.

**표준 답변** (40 초)
> DEEP 1M 과 DEEP 8M 모두 같은 source (Yandex DEEP1B) 의 sub-sample 로, 동일한 deep learning 모델 (96 차원 image feature) 로 추출됐습니다. underlying distribution 은 동일하고, 1M / 8M 은 그 분포의 다른 sample size 입니다. 따라서 cluster 분포의 CV 는 sample size 가 충분히 크면 underlying CV 로 수렴하고, 1M 과 8M 에서 CV 가 비슷하게 나오는 것이 정상입니다. 본 연구의 cross-dataset 비교 (DEEP vs SIFT) 는 *다른 underlying distribution* 의 비교이고, scale-invariance 검증 (DEEP 1M vs DEEP 8M) 은 *같은 underlying distribution 의 다른 sample size* 의 비교입니다. 두 비교 모두 효과의 robustness 확인에 기여합니다.

### Q7.6 cross-dataset 효과 격차가 *DEEP 의 +1.64% vs SIFT 의 +3.07%, 약 두 배* 인데, 이게 정말 *분포의 skewness* 때문인가요? 다른 가능한 설명은?

**핵심 한 줄**: 분포의 skewness (CV 0.234 vs 0.394, 68 % 격차) 가 효과 격차 (1.64 % vs 3.07 %, 약 두 배) 와 *동일 방향으로 증가* 하는 것이 1차 증거이고, two-level decomposition 에서 *Level 2 (공간 인식) 단독* 이 SIFT 에서 +2.06 % vs DEEP 에서 -0.56 % 로 측정된 것이 *기전 (mechanism) 단위 분리* 의 인과 증거입니다.

**표준 답변** (50 초)
> 두 갈래 인과 증거가 있습니다. 첫째, 상관관계: CV 격차 (DEEP 0.234 vs SIFT 0.394, 68 %) 와 효과 격차 (1.64 % vs 3.07 %, 약 87 %) 가 *동일 방향으로 동반 증가* 합니다. 이는 association 증거입니다. 둘째, 기전 단위 분리: two-level decomposition 으로 *Level 1 (proportional allocation) 효과* 와 *Level 2 (spatial awareness) 효과* 를 분리했습니다. SIFT 의 Level 2 단독 효과 (+2.06 %) 가 DEEP 의 Level 2 효과 (-0.56 %) 보다 *기전 자체로* 큽니다. 즉 "분포가 더 skewed → spatial awareness 단독 효과가 커짐" 의 인과 관계가 데이터에서 직접 확인됩니다. 다른 가능한 설명 (차원 차이, 데이터 종류 차이, 임베딩 모델 차이) 은 모두 분포의 skewness 와 *공변* 하기는 하지만, two-level 분해로 이 모두를 통제했을 때도 *Level 2 단독 효과* 가 남는다는 점이 본 연구의 강력한 인과 증거입니다.

# 섹터 8. Two-Level Decomposition (인과 입증)

> *KM20 vs RANDOM20 = Level 1 vs Level 2. 본 연구의 가장 강력한 인과 증거. s=0.010 에서 19.6%p 격차.*

### Q8.1 Two-Level decomposition 이 정확히 무엇인가요? 왜 그런 분해를 했나요?

**핵심 한 줄**: KM20 (k-means 거리 기반 분할) 과 RANDOM20 (무작위 분할) 둘 다 K=20 으로 stratified sampling 을 하지만, 전자만 *공간 인식* 효과를 가지므로, KM20 - RANDOM20 = Level 2 (spatial awareness) 단독 효과로 *기전 단위 분리 측정* 이 가능합니다.

**표준 답변** (50 초)
> 본 연구가 KM20 의 효과를 측정했는데, 그 효과가 *어디서 오는가* 를 분해해야 학술적 가치가 있습니다. 두 가지 가능성이 있습니다 — (a) 단순히 K=20 으로 나누어 비례 배분만 해도 표본 안정화로 효과가 나오는 것 (Level 1 = proportional allocation effect), (b) 거리 기반 분할이 데이터 공간 구조를 반영해 추가 효과를 만드는 것 (Level 2 = spatial awareness effect). 둘을 분리하기 위해 같은 K=20 으로 분할하되 *무작위로* 행을 할당한 RANDOM20 을 control 로 두고, 같은 sample_size 와 같은 비례 배분을 적용해 두 모드의 효과를 비교합니다. KM20 - RANDOM20 의 차이가 정확히 Level 2 (spatial awareness) 단독 효과입니다. DEEP 1M selectivity 0.010 에서 KM20 +8.93 % vs RANDOM20 -10.67 % → Level 2 단독 +19.6 %p 의 측정이 본 연구의 가장 강력한 *인과 증거* 입니다.

---

### Q8.2 selectivity 0.500 에서는 KM20 (+1.64%) 이 RANDOM20 (+2.20%) 보다 오히려 작은데, 모순 아닌가요?

**핵심 한 줄**: selectivity 0.500 에서는 Level 1 (proportional allocation) 효과만 작동하고 Level 2 (spatial awareness) 가 불필요하기 때문이며, KM20 과 RANDOM20 의 0.56 %p 차이는 seed 간 분산 (~0.5~1 % std) 안에 있는 *비유의적* 차이입니다.

**표준 답변** (50 초)
> selectivity 0.500 에서 true_card 가 ~50 만 (전체의 50 %) 으로 *모든 cluster 에 고르게 분포* 합니다 (cluster HHI ≈ 1/K = 0.067). 이 영역에서는 query 결과가 spatial concentration 을 보이지 않으므로, *공간 인식* 효과가 발현될 여지가 없습니다. 단순히 K=20 으로 나누어 비례 배분하는 효과 (Level 1) 만으로 충분하고, KM20 과 RANDOM20 모두 같은 정도의 표본 안정화 효과를 갖습니다. 두 mode 의 0.56 %p 차이 (-0.56) 는 5-seed 의 std (~0.5 ~ 1 %) 안에 있어 *통계적으로 비유의* 합니다. 이는 모순이 아니라 *Level 2 가 selectivity-dependent* 라는 본 연구의 핵심 발견을 직접 확인하는 evidence 입니다 — 넓은 영역 (s=0.500) 에서는 Level 2 가 0 에 수렴하고, 좁은 영역 (s=0.010) 에서는 +19.6 %p 로 dominant 가 됩니다. anomaly_analysis.md 에 이 anomaly 의 *기전적 설명* 이 명시되어 있습니다.

### Q8.3 19.6 %p 격차의 통계적 유의성은 어떻게 산출했나요? 단순 difference of means 인가요?

**핵심 한 줄**: KM20 5-seed CI [+6.59, +10.95] 와 RANDOM20 5-seed CI [-15.26, -6.51] 가 *완전히 분리* 되어 (겹치지 않음) 통계적으로 유의한 difference 임이 확정되며, 19.6 %p 는 두 mean 의 산술적 차이 (8.93 - (-10.67)) 입니다.

**표준 답변** (45 초)
> 두 갈래 통계 증거가 있습니다. 첫째, *CI 분리*: KM20 CI [+6.59, +10.95] 와 RANDOM20 CI [-15.26, -6.51] 가 완전히 분리되어 (KM20 lower bound 6.59 vs RANDOM20 upper bound -6.51) 두 분포의 mean 차이가 통계적으로 유의함이 확정됩니다. 둘째, *paired comparison*: KM20 의 5/5 seed 모두 양수 (+8.51, +11.42, +11.53, +4.33, +8.87 %), RANDOM20 의 5/5 seed 모두 음수 (-10.63, -7.77, -11.51, -19.01, -4.43 %) — 즉 *완전 분리된 sign* 으로 unsigned binomial test 에서도 p < 1e-3 의 강한 신호입니다. 19.6 %p 는 두 mean 의 산술적 차이 (8.93 - (-10.67)) 이며, 두 5-seed CI 가 분리되어 있으므로 이 격차도 robust 합니다.

### Q8.4 selectivity 가 줄어들수록 Level 2 효과가 커진다는 것이, *기전적으로* 어떻게 설명되나요?

**핵심 한 줄**: selectivity 가 줄어들면 (좁은 영역) query 결과가 *소수 cluster 에 집중* 되어 cluster HHI 가 급증하고 (s=0.010 에서 HHI ≈ 0.50, 균일 대비 10 배), 이때만 *cluster 구조를 아는 KM20* 이 집중 영역에서 정확한 표본을 추출할 수 있는 반면 *cluster 구조를 모르는 RANDOM20* 은 이를 반영하지 못해 추정을 왜곡합니다.

**표준 답변** (60 초)
> selectivity 와 cluster HHI 의 관계가 핵심입니다. selectivity 가 클 때 (s=0.500) query 결과가 *모든 cluster 에 고르게 분포* 하므로 cluster HHI ≈ 1/K = 0.067 (균일 수준) 이고, partition 품질과 무관하게 비례 배분만으로 충분합니다. selectivity 가 작아질수록 (s=0.010) query 결과가 *소수의 인접 cluster 에 집중* 되어 cluster HHI 가 급증하며 (실측 0.503, 균일 대비 10 배), *어느 cluster 가 hit 의 대부분을 가지는지* 가 추정 정확도를 결정합니다. KM20 은 cluster 구조를 알고 있어 hit 가 집중된 cluster 에서 비례 배분으로 정확한 sample 을 가져오지만, RANDOM20 은 cluster 라벨이 무작위라 hit 가 어느 stratum 에 있는지 *모르고*, 잘못 라벨이 붙은 hit cluster 에서 small sample 을 뽑아 추정을 *심하게 왜곡* 합니다. 이 기전이 정확히 *spatial awareness 의 정의* 이며, hhi_python_summary.json 의 selectivity 별 HHI 변동이 이를 정량적으로 뒷받침합니다.

### Q8.5 Two-Level decomposition 이 *원래 stratified sampling 이론* 에 있는 분해인가요? 아니면 본 연구의 새 framework 인가요?

**핵심 한 줄**: Stratified sampling 이론에서 분산 감소를 *between-stratum variance 감소* 와 *within-stratum 표본 안정화* 두 갈래로 분해하는 것은 표준 (Cochran 1977, Lohr 2010) 이며, 본 연구는 이를 *empirical RANDOM20 control* 로 직접 측정 가능한 형태로 specialize 했습니다.

**표준 답변** (45 초)
> 분산 분해 이론적 배경은 표준 sampling theory 입니다. Cochran 의 *Sampling Techniques* (1977) 에서 stratified sampling 의 분산은 within-stratum variance 의 weighted sum 으로 분해되며, 이를 *Var(ŷ_strat) ≤ Var(ŷ_SRS)* 의 부등식으로 보장합니다. 본 연구의 Level 1 / Level 2 분해는 이 이론을 *empirical RANDOM20 control* 로 측정 가능한 형태로 specialize 한 것입니다. 핵심 기여는 *RANDOM20 partition 으로 within-stratum variance 의 baseline 을 잡고, KM20 의 spatial awareness 가 이를 얼마나 추가로 줄이는지* 를 직접 측정한다는 점입니다. 이 framework 자체가 distribution-agnostic 한 RQ3 의 evaluation metric (Recovery Rate) 의 기초가 됩니다.

# 섹터 9. HHI / CV 정량화 (Cluster Skewness)

> *데이터의 쏠림을 어떻게 잰 것인가? CV 0.234 vs 0.394 의 의미.*

### Q9.1 HHI 가 정확히 무엇인가요? 왜 그 지표를 골랐나요?

**핵심 한 줄**: Herfindahl-Hirschman Index 는 각 cluster 가 차지하는 비율의 제곱합으로 산업조직론에서 *시장 집중도* 를 잴 때 표준이며, 균일 분포 (1/K = 0.05) 와 완전 집중 (1.0) 사이의 단조 함수라 *분포 쏠림의 정량 지표* 로 직관적입니다.

**표준 답변** (40 초)
> HHI = sum_i (size_i / total_size)^2 로, 각 cluster 의 비중을 제곱해 합한 값입니다. 균일 분포 (모든 cluster 가 1/K) 에서 K × (1/K)² = 1/K 이고, 한 cluster 가 모두 차지할 때 1.0 입니다. 본 연구는 K=20 이므로 HHI 균일 기준 = 0.05, max = 1.0. DEEP 1M HHI 0.05274 는 균일 대비 5.5 % 큰 쏠림이고, SIFT HHI 0.05776 은 15.5 % 큰 쏠림입니다. 두 값의 절대 차이는 작아 보이지만 *균일 기준 0.05 대비* 의 비율로 보면 SIFT 가 DEEP 의 약 3 배 더 쏠려 있습니다. HHI 외에 CV (변동계수) 도 함께 보고하는데, 두 지표가 직교적으로 *분포의 쏠림* 을 잡아내기 때문입니다.

---

### Q9.2 CV (Coefficient of Variation) 와 HHI 는 어떻게 다른가요? 둘 다 보고한 이유는?

**핵심 한 줄**: HHI 는 *비중의 제곱합* 이라 큰 cluster 에 더 민감하고, CV 는 *상대적 표준편차* 라 모든 cluster 의 변동을 동일하게 반영하므로, 두 지표를 같이 보면 *위쪽 꼬리* 와 *전체 분포 변동* 을 함께 평가할 수 있습니다.

**표준 답변** (45 초)
> HHI 는 sum (p_i)² 로 큰 cluster 의 영향이 *제곱* 으로 들어가, 한 cluster 가 dominant 할 때 빠르게 증가합니다 — 즉 *위쪽 꼬리* 에 민감합니다. CV = std / mean 은 모든 cluster 의 deviation 을 동일하게 반영하는 *전체 분포 변동* 지표입니다. DEEP 1M 에서 HHI 균일 대비 격차 0.00274 (5.5 %), SIFT 에서 HHI 격차 0.00776 (15.5 %) — *3 배 비례*. CV 는 DEEP 0.234, SIFT 0.394 → 68 % 격차. 두 격차의 비율이 다르다는 것은 *위쪽 꼬리 (한두 큰 cluster) 의 영향이 SIFT 에서 상대적으로 더 큼* 을 의미합니다. 실제로 SIFT 의 cluster 1 (14.8 만) 과 cluster 18 (14.0 만) 두 개가 전체의 19 % 를 차지 (기대 10 % 의 약 두 배) 합니다. 두 지표를 같이 보면 *어떻게 쏠려 있는지* 도 알 수 있습니다.

---

### Q9.3 K=20 fixed 에서 측정한 HHI 인데, K 가 달라지면 HHI 도 달라지지 않나요?

**핵심 한 줄**: 맞습니다. HHI 는 K 에 의존하므로 *K=20 condition 에서의 cluster skewness* 만 보고합니다. K sweep (W5) 에서 K=10, 20, 50 의 HHI 변동을 측정 예정이며, 본 연구의 결론은 "K=20 baseline 에서 SIFT 가 DEEP 보다 더 쏠려 있다" 로 한정됩니다.

**표준 답변** (35 초)
> HHI 의 K 의존성은 sampling theory 의 표준 caveat 입니다. K 가 늘어나면 모든 cluster 의 비중이 작아지므로 균일 기준 HHI = 1/K 도 작아지고, 같은 데이터의 partition 결과도 달라집니다. 본 연구는 *K=20 baseline 에서의 cluster skewness 비교* 로 결론을 한정했고, K sweep (K = 5, 10, 20, 50, 100) 은 W5 보충 실험에 포함됩니다. K 와 무관한 *분포의 underlying skewness* 는 PCA EVR1 같은 dimension-free 지표로 측정 가능한데, 본 연구는 stratified sampling 의 evaluation 에 직결되는 *partition-specific skewness* 측정에 집중했습니다.

### Q9.4 SIFT 의 cluster 1 (14.8 만) 이 cluster 18 (14.0 만) 과 비슷한 크기인데, 우연 아닌가요?

**핵심 한 줄**: 5 seed × 100 query 측정 전반에서 *cluster 1 + cluster 18* 의 hit 집중도가 일관되게 다른 cluster 보다 높게 측정되어, 단순 우연이 아닌 *데이터 자체의 cluster 구조* 임이 확인됩니다.

**표준 답변** (40 초)
> mini-batch k-means (seed=42, n_iter=100, batch_size=4096) 의 *결정론적 학습* 으로 SIFT 1.5M 을 K=20 으로 분할했을 때, cluster 1 과 cluster 18 이 공동 dominant 로 떠올랐습니다. 5 seed 측정 (sample 추출 seed) 에서 모든 5 seed 가 같은 cluster 라벨링을 사용하므로 (cluster 라벨 자체는 1 seed = 42 로 고정), cluster 1·18 의 dominance 는 partition 결과의 *결정론적 특성* 입니다. 이 dominance 가 SIFT 의 KM20 효과를 DEEP 보다 약 두 배로 키우는 직접 원인이며, cluster_distribution.md 에 정량 기록되어 있습니다.

### Q9.5 *균일 기준* 이라는 게 정확히 무엇인가요? 비교의 의미는?

**핵심 한 줄**: 데이터가 K개 cluster 에 *완전 균일하게* 분포한다고 가정한 이론적 기준선이며, HHI 균일 기준 = 1/K = 0.05, CV 균일 기준 = 0.0 입니다. 실측이 균일 기준에 *얼마나 가까운가* 가 분포의 쏠림 정도입니다.

**표준 답변** (30 초)
> "균일 기준" 은 K=20 의 cluster 에 데이터가 정확히 1/K = 5 % 씩 분포한다고 가정한 이론적 baseline 입니다. HHI 의 경우 K × (1/K)² = 1/K = 0.05 가 baseline 이고, CV 의 경우 모든 cluster size 가 같으므로 std = 0, CV = 0 입니다. 실측 HHI 가 0.05 에 가까울수록, CV 가 0 에 가까울수록 *균일* 합니다. DEEP 1M HHI 0.05274 는 균일 기준 +5.5 % 격차, SIFT 0.05776 은 +15.5 %. 즉 *완전 균일* 과 *실측* 의 격차로 쏠림 정도를 직관적으로 잴 수 있습니다.

# 섹터 10. 통계 방법론 (전반)

### Q10.1 paired Wilcoxon 외에 *다른 통계 검정* 도 함께 보고하나요? 예를 들어 paired t-test 의 결과가 다르면?

**핵심 한 줄**: paired Wilcoxon 이 lognormal Q-error 분포에 robust 한 비모수 검정이므로 primary metric 으로 채택했고, paired t-test (log-transformed) 는 W6 (5/12 경) 보충 분석에 포함됩니다. 두 결과가 일치할 것으로 예상하며 일치하지 않으면 두 결과를 모두 보고합니다.

**표준 답변** (40 초)
> Q-error 는 추정값과 실제값의 비율로 lognormal 또는 heavy-tail 분포를 갖습니다. paired t-test 는 정규성 가정이 필요한데 lognormal 데이터에 직접 적용 시 outlier 영향이 크고 false positive 위험이 있습니다. paired Wilcoxon 은 *분포 가정 없이* paired difference 의 median 을 검정하는 robust 비모수라 primary metric 으로 채택했습니다. paired t-test 는 *log Q-error* 로 transform 한 후 적용 가능하며, W6 보충 분석에서 두 검정 결과를 모두 보고하고 일치성을 검증합니다. 만약 두 결과가 다르다면 어느 한 쪽의 가정이 깨진 것이므로 raw distribution 을 직접 점검할 예정입니다.

### Q10.2 *Multiple comparison* 보정은 어떻게 했나요? 6 selectivity × 3 dataset = 18 셀에 대해 각각 p-value 를 산출했는데?

**핵심 한 줄**: 본 보고서 시점에서는 셀별 raw p-value 만 보고하고, *Benjamini-Hochberg FDR* 보정 후 *family-wise* 또는 *false discovery rate* control 결과는 W6 (5/12 경) 보충 분석에 포함됩니다. 핵심 셀 (DEEP 1M s=0.5 KM20 p < 1e-5, SIFT s=0.5 p < 1e-8) 은 어떤 보정 후에도 유의합니다.

**표준 답변** (45 초)
> Multiple comparison 위험은 *6 selectivity × 3 dataset × 2 mode (KM20 / RANDOM20) = 36 셀* 에 paired Wilcoxon 을 적용했을 때 약 36 × 0.05 = 1.8 개의 false positive 가 기대됩니다. 본 보고서 시점에서는 *셀별 raw p-value 와 5-seed CI* 만 보고하며, 핵심 anchor (DEEP 1M s=0.5 KM20: per-seed p < 1e-5, SIFT s=0.5 KM20: per-seed p < 1e-8) 은 어떤 보정 (Bonferroni 36 × p, BH-FDR) 후에도 유의합니다. 보충 분석 (W6) 에서는 *36 셀 동시* 의 BH-FDR adjusted p, TOST equivalence test, Cohen's d effect size 를 모두 산출해 *family-wise control* 한 결과를 보고합니다. 출판 시 reviewer 가 multiple comparison 을 우려할 가능성을 사전에 차단하기 위한 단계입니다.

### Q10.3 *Cohen's d* 같은 effect size 는 측정했나요?

**핵심 한 줄**: 본 보고서 시점에서는 *paired difference 의 mean 과 95% CI* 를 effect size proxy 로 사용했고, 표준 Cohen's d (paired-sample 변형) 는 W6 보충 분석에 포함됩니다.

**표준 답변** (40 초)
> Cohen's d_z (paired-sample Cohen's d) = mean_diff / std_diff 로, paired Wilcoxon 의 effect size 표준 metric 입니다. 본 연구의 DEEP 1M s=0.5 KM20 의 mean_diff = 1.6366 %, std_diff = 0.4416 % → d_z = 3.71 로 *very large* 효과 (Cohen 1988 기준 0.8 이상은 large) 입니다. 다만 본 보고서 시점에서는 raw mean diff (+1.64 %) 와 95% CI [+1.09, +2.18] 만 표 2 에 직접 인용했고, Cohen's d 는 W6 보충 분석에 포함됩니다. 효과 크기와 CI 가 모두 robust 하므로 추가 metric 없이도 *통계적·실질적 유의성* 이 모두 확인됩니다.

### Q10.4 5-seed 의 CI 산출에 t-distribution 을 썼는데, *bootstrap CI* 와 다르지 않나요? 어느 것을 보고하시는 건가요?

**핵심 한 줄**: 보고서·발표의 CI 는 *t-based* (mean ± t(4) × std / √5) 로 산출했고, raw json 의 `bootstrap_95ci` 는 별도 bootstrap 방식 산출입니다. 두 방식 모두 valid 하며, 다만 동일 보고서 안에서 일관된 한 가지 방식만 쓰는 것이 좋고, *최종 보고서 (6월) 에서는 t-based + bootstrap 둘 다 표기* 할 예정입니다.

**표준 답변** (50 초) — *솔직한 자체 정정 답변*
> 좋은 지적이십니다. 본 보고서·발표의 CI 는 *t-distribution 기반* 으로 산출했습니다 — DEEP 1M s=0.500 KM20 의 mean = 1.6366, std = 0.4416, n = 5, t(4, 0.975) = 2.776 으로 CI = mean ± t × std/√5 = [+1.09, +2.18]. raw data 의 phase6_multiseed_summary.json 에 별도로 산출된 `bootstrap_95ci` [+1.25, +2.02] 는 percentile bootstrap 방식이며, 두 방식이 약간 다릅니다. n = 5 의 small sample 에서는 t-based 와 bootstrap CI 가 다소 다르게 나오는 것이 통계적으로 정상이며, 두 방식 모두 valid 합니다. 본 보고서는 *t-based 만* 일관되게 보고하고, 최종 보고서 (6 월) 에서는 *두 방식 모두 표기* 해 reviewer 가 직접 비교 가능하도록 할 예정입니다. 효과의 *방향성* 과 *유의성* 은 두 방식 모두에서 동일하게 확정 (양수 CI) 입니다.

### Q10.5 통계적으로 유의하다고 *임상적으로 (실무적으로) 의미가 있는가* 는 다른 문제인데, +1.6 % 가 실제로 어느 정도 의미 있는 개선인가요?

**핵심 한 줄**: Q-error 의 1.6 % 개선이 *옵티마이저 plan 선택의 임계점 근처 쿼리* 에서 plan 단위 변경을 일으킬 수 있고, plan 한 번의 잘못이 실행 시간을 1 만 배까지 늘릴 수 있다는 Exqutor 원논문의 보고를 고려하면, *실용적 의미가 있다* 고 판단됩니다.

**표준 답변** (50 초)
> 두 갈래 답변이 가능합니다. 첫째, *micro-level*: 1.6 % 의 정확도 개선 자체는 작아 보이지만, 이는 *median 수준의 개선* 입니다. distribution 의 tail 에서는 더 큰 개선이 일어나며, 옵티마이저의 plan 선택은 distribution 전체가 아닌 *임계점 근처* 에서 결정됩니다. 그래서 median 1.6 % 개선이 *임계점 근처 쿼리에서 잘못된 plan 을 고를 확률* 을 줄이는 효과를 갖습니다. 둘째, *macro-level*: Exqutor 원논문이 보고한 VBASE 1 만 배 이상의 실행 시간 격차가 plan 한 번의 잘못에서 옵니다. 따라서 1.6 % 의 정확도 개선이 *plan 변경 확률* 을 1 % 줄여도, 영향받는 쿼리에서 1 만 배의 실행 시간 차이를 만들 수 있습니다. End-to-end query time 영향은 본 연구 범위 밖이지만, plan 선택 메커니즘으로 *실용적 의미가 있다* 는 근거는 충분합니다.

### Q10.6 *통계적 power* 분석은 했나요? Type II error 위험을 통제했나요?

**핵심 한 줄**: paired Wilcoxon 의 *medium effect (Cohen's d ≈ 0.5) at α = 0.05, power 0.8* 기준으로 약 50 ~ 70 paired sample 이 필요하며, 본 연구는 5-seed × 100 query = 500 paired 로 이 기준의 7 ~ 10 배입니다.

**표준 답변** (35 초)
> Power 분석은 paired Wilcoxon 의 표준 software (G*Power 또는 R pwr 패키지) 로 산출 가능합니다. medium effect (Cohen's d_z ≈ 0.5) 를 α = 0.05 양측, power = 0.8 기준으로 잡으려면 약 50 ~ 70 paired sample 이 필요합니다. 본 연구의 5-seed × 100 query = 500 paired 는 이 기준의 7 ~ 10 배이고, 각 5-seed 가 독립이므로 mean diff 의 표준오차는 std/√5 로 줄어듭니다. 따라서 *Type II error (effect 가 있는데 못 잡는 위험)* 는 충분히 통제되어 있습니다. small effect (d_z ≈ 0.2) 를 잡으려면 약 200 ~ 300 paired 가 필요한데, 이는 W6 의 10-seed × 500-쿼리 = 5000 paired 측정에 포함됩니다.

# 섹터 11. RQ3 — 분포 무인지 7 가지 방법 (탐색 단계)

### Q11.1 RQ3 의 7 가지 방법은 어떤 기준으로 골랐나요? 24 개 후보 중 17 개가 탈락했는데, 그 사유는?

**핵심 한 줄**: 4 가지 평가 축 — (a) *이론적 정당성* (이론 백그라운드), (b) *6주 내 구현 가능성* (학부 캡스톤 timeline), (c) *KM20 과의 차별성* (단순 변형 제외), (d) *우리 측정 파이프라인 적합성* (hook_est + stratum_id 기반) — 으로 24 개 후보를 score 해 7 개를 확정했습니다.

**표준 답변** (60 초)
> 24 개 후보를 4 갈래로 분류해 평가했습니다. 첫째, *이미 검증된 단순 방법* — Random Projection (C), LSH (A), Hilbert curve (E), Mini-batch K-means (F) 4 개. 둘째, *쿼리 적응 방법* — Distance-Shell (G), KDE-pilot (B) 2 개. 셋째, *비분할 방법* — Importance Sampling (H) 1 개. 총 7 개. 탈락 17 개는 (a) Latin Hypercube 같은 *고차원에서 동작 안 하는 방법*, (b) Tree-based / Spectral / Optimal Transport 같은 *KM20 과 비용 비슷하면서 차별성 없는 방법*, (c) Coreset / Multi-armed Bandit 같은 *RQ3 범위 밖 (sample selection vs cardinality estimation 문제) 방법*, (d) Density-Inverse Pre-weighting 같은 *기존 7 개의 변형* 으로 분류해 모두 사유 기록과 함께 탈락시켰습니다. 이 분류가 RQ3 설계안 문서에 *24 → 7 의 결정 트리* 로 정리되어 있어 reviewer 가 우리의 *공간 탐색 폭* 을 직접 검증할 수 있습니다.

**디테일 보강** (2 분)
> 17 개 탈락 후보의 구체적 사유를 일부 들면: (1) Latin Hypercube — 96d 에서 K^d 셀 폭발로 차원 축소 필수 → C (Random Projection) 와 동치. (2) Tree-based (VP/KD/Ball tree) — 구축 비용 O(N · log N) 으로 k-means 와 같은 order, 차별성 0. (3) Coreset Construction — sample selection 을 직접 지정해야 해서 hook_est 로그 파싱 불가, 7-way fair comparison 안 됨. (4) Multi-armed Bandit — 반복 쿼리 학습이 본 연구의 *single query estimation* 세팅과 부적합. (5) Optimal Transport (Wasserstein) — 이론적이나 1M 데이터에 비현실적. (6) Spectral Clustering — O(N²) 메모리. (7) Random Voronoi — F (MiniBatch) 의 learning_fraction = 0 % case → F 로 통합. (8) Anchor-based Distance Profile — M 차원 프로필에 A/C/E/F 중 하나 적용 → 독립 방법 아님. (9) Ensemble (다중 방법 투표) — LSH (A) 가 정확히 이것 (p 개 hyperplane). 24 개 후보 모두 RQ3 설계안 [`plans/RQ3설계안_20260416_213500.md`](plans/RQ3설계안_20260416_213500.md) §X 의 표에 사유와 함께 기록되어 있습니다.

### Q11.2 D (Exqutor Hybrid — Adaptive + KM20 결합) 는 *왜* 가장 자연스러운 출발점인데 제외했나요?

### Q11.3 7 가지 방법 중 *가장 기대되는* 것은? 그 이유는?

**표준 답변** (40 초)

**표준 답변** (45 초)

(2) A (LSH p hyperplane) 와 E (Hilbert curve) 와 G (Distance-Shell) 가 30 ~ 60 % 의 비슷한 영역. (3) B (KDE-pilot) 와 H (Importance Sampling) 가 50 ~ 80 % 의 정교한 적응형. ### Q11.5 H (Importance Sampling) 의 *2×2 factorial* 이 정확히 무엇인가요? 왜 다른 방법과 다르게 처리하나요?

**핵심 한 줄**: H 는 다른 6 방법과 달리 *hook_est 반환 공식 (uniform mean → weighted mean)* 자체를 수정하므로, 7-way 단순 비교에서 *allocation 효과* 와 *estimator 공식 효과* 가 confounded 됩니다. 이를 분리하기 위해 H 만 (KM20 vs no partition) × (uniform vs IS estimator) 4 조합을 모두 측정합니다.

**표준 답변** (50 초)
> 다른 6 방법 (C / A / E / F / G / B) 은 모두 *stratum_id 할당 방식만 다름* 이고 hook_est 반환 공식 (`sum_h N_h × hit_h / n_h`) 은 동일합니다. H 는 stratum 자체를 만들지 않고 *각 sample 의 inclusion probability 의 역수로 가중* 합니다 — 즉 hook_est 공식이 `sum_i 1/p_i × indicator_i` 로 바뀝니다. 따라서 H vs KM20 의 비교에는 *allocation 효과 (stratum 분할 여부)* 와 *estimator 공식 효과 (uniform mean vs IS weighted mean)* 가 섞여 있습니다. 두 효과를 분리하려면 4 조합 — (KM20 + uniform), (KM20 + IS), (no partition + uniform = bernoulli), (no partition + IS = H 본설계) — 의 2×2 factorial 측정이 필요합니다. (KM20 + IS) − (KM20 + uniform) = estimator 공식 효과 단독, (KM20 + IS) − (H + IS) = allocation 효과 단독. 이 factorial 결과는 RQ3 의 appendix 에 보고하고, 7-way 단순 비교에서는 H 를 *대표 메커니즘* 으로만 제시합니다.

# 섹터 12. Recovery Rate metric

> *RQ3 의 핵심 evaluation metric. 분모 붕괴 규칙이 핵심 caveat.*

### Q12.1 Recovery Rate 의 정확한 산출 공식은?

**핵심 한 줄**: Recovery Rate = (방법X − RANDOM20) / (KM20 − RANDOM20) 으로, KM20 의 oracle 효과를 1.0 으로 두고 RANDOM20 을 0.0 으로 두었을 때 새 방법이 그 사이 어디에 위치하는지 정량화한 값입니다.

**표준 답변** (40 초)
> 분모는 *분포 인지 oracle 의 효과* (KM20 − RANDOM20), 분자는 *새 방법이 회수한 효과* (방법X − RANDOM20) 로, 두 값의 비율이 Recovery Rate 입니다. 1.0 이면 KM20 과 동등 (oracle 수준), 0.0 이면 RANDOM20 과 동등 (분포 인지 없음), 음수면 RANDOM20 보다 더 나쁨, 1.0 초과면 oracle 보다 더 좋음 (rare). 본 연구의 핵심 hypothesis 는 *F (MiniBatch) ≈ 0.8, B (KDE) ≈ 0.6, A (LSH) ≈ 0.5, E (Hilbert) ≈ 0.4, G (Shell) ≈ 0.4, H (Importance) ≈ 0.5, C (RandProj) ≈ 0.2* 의 단조 구조이며, 5 월 측정에서 검증됩니다.

---

### Q12.2 *분모 붕괴* (denominator collapse) 가 무엇이고, 왜 별도 규칙이 필요한가요?

**핵심 한 줄**: 일부 데이터셋·selectivity 조합에서 |KM20 − RANDOM20| 의 절대값이 seed 간 표준편차보다 작아져, Recovery Rate 의 *분모* 가 noise 안에 들어갑니다. 이 영역에서는 0/0 같은 *수학적 정의 불능* 이 발생하므로 절대 개선폭으로 따로 보고하는 사전 규약을 두었습니다.

**표준 답변** (50 초)
> RQ2 실측에서 일부 셀이 |KM20 − RANDOM20| ≤ 1 %p 또는 seed std 이하로 측정되었습니다. 예를 들어 DEEP 1M s=0.500 에서 KM20 +1.64 %, RANDOM20 +2.20 %, 격차 -0.56 %p (분모 음수). 이 영역에서 Recovery Rate 를 산출하면 -1.5 같은 *비정상 값* 이 나오는데, 이는 새 방법의 effective performance 가 아니라 *분모가 noise* 인 것입니다. 그래서 본 연구는 *분모 붕괴 규칙* — |KM20 − RANDOM20| ≤ 1 %p 또는 seed σ 이하 셀에서는 Recovery Rate 보고 X, *절대 Q-error 개선폭 (방법X − BERN)* 을 primary metric 으로 사용 — 을 사전 규약 (pre-register) 했습니다. 이 규약은 측정 *전* 결정한 것으로, post-hoc cherry-picking 위험을 차단합니다.

---

### Q12.3 분모 붕괴 영역이 *얼마나 많은* 셀에 해당하나요?

**핵심 한 줄**: RQ2 의 14 개 측정 셀 (3 데이터셋 × 다양한 selectivity) 중 약 4 개 셀이 분모 붕괴 영역으로 분류되며, 나머지 10 개 셀에서는 Recovery Rate 가 정상 산출됩니다.

**표준 답변** (40 초)
> 분모 붕괴 셀 후보: (1) DEEP 1M s=0.500 (KM 1.64 vs RAND 2.20, 격차 -0.56 %p, 분모 음수), (2) DEEP 8M s=0.050 (KM 0.55 vs RAND 0.20, 격차 +0.35 %p, < 1 %p), (3) DEEP 8M s=0.500 (KM 1.76 vs RAND 1.10, 격차 0.66 %p, < 1 %p), (4) SIFT 1M s=0.500 잠재적 corner 케이스. 이 4 개 셀에서는 절대 Q-error 개선폭 으로만 보고합니다. 나머지 10 개 셀 — 특히 DEEP 1M s=0.010 (격차 19.6 %p), SIFT s=0.010 (11.6 %p), DEEP 1M s=0.300 (2.4 %p), s=0.100 (2.5 %p), SIFT s=0.500 (2.1 %p), s=0.050 (4.4 %p) — 에서는 Recovery Rate 가 정상 산출됩니다. 즉 *대부분의 셀에서 Recovery Rate metric 사용 가능* 하고, 분모 붕괴는 *예외 처리* 입니다.

---

### Q12.4 Recovery Rate 외에 *다른 evaluation metric* 도 함께 보고하나요?

**핵심 한 줄**: Primary 가 Recovery Rate, secondary 로 *절대 Q-error 개선폭 (방법X − BERN)*, *paired Wilcoxon p-value*, *cost-effect ratio (recovery / training_time)* 4 가지를 함께 보고합니다.

**표준 답변** (35 초)
> Recovery Rate 가 *상대적 oracle 회수율* 이라면, 절대 Q-error 개선폭은 *통계적 유의성*, paired Wilcoxon p 는 *통계적 신뢰도*, cost-effect ratio (recovery / training_time) 는 *실용적 가치* 를 잡습니다. 4 metric 을 모두 보고해야 *recovery 는 높지만 training cost 가 KM20 과 같음* 같은 false comparison 을 방지할 수 있습니다. 특히 cost-effect ratio 는 RQ3 의 핵심 학술 기여 — *얼마만큼의 사전 학습으로 충분한가* — 의 직접 metric 입니다. F (MiniBatch) 의 learning_fraction sweep 에서 이 ratio 가 어떻게 변하는지가 본 연구의 가장 흥미로운 figure 가 될 예정입니다.

(3) `estimate_cardinality_with_stratified_sampling` 함수 추가 (228 라인) — k-means centroid 메모리 로드, stratum_id 사전 계산, Horvitz-Thompson estimator (`sum_h N_h × hit_h / n_h`), GUC `vector.sampling_method` 설정. 발표에서 "세 줄" 이라고 부르는 것은 *직관적 표현* 이고, 실제 코드 변경은 보조 함수 포함 약 230 라인입니다. 학술 정확성 측면에서 발표 슬라이드 6 (vector.c snippet) 에 핵심 3 변경 위치를 명시했습니다.

### Q13.4 `update_sample_size = off` 설정이 무엇이고, 왜 그게 필요한가요?

**핵심 한 줄**: Exqutor 의 Adaptive Sampling 이 단일 테이블 시나리오에서 SIGSEGV crash 하는 design constraint #5 의 *회피 수단* 이며, sample_size 의 동적 업데이트를 비활성화해 *sampling method 자체의 효과만 분리 측정* 합니다.

**표준 답변** (45 초)
> Exqutor 의 GUC `vector.update_sample_size` 가 default = on 일 때 Adaptive update path 가 모멘텀 기반으로 sample_size 를 동적으로 조정합니다. 그런데 단일 테이블 시나리오에서 이 update path 가 SIGSEGV crash (q3 정도에서 PG process 가 signal 11 로 종료) 하는 design constraint #5 가 발견되었습니다 (Phase 4 sanity check, 4/14). 회피 수단으로 `SET vector.update_sample_size = off` 로 sample_size 를 385 fixed 로 유지하고 estimate 만 합니다. 이 설정은 *Adaptive update 효과를 차단* 하므로 본 연구가 측정하는 것은 *sampling method 자체* (system / bernoulli / stratified) 의 효과이고, Adaptive update 의 효과는 RQ3 또는 후속 연구의 영역입니다. 4 월 19 일 ultrareview 에서 이 설정이 default 로 추가되어, 향후 측정 모두 동일 환경에서 진행됩니다.

### Q13.5 코드 변경이 Exqutor 의 *multi-table 시나리오* 동작을 깨지는 않나요?

**핵심 한 줄**: 본 연구의 모든 코드 변경은 기존 동작 경로 *옆에 추가* 되도록 짜여 있어, multi-table 시나리오에서는 기존 경로 (TABLESAMPLE SYSTEM, hook trigger > 2, default Adaptive Sampling) 가 그대로 유지됩니다.

**표준 답변** (45 초)
> 코드 변경의 *additive design* 이 핵심입니다. (1) line 243 의 hook trigger 조건은 *완화* (≥1) 인데, 이는 multi-table (table_count > 2) 시나리오에서도 여전히 trigger 되므로 기존 동작에 영향 없음. (2) line 889 의 TABLESAMPLE 변경은 sampling_method GUC 로 분기되는데, default = bernoulli 이고 multi-table 시나리오에서도 동일하게 적용. (3) Stratified 분기는 GUC `sampling_method = stratified` 일 때만 활성화되고, default 는 bernoulli 라 multi-table 의 default 동작 그대로 유지. 또한 Stratified 분기 안에서도 stratum_id 컬럼이 없으면 자동으로 bernoulli fallback. 즉 *opt-in 변경* 이고, multi-table 시나리오의 동작은 아무것도 깨지지 않습니다.

# 섹터 14. 한계점 & Threats to Validity

> *학술적 정직성. 본 연구가 *하지 않은* 것을 명확히 인정.*

### Q14.1 본 연구의 *가장 큰 한계* 는 무엇인가요?

**핵심 한 줄**: *End-to-end query time 의 직접 측정* 이 빠진 점이 가장 큰 한계입니다. Q-error (추정 정확도) 만 측정했고, plan 변경으로 인한 실행 시간 영향은 옵티마이저 메커니즘으로 *간접 추론* 했습니다.

**표준 답변** (50 초) — *솔직한 한계 인정*
> 가장 큰 한계는 *end-to-end query time 미측정* 입니다. 본 연구는 Q-error (추정값과 실제값의 비율) 의 개선만 측정했고, 그 개선이 *옵티마이저 plan 선택의 변화* 와 *실행 시간 단축* 으로 이어지는 메커니즘은 Exqutor 원논문의 보고 (VBASE 1 만 배 이상) 와 옵티마이저 표준 동작에 의존해 *간접 추론* 했습니다. 직접 측정하려면 (1) plan 변경 빈도, (2) 변경된 plan 의 실행 시간 비교, (3) 다양한 워크로드 (single-query / batch / mixed) 에서의 평균 영향 측정이 필요한데, 이는 RQ3 보충 또는 후속 연구의 영역입니다. 본 보고서·발표에서 이 한계를 *명시* 하고, end-to-end 영향을 *간접 추론* 했다는 사실을 솔직하게 인정합니다. W6 (5/12 경) 보충 분석에서 EXPLAIN ANALYZE 기반 plan 변경 빈도 측정을 시도할 예정입니다.

---

### Q14.2 *데이터셋 두 개* (DEEP, SIFT) 만 사용한 것이 일반화에 충분한가요?

**핵심 한 줄**: 두 데이터셋이 *대조적 분포 특성* 을 가진 anchor pair 라는 점에서 cross-dataset 비교의 minimal 조건은 만족하지만, 광범위한 일반화 (text embedding, audio embedding, multimodal) 는 W5-W7 보충 실험과 후속 연구의 영역입니다.

**표준 답변** (40 초)
> Two-sample minimum 의 cross-dataset 비교는 *효과의 방향성 일관성* 검증에 충분합니다. DEEP (96d, deep image feature, 균일) 과 SIFT (128d, image keypoint, skewed) 가 *대조적 anchor pair* 로, 두 데이터셋 모두에서 KM20 효과가 양수 확정 + 더 skewed 한 SIFT 에서 효과가 두 배라는 일관성을 확인했습니다. 다만 광범위한 일반화 (text embedding 인 BERT 768d, multimodal 인 CLIP 512d, audio 인 wav2vec 768d) 는 W5-W7 보충 실험에 wiki 768d 를 추가해 1 회 더 검증할 예정이고, 본격 multi-modality 일반화는 후속 연구의 영역입니다. 본 연구의 conservative claim 은 *vector embedding range query 의 cardinality estimation 에서 분포의 cluster skewness 와 KM20 효과가 단조 관계를 갖는다* 까지입니다.

---

### Q14.3 *K = 20 fixed* 가 가장 큰 design choice 인데, K sensitivity 측정 안 했나요?

**핵심 한 줄**: phase6_layer_compare 에서 K=10 과 K=20 비교를 했고 K=20 우세를 확인했지만, K sweep (5, 10, 20, 50, 100) 의 본격 측정은 W5 (5/4 경) 보충 실험에 포함됩니다.

**표준 답변** (40 초)
> K sensitivity 의 부분 측정은 phase6_layer_compare 에서 K=10 vs K=20 비교로 수행했고, K=20 이 selectivity 0.100 (+2.25%, p=0.0042), 0.300 (+0.76%, p=0.016), 0.500 (+0.33%, p=0.016) 모두에서 K=10 보다 우세였습니다. 다만 K=5, K=50, K=100 같은 다른 값은 W5 보충 실험에 포함되며, 본 보고서 시점에서는 *K=20 이 K=10 보다 우세* 의 부분 결론까지만 보고합니다. K sensitivity 의 광범위한 sweep 은 RQ3 의 F (MiniBatch K-means) 에서도 함께 다루며, *최적 K 가 데이터셋·selectivity 에 의존* 한다면 그 자체로 흥미로운 finding 입니다.

---

### Q14.4 *Adaptive Sampling 과 직접 비교* 한 head-to-head 측정이 없는데, 그게 정당한가요?

**핵심 한 줄**: Adaptive Sampling 의 update path 가 단일 테이블에서 SIGSEGV crash 하는 design constraint #5 로 *직접 비교 측정 자체가 불가능* 하며, update_sample_size=off 회피 환경에서는 sample_size 가 fixed 라 본 연구의 STRAT/BERN/SYSTEM 비교와 동일한 baseline 위에 놓입니다.

**표준 답변** (50 초)
> Adaptive Sampling 과 직접 head-to-head 비교는 측정 자체가 불가능합니다. update_sample_size = on 으로 Adaptive update path 를 활성화하면 단일 테이블 시나리오에서 q3 정도 (3 번째 query) 에 SIGSEGV crash 가 발생합니다 (design constraint #5). 회피 수단인 update_sample_size = off 환경에서는 sample_size 가 fixed (385) 인데, 이는 본 연구의 STRAT / BERN / SYSTEM 비교와 동일한 baseline 입니다. 즉 본 연구의 측정 환경은 *Adaptive Sampling 의 핵심 특성 (모멘텀 기반 동적 sample_size 조정)* 을 비활성화한 환경이고, 이 점은 보고서 §4.1 (RQ1) 에 design constraint 로 명시되어 있습니다. Adaptive 와의 fair comparison 은 (1) update path bug fix → (2) Adaptive 모멘텀 활성화 → (3) STRAT 와 paired 측정 의 3 단계가 필요하며, 이는 RQ3 또는 후속 연구의 영역입니다.

---

### Q14.5 *데이터의 INSERT/UPDATE* 같은 동적 환경에서는 어떻게 동작하나요?

**핵심 한 줄**: 본 연구는 *static dataset* 환경의 cardinality estimation 만 다루며, 동적 데이터에서의 stratum_id 재계산·KM20 centroid 갱신은 본 연구의 limitation 으로 명시되어 있고, RQ3 의 G (Distance-Shell) 와 B (KDE-pilot) 가 *online query-adaptive* 패러다임으로 동적 환경 대응을 시도합니다.

**표준 답변** (40 초)
> 본 연구의 KM20 은 *데이터 적재 시 1 회 학습 후 stratum_id 컬럼 사전 계산* 의 offline 방식이라, INSERT 가 빈번하면 새 행의 stratum_id 할당 (O(d × K) 의 nearest centroid lookup) 과 centroid 의 stale 처리가 필요합니다. RQ3 의 G (Distance-Shell) 는 쿼리 시점에 동심원 분할을 하므로 INSERT 에 자동 대응하고, B (KDE-pilot) 도 pilot sample 을 매 쿼리마다 새로 뽑으므로 동적 환경 친화적입니다. RQ3 의 F (MiniBatch K-means) 는 1 ~ 5 % learning fraction 으로 incremental update 가 가능합니다. 즉 RQ3 가 *동적 환경 대응* 을 직접 다루는 영역이며, 본 보고서 시점의 KM20 은 static baseline 으로 한정됩니다.

---

### Q14.6 *5-seed* 로 충분한가요? 더 많은 seed 가 필요하지 않나요?

**핵심 한 줄**: 5-seed 의 t-based CI 가 핵심 anchor (DEEP 1M s=0.500, SIFT s=0.500) 에서 양수 확정 + CI 분리 + per-seed p < 1e-5 ~ 1e-8 로 robust 하지만, 본격 검정력 (10-seed × 500-쿼리 + BH-FDR + Cohen's d) 은 W6 보충 분석에 포함됩니다.

**표준 답변** (35 초)
> 5-seed 의 *방향성 robust* 는 CI 양수 확정 + per-seed sign 분리 + per-seed p < 1e-5 ~ 1e-8 로 확인되었습니다. 다만 small effect 영역 (s=0.05 같은) 에서는 CI 가 0 을 포함하는 셀이 있어 검정력 부족 가능성. 본격 검정력 측정은 W6 (5/12 경) 의 10-seed × 500-쿼리 = 5000 paired 단위로 확보 예정이며, 이는 small effect (Cohen's d ≈ 0.2) 도 power 0.8 로 잡을 수 있는 sample size 입니다. 본 보고서 시점은 *medium effect 이상의 robust 검증* 으로 conservative 하게 한정됩니다.

# 섹터 15. 차별성 & 비교 (Comparison)

> *학습 기반 카디널리티 estimator 와의 비교, VBASE/pgvector/DuckDB 직접 비교가 안 된 이유.*

### Q15.1 *학습 기반 카디널리티 estimator* (LearnedCard, MSCN, NeuroCard) 와는 비교 안 했나요?

**핵심 한 줄**: 학습 기반 estimator 는 일반 SQL 술어에는 좋은 결과를 내지만 *벡터 거리 조건* 에 직접 적용된 사례가 적고, 본 연구는 *Exqutor 의 sampling-based 접근* 의 단일 테이블 사각지대를 메우는 데 집중했으며, 학습 기반 비교는 후속 연구의 영역입니다.

**표준 답변** (50 초)
> LearnedCard (Kipf et al. 2019), MSCN (Multi-Set Convolutional Network), NeuroCard 같은 학습 기반 estimator 는 일반 SQL 술어 (range, equality, join) 에는 좋은 결과를 보고합니다. 그러나 벡터 거리 조건처럼 *96 ~ 1024 차원의 비선형 술어* 에 직접 적용된 사례는 적고, 학습 데이터 (query workload) 의존성이 크다는 caveat 가 있습니다. 본 연구는 *Exqutor (sampling-based) 의 단일 테이블 사각지대* 를 메우는 데 집중했고, 두 패러다임 (sampling-based vs learning-based) 의 직접 비교는 후속 연구의 영역입니다. 본 연구의 RQ3 가 distribution-agnostic sampling 의 7 가지 방법 비교를 마치면, 그 결과를 anchor 로 학습 기반과의 fair comparison framework 를 설계할 수 있습니다.

---

### Q15.2 *VBASE / pgvector / DuckDB 와 head-to-head 비교* 가 보고서에 없는데, 왜 안 했나요?

**핵심 한 줄**: 본 연구는 *Exqutor 코드 자체를 수정하는 형태* 로, 다른 시스템과 직접 비교하려면 (1) 각 시스템에 동일한 코드 수정 적용 또는 (2) baseline 카디널리티 추정 방식의 fair comparison framework 가 필요한데, 둘 다 본 연구 범위 밖입니다.

**표준 답변** (50 초)
> 두 갈래 이유입니다. 첫째, *기술적 측면*: 본 연구의 코드 수정은 Exqutor 의 vector extension 위에서 이루어지고, VBASE / pgvector vanilla / DuckDB 는 각각 다른 카디널리티 추정 메커니즘 (고정 비율 50 % / 33.3 % / 100 %) 을 갖습니다. 같은 stratified sampling 을 다른 시스템에 직접 이식하려면 각 시스템의 인덱스·plan optimizer 코드 수정이 별도로 필요합니다. 둘째, *학술적 측면*: 본 연구의 baseline 은 *Exqutor 의 BERNOULLI sampling* 이고, 그 위에 KM20 stratification 을 추가했을 때의 효과를 측정합니다. VBASE 의 fixed 50 % vs Exqutor 의 BERNOULLI vs Exqutor + KM20 같은 multi-system 비교는 *어느 baseline 이 fair 한가* 의 framework 자체가 별도 연구입니다. Exqutor 원논문의 1 만 배 이상 격차 보고가 *시스템 간 비교의 anchor* 가 되며, 본 연구는 *Exqutor baseline 위에 추가 개선* 의 정량화로 한정됩니다.

---

### Q15.3 그래도 *간접적인* 비교 수치는 있나요?

**핵심 한 줄**: Exqutor 원논문의 보고 — pgvector 33.3 % / VBASE 50 % / DuckDB 100 % 고정 비율 vs Exqutor ECQO + Adaptive — 가 system-level baseline 비교의 anchor 이고, 본 연구의 KM20 은 그 위에 추가된 *Exqutor 단일 테이블 시나리오 보완* 입니다.

**표준 답변** (40 초)
> Exqutor 원논문 Table 1 의 보고: pgvector 의 카디널리티 추정 정확도 (Q-error mean) 는 시나리오에 따라 100 ~ 10000 배, VBASE 는 50 ~ 5000 배, DuckDB 는 항상 100 % 추정으로 1 ~ 1000 배의 Q-error. Exqutor 의 ECQO 는 인덱스가 있을 때 Q-error ≈ 1 (정확값) 로 근접하고, Adaptive Sampling 은 multi-table 에서 Q-error 1 ~ 3 수준. 본 연구의 KM20 은 *Exqutor Adaptive 의 단일 테이블 사각지대 보완* 으로, BERNOULLI baseline 의 Q-error 1.04 ~ 8.93 영역에서 stratification 으로 1 ~ 9 % 추가 개선. 즉 본 연구의 위치는 *시스템 비교의 새 차원* 이 아니라 *Exqutor 위의 layered 보완* 입니다.

### Q15.4 본 연구가 *기존 stratified sampling 연구* 와 어떻게 다른가요?

**핵심 한 줄**: Survey sampling 과 SQL 카디널리티 추정에서 stratified sampling 은 표준이지만, *벡터 거리 조건* 에 적용된 사례는 매우 적고, *분포 인지 (KM20) vs 무인지 (RANDOM20) 의 직교 분리 측정* 도 본 연구의 새로운 framework 입니다.

**표준 답변** (45 초)
> Stratified sampling 자체는 Cochran (1977) 이래 survey sampling 의 표준이고, SQL 카디널리티 추정에서도 stratified histogram (Poosala et al. 1996) 같은 형태로 적용됩니다. 그러나 *벡터 거리 조건의 카디널리티 추정* 에 stratified sampling 을 적용한 사례는 매우 적습니다. 본 연구의 *새로움* 은 (1) k-means K=20 의 거리 기반 분할을 stratum 으로 직접 사용, (2) RANDOM20 control 로 Level 1 (proportional allocation) 과 Level 2 (spatial awareness) 의 직교 분리, (3) cross-dataset 의 cluster skewness 와 효과 격차의 단조 관계 입증입니다. 이 framework 가 RQ3 의 distribution-agnostic 방법 비교의 evaluation metric (Recovery Rate) 의 기초가 되며, 다른 cardinality estimation 연구로 확장 가능합니다.

---

### Q15.5 *Histogram-based estimator* (PostgreSQL ANALYZE, multi-column histograms) 와 비교는?

**핵심 한 줄**: PostgreSQL ANALYZE 의 histogram 은 *single-column* 의 *equality / range* 술어에 최적화되어 있고, 96 ~ 128 차원 벡터의 *거리 기반* 술어에는 직접 적용되지 않습니다. Multi-dimensional histogram 은 차원의 저주로 1M+ 데이터에 비현실적입니다.

**표준 답변** (40 초)
> PostgreSQL ANALYZE 가 만드는 histogram 은 single-column 의 equi-depth 또는 equi-width buckets 으로, equality / range 술어에는 좋은 정확도를 냅니다. 그러나 vector 거리 조건 `WHERE (v <-> q) < D` 는 *96 차원의 모든 차원의 비선형 함수* 라 single-column histogram 으로 표현 불가능합니다. Multi-dimensional histogram 은 K^d 셀로 차원의 저주가 일어나 96d 에서는 비현실적이고, 차원 축소 후 histogram 은 RQ3 의 C (Random Projection) 또는 E (Hilbert curve) 와 본질적으로 같은 형태가 됩니다. 즉 traditional histogram 은 vector cardinality estimation 에 직접 적용할 수 없고, *sampling-based* (Exqutor) 또는 *learned* (LearnedCard) 두 패러다임이 주류가 됩니다.

# 섹터 16. 일반화 가능성 (Generalizability)

> *다른 임베딩, 다른 거리 metric, 다른 인덱스, 다른 DB 로의 확장 가능성.*

### Q16.1 다른 *임베딩 모델* (BERT, CLIP, ResNet) 에서도 KM20 효과가 같을까요?

**핵심 한 줄**: KM20 의 효과는 *데이터의 cluster skewness* 에 의존하는데, 임베딩 모델별로 representation 의 isotropic 정도가 다르므로 효과 크기는 변동 가능합니다. SIFT 와 DEEP 의 격차 (CV 0.394 vs 0.234) 가 그 변동의 *one example* 입니다.

**표준 답변** (45 초)
> 본 연구의 *underlying mechanism* 은 cluster skewness → spatial awareness 효과 의 단조 관계입니다. 임베딩 모델이 어떻든 *그 모델의 representation 이 isotropic 인가* 가 핵심이고, 이는 모델 학습 방식 (contrastive loss, cross-entropy, supervised) 에 따라 다릅니다. ResNet feature 는 일반적으로 isotropic 에 가깝고 (DEEP 와 비슷한 CV 0.2 ~ 0.3), CLIP 은 contrastive 학습으로 anisotropic 한 경향 (CV 0.4 ~ 0.6 추정), BERT 는 sentence embedding 의 *anisotropic problem* 으로 알려져 있어 (Ethayarajh 2019) 더 큰 cluster skewness 가능. 따라서 KM20 효과는 *모델별로 변동* 하지만 *방향은 일관* (skewed → 큰 효과) 할 것이라는 hypothesis 가 본 연구의 자연스러운 generalization 입니다. wiki 768d (text embedding) 측정이 W5-W7 에 포함되어 이 hypothesis 의 1 차 검증을 시도합니다.

---

### Q16.2 다른 *거리 metric* (cosine, inner product) 에서도 KM20 동작하나요?

**핵심 한 줄**: 본 연구는 L2 (Euclidean) 거리 기반 range query 만 측정했고, cosine / inner product 도 같은 *cluster skewness 메커니즘* 이 적용될 것으로 예상하지만, 실측 검증은 후속 연구의 영역입니다.

**표준 답변** (40 초)
> 본 연구의 측정은 L2 거리 기반 `WHERE (v <-> q) < D` 의 range query 입니다. Cosine 거리는 unit vector 정규화 후 L2 와 *수학적으로 동등* 하므로 같은 메커니즘이 적용될 것으로 예상하고, inner product 는 vector norm 분포에 의존하므로 *추가 보정* 이 필요할 수 있습니다. k-means clustering 은 L2 기반이라 cosine / IP 데이터에서 직접 사용하려면 (1) cosine 의 경우 unit normalization 후 사용, (2) IP 의 경우 추가 보정 후 또는 다른 분할 알고리즘 사용. 후속 연구에서 *metric-agnostic stratification* 의 framework 로 확장 가능합니다.

---

### Q16.3 *HNSW 인덱스* 가 있을 때는 어떻게 동작하나요? Exqutor 의 ECQO 와 충돌하지 않나요?

**핵심 한 줄**: 본 연구는 의도적으로 HNSW 인덱스를 *제외* 한 환경에서 측정했습니다 — sampling 경로를 강제하기 위함입니다. 인덱스가 있을 때는 Exqutor ECQO 가 정확값 (Q-error ≈ 1) 을 주므로 stratified sampling 의 추가 효과가 미미할 것으로 예상합니다.

**표준 답변** (40 초)
> 본 연구의 측정 환경은 *HNSW 인덱스 없는 단일 테이블* 입니다. 인덱스가 있으면 ECQO 가 plan 단계에서 정확한 카디널리티 (Q-error ≈ 1) 를 주므로 stratified sampling 의 layered 보완은 *불필요* 합니다. 본 연구의 가치는 *인덱스가 없거나 stale 한 환경* 에서 발현되며, 이는 (a) 데이터 적재 직후, (b) 동적 INSERT 가 빈번한 환경, (c) 인덱스 빌드 비용을 감당하기 어려운 시나리오에 해당합니다. 즉 ECQO (인덱스 있을 때) + Stratified Sampling (인덱스 없을 때) 의 *2 layer fallback 구조* 가 본 연구의 자연스러운 positioning 이며, 두 mechanism 은 *서로 충돌하지 않고 보완적* 입니다.

---

### Q16.4 다른 *벡터 DB* (Milvus, Pinecone, Weaviate) 에 적용 가능한가요?

**핵심 한 줄**: 본 연구의 *KM20 stratified sampling* 은 PostgreSQL extension 위에 구현되었지만, *underlying mechanism (Horvitz-Thompson estimator on k-means strata)* 은 system-agnostic 이며, 다른 벡터 DB 에 이식 가능합니다. 다만 각 DB 의 sampling API 와 plan optimizer 통합은 별도 구현이 필요합니다.

**표준 답변** (40 초)
> 본 연구의 mechanism — k-means 분할 + 비례 배분 + Horvitz-Thompson estimator — 는 system-agnostic 입니다. Milvus 는 IVF 인덱스를 internal partition 으로 사용하므로 IVF 의 cluster 를 stratum 으로 재해석하면 자연스러운 적용이 가능하고, Pinecone 의 namespace 도 비슷한 partition 으로 이용 가능합니다. Weaviate 는 HNSW 만 지원하므로 stratified sampling 의 적용 범위가 *인덱스 없는 fallback path* 로 한정됩니다. 즉 *각 시스템의 sampling API 와 plan optimizer 통합* 은 별도 엔지니어링이지만, mechanism 자체의 일반화는 가능합니다. 후속 연구로 *multi-system stratification framework* 가 자연스러운 확장입니다.

---

### Q16.5 *고차원 (1024 차원, 4096 차원)* 에서도 동작하나요?

**핵심 한 줄**: k-means 의 차원 효과로 학습 안정성이 떨어지지만, mini-batch k-means 의 결정론적 학습 + 768d wiki 보충 실험에서 일관된 효과가 확인되면 high-dimensional generalization 의 1 차 evidence 가 됩니다.

**표준 답변** (40 초)
> k-means 는 *차원의 저주* 로 고차원에서 cluster 경계가 흐려지지만, mini-batch k-means + n_iter=100 의 결정론적 학습은 96 / 128 차원에서 안정적입니다. 768 차원 wiki 데이터셋이 W5-W7 보충 실험에 포함되며, 768d 에서도 KM20 효과가 양수 + cluster skewness 와 단조 관계 라면 *high-dimensional generalization* 의 1 차 증거가 됩니다. 1024 차원, 4096 차원 같은 더 높은 차원은 후속 연구의 영역이며, 이때는 *차원 축소 후 stratification* (RQ3 의 C — Random Projection 의 변형) 이 더 자연스러울 수 있습니다.

**표준 답변** (45 초)
> 5 갈래 후속 연구. (1) *Multi-system*: 본 연구의 KM20 + Recovery Rate framework 를 Milvus, Pinecone, Weaviate 같은 다른 벡터 DB 에 이식해 *system-agnostic stratification* 을 구성. (2) *Multi-modality*: text embedding (BERT, sentence-BERT), audio (wav2vec), multimodal (CLIP) 의 cluster skewness 와 stratification 효과의 일반화. (3) *Dynamic data*: INSERT/UPDATE 가 빈번한 환경에서 stratum_id 의 incremental update 와 centroid drift 처리. (4) *End-to-end*: Q-error 의 plan 변경 영향 → 실행 시간 단축의 직접 측정. (5) *Hybrid*: learning-based estimator (LearnedCard, MSCN) 와 sampling-based (KM20) 의 ensemble 또는 hierarchical hybrid. 본 연구의 framework 가 *5 갈래 모두의 anchor* 가 됩니다.

# 부록 B — 명사답변 (어려운 질문 25 종, 각 1 ~ 2 문장)

> *심사위원이 작정하고 추궁할 때. 자신감 + 솔직성 균형. 답변 후 *질문자에게 다시 공* 을 넘기지 않음.*

### B1. "Q-error 1.04 가 1.05 가 되는 게 정말 plan 을 바꾸나요? 임계점을 직접 측정한 적 있나요?"

> "Plan 변경 임계점은 옵티마이저의 cost model 에 의존하며, 본 보고서 시점에서는 직접 측정하지 못했습니다. W6 의 EXPLAIN ANALYZE 보충 분석에서 *plan 변경 빈도* 를 직접 측정해 임계점 근처 쿼리의 비율을 정량화할 예정이고, 본 시점의 1 % 정확도 개선이 *옵티마이저의 표준 메커니즘으로 plan 변경 확률을 줄인다* 는 conservative claim 까지가 본 연구의 한계입니다."

### B2. "Phase 7 artifact 를 자체 발견한 게 자랑이 아니라 *그런 artifact 를 처음에 만든* 게 문제 아닌가요?"

> "정확한 지적이십니다. Plan tree parsing 의 metric 선택 (plan_rows vs hook_est) 자체가 *측정 도구의 선택 오류* 였고, hook_est 가 authoritative 임은 Phase 6 Step 4 에서 명시되었어야 했습니다. 자체 검증으로 24 시간 내 발견·철회·redo 한 점을 *학술 정직성* 으로 framing 했지만, 처음부터 metric 을 명확히 했어야 함을 인정합니다. 후속 측정에서는 *metric pre-registration* 을 표준 절차로 도입했습니다."

### B3. "RANDOM20 의 *random seed* 가 결과에 큰 영향 미치지 않나요? 5 seed 가 너무 작은 것 아닌가요?"

> "RANDOM20 의 sample 추출 seed 는 5 개 (0.1 ~ 0.5) 고정이고, RANDOM20 의 *partition assignment* 자체는 random_seed_sql = 0.42 의 SQL random 으로 1 회 결정됩니다. 즉 partition 자체는 한 번 정해진 결과이고, 5 seed 는 sample 추출의 변동만 측정합니다. *partition 자체의 random 변동* 은 다른 seed (0.1, 0.5, 0.9) 로 partition 을 재생성해 측정하는 별도 실험이 W5 보충에 포함됩니다."

### B4. "RQ3 의 7 방법 중 *D (Exqutor Hybrid) 를 제외한 결정* 이 본 연구의 정당성을 약화시키지 않나요? 가장 자연스러운 baseline 인데?"

> "D 가 자연스러운 baseline 이라는 점은 동의하지만, 4 가지 issue (SIGSEGV, negative finding, RQ3 취지 불일치, 6주 비현실적) 를 누적 평가했을 때 제외가 정당합니다. RQ3 의 취지가 *새로운 distribution-agnostic 방법론 제안* 이므로 *Exqutor Adaptive 의 버그 수정* 은 다른 연구 (Adaptive Sampling sanitization) 의 영역입니다. D 는 후속 연구로 분리하는 것이 더 깨끗한 framing 입니다."

### B5. "본 연구가 *Exqutor 원논문에 배경* 으로 너무 의존하지 않나요? 독립적 기여가 있나요?"

> "정확한 지적이십니다. 본 연구는 Exqutor 의 *layered extension* 형태로 design intent 를 깨지 않고 사각지대를 메웁니다. 독립적 기여는 (1) 단일 테이블 사각지대의 발견 + 5 design constraint 정량화, (2) Two-Level decomposition framework, (3) cluster skewness vs effect 의 cross-dataset 단조 관계 입증, (4) RQ3 의 distribution-agnostic 7 방법 체계적 비교 framework + Recovery Rate metric. 이 4 가지가 Exqutor 원논문에 *없는* 기여입니다."

### B6. "K-means 의 *seed 의존성* 은 어떻게 통제했나요? seed=42 로 fix 한 것이 결과에 영향 없나요?"

> "K-means 학습 seed = 42 fix 의 영향은 *partition 자체의 결정론적 재현 가능성* 이고, 다른 seed 에서 partition 이 달라지면 KM20 효과도 변동 가능합니다. 다른 k-means seed (1, 7, 42, 100, 1000) 에서의 partition 변동 측정은 W5 보충 실험에 포함되며, 본 연구의 결론은 *seed=42 partition baseline 에서의 효과* 로 conservative 하게 한정됩니다. 다행히 mini-batch k-means 의 inertia (0.692) 가 stable convergence 를 시사해 partition 자체의 robustness 는 확보되어 있습니다."

### B7. "본 연구의 *통계적 유의성과 실용적 의미* 의 gap 이 너무 크지 않나요?"

> "Cohen 의 effect size 가이드라인에서 본 연구의 *9.6 % Q-error 개선* 은 small-to-medium effect 입니다. 그러나 옵티마이저의 plan 선택은 *임계점 근처에서 categorical change* 를 일으키고, plan 한 번의 잘못이 1 만 배 실행 시간 차이를 만드는 환경에서 small effect 도 macro-level 영향이 큽니다. *통계 vs 실용* 의 gap 은 옵티마이저 메커니즘이 메우며, end-to-end query time 직접 측정 (W6 보충) 으로 이를 정량화할 예정입니다."

### B8. "Phase 7 의 redo 측정 자체가 *cherry-picked D_target* 으로 만든 것 아닌가요?"

> "정확한 우려이십니다. D_target 재계산은 *모든 query 에서 actual selectivity ≈ 0.5 가 되도록 binary search* 한 결과이고, 이는 *측정 조건의 일관성* 을 위한 표준 절차입니다. cherry-picking 의심을 차단하기 위해 D_target 재계산 절차와 결과 (per-query D_target + actual_sel) 가 phase7_8m_dtarget_recalc_clean.json 에 100 query 모두 보존되어 있고, reviewer 가 직접 검증 가능합니다."

### B9. "*5-seed t-based CI* 가 small sample 의 *t-distribution conservatism* 으로 너무 wide 하지 않나요? bootstrap 이 더 정확하지 않나요?"

> "n=5 의 t(4) = 2.776 이 t-based CI 의 conservatism 을 만드는 것은 맞고, percentile bootstrap CI 가 더 narrow 한 경우가 있습니다. 두 방식 모두 valid 하며, 본 보고서는 *conservative t-based* 를 채택해 *효과의 lower bound* 를 강조합니다. 최종 보고서에서는 두 방식 모두 표기해 reviewer 의 직접 비교를 가능하게 할 예정입니다."

### B10. "본 연구의 *generalization* 이 너무 narrow 하지 않나요? 단일 테이블 + L2 거리 + range query 만?"

> "정확한 한계 인정입니다. 본 연구의 conservative claim 은 *단일 테이블 + L2 거리 + range query + DEEP-SIFT-style image embedding 의 cardinality estimation* 에서 stratified sampling 의 효과가 cluster skewness 와 단조 관계 까지입니다. (1) Multi-table → join cardinality, (2) cosine / IP → metric-agnostic, (3) top-k → range 가 아닌 ordering, (4) text / audio embedding → modality 일반화 는 모두 후속 연구의 영역으로 명시됩니다."

### B11. "*Sample_size = 385 fixed* 가 모든 selectivity 와 데이터 규모에서 valid 한가요?"

> "385 는 95 % CI ±5 % 마진의 binomial proportion estimation 기준의 conservative 값입니다. small selectivity (s ≤ 0.01) + large data (8M) 영역에서는 sample 안 hit 수가 0 ~ 1 같은 작은 정수로 양자화되어 *분해능 한계* 가 발현됩니다 (anomaly_analysis.md §Anomaly 2). Sample_size sensitivity (385, 770, 1540) 의 sweep 은 W5 보충 실험에 포함됩니다."

### B12. "*HHI / CV* 외에 다른 skewness 지표 (Gini, Theil, Atkinson) 도 측정해야 하지 않나요?"

> "HHI 와 CV 가 *위쪽 꼬리* (HHI) 와 *전체 변동* (CV) 의 직교 차원을 잡으므로 1 차 anchor 로 충분합니다. Gini coefficient 와 Theil index 는 income inequality 분야의 표준이며 cluster size 분포에도 적용 가능. Gini 는 본 연구의 RANDOM20 control 에서 km20_gini = 0.1275 / rand_gini = 0.0027 의 보조 지표로 측정되어 있고, 추가 지표 보고는 RQ3 의 보충 분석에 포함될 예정입니다."

### B13. "*8 지표 무상관* finding 이 너무 약한 결론 아닌가요? 다른 feature 도 시도해야 하지 않나요?"

> "8 지표 (글로벌 4 + 로컬 4) 가 *분포 쏠림 측정의 4 패러다임 × 2 스코프* 의 직교 공간을 cover 하므로 *전수 부재* 라는 강한 결론이 가능합니다. 다른 feature (semantic feature, query log statistics) 는 *분포 쏠림이 아닌 다른 차원* 의 시도이며, 본 연구의 결론은 *분포 쏠림 휴리스틱의 사전 식별 불가능성* 으로 한정됩니다. 다른 feature 의 효과는 후속 연구 (학습 기반 estimator) 의 영역입니다."

### B14. "본 연구의 *코드가 공개* 되어 있나요? 외부 검증 가능한가요?"

> "네, GitHub (`https://github.com/johyunbin/Capstone`) 에 모든 측정 스크립트와 결과 raw data, 보고서·발표 자료가 공개되어 있습니다. Exqutor source 의 변경분도 백업 파일과 함께 보존되어 있으며, README 에 빌드 절차와 측정 명령이 정리되어 있습니다. 외부 검증자가 동일 환경 재현 가능합니다."

### B15. "*Cluster 1 + Cluster 18 dominance (SIFT)* 가 *데이터 자체의 특성* 인지 *k-means seed=42 의 artifact* 인지 어떻게 구분하나요?"

> "정확한 지적이십니다. seed=42 fix 의 partition artifact 가능성을 통제하려면 다른 seed 의 partition 결과를 비교해야 하고, 이는 W5 보충 실험에 포함됩니다. SIFT 자체의 cluster skewness 는 *임의의 partition seed 에서 일관되게* 더 큰 CV 를 보일 것으로 예상되며, 1 ~ 2 seed 추가 측정으로 robustness 검증 예정입니다."

### B16. "*Two-Level decomposition* 이 *Cochran 1977 의 분산 분해* 와 어떻게 다른가요?"

> "Cochran 의 분산 분해는 *within-stratum variance* 의 weighted sum 으로 stratified sampling 의 분산을 표현하는 *이론적 분해* 입니다. 본 연구의 Two-Level 은 그 이론을 *empirical RANDOM20 control* 로 측정 가능하게 specialize 한 것입니다. 즉 이론은 same, *측정 framework 의 새로움* 이 본 연구의 기여이며, RANDOM20 partition 으로 *spatial-awareness-free baseline* 을 직접 잡은 점이 핵심입니다."

### B17. "본 연구가 *재현 가능* 하다고 했는데, *random seed 외 다른 nondeterminism* 은 통제했나요?"

> "(1) k-means batch_size, n_iter, seed 모두 명시. (2) sample 추출 seed 5 개 fix. (3) PostgreSQL 의 query plan random 을 위한 GUC `random_page_cost`, `cpu_tuple_cost` 등은 default 사용 + 측정 환경 명세에 기록. (4) 측정 환경 (PG 16.9, pgvector 0.7.1, OS, hardware) 모두 명세. nondeterminism 의 *모든 원천* 을 통제하기는 어렵지만 (BLAS lib, CPU instruction, OS scheduler), random seed 통제로 1 차 재현 가능성은 확보되어 있습니다."

### B18. "*다른 distribution-agnostic 방법* (Locality-Sensitive Hashing, Bloom filter) 과 비교는?"

> "LSH (A) 가 RQ3 의 7 방법에 포함되어 있고 5 월에 측정합니다. Bloom filter 는 set membership testing 도구로 *cardinality estimation* 에 직접 적용되지 않아 RQ3 범위 밖입니다. HyperLogLog (Flajolet et al. 2007) 는 distinct count estimation 의 표준이고, vector range query 에는 적용 어렵습니다. 비교 대상의 선정 기준 (4 평가 축) 이 RQ3 설계안 §X 에 명시되어 있습니다."

### B19. "*Hilbert curve (E)* 가 96 차원에서 동작 안 할 가능성은? Negative finding 이라도 학술 가치 있나요?"

> "Hilbert curve 의 locality preservation 이 96 / 128 차원에서 약화될 수 있다는 caveat 는 RQ3 설계안에 명시되어 있습니다. Negative finding 이라도 *공간 DB 30 년 standard 가 vector range query 에 적용 안 되는 영역* 의 정량화는 학술 가치가 있고, 본 연구가 negative finding 도 *학술 기여* 로 framing 합니다."

### B20. "*Sample_size sensitivity* 가 측정 안 됐는데, 본 연구의 결론이 *sample_size = 385 의 corner case* 일 가능성은?"

> "정확한 우려입니다. Sample_size sensitivity (385, 770, 1540, 3080) 측정은 W5 보충 실험에 포함되며, 본 연구의 결론이 *sample_size = 385 baseline 에서* 의 효과 로 conservative 하게 한정됩니다. 다른 sample_size 에서 효과 크기 / 방향이 어떻게 변하는지가 RQ3 보충 분석의 핵심 질문 중 하나입니다."

### B21. "본 연구가 *deep learning 기반 estimator* 와의 *fundamental gap* 을 메우려는 시도인가요?"

> "본 연구는 *sampling-based estimator 의 framework 내 개선* 이고, learning-based estimator 와는 *직교적 패러다임* 입니다. 두 패러다임의 hybrid (예: learned stratification + sampled estimation) 는 후속 연구의 자연스러운 확장이며, 본 연구의 framework 가 learning-based 와의 fair comparison 의 anchor 가 될 수 있습니다."

### B22. "*Hook 의 plan replacement 부작용* 이 *원논문에 명시* 되지 않은 이유는 *Exqutor 가 의도적으로 단일 테이블을 제외* 한 것 아닌가요?"

> "정확한 추론입니다. Exqutor 의 design intent 가 *multi-table join 의 base table cardinality 보정* 이고, 단일 테이블은 *intentional exclusion* 으로 보입니다. 다만 *원논문 본문에 명시되지 않은 점* 이 본 연구의 빈자리이며, 단일 테이블이 실무 응용의 핵심 형태라는 점에서 *명시되지 않은 사각지대를 메우는 학술 가치* 가 있습니다."

### B23. "*Exqutor 원논문* 의 1 만 배 격차가 *최악의 시나리오 cherry-pick* 일 가능성은?"

> "Exqutor 원논문 Table 1 은 시나리오별 분포의 *최대값* 을 보고하므로, 1 만 배는 *상한이 아닌 가능한 최대값* 입니다. 평균은 더 작을 수 있고, 본 연구가 *Exqutor 원논문의 가능한 최대값 시나리오* 에 의존하지는 않습니다. 본 연구의 정량 결과 (9.6 % + 1.6 ~ 4.4 %) 는 Exqutor 원논문과 독립적인 *우리 환경의 직접 측정* 이며, 1 만 배 격차는 *plan 변경의 macro-level 영향 framing* 으로만 인용됩니다."

### B24. "*RQ3 가 5 월에 7 방법 모두 측정* 되지 못하면 어떻게 되나요?"

> "RQ3 의 priority 는 (1) Offline Partition 4 (C/A/E/F) → (2) Online + Weight 3 (G/B/H) → (3) H 의 2×2 factorial 의 순서이고, 시간 부족 시 Offline 4 만으로도 *체계적 비교* 의 1 차 결론 가능합니다. Online + Weight 는 W7 후반 또는 후속 연구로 분리. F (MiniBatch) 의 learning_fraction sweep 이 *cost-effect ratio* 의 핵심 finding 이므로 우선순위 1 위로 보장됩니다."

### B25. "본 연구가 *졸업 논문* 으로 충분한가요?"

> "본 연구의 학술적 기여 (사각지대 발견 + 직교 측정 + 인과 입증 + RQ3 framework) 는 학부 캡스톤의 expected level 을 상회한다고 자평합니다. 다만 reviewer 의 평가는 별도이며, 본 보고서·발표 자료가 *체계성 + 정직성 + 정량성* 을 모두 갖추도록 4 차에 걸친 ultrareview (4/19, 4/27, …) 로 보강했습니다. 졸업 자격 충족 여부는 caveat 으로 남겨둡니다."

(2) Design constraint 5 종은 *Exqutor design intent 의 systematic 분석* 으로 학술 가치. (3) Phase 7 artifact 자체 정정은 *학술 정직성의 본보기*. 즉 negative finding 들이 본 연구의 *체계성* 을 강화하며, positive finding (9.6 % + 1.6~4.4 %) 과 *상호 보완* 합니다. # 부록 F — KILLER QUESTIONS (발표자 반드시 외워야 할 5 개 답변)

> *4/27 22:00 Opus 4 개 병렬 ultrareview 결과 식별된 *답변 못 하면 발표 신뢰도 흔들리는* 5 개 질문. 발표자가 이 답변을 외워서 자신감 톤으로 답하면 최악의 경우 대비 완성. 본문 어떤 다른 답변보다도 *우선* 외워야 한다.*

### KQ1. "9.6 % 가 *베르누이의 단위 변경 효과* 가 아니라 *expected sample size variance 효과* 일 가능성은? Sample_size 일치 통제 비교가 있나요?"

**위험도**: 매우 높음 (5/5). RQ2-1 의 핵심 mechanism claim 자체가 흔들리는 질문.

**최선 답변** (50 초)
> 정확한 지적이십니다. Sample_size = 385 GUC 로 *expected* sample size 는 동일하게 통제했지만, *실제* sample size 의 variance 는 두 추출 방식이 다릅니다. SYSTEM 은 8KB block 단위 추출이라 actual sample size 가 ±5 ~ 10 % 변동하고, BERNOULLI 는 row 단위 inclusion 이라 actual sample size 가 더 narrow 하게 변동합니다. 본 연구의 9.6 % 개선은 *actual sample size 의 variance 차이* 와 *block-internal row dependency* 두 효과의 confounded 결과로 해석되며, 두 효과의 분리는 *strict sample size matching* (예: TABLESAMPLE 후 randomly select N=385 rows) 의 추가 실험이 필요합니다. 이 분리 측정은 W5 보충 실험에 포함되며, 본 시점의 9.6 % claim 은 *SYSTEM-vs-BERNOULLI 의 두 mechanism combined effect* 까지로 conservative 하게 한정됩니다.

### KQ2. "100 개 query 가 어떻게 생성됐나요? Random vector 인가요? 데이터에서 sample 한 vector 인가요? 그 선정 자체에 selection bias 가 있다면 본 연구의 모든 결과가 흔들립니다."

**위험도**: 매우 높음 (5/5). 답변 못 하면 *실험 설계의 근본 결함* 노출.

**최선 답변** (40 초)
> 100 개 query 는 dataset 내부에서 *uniform random sampling* 으로 선정한 vector 입니다. 즉 query vector 자체가 dataset 의 underlying distribution 을 따르므로, *cluster 1 / cluster 18 같은 dominant cluster 의 query 가 expected proportion 으로 포함* 됩니다. 이는 *real-world workload* 와는 다를 수 있는데, 실제 검색에서는 *out-of-distribution query* 도 빈번합니다. Out-of-distribution query 의 cardinality estimation 은 본 연구 범위 밖이며 후속 연구의 영역입니다. Query selection 의 random_seed = 42 fix 와 100 개 query vector 의 raw 가 `query_pool.parquet` 에 보존되어 있어 외부 reviewer 가 직접 검증 가능합니다.

### KQ3. "Phase 7 artifact 자체 정정 사례를 *학술 정직성의 본보기* 로 framing 했는데, 그건 *처음부터 metric 을 잘못 선택* 한 것이지 *학술 정직성* 이 아닙니다. plan_rows 가 estimator 출력이 아닌 LIMIT 상수임을 *측정 시작 전* 검증했어야 합니다. 본 연구의 *측정 도구 검증* 자체가 부실했다는 증거 아닌가요?"

**위험도**: 매우 높음 (5/5). 학술 정직성 framing 자체가 약점이 됨. **Q10.7 본문 답변보다 이 답변을 우선 사용**.

**최선 답변** (45 초)
> 정확하게 인정합니다.
