## §1. 우리 연구의 큰 그림 — 왜 이걸 하고 있나

### 1-1. 출발점: Exqutor 논문의 빈 공간

본 연구의 모든 출발점은 Exqutor 논문 (BDAI-Research, arXiv:2512.09695v2) 이다. 이 논문은 한 줄로 말하면 "벡터 + 분석 쿼리에서 카디널리티 (cardinality, 결과 row 의 개수) 를 정확히 추정해서, 데이터베이스가 더 좋은 실행 계획을 세우게 하자" 이다.

기존 시스템들은 카디널리티를 매우 단순하게 추정한다.

| 시스템 | 추정 방식 | 한계 |
|---|---|---|
| pgvector | 고정 33.3% 가정 | 작은 sel 에 매우 부정확 |
| VBASE | 고정 50% 가정 | 마찬가지 |
| DuckDB | 100% (전체 스캔) | 비효율 (작은 sel 일 때 낭비) |

Exqutor 는 이 문제를 두 가지 방식으로 해결한다.

1. **ECQO (Extended Cost-based Query Optimizer)**: 인덱스 (HNSW) 가 있을 때, range query (거리 r 이하의 점 개수) 를 직접 실행해 1~2 ms 안에 정확한 카디널리티를 얻는 방법.
2. **Adaptive Sampling**: 인덱스가 없을 때, 동적으로 sample size 를 늘려가며 추정값이 "수렴" 할 때까지 sampling 하는 방법 (momentum 기반).

여기서 우리가 노린 빈 공간은 **Adaptive Sampling 의 *전 단계*** 이다. Adaptive Sampling 은 "얼마나 많이 sample 할까" 를 동적으로 정하지만, "어떻게 sample 을 분배할까" (proportional vs Neyman vs distribution-aware) 는 다루지 않는다. 그리고 Exqutor 의 momentum 방식은 분포가 한쪽으로 치우친 데이터 (skewed distribution) 에서 **정확도가 떨어진다**. 이 두 빈틈이 우리의 연구 영역이다.

### 1-2. 비유: 카디널리티 추정 = "전체 인구 중 몇 명이 키 180 이상일까"

비유로 풀면 이해가 쉽다. 우리가 한 도시 (table = 800만 명) 에서 "키 180 이상인 사람의 비율" 을 알고 싶다고 하자.

- **pgvector 방식**: "33% 일 거야" 그냥 가정 → 틀릴 가능성 높음.
- **DuckDB 방식**: 800만 명 전부 키 재 봄 → 정확하지만 너무 오래 걸림.
- **Random sampling (BERN 베이스라인)**: 무작위 1만 명 뽑아 평균 → 운에 따라 ±5%p 부정확.
- **분포 정보 활용 (KM20 등 우리 method)**: 도시를 동네 (cluster) 로 나누고 각 동네에서 균형 있게 sample → 정확도 ↑.

이 마지막 단계의 가치를 정량화하는 것이 우리의 연구 contribution 이다.

### 1-3. 우리의 핵심 contribution 여섯 가지 (5/9 morning update — 5 paradigm + Adaptive 추가)

본 연구가 새로 발견한 것 (5/9 morning 시점 W4 + W5 sprint 결과 기준):

1. **분포 정보 활용 sampling 의 정량 가치 입증** — random 대비 최대 −32% 정확도 개선 (SIFT_sf1).
2. **Selectivity Gradient** — sel 이 작을수록 random 의 부정확이 단조 증가 (5 dataset 100% 부호 일관).
3. **5 paradigm × 11 method framework + 4강 distinct representative** (5/8 22:00 finalize) — 5 inductive bias paradigm (P1 Density Cluster / P2 Spatial Locality / P3 Online Streaming / P4 Linear Projection / P5 Quasi-random) 의 distinct representative 4 종 = HDBSCAN(P1) / MB_partial(P3) / Hilbert(P2) / **sparse RP(P4)** 가 4강. *기존 4강 = Hilbert / Hybrid / MB_partial / HDBSCAN 의 Hybrid → sparse RP 교체* (5 paradigm coverage + 산업 친화 anchor).
4. **Recovery Rate Framework** — "분포를 모를 때, 우리 method 가 oracle (KM20) 의 몇 %를 회복하는가" 평가 틀.
5. **(5/7 발견) SSN++ ceiling 효과** — 우리 method 가 *적용되지 않는* 영역 (well-spread + balanced distribution) 의 정량 boundary.
6. **(5/8~5/9 NEW) Exqutor Adaptive Sampling 본 논문 직접 비교** — 단일 10 cell paired Wilcoxon **Outcome A + B 혼합** (★1~★3 우위 / ★4 동등), Multi 6 cell **Outcome C dominant + 부분 D** (단일 우위가 multi 환경에서 통계 보정 어느 기준에서도 불성립) — 분포 정보 marginal value 의 단일 한정 정량 입증 + multi 환경 약화 정량 확인 (24.5× shrinkage chain).

마지막 다섯 번째 (SSN++ ceiling) + 여섯 번째 (Adaptive 비교) 가 가장 큰 honest reporting 의 핵심이다. "우리 method 가 만능이 아니다, 어디서 작동하는지 정량 boundary 까지 입증했다" 를 정량적으로 보여주는 것이 오히려 연구의 신뢰도를 높인다.

## §3. 4강 method 직관적 설명 — 비유로 이해하기 (production criteria 결정)

이번 섹션은 회의에서 method 이름이 나올 때 팀원이 즉각 "그게 뭐였더라?" 고민하지 않도록 비유로 풀었다. 5/8 11:40 가지치기 결과 confirm 후 4강은 **production criteria** (cell 별 1위 횟수 + cost 차별화 + interpretability) 기준 결정되었으며, 각 method 가 차별화된 narrative 역할을 담당한다.

### 3-1. ★2 Hilbert curve — "공간을 한 줄로 휘어서 펴는 곡선" (production sweet spot)

상상해보자. 8M 개의 점이 96차원 공간에 흩어져있다. 이걸 한 줄로 정렬해야 한다. 가장 단순한 방법은 첫 번째 좌표 기준 정렬이지만, 그러면 두 번째~세 번째 좌표는 무시된다.

**Hilbert curve** 는 공간을 휘어서 한 줄로 만드는 곡선이다. 핵심 성질: **공간상에서 가까운 점은 곡선 위에서도 가깝다**. 즉, 96차원 공간을 1차원 곡선으로 펼쳐도 "이웃 관계" 가 잘 보존된다.

이걸 sampling 에 활용하면, 곡선을 따라 균등 간격으로 sample 을 뽑으면 → 공간상에서도 잘 분산된 sample 이 된다. 이 균형이 분포 정보 활용의 본질이다.

**왜 4강 ★3 인가**: avg_Δ% -7.54, SIFT_sf1 -33.53% 강력 + YFCC_sf10 -5.21% (단일 100% 마지막 cell). 학습 비용이 거의 0 (Hilbert index 는 한 번 계산하면 끝, 수 초). **production 에서 가장 가벼운 method** — KM20 oracle 처럼 무거운 학습 없이도 oracle 의 효과 일부를 회복. CI 9/10 완벽 강력. 4강 역할 = **production sweet spot**.

### 3-2. ★4 sparse RP — "데이터 분포 *모르는* 채로 random matrix 곱해서 1차원 투영" (data-independent paradigm anchor) ⭐ 5/8 22:00 finalize

**5/8 22:00 결정**: 4강 ★4 가 기존 Hybrid 에서 **sparse Random Projection** (Achlioptas 2003 PODS) 으로 교체. 이유는 5 paradigm × 11 method framework 의 P4 (Linear Projection) anchor 로서 paradigm coverage 완성 + 산업 친화 (data-independent + 학습 cost 0) 가치.

상상해보자. 데이터 분포를 *전혀 모르는* 상태에서 high-dimensional vector (96d, 768d 등) 을 1차원으로 투영해야 한다. 가장 단순한 방법은 *무작위 행렬* 을 곱하는 것이다.

**sparse Random Projection** 은 다음과 같이 작동한다.
1. D-dim → 1-dim 투영 행렬 R (D × 1) 을 무작위 생성 — 각 element 는 {−√3, 0, +√3} 또는 {0, ±1/√D} 중 하나 (Achlioptas 2003 / Li et al. 2006 KDD variant). 0 이 압도적으로 많아 *희소* (sparse).
2. 모든 vector v 에 대해 v·R 의 1-dim 값 계산.
3. 그 1-dim 값을 quantile 으로 K stratum 분할 → BERN 보다 정보량 많은 stratification.

핵심 성질 (Johnson-Lindenstrauss lemma): 무작위 투영이라도 ε-error 안에서 distance 를 보존한다. 즉 분포를 *몰라도* 정보 손실 적게 1차원으로 압축 가능.

**왜 4강 ★4 인가** (5/8 22:00 finalize):
- avg_Δ% **−6.91** (4강 4위, 0.22%p 차이로 ★1~★3 와 동급 영역)
- 4강 中 **유일한 data-independent inductive bias** — P4 (Linear Projection) paradigm 의 representative anchor
- **학습 cost 0** (random matrix 한 번 sampling, sklearn `SparseRandomProjection` 호환)
- **Adaptive Sampling 본 논문과 통계적 동등** (single 10 cell paired Wilcoxon **0/10 sig** 동등) — 이는 단점이 아니라 학습-free production-friendly tier 에서의 paradigm coverage 가치 reframe
- 단일 sweet spot 에서는 ★1~★3 와 약간 차이, multi 환경에서는 4강 모두 BERN-equivalent 수준으로 수렴

4강 역할 = **data-independent paradigm anchor + 산업 친화 production sweet spot** (P4 Linear Projection coverage + ARI orthogonality #1 vs ★1~★3 cluster-based).

> **기존 ★4 Hybrid 의 위치**: 5/8 22:00 finalize 에서 ★4 후보 비교 결과 sparse RP 가 paradigm coverage 우위로 채택. Hybrid (KMeans + Hilbert) 는 ablation 차원의 mechanism narrative 보조 method 로 demote — 보고서 limitation/ablation 절에서 *clustering vs ordering* source 분리 ablation 으로 한정 사용.

### 3-3. ★3 MiniBatch_partial — "K-means 의 점진적 학습 버전 (OLTP friendly)" (OLTP narrative 유일)

K-means 의 표준 fit 은 전체 데이터를 메모리에 올린 뒤 한 번에 학습한다 (~30분 / 8M row). 이건 OLTP 환경 (트랜잭션이 계속 들어오는 운영 환경) 에서 부적합하다.

**MiniBatch_partial** (sklearn 의 `partial_fit`) 은 작은 batch 씩 점진적으로 학습한다. 새로운 row 가 들어와도 기존 모델 위에 *증분* 학습 가능. **production-ready** 하다는 의미가 이것.

**왜 4강 ★2 인가**: avg_Δ% -7.63, **CI excludes 0 in 9/10 cell 강력 일관**. 4강 中 **유일한 online learning method** — pre-computed cluster 없이 stream 으로 partial_fit 가능. 4강 역할 = **OLTP narrative 유일**.

### 3-4. ★1 HDBSCAN — "밀도 기반 클러스터링, 노이즈 자동 분리" (strongest narrative, oracle 영역)

K-means 와 달리 HDBSCAN 은 클러스터 개수 K 를 사전에 정하지 않는다. 대신 "밀도가 높은 영역 = 클러스터, 낮은 영역 = 노이즈" 로 자동 판별한다.

**왜 좋은가**: 데이터 분포가 균일하지 않을 때 (skew 가 심할 때) K-means 가 만든 동일 크기 클러스터보다 *자연스러운* 클러스터링이 가능.

**왜 4강 ★1 인가**: avg_Δ% **-8.04 (4강 중 가장 강력)** + 8/10 cell sign + 8/10 cell CI excludes 0 + SIFT_sf1 -34.17% / YFCC_sf1 -8.40% 1위. 단점: fit time 무거움 (~4313s) → **oracle 영역 (production X)** — KM20 oracle 과 동일 한계. 4강 역할 = **strongest narrative (가장 강한 magnitude + avg 1위)**.

## §5. SSN++ ceiling 효과 — 가장 중요한 honest finding

### 5-1. 직관적 비유

SSN++ 의 ceiling 효과는 비유로 풀면 명확하다.

> "이미 너무 잘 정리된 책장에는 더 정리할 여지가 없다."

SSN++ 데이터는 Facebook 의 SimSearchNet++ embedding 으로, 사전 훈련 + L2 normalization 으로 *이미* 균형 잡힌 분포를 가진다. 우리 method 가 분포 정보를 활용해 stratification 하려 해도, 이미 모든 stratum 이 거의 동일한 모양 → stratified vs random 이 거의 같음 → 오히려 method 의 학습 noise (cluster fitting 부정확) 때문에 **+1.4 ~ +2.3% 약간 hurt**.

### 5-2. 4 가지 정량 증거 (HIGH confidence)

이게 측정 bug 가 아닌 진짜 distribution 특성이라는 증거 4 가지:

**증거 1 — Vector norm CV (변동계수)**
```
DEEP    : 0.0000 (L2 normalized, 모든 norm = 1)
SIFT    : 0.0932 (norm 이 흩어져 있음)
SSN_sf1 : 0.0049 (norm 이 거의 동일, 1778.52 ± 8.78)
SSN_sf10: 0.0049 (sf1/sf10 동일)
```
SSN++ 의 norm CV 는 SIFT 의 1/19. 즉 모든 vector 가 거의 같은 sphere shell 위.

**증거 2 — Intrinsic dim ratio (PCA 90% 설명 dim / declared dim)**
```
DEEP_sf1 (96d) : 0.6771 (~65 dim 으로 90% 설명)
SIFT_sf1 (128d): 0.6406 (~82 dim 으로 90%)
SSN_sf1 (256d) : 0.8828 (~226 dim 으로 90%) ← 거의 모든 dim 사용
```
SSN++ 는 거의 모든 dim 이 의미 있는 정보를 운반 → near-isotropic, 어느 방향에서 봐도 비슷.

**증거 3 — KMeans (K=20) cluster size CV**
```
DEEP_sf1 : 0.2368 (max/min ratio = 2.97)
SIFT_sf1 : 0.3432 (4.67)
SSN_sf1  : 0.0551 (1.25) ← 모든 cluster 가 거의 동일 크기
```
KMeans 가 SSN++ 를 거의 동일 크기로만 자른다 → 분할의 차별 효과 = 0.

**증거 4 — BERN baseline 자체 q_error 가 이미 낮음**
```
sel=0.10 BERN q_error:
SSN_sf10: 1.1394 (8 cell 중 최저)
SSN_sf1 : 1.1401
DEEP_sf10: 1.1521
SIFT_sf1 : 1.7612 (가장 큼)
```
SSN++ 는 BERN 이 이미 충분히 정확. **KM20 oracle 이 BERN 대비 단 0.49% 만 개선 가능 (headroom 0.49%)** — 이는 SIFT_sf1 의 headroom 34.46% 의 1/70.

### 5-3. 의의 — 본 연구의 boundary 정의

SSN++ ceiling 의 발견은 본 연구의 *honest limitation* 으로 narrative 에 포함된다.

> "본 연구의 4강 method 는 모든 distribution 에서 universal improve 하지 않는다. cluster_size_ratio < 1.3 + intrinsic_dim_ratio > 0.85 영역 (예: SSN++) 에서는 BERN ceiling 으로 method 의 net Δ 가 +0~+2% hurt 으로 표시되는 것이 자연스럽다 — 본 연구 method 의 적용 boundary 를 정량 입증한 negative control."

회의에서 이 발견을 *약점이 아니라 contribution* 으로 frame 하는 것이 중요하다. "우리는 우리 method 가 *어디서* 작동하는지 정량 boundary 까지 입증했다" 는 narrative 가 5/27 발표의 신뢰도를 높인다.

### 5-4. 학술 confirmation — PDX (SIGMOD 2025) 의 동일 결론

본 SSN++ ceiling 가설은 우리만의 단독 결론이 아니다. SIGMOD 2025 (top-tier DB conference) 의 **PDX 논문** [Kuffo, Krippner, Boncz, CWI Amsterdam, *PDX: A Data Layout for Vector Similarity Search*, arXiv:2503.04422] 이 NYTimes/GloVe/SIFT/GIST/DEEP/MSong/Contriever/arXiv/OpenAI 등 10 benchmark dataset 에서 정확히 동일한 결론을 학술 confirmation 했다.

> PDX 핵심 결론 (Section 5):
> - "two types of value distributions — **normal vs skewed**"
> - "**normally distributed datasets are more challenging to prune than skewed datasets**"
> - "**intrinsic dimensionality and skewness metrics should govern algorithm selection** rather than fixed parameter tuning"

→ PDX 의 skewness + intrinsic_dim metric 과 본 연구의 cluster_ratio + intrinsic_dim_ratio metric 이 **정확 일치**. 즉 본 SSN++ ceiling 가설은 SIGMOD 2025 학술 robust 결론이며, 5/27 발표에서 "우리는 우리 method 가 어디서 작동하는지 정량 boundary 까지 입증했고, 이 boundary 는 SIGMOD 2025 PDX 와 일치한다" 라는 narrative 가 완성된다.

**비유**: PDX 논문 (SIGMOD 2025) 도 우리와 같은 결론 — 분포가 균형 잡힌 dataset 은 method 효과 약함. 즉 우리 SSN++ ceiling 가설은 학술 인정.

→ **complementary contribution**: PDX 는 vector similarity search 의 **compute** layer (data layout) 를 분포 인지로 최적화. 본 연구는 **pre-process** layer (sampling/clustering) 를 분포 인지로 최적화. 두 contribution 은 정확 complementary. 5/27 발표 future work 에 PDX 통합 (end-to-end skewness-aware pipeline) 명시.

## §8. 한계 (Limitation) 와 향후 작업 (Future Work)

본 연구의 honest limitation 9 가지. 회의 + 자문 메일 + 발표에서 정직 reporting 의 핵심.

### 8-1. KM20 oracle 의 production 적용성

**한계**: KM20 (K-means K=20) 은 *oracle baseline* 으로 학습 시간 ~30 분 (8M row 기준). production 환경에서 매 query 마다 학습 불가능.

**보완**: 4강 production-ready method (Hilbert / MiniBatch_partial / Hybrid / HDBSCAN) 가 KM20 oracle 의 70-100% 회복 (Recovery Rate). MiniBatch_partial 은 점진적 학습 가능 → OLTP friendly.

### 8-2. 사전 계산 one-time cost

**한계**: 4강 method 도 처음 한 번은 학습 필요 (예: MiniBatch K-means 의 K=20 cluster 학습, Hilbert curve index 계산). 이 cost 가 production 에 부담?

**보완**: one-time cost (한 번만, 결과 저장 가능). query time cost 는 수 ms. 분기 단위로 retrain 하면 충분.

### 8-3. OLTP 범위 외 (HNSW UPDATE 매우 느림)

**한계**: pgvector 의 HNSW index 는 INSERT/UPDATE/DELETE 가 매우 느림 (특히 UPDATE 가 ms 가 아닌 초 단위). 본 연구는 read-heavy + 정적 데이터 가정.

**향후 작업**: 동적 데이터 (실시간 업데이트) 환경에서 분포 정보 활용 sampling 의 효과 검증.

### 8-4. 단일 → 멀티 일반화 (5/9 02:20 multi 6 cell × 11 method finalize, sparse_rp 추가 후 24.5× shrinkage 재계산)
