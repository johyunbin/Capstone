## Slide 5 — Background: Exqutor의 두 갈래 (45s)

**메인 멘트**:
> "Exqutor는 두 가지 메커니즘을 제안합니다.
> 인덱스가 있을 때는 **ECQO** — HNSW range query로 1~2 밀리초 안에 정확한 카디널리티를 얻고,
> 인덱스가 없을 때는 **Adaptive Sampling** — 모멘텀 기반으로 표본 크기를 동적으로 조정합니다.
> 다만 인덱스가 없는 경로의 Adaptive Sampling은 **🎯 uniform sample 가정**에 기대고 있어, 분포가 강하게 쏠리면 보정 메커니즘이 작동하지 못합니다.
> ⏸ **본 연구는 바로 이 인덱스 없는 경로의 sampling을 다시 설계합니다**."

**압축 모드**:
> "Exqutor는 인덱스 있을 때(ECQO)와 없을 때(Adaptive Sampling) 두 갈래로 나뉘는데, 후자가 uniform sample 가정에 기대고 있어 skewed 분포에서 무력합니다. 본 연구는 이 경로를 다시 설계합니다."

**🎯 강조**: "본 연구는 ... 다시 설계합니다" — 톤 한 단계 올리기.
**👀 시선**: ECQO 설명 시 슬라이드 좌측 / AS 설명 시 우측 손가락 가리키기.

**⚠️ 실수 경고**:
- ECQO = Extended Cardinality Query Optimizer (확장된, 라기보다는 본 연구에서는 그냥 "ECQO" 약어로 부름. 혹시 풀네임 묻는 질문 시 주의)

## Slide 6 — Approach: 단계적 분해 (50s)

**메인 멘트**:
> "저희는 단순한 sampling rule 개선이 아닌, 기존 방식의 **두 가지 문제를 분리**해서 접근합니다.
> 하나는 **block-level sampling bias** — PostgreSQL 기본 표본이 페이지 단위라 행 간 독립성이 깨지는 문제이고,
> 다른 하나는 **spatial skew** — 벡터 공간에서 한쪽으로 쏠림이 발생하는 문제입니다.
> 각 문제에 대한 보정을 단계별로 적용합니다.
> 🎯 **SYSTEM** — block 단위 기본 표본 — 에서 출발해, **BERN** — 행 단위 Bernoulli sampling으로 block bias를 제거하고, **KM20** — k-means 20 클러스터로 spatial skew까지 반영합니다.
> 검증 도구는 **RANDOM20**과 **Two-Level 분해** — '안정화 효과'와 '공간 인식 효과'를 정량적으로 분리합니다."

**압축**:
> "두 가지 문제를 분리합니다. block bias를 BERN으로 제거하고, spatial skew를 KM20 stratified sampling으로 반영합니다. RANDOM20 비교와 Two-Level 분해로 효과를 분리 측정합니다."

**🎯 강조**: SYSTEM → BERN → KM20 화살표 따라가며 각 단계 명시.
**👀 시선**: 화살표 따라 슬라이드 좌→우 시선 이동.

**⚠️ 실수 경고**:
- SYSTEM (대문자, PostgreSQL TABLESAMPLE 함수명)
- BERN (대문자 약어, BERNOULLI 풀네임 가능)
- KM20 (k는 소문자, 20은 클러스터 수)

**확장**: "이 두 보정을 분리한 이유는, 어느 것이 진짜 효과의 원천인지를 측정하기 위해서입니다. 그냥 합쳐서 KM20만 적용하면 효과는 보이지만 '왜 효과가 났는지'를 모릅니다."

**🔁 전환**: "Experiments 섹션에서 이 분해를 정량적으로 보여드리겠습니다."

## Slide 7 — RQ1: Local Skew 검증 (45s)

**메인 멘트**:
> "RQ1에서는 **query 측에서 skewed 영역을 감지할 수 있는지**를 확인했습니다.
> Phase 5에서 **query-side local skew 지표 4가지 × selectivity 6 구간 — 총 24개 조합**을 분석했고,
> 결과는 — 🎯 **모든 24개 조합에서 Spearman 상관계수 절댓값이 0.2 미만**.
> 즉, query 정보만으로는 어떤 sampling layer를 적용할지 결정하기 어렵다는 결론입니다.
> ⏸ 따라서 **시스템 차원의 보정**이 필요합니다 — 이것이 RQ2와 RQ3의 직접적 동기입니다."

**압축**:
> "Query-side local skew 지표 4 × selectivity 6 = 24 조합 모두 \|ρ\| < 0.2. Query 정보만으로는 sampling layer 결정이 불가능하므로 시스템 차원의 보정이 필요합니다."

**🎯 강조**: "\|ρ\| < 0.2" — 천천히. "**모든** 24 조합" — 모든을 강세.

**👀 시선**: |ρ| < 0.2 말할 때 청중 정면.

**⚠️ 실수 경고**: Spearman 상관계수 (단순히 "상관계수"라고 부르면 Pearson이라 오해 가능).

**확장**: "여기서 local skew 지표 4가지란 query 벡터 주변의 (1) 평균 거리, (2) 거리 표준편차, (3) k-NN 거리, (4) 클러스터 중심까지의 거리입니다. 모두 query 시점에서 계산 가능한 metadata지만 결과 카디널리티와 약한 상관만 보였습니다."

**🔁 전환**: "그럼 시스템 측에서 어떤 보정이 효과적이었는지 — RQ2-1입니다."

## Slide 8 — RQ2-1: BERN vs SYSTEM (75s)

**메인 멘트**:
> "RQ2-1은 **첫 번째 보정 — block bias 제거**의 효과 측정입니다.
> 표를 보시면 selectivity 0.05부터 0.5까지 — 즉 중간 이상의 영역에서 — 🎯 **BERN이 SYSTEM보다 일관되게 낮은 Q-error**를 보입니다.
> 핵심 결과는 — ⏸ **selectivity 0.500에서 median Q-error가 1.153에서 1.052로 +9.6% 개선**, **100개 query 중 78개가 BERN 우위**, **p-value < 0.001**로 통계적으로도 매우 유의합니다.
> 한편 매우 낮은 selectivity 구간에서는 true cardinality가 작아 Q-error 자체가 크게 흔들리는데, 이는 RQ2-3 추가 분석에서 다룹니다."

**압축**:
> "BERN이 SYSTEM 대비 selectivity 0.5에서 +9.6% 개선, 78/100 query 우위, p<0.001. low selectivity 변동성은 RQ2-3에서 추가 분석합니다."

**🎯 강조**:
- "1.153에서 1.052" → 천천히 두 숫자 모두 또렷이.
- "+9.6%" / "78/100" / "p<0.001" — 세 숫자가 핵심.

**⚠️ 실수 경고**:
- 1.153 (소수점 세 자리. 보고서는 1.1527로 네 자리지만 PPT는 세 자리).
- 78/100 (78개. 78%가 아닌 78개 query).
- p<0.001 (소문자 p, 작다 부등호).

**👀 시선**: 표 셀을 손가락으로 짚어가며 — s=0.500 행 → BERN 칼럼 → diff% 칼럼 → 행 단위 우위 칼럼.
**⏸ pause**: "78개가 BERN 우위" 이후 1초.

**확장**: "이 결과는 PostgreSQL의 기본 SYSTEM 표본이 사실상 page 단위로 행을 묶어 추출하기 때문에, 같은 page 내 행들이 함께 추출/제외되어 추정 분산을 키우는 구조적 한계를 보여줍니다. BERN은 행 단위 독립 sampling으로 이 분산을 줄입니다."

**🔁 전환**: "이제 두 번째 보정 — KM20의 추가 효과 — RQ2-2입니다."

**메인 멘트**:
> "RQ2-2는 **두 번째 보정 — spatial-aware allocation의 추가 효과**입니다.

> 결과 — 🎯 **selectivity 0.500에서 KM20이 BERN 대비 +1.64%**, **5-seed 95% 신뢰구간 [+1.11, +2.18]**.
> ⏸ CI 하한이 +1.11로 양수 확정 — 통계적으로 유의한 추가 개선입니다.
> selectivity 0.050과 0.010 구간에서도 개선 신호는 있으나, 일부는 low-cardinality noise 영역이라 해석을 보류하고 W6에서 보강할 예정입니다.
> 핵심 메시지는 — **🎯 KM20의 역할은 sample size 증가가 아니라 vector-space region별 sample allocation 보정**이라는 점입니다."

**압축**:
> "KM20이 BERN 대비 s=0.5에서 +1.64%, CI [+1.11, +2.18] — 양수 확정으로 유의한 추가 개선. KM20의 역할은 sample size 증가가 아니라 region별 allocation 보정입니다."

**🎯 강조**:
- "+1.64%" — 또렷이.
- "[+1.11, +2.18]" — 두 숫자 모두 명확하게.
- 마지막 메시지 ("KM20의 역할은 ...") — 톤 한 단계 올림.

**⚠️ 실수 경고**:
- BERN 대비 (BERN 은 baseline)
- 5-seed (하이픈 포함). "5개 seed" 아님.
- CI [+1.11, +2.18] — 둘 다 양수.

## Slide 11 — RQ3: 7-way 비교 설계 (60s)

**메인 멘트**:
> "RQ3는 **분포를 사전에 모르는** Distribution-Agnostic 환경으로의 확장입니다.
> 7가지 방법을 3가지 paradigm으로 묶었습니다.
> 첫째 **Offline partition** — Random Projection, MiniBatch k-means, Hash partition LSH,
> 둘째 **Online query-adaptive** — Distance-Shell sampling과 KDE-pilot,
> 셋째 **Weight-based** — Importance sampling과 Density-based reweighting.
> 평가 지표는 — 🎯 **Recovery Rate** = (방법X − RANDOM20) / (KM20 − RANDOM20).
> RANDOM20을 0%, KM20을 100%로 두고, 분포-비인지 방법이 KM20 효과를 얼마나 회수하는지를 비율로 정량화합니다.
> 즉 — 분포를 모르는 상태에서 KM20에 얼마나 가까이 갈 수 있는지를 동일 조건으로 비교합니다."

**압축**:
> "RQ3는 분포를 모를 때 KM20 효과를 얼마나 회수할 수 있는지를 7가지 방법 × 3 paradigm으로 비교합니다. 평가 지표는 Recovery Rate — KM20 효과 대비 회수율."

**🎯 강조**:
- "Distribution-Agnostic" — 영어 발음 명확히.
- "Recovery Rate" — 정의 한 줄로 명확히.

**⚠️ 실수 경고**:

**👀 시선**: 3 paradigm 각각 손가락 카운팅.

## 약어·용어 빠른 참조

| 약어 | 풀이 |
|---|---|
| **BERN** | Bernoulli 행 단위 sampling |
| **SYSTEM** | PostgreSQL 기본 block 단위 sampling (=SYS) |
| **KM20** | MiniBatch k-means로 만든 20 클러스터 stratified sampling |
| **RANDOM20** | 무작위 20 그룹 분할 (KM20 ablation baseline) |
| **ECQO** | Extended Cardinality Query Optimizer (인덱스 있을 때) |
| **AS** | Adaptive Sampling (인덱스 없을 때) |
| **HNSW** | Hierarchical Navigable Small World — 그래프 기반 ANN 인덱스 |
| **ANN** | Approximate Nearest Neighbor — 근사 최근접 이웃 검색 |
| **Q-error** | \|estimate − true\| / true (1.0 = 완벽, 클수록 부정확) |
| **CV** | Coefficient of Variation — std/mean, 클수록 분산 큼 |
| **HHI** | Herfindahl-Hirschman Index — 균일하면 1/K, 집중되면 1.0 |
| **Recovery Rate** | RQ3 평가 지표 — (방법X − RANDOM20)/(KM20 − RANDOM20) |
| **Two-Level 분해** | L1 (안정화) + L2 (공간 인식) |
| **selectivity** | 전체 데이터 중 쿼리 조건 만족 비율 (0.001~0.500) |
