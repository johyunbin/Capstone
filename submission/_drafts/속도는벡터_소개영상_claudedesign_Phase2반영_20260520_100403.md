## 상황 (왜 이 신설이 필요한가)

본 소개영상(223845, 13장)은 5월 28일 캡스톤 전시회 제출 정본이며, 4:00~4:30 길이의 narration 기반 영상이다. 13장 가운데 슬라이드 8~11 영역에 본 연구의 핵심 측정 결과(1,508건 3-way 오프라인 측정)가 들어 있고, 그 다음 슬라이드 12부터 결론·다음 단계로 이어진다. 그러나 그 사이에 본 연구가 지난 한 주에 걸쳐 새로 완료한 핵심 결과 — **검증된 추정치를 실제 PostgreSQL에 주입한 엔진 적용 검증(12 구간 × 16 변형 × 15 반복 = 2,880회 측정)** — 가 통째로 빠져 있다. 이 결과는 본 연구가 "추정 정확도 → 실행 계획 → end-to-end 실행 시간" 의 인과 사슬을 직접 측정으로 닫아냈음을 보여 주는 closing the loop 슬라이드이며, 전시회 관람객에게 가장 인상적으로 남길 한 방이다.

본 수정은 슬라이드 11("모든 조건에서 일관되게 우월")과 슬라이드 12(결론과 다음 단계) 사이에 새 슬라이드 두 장(s11b·s11c)을 끼워 13장 → 15장으로 확장한다. 나머지 13장(슬라이드 1~11·12~13)은 한 자도 건드리지 않는다.

신설 2장은 영상에 추가될 분량 9~13초이며, 본 영상의 4:00~4:30 목표 시간 안에 들어간다(현재 누적 3:51 → 신설 후 약 4:04 — 안전 마진 안).

## 절대 규칙 (수정 시 동결)

이 9가지를 신설 2장에서도 어김없이 지킨다 — 기존 13장의 규칙과 동일.

1. **코드명 노출 금지**: B1·CaseA·CaseB·oracle·baseline 같은 영문 코드명을 슬라이드 본문·표·도식·narration text 에 노출하지 않는다. 한국어 라벨로 — "기본 엔진" / "베이스라인 방식" / "정답 계획" / "결합 방식" 으로 통일.
2. **"영역" 필러 금지**: "검증 영역" / "결과 영역" / "분석 영역" 같은 무의미 토큰을 본문·라벨·헤더·narration 어디에도 쓰지 않는다. "구간" / "단계" 또는 의미 있는 명사로.
3. **수식 노출 금지**: est_final = (est_b1 + est_method) / 2.0 식의 코드 수식을 본문에 노출하지 않는다. "두 추정값을 평균" 같은 한국어 표현으로.
4. **영문 메타 라벨 금지**: "Phase 2 results" / "Method comparison" / "INPUT" / "OUTPUT" / "STEP" / "PANEL" 같은 영문 메타 라벨을 헤더·소제목·박스 라벨에 쓰지 않는다. "엔진 적용 검증" 같은 한국어 헤더.
5. **이분법 강조 금지**: "베이스라인 vs 결합" 식 두 대립 항목만 강조하는 이분법 표현 금지. 4갈래(기본 엔진·베이스라인 방식·정답 계획·결합 방식) 의 흐름을 명시.
6. **별표(★) 금지**: 강조 표식으로 ★를 슬라이드에 쓰지 않는다 (스피커 노트는 OK).
7. **텍스트 잘림/겹침 금지**: 모든 글자가 박스·그라데이션·다른 텍스트와 겹치지 않게. 단어 중간 줄바꿈 금지(어절 단위로 끊는다).
8. **design system 유지**: navy 앵커 `#1E3A5F` + 악센트 4색(청록·코랄·그린·바이올렛) + Apple SD Gothic Neo(한글)·Inter(숫자) + 흰 배경 + 청록 그라데이션 hero. 색을 예전으로 되돌리지 않는다.
9. **narration timing**: 슬라이드당 4-7초, 한국어 한 문장 narration text 를 speaker note 에 기록. 천천히 읽어도 한 문장이 7초를 넘기지 않게.

## 신설 슬라이드 정의

### 슬라이드 11b — 엔진 적용 검증: 검증된 추정치를 실제 데이터베이스에 넣었더니 3배에서 7배까지 빨라졌다

배경 국면: **결과 국면 그린** (좌상단 작은 그린 표식 "엔진 적용 검증"). 슬라이드 9~11의 결과 국면 그린 흐름을 잇는다.

hero number: **"3-7×"** (navy → 청록 그라데이션, 슬라이드 9의 89.1% hero 동일 패턴).

구성 (위→아래 3 블록):

1. 헤더: 좌상단 작은 그린 표식 "엔진 적용 검증" + 슬라이드 제목 "검증된 추정치를 실제 데이터베이스에 넣었더니, 모든 12 구간에서 3배에서 7배까지 빨라졌다"
2. 측정 설계 박스: "TPC-H Q3·Q9·Q10·Q12 · DEEP 8천만 벡터 · 12 구간 · 16 변형 · 15회 반복 · 총 2,880회 측정". 그 옆 작은 흐름 도식: '추정치 → 데이터베이스에 주입 → 실행 계획 변화 → 실행 시간 측정' 4단계 아이콘 흐름.
3. 12 구간 가속 매트릭스 (작은 막대 또는 히트맵): Q3 평균 7배·Q9 평균 3배·Q10 평균 6배·Q12 평균 6배. 모든 12 구간이 1배 위에서 가속됨을 visually 강조. 색은 청록 농도 그라데이션(짙을수록 빠름).
4. 하단 통계 검증 캡션 띠 (옅은 그린 틴트 + 그린 세로 바): "기본 엔진 대비 180건 짝지은 통계 검정 100% 유의 — 의심의 여지 없는 가속".

narration text (speaker note, 약 5-6초):
> "검증된 추정치를 실제 데이터베이스에 주입했더니, 모든 12 측정 구간에서 기본 엔진보다 3배에서 7배까지 빨라졌습니다."

### 슬라이드 11c — 엔진 적용 검증: 결합 방식이 정답 계획을 94.9% 견고하게 회복

배경 국면: **결과 국면 그린** (좌상단 작은 그린 표식 "엔진 적용 검증").

hero number: **"94.9%"** (navy → 청록 그라데이션, 11b의 "3-7×" hero pair).

구성 (위→아래 3 블록):

1. 헤더: 좌상단 그린 표식 "엔진 적용 검증" + 슬라이드 제목 "결합 방식이 정답 계획을 견고하게 회복한다"
2. 대조 박스 2개 (좌·우 나란히):
   - **좌 (베이스라인 방식)**: 큰 분수 "7 / 12" + 라벨 "정답 계획 회복 · 58%" + 한 줄 설명 "질의 벡터에 따라 회복 여부가 흔들린다 (질의 0 = 0/4, 질의 1 = 4/4, 질의 2 = 3/4)". 박스 색조 = 코랄(완전 대체와 동계열 — fragile 시각화).
   - **우 (결합 방식, 13종 평균)**: 큰 분수 "148 / 156" + 라벨 "정답 계획 회복 · 94.9%" + 한 줄 설명 "질의 벡터와 무관하게 견고. 회복 실패 8건은 모두 Q3 한정". 박스 색조 = 청록(결합 개념색).
3. 하단 핵심 해석 띠 (옅은 그린 틴트 + 그린 세로 바): "두 방식의 실행 시간은 거의 같다. 결합 방식의 가치는 정답 계획을 더 흔들림 없이 만든다는 그 견고함."

narration text (speaker note, 약 6-7초):
> "결합 방식은 13종 method 평균 94.9퍼센트의 비율로 정답 계획을 견고하게 회복합니다. 베이스라인 방식이 보이는 흔들림을 결합 방식이 해소합니다."
