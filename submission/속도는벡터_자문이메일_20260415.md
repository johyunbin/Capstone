## 본문

멘토님, 안녕하십니까.

연세대학교 캡스톤 디자인 속도는벡터 팀의 조현빈입니다. 4월 3일 교수님 미팅 후 합의된 Skew-Aware Sampling 연구 방향(v3) 위에서 4월 14일~15일 이틀에 걸쳐 RQ1 Motivation 1차 실험과 RQ2 본선의 외적 타당성 확장 (Phase 1~7) 까지를 완주했습니다. 본 실험의 결과가 당초 가설을 기각하면서 동시에 대체 가설들의 매우 강력한 정량 신호 — paired Wilcoxon p=4.01e-05 (Phase 6 Step 4, 1M deep s=0.500) 와 p<1e-18 (Phase 7-1 deep 8M, 100/100 query, ratio 2168×) — 를 확보했습니다. 중간발표(4월 28일)까지 13일 남은 상황에서, 본 팀이 이번 주 내에 확정해야 할 세 가지 방향성 결정에 대해 멘토님의 자문을 요청드립니다. 본 메일의 §1~6 은 진행 경위와 정량 결과를, §7 은 자문 요청 3 항목을 정리합니다.

### 1. 4월 3일 합의의 요약

4월 3일 교수님 미팅에서 본 팀은 Exqutor(arXiv:2512.09695v2) 논문을 기반으로 다음과 같은 연구 방향을 확정했습니다. Exqutor의 Adaptive Sampling이 skewed 거리 분포에서 카디널리티 추정 정확도가 떨어지는 문제를 공략하며, (i) RQ1 Motivation 실험에서 skewness와 Q-error 사이의 상관을 정량 드러내고, (ii) RQ2에서 분포를 알 때의 stratified sampling 개선 효과를 측정하며, (iii) RQ3에서 분포를 모를 때의 KDE-pilot 기반 자동 층화를 제안하는 세 단계 구조입니다. 본선 시나리오는 multi-table join with vector range filter로 가정했고, 첫 단계의 판단 기준은 "Fisher skewness |γ| > 1 그룹의 Q-error가 |γ| < 0.5 그룹 대비 2배 이상 악화"로 설정했습니다.

### 2. 4월 14일 실험에서 마주한 문제

본 팀은 연세대학교 BDAI Lab 서버(임채림 석사 관리)에 Exqutor 전용 PostgreSQL 인스턴스(port 55436, Exqutor patched)를 구축하고, `partsupp_deep_10` (TPC-H sf10 + 96차원 DEEP 벡터, 8M 행) 의 1M 서브셋에 대해 RQ1 1차 실험을 Stage 1~5 + Phase 3~6 Step 4의 순서로 수행했습니다. 실험은 다음 네 가지 중대한 finding을 산출했습니다.

**첫째, 가설 H1 기각**. 4월 3일 합의의 판단 기준은 "|γ|>1 그룹과 |γ|<0.5 그룹의 Q-error 비율이 2배 이상"이었습니다. 본 실험에서 100 query × 6 selectivity × 5 seed = 3000 Adaptive Sampling 측정을 수행했고, 4가지 글로벌 skewness 지표(Fisher γ, log-Fisher γ, tail ratio P99/P50, Bowley skew)에 대해 24개 조합(4 지표 × 6 선택도) 모두에서 query별 median Q-error와 Spearman 상관 |ρ| < 0.2로 신호가 사실상 부재했습니다. 그룹 비교도 12개 조합 모두에서 ratio ≈ 1.0으로 2배 기준 미달이었습니다. 100 query 모두 Fisher γ가 음수(range −3.86 ~ −0.32, median −1.07)로 left-skewed이며 설계안 v3의 right-skewed 가정과 정반대였고, tail ratio P99/P50도 1.07~1.17 좁은 범위에 집중되어 있어 고차원 거리 집중(distance concentration) 현상이 글로벌 지표의 변별력을 평탄화한 것으로 해석됩니다.

**둘째, Exqutor의 4가지 design constraint 발견**. 본 팀은 Python 재구현이 Exqutor 네이티브와 정확히 일치함을 bitwise로 확인하기 위해 Phase 3 옵션 A(Exqutor 네이티브 100 query × 6 selectivity 직접 측정)를 시도했고, 그 과정에서 Exqutor 원논문 본문에 명시되지 않은 네 가지 design constraint를 소스 검증으로 직접 확인했습니다.

(i) **Hook trigger 사각지대**: `pgvector/src/vector.c` line 243의 `if (table_count > 2)` 조건이 단일 테이블 vector range query를 hook 경로에서 배제합니다. 즉 `SELECT count(*) FROM t WHERE (vec <-> q) < D` 형태는 Exqutor의 Adaptive Sampling 함수 자체에 도달하지 못하고 PostgreSQL default selectivity 1/3로 fall-through됩니다. Exqutor의 Adaptive Sampling은 multi-table join 시나리오에만 한정된 해법이며, 단일 테이블 시나리오는 사각지대로 남아 있습니다.

(ii) **Plan replacement 부작용**: hook 우회 후 (vector.c line 243을 `>= 1`로 한 줄 수정) outer query의 base relation 노드 자체가 PostgreSQL의 `Sample Scan`으로 plan-tree가 교체되어(예: `Sampling Method: system, Sampling Parameters: ['0.0385'::real]`), 단일 테이블 시나리오에서는 outer query 결과 자체가 sample 안 부분 카운트로 격하됩니다. true=100,000 query에서 `SELECT count(*)`가 32를 반환한 사례가 있습니다. Exqutor의 hook이 단순 cardinality estimation이 아니라 plan execution 자체를 sample scan으로 격하시키는 동작임을 보여줍니다.

(iii) **Block sampling bias**: Exqutor는 `TABLESAMPLE SYSTEM(%f)` 을 `vector.c` line 889(사후 offset)에서 단일 호출하며, 본 팀의 Python 재구현에 BERNOULLI 시뮬레이션을 추가해 비교한 결과 SYSTEM이 Bernoulli 대비 selectivity ≥ 0.05에서 median Q-error를 3.8%~9.1% 더 높였습니다. native 경로에서도 Phase 4의 4 구간(s=0.050, 0.100, 0.300, 0.500) 모두에서 paired Wilcoxon p < 0.001로 재현되었습니다. 구체적으로 s=0.500에서 median 1.1527 vs 1.0519, p < 0.001, 100 query 중 78 query가 SYSTEM 쪽으로 불리한 방향으로 움직였습니다.

(iv) **Query feature 사전 식별 불가능성**: Phase 5에서 로컬 4 지표(k-NN distance entropy, k-NN PCA EVR1, KDE modality count, NN clustering coefficient)를 추가로 구현해 24개 조합(4 로컬 지표 × 6 선택도)을 전수 검증한 결과, 역시 모두 |ρ| < 0.2로 무효화되었습니다. 글로벌 4 + 로컬 4, 총 8 지표 전수 검증 후 query-conditional layer 정의가 사전 식별 불가능함이 확정되었습니다.

### 3. 수정된 연구 계획 — Pivot A + Pivot C 병합 노선

위 네 finding을 근거로, 본 팀은 4월 14일 17:35 KST에 다음과 같은 수정 연구 계획을 확정했습니다. 4월 3일 합의의 큰 3단계 구조(베이스라인 → 분포 인지 → 분포 무인지)와 핵심 동기(Exqutor 정확도 개선)는 그대로 유지한 채, 각 단계의 측정 정의를 4/14 결과 위에서 정교화한 결과입니다. 본선 시나리오는 multi-table join에서 **단일 테이블 vector range query 사각지대**로 좁히고, 이 좁힘 자체를 RQ1 Motivation의 새로운 첫 줄로 격상합니다. 시나리오 좁힘의 실무적 정당성은 이미지 검색, 추천 시스템, RAG의 retrieval 단계가 모두 단일 테이블 vector range query의 전형이라는 관찰에서 확보합니다.

RQ2(분포 인지)는 두 개의 직교적 sanitize로 재정의됩니다. **Pivot A**는 `vector.c` line 889의 `TABLESAMPLE SYSTEM(%f)`을 `TABLESAMPLE BERNOULLI(%f)`로 한 줄 교체하여 Exqutor의 block sampling bias를 제거하는 도구입니다. Pivot A는 단독 기여보다는 fair baseline 구축 단위로 분리되며, Pivot C의 측정에 사용됩니다. **Pivot C**는 `vector.c`에 +228 줄의 data-side stratified sampling 분기를 추가합니다. 데이터 자체에 numpy mini-batch k-means K=20(seed=42)으로 partition을 학습해서 `stratum_id smallint` 컬럼을 부여하고, `vector.sampling_method = 'stratified'` GUC 활성화 시 per-stratum `ORDER BY random() LIMIT sample_size/K` 형태의 SPI SQL로 층별 균등 sample을 추출해 Horvitz-Thompson 가중 카디널리티 추정식 `est = Σ (n_i × cnt_i / s_i)`을 native에서 계산합니다. Query 시점의 overhead는 pre-materialized stratum_id를 사용하므로 0 이며, 전체 추가 비용은 per-stratum random sort 때문에 BERN 대비 11배입니다(추후 최적화 대상).

RQ3(분포 무인지)은 고차원 k-means 재학습을 회피하는 경량 경로로 재정의됩니다. 구체적으로 query별 pilot sample(전체의 1% 수준)의 거리 값을 1D Gaussian KDE로 fit한 후, quantile 경계로 층화해 stratum을 자동 정의합니다. Query feature가 고차원에서 사전 식별 불가능하더라도 같은 query의 sample된 거리 값 자체는 1D로 환원되므로 KDE가 안정적으로 동작합니다. RQ3는 중간발표에는 진입하지 않고, 최종보고서(6/11) 국면(W7, 5/12~5/18)에서 구현합니다.

### 4. 현재 실험 진행과 정량 결과

본 팀은 4월 14일 하루에 위 수정 계획의 첫 단계 구현을 Phase 4 ~ Phase 6 Step 4까지 완주했습니다. 구체적 수치는 다음과 같습니다.

**Phase 4 — Pivot A native 검증 완주** (2026-04-14 19:30~19:40 KST). `vector.c` line 889 한 줄 교체 후 재빌드하고, 100 query × 6 selectivity × 1 seed × 2 mode = 1200 query를 native 경로에서 실행했습니다. 결과는 selectivity ≥ 0.05의 4개 구간에서 paired Wilcoxon (alt: SYSTEM > BERNOULLI) p < 0.001로 SYSTEM의 q-error가 BERNOULLI보다 통계적으로 유의하게 큽니다. 가장 큰 효과는 s=0.500에서 median 1.1527 vs 1.0519, diff +9.6%, 100 query 중 78개가 SYSTEM 쪽 불리. Phase 4의 native 수치는 §II.5의 Python counterfactual(+3.8~9.1%)과 같은 order of magnitude로 방향 일치.

**Phase 5 — Local skew 4 지표 전수 무효화** (2026-04-14 20:09 KST). k-NN distance entropy, k-NN PCA EVR1, KDE modality count, NN clustering coefficient 4 지표를 numpy + scipy만으로 구현해 24 조합을 전수 검증했고, 모두 |ρ| < 0.2 (최대 nn_clustering_coef × s=0.010에서 −0.166, p=0.099)로 임계 미달. 글로벌 4 + 로컬 4 = 8 지표 전수 검증 후 query-conditional layer 정의가 고차원 vector dataset에서 사전 식별 불가능함이 확정되었습니다.

**Phase 6 Step 3' — Layer 비교**(2026-04-14 20:45 KST). data-side partition의 4 후보(bernoulli baseline, PCA decile, k-means K=10, k-means K=20)를 단일 스크립트로 동시 측정해 12 000 행의 long-form 결과를 얻었습니다. paired Wilcoxon vs BERN 18 test에서 KM20이 3 selectivity 구간(s=0.100, 0.300, 0.500)에서 p < 0.05로 가장 넓은 적용 범위를 확보. 특히 s=0.100에서 KM20은 +2.25% (p=0.0042)의 단일 최대 효과 크기를 달성하며, PCA decile(+0.76%, p=0.478)과 KM10(+0.19%, p=0.536)에는 없는 신호를 확보했습니다. KM20이 "96d의 모든 차원을 사용하는 fine-grained partition"의 이점을 transitional selectivity 영역에서 처음 발현한 결과로 해석됩니다.

**Phase 6 Step 4 — KM20 Native 구현 + 재현성 검증**(2026-04-14 22:00 KST). `vector.c`에 +228 줄의 stratified sampling 분기를 직접 구현하고, 데이터 사이드 ALTER TABLE 경로로 `partsupp_deep_10_subset_1m` 에 `stratum_id smallint` 컬럼을 부여했습니다. Python Step 3'의 KM20 결과를 native 경로로 재현한 결과, 3 selectivity 구간(s=0.050, 0.100, 0.500)에서 paired Wilcoxon p < 0.05로 BERNOULLI 대비 우위임을 확인했습니다. 최강 신호는 **s=0.500에서 p=4.01e-05 (★★★)** 로 Phase 4~6 전체의 최강 통계적 유의 구간이며, effect size +1.81%로 Python counterfactual의 +0.33%보다 5배 이상 큽니다. 해석은 native의 `ORDER BY random() LIMIT` 가 per-stratum 정확 균등 sample을 보장하므로 Python numpy의 rng.choice 보다 sample allocation variance가 작아 baseline noise가 감소한 결과입니다.

### 5. β 외적 타당성 확장 — Phase 7 측정 완료 (2026-04-15 08:31 KST)

Phase 6 Step 4 직후의 1M subset × 96d DEEP 단일 dataset 결과는 외적 타당성이 부족하다는 자체 평가에 따라, 본 팀은 4월 15일 오전에 두 확장 실험을 추가로 수행했습니다.

**Phase 7-1 sf10 8M 재현** (`partsupp_deep_10_phase7_8m_subset`, 옵션 B 안전 경로): 원본 `partsupp_deep_10` 8M 행을 별도 테이블로 COPY 후 (보존), KM20 (seed=42) 으로 8M 전체에 stratum_id 학습 + UPDATE + 인덱스 + VACUUM ANALYZE 까지 17 분 소요. 그 위에서 BERN + STRAT × 100 query × s=0.500 D_target = 200 query 측정.

**Phase 7-2 sift 128d 확장** (`customer_sift_10_phase7_noidx_subset`): `customer_sift_10` 1.5M 행을 vanilla PG 55435 → Exqutor PG 55436 으로 minimal transfer (c_custkey, c_embedding 만, 838 MB, 2 분 33 초), HNSW 없이 별도 테이블 부여, KM20 (seed=42, 128d 공간) 학습 + UPDATE + 인덱스. 그 위에서 BERN + STRAT × 100 query × s=0.500 D_target = 200 query 측정.

**중요한 부수적 발견 — D_target 의 dataset 간 scaling**. 본 두 실험의 D_target 은 1M subset 의 `query_selectivity.parquet` 사전 계산값 (s=0.500 = 1M 거리 분포의 quantile 0.5) 또는 sift 의 numpy quantile 0.5 였습니다. 그러나 8M 원본 / 128d sift 의 거리 분포가 1M / 96d 와 다르게 dense 한 구조여서, 같은 D_target 에서의 actual selectivity 가 의도한 0.500 이 아니라 약 0.0001 영역으로 이동했습니다 (Phase 7-1 actual sel = 0.000024, Phase 7-2 actual sel = 0.000128). 이는 paired 비교의 타당성을 깨지 않으며, 같은 D_target 위에서 두 모드의 q_error 차이는 valid 한 측정입니다. 오히려 이 작은 selectivity 영역은 Phase 6 Step 4 의 1M deep 에서 BERN 과 STRAT 가 동률이었던 cnt-clamp fallback 영역 (sample 385 안에서 매칭 0~1개) 과 정확히 같은 메커니즘 영역이며, 본 Phase 7 의 8M 규모 / 128d 차원에서 동일 영역이 어떻게 동작하는지를 직접 측정한 결과입니다.

본 표가 보여주는 본 연구 RQ2 본선의 핵심은 다음 세 가지로 정리됩니다.

첫째, **Pivot C (KM20 stratified) 의 정확도 우위가 정상 selectivity 영역과 small selectivity 영역 양쪽에서 정량 확인됨**. 정상 영역 (Phase 6 Step 4 의 s=0.500) 에서는 +1.81% 의 정량 개선과 paired Wilcoxon p=4.01e-05 의 통계적 유의로 측정되며, small selectivity 영역 (Phase 7 의 actual sel ≈ 0.0001) 에서는 medain q-error 가 BERN 의 1/409 ~ 1/2168 수준으로 감소합니다. 두 영역은 효과 크기 (1.018x vs 2168x) 가 매우 다르지만, 두 영역 모두에서 STRAT 가 win 한다는 일관성 자체가 본 노선의 강건성을 입증합니다.

둘째, **Small selectivity 영역의 강한 효과는 BERN 의 cnt-clamp fallback 의 구조적 한계와 STRAT 의 stratum 균등 추출 + HT 가중 estimator 의 차이를 정량 드러냅니다**. BERN 은 sample 385 안에서 dense cluster 의 매칭이 우연히 들어오면 estimator 가 sample × N/sample_size 로 huge 값을 반환하는데 (Phase 7-1 의 median plan_rows ≈ 4M, true ≈ 200, q_error ≈ 20810), STRAT 는 20 stratum 으로 cluster 를 사전 분리해서 dense cluster 의 매칭에 작은 weight 를 적용하므로 estimator 가 안정적 (median q_error 9.60). 이는 본 연구가 Pivot C 의 학술적 motivation 으로 제시한 "data-side partition 의 효과는 sample 안 분포 균등성에서 온다" 라는 명제를 직접 데이터로 확인한 결과입니다.

셋째, **Phase 7-1 deep 8M 의 ratio 2168× 는 본 연구 전체의 단일 최강 신호** 이며, Phase 6 Step 4 의 s=0.500 p=4.01e-05 와 함께 RQ2 본선의 양대 anchor 가 됩니다. 본 두 anchor 는 정확도 영역의 양극단 (정상 selectivity, small selectivity) 을 커버하며, 상호 보완적입니다.

본 Phase 7 측정 진행 과정에서 발견한 기술적 finding 들 — psycopg3 copy iterator 의 memoryview chunk yield, pre-측정 GUC 설정의 snapshot 부재 에러, Exqutor stratified hook 의 normal SELECT 와의 plan tree 충돌, hook estimate log parsing 의 align 어려움 — 은 모두 본 메일 발송 시점까지 fix 완료되어 현재의 정량 결과를 확보했습니다. 본 finding 들은 RQ1 motivation 의 Exqutor design constraint 목록에 추가되지 않으며, 본 팀의 측정 코드 안정화 작업으로 분류됩니다.

### 6. 남은 로드맵 — 중간발표 β + 최종발표 W5~W8

중간발표(4/28)까지의 본선 범위는 β 옵션(Phase 7-1 + Phase 7-2 + 기존 1M Phase 6 Step 4 + 시각화 Stage 5b)으로 확정했습니다. 3 dataset × 6 selectivity × 10 seed × 500 query 전면 ablation은 최종발표(5/27) γ 단계로 이월합니다. 근거는 두 가지입니다. 첫째, 중간발표의 목적은 내부/외부 타당성 baseline 제시이지 full ablation이 아니라는 것, 둘째, 서버 HDD 환경에서 현재 STRAT의 `ORDER BY random() LIMIT` 비용이 BERN 대비 11배이므로 3 dataset 전면 ablation의 예산이 기하급수적으로 증가한다는 것입니다.

최종발표까지의 4주는 W5~W8로 나눠서 (W5) per-stratum TABLESAMPLE BERNOULLI 최적화 + Layer sweep + wiki 768d 검증, (W6) 3 dataset × 3 mode × 6 sel × 10 seed × 500 query 전면 ablation, (W7) RQ3 KDE-pilot 구현 + sensitivity, (W8) 최종보고서 작성 + 포스터 + 전시회 데모 + 리허설로 구성했습니다. 본 로드맵의 3가지 리스크(측정 시간 폭발, wiki 768d k-means 재학습 실패, RQ3 고차원 KDE 불안정성) 각각에 대응 경로도 확정했습니다. 자세한 로드맵은 `plans/수정 연구 설계안_20260415_001500.md §IX`에 정리되어 있으며, 본 메일 첨부로 포함합니다.

### 7. 자문 요청 3항목

위 진행을 바탕으로, 본 팀이 이번 주 내에 확정해야 할 세 가지 방향성 결정에 대해 멘토님의 자문을 요청드립니다.

**자문 요청 (a) — 시나리오 전환의 학술적 정당성**. 본 팀의 4월 3일 합의 시나리오는 multi-table join with vector range filter였으나, 4/14 Phase 3~4의 design constraint 발견 후 단일 테이블 vector range query 사각지대로 시나리오를 좁혔습니다. 이 전환이 학술적으로 정당한지, 본 §2의 네 가지 design constraint(특히 (i) Hook trigger 사각지대와 (ii) plan replacement 부작용)가 전환의 충분 근거인지 멘토님의 판단을 구합니다. 본 팀의 입장은 "충분 근거이며 동시에 새 학술적 빈자리"이지만, reviewer 관점에서 "원래 합의에서 도망쳤다"로 읽힐 위험이 있는지 염려하고 있습니다.

**자문 요청 (b) — Pivot A + Pivot C 병합의 기여 정당성**. 본 팀은 당초 4월 3일 합의에서 stratified sampling 단일 기여를 상정했으나, 4/14 Phase 4에서 발견된 block sampling bias를 Pivot A(BERNOULLI 한 줄 교체)로 sanitize하고 이를 Pivot C(KM20 stratified)의 fair baseline으로 사용하는 병합 노선을 채택했습니다. Pivot A는 단독으로는 한 줄 변경이지만 Pivot C와 결합한 직교 ablation matrix의 일부로서 학술적 가치가 있다는 입장입니다. 이 병합이 "기여 인플레이션"으로 보일 위험이 있는지, 아니면 정당한 두 단계 sanitize로 받아들여질지 멘토님의 판단을 구합니다.

**자문 요청 (c) — 중간발표 슬라이드의 design constraint 노출 수위**. 본 팀이 발견한 4가지 design constraint 중 (i) Hook trigger 사각지대와 (ii) plan replacement 부작용은 본 연구의 새 motivation 첫 줄로 격상하는 것이 본 팀의 기본 입장입니다. 나머지 (iii) q-error inf 발산과 (iv) sample_size NaN 발산(그리고 Phase 4에서 발견한 (v) Adaptive update path SIGSEGV)은 Adaptive Sampling의 단일 테이블 시나리오 수치 불안정성으로 분류되는 기술적 finding입니다. 중간발표 슬라이드에 네 가지 모두를 드러낼지(완전 정직 보고, 슬라이드 3~4장 소요), 첫째·둘째만 드러낼지(motivation 강화, 슬라이드 1~2장), 첫째만 드러낼지(시간 제약, 슬라이드 1장) 멘토님의 판단을 구합니다. 본 팀의 기본 결정은 (a) 첫째·둘째만 본문 노출이지만 자문 결과에 따라 조정하겠습니다.
