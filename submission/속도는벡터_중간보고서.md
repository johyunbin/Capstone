## 1. 연구 주제

본 연구는 벡터 데이터베이스의 카디널리티 추정 정확도 문제를 해결한 Exqutor (arXiv:2512.09695v2) 의 Adaptive Sampling 이 가진 두 단계 한계 — 단일 테이블 vector range query 사각지대 (motivation finding) 와 naive uniform sampling 의 정확도 손실 (개입 측정) — 를 정량 드러내고, `vector.c` 한 줄 교체 (Pivot A) 와 data-side k-means K=20 기반 stratified sampling 의 native 구현 (Pivot C) 으로 두 sanitize 를 직교 ablation matrix 로 분리 측정한다. 본 보고서는 4월 14일~15일 사이에 수행한 RQ1 Motivation + RQ2 본선 (Phase 1~7) 의 결과를 정리하고, 6월 11일 최종보고서까지의 RQ3 Distribution-Agnostic 확장 로드맵을 함께 제시한다.

## 2. 연구의 필요성

### 2.1 벡터 카디널리티 추정 문제

벡터 데이터베이스에서 *주어진 query 벡터와 유사도가 임계값 이상인 행의 개수* 를 추정하는 문제는 옵티마이저의 실행 계획 선택에 직접 영향을 미치는 핵심 작업이다. pgvector 는 벡터 조건의 선택도를 33.3% 로 고정 추정하고, VBASE 는 50%, DuckDB 는 100% 로 추정한다. 그러나 실제 선택도는 query 에 따라 0.001% 부터 90% 까지 매우 넓은 범위를 가지며, 고정 비율 추정으로는 옵티마이저가 nested loop join 과 hash join 사이, 또는 vector index 사용 여부 사이에서 잘못된 선택을 내리는 사례가 빈번하다. Exqutor 는 이 문제에 두 가지 해법을 제시했다. **ECQO** 는 HNSW 인덱스가 있을 때 range query 를 직접 실행해 1~2 ms 안에 정확한 카디널리티를 획득하는 방식이며, **Adaptive Sampling** 은 인덱스가 없을 때 모멘텀 기반 동적 샘플링으로 카디널리티를 근사한다. 두 방법으로 Exqutor 는 pgvector 에서 최대 1000 배, VBASE 에서 10000 배, DuckDB 에서 1.5~37 배 성능 향상을 보고했다.

### 2.2 Exqutor Adaptive Sampling 의 잠재적 약점

본 팀의 출발 가설은 4 월 3 일 교수님 미팅에서 합의된 명제로 정리된다. *Exqutor 의 Adaptive Sampling 은 무작위 샘플이 전체 데이터의 거리 분포를 대표한다는 암묵적 가정 위에 동작하며, 거리 분포가 한쪽으로 치우친 (skewed) 환경에서는 무작위 샘플이 밀도가 높은 영역에 편중되어 카디널리티 추정 정확도가 떨어진다.* 본 가설을 데이터로 확인하고, distribution-aware sampling (분포를 알 때) 과 distribution-agnostic sampling (분포를 모를 때) 두 노선에서 정확도 개선을 정량 측정하는 것이 본 연구의 큰 골격이었다.

본 가설을 4 월 14 일에 직접 검증하는 과정에서 본 팀은 두 가지 발견에 도달했다. 첫째, 4 월 3 일 합의의 핵심 명제 — *글로벌 skewness 지표 (Fisher γ 등) 가 클수록 Q-error 도 크다* — 는 96 차원 DEEP 벡터의 1M subset 100 query × 6 selectivity × 5 seed × 2 mode = 6000 측정에서 강하게 기각되었다. 둘째, 같은 데이터에서 Exqutor 가 사용하는 `TABLESAMPLE SYSTEM` 의 block sampling bias 와 `vector.c` 의 hook trigger 조건 (`table_count > 2`) 이 만드는 단일 테이블 vector range query 사각지대 등 다섯 가지 design constraint (본문 4 + 부록 1) 를 발견했다. 본 두 발견은 4 월 3 일 합의의 큰 골격을 유지한 채, 측정 정의와 본선 시나리오를 정교화한 결과 (이하 v4 수정 설계안) 로 이어졌다. 본 보고서의 §4 는 이 정교화의 모든 단계를 정량 결과와 함께 정리한다.

## 3. 연구 질문

본 연구는 4 월 3 일 합의의 RQ1/RQ2/RQ3 세 단계 구조를 그대로 유지하며, 각 RQ 의 측정 정의를 4 월 14 일~15 일의 정량 결과 위에서 정교화한다.

**RQ1 — Motivation 검증 (단일 테이블 사각지대 + 구조적 finding)**. Exqutor 의 Adaptive Sampling 은 단일 테이블 vector range query 시나리오에서 어떤 구조적 한계를 가지며, 그 한계는 어디에서 측정 가능한가? 본 RQ 는 (i) Hook trigger 사각지대, (ii) plan replacement 부작용, (iii) `TABLESAMPLE SYSTEM` block bias, (iv) query feature 사전 식별 불가능성의 네 finding 을 직접 소스 검증과 EXPLAIN ANALYZE 로 정량 드러낸다.

**RQ2 — Distribution-Aware (Pivot A + Pivot C 병합)**. 분포를 알 때 (또는 데이터 자체의 partition 을 사전 학습할 수 있을 때), 두 단계 sanitize — `vector.c` L889 한 줄 교체로 block sampling bias 제거 (Pivot A) + data-side k-means K=20 기반 stratified sampling 의 native 구현 (Pivot C) — 가 카디널리티 추정 정확도를 얼마나 개선하는가? 본 RQ 는 BERN/STRAT × dataset × selectivity 의 직교 ablation matrix 로 두 sanitize 의 효과를 분리 측정한다.

**RQ3 — Distribution-Agnostic (1D distance KDE + quantile 경계)**. 분포를 모르는 상황에서, query 별 pilot sample 의 거리 값을 1D Gaussian KDE 로 fit 하고 quantile 경계로 자동 stratification 하면, 사전 학습 없이도 RQ2 에 준하는 정확도를 얻을 수 있는가? 본 RQ 는 고차원 k-means 재학습을 회피하는 경량 경로로 구현되며, 본 중간 보고서 시점 (4/28) 에서는 진입하지 않고 최종 보고서 (6/11) 국면 (W7, 5/12~5/18) 에서 수행한다.

## 4. 연구 내용 — 4월 14일 ~ 15일의 측정 결과

### 4.1 출발점 — 4월 3일 교수님 합의

4 월 3 일 미팅에서 본 팀은 Exqutor 의 Adaptive Sampling 정확도 개선을 본선 주제로 확정하고, 두 트랙 — 분포 인지 / 분포 무인지 — 의 3 단계 실험 구조 (베이스라인 → 트랙 A → 트랙 B) 를 합의했다. 본선 시나리오는 **multi-table join with vector range filter** 로 가정되었고, 첫 단계의 판단 기준은 *Fisher 의 skewness γ 큰 그룹의 Q-error 가 작은 그룹 대비 2 배 이상* 이었다. 본 합의의 자세한 narrative 는 `plans/연구 설계안_20260403_162818.md` (v3) 에 정리되어 있으며, 본 보고서의 모든 정교화는 v3 의 큰 골격을 유지한 채 측정 정의만 4/14~15 데이터 위에서 단단하게 만든 결과다. v4 수정 설계안 (`plans/수정 연구 설계안_20260415_001500.md`) 이 두 버전의 차이를 표로 정리한다.

### 4.2 RQ1 1차 실험 — 가설 H1 기각과 Phase 5 8지표 전수 검증

본 팀은 4 월 14 일 오전에 연세대학교 BDAI Lab 서버 (`capstone2026@165.132.140.240`) 에 vanilla PG 16.9 + pgvector 0.7.1 환경을 구축하고, `partsupp_deep_10` (TPC-H sf10 + 96 차원 DEEP 벡터, 8M 행) 의 1M 결정론적 서브셋 위에서 RQ1 1차 실험을 5 단계 (Stage 1~5) 로 수행했다. 100 query 를 무작위 추출하고, 각 query 에 대해 6 개 선택도 구간 (0.001 / 0.010 / 0.050 / 0.100 / 0.300 / 0.500) 의 D_target 을 사전 계산한 뒤, Adaptive Sampling 을 Python 으로 재구현해 5 seed × 2 mode (`bernoulli`, `block_system`) × 100 query × 6 selectivity = 6000 측정의 q-error 를 산출했다. 본 실험의 자세한 절차와 산출물은 `experiments/results/rq1_motivation/summary.md §I~II` 에 정리되어 있다.

검증 결과는 가설 H1 을 강하게 기각했다. 4 가지 글로벌 skew 지표 (Fisher γ, log-Fisher γ, tail ratio P99/P50, Bowley skew) 와 query 별 median Q-error 의 Spearman 상관은 모든 24 개 조합 (4 지표 × 6 선택도) 에서 절대값이 0.2 미만이었으며, `|γ| > 1` 그룹과 `|γ| < 0.5` 그룹의 median Q-error 비율도 12 개 조합 모두에서 1.00 근처였다. 100 query 가 모두 Fisher γ < 0 (left-skewed) 이며 tail ratio P99/P50 도 1.07~1.17 의 좁은 범위에 모여 있어, 96 차원 벡터의 *고차원 거리 집중 (distance concentration)* 현상이 글로벌 skewness 지표의 변별력을 평탄화시켰다는 것이 1 차 진단이었다.

본 진단을 보강하기 위해 4 월 14 일 저녁 (Phase 5) 에 **로컬 4 지표** — k-NN distance entropy, k-NN PCA EVR1, KDE modality count, NN clustering coefficient — 를 numpy + scipy 만으로 직접 구현해 같은 100 query 에 적용했다. 결과는 24 개 조합 (4 지표 × 6 선택도) 모두에서 |Spearman ρ| < 0.2 였다. 글로벌 4 + 로컬 4 = **8 지표 전수 검증 후 query-conditional layer 정의가 사전 식별 불가능** 함이 확정되었다. 이는 본 연구의 중요한 negative result 이며, RQ1 motivation 의 한 축으로 직접 편입되어 *query feature 가 아닌 data-side 에서 layer 를 가져와야 한다* 는 Pivot C 의 정당화로 사용되었다.

### 4.3 Exqutor Design Constraint 발견 — 새 motivation 첫 줄

H1 기각의 정량 결과 위에서 본 팀은 Python 재구현이 Exqutor 네이티브와 정확히 일치하는지 확인하기 위한 옵션 A (Phase 3 native bitwise 검증) 를 같은 날 오후에 시도했다. 그 시도는 두 가지 강력한 finding 으로 이어졌으며, 본 두 finding 은 본 연구 motivation 의 새 첫 줄로 격상되었다.

**첫째 — Hook trigger 사각지대**. Exqutor 의 `pgvector_set_baserel_rows_estimate_hook` 은 `vector.c` line 243 의 `if (table_count > 2)` 조건을 통과해야만 활성화된다. 본 팀의 검증 query 인 `SELECT count(*) FROM partsupp_deep_10_subset_1m WHERE (ps_embedding <-> q) < D` 는 단일 테이블이므로 `table_count = 1` 이고, 따라서 hook 이 우회되어 PostgreSQL default selectivity 1/3 으로 fall-through 된다. 즉 단일 테이블 vector range query 는 Exqutor 의 Adaptive Sampling 함수 자체에 도달하지 못하는 사각지대다. 이는 Exqutor 원논문 본문에 명시되지 않은 design constraint 이며, 본 팀의 직접 소스 검증으로 처음 정량 확인되었다. 이미지 검색, 추천 시스템, RAG 의 retrieval 단계가 모두 단일 테이블 vector range query 의 전형이라는 실무적 관찰은 본 사각지대를 본 연구가 채울 수 있는 학술적 빈자리로 격상시킨다.

**둘째 — Plan replacement 부작용**. 위 hook 을 `if (table_count >= 1)` 로 한 줄 우회하면, outer query 의 base relation 노드 자체가 PostgreSQL 의 `Sample Scan` 으로 plan-tree 가 교체된다 (`Sampling Method: system, Sampling Parameters: ['0.0385'::real]`). 단일 테이블 시나리오에서는 outer query 결과 자체가 sample 안 부분 카운트로 격하되어 (예: true=100,000 query 에서 `SELECT count(*)` 가 32 반환), outer query 의 정확성이 깨진다. multi-table join 에서는 base table sample scan 으로의 교체가 join 결과의 부분 영향만 주지만, 단일 테이블에서는 outer query 의 의미를 잃게 만드는 design constraint 다.

본 두 finding 외에도 옵션 A 시도 중 (iii) q-error inf 발산, (iv) sample_size NaN 발산, (v) Adaptive update path SIGSEGV 의 세 가지 추가 design constraint 가 발견되었다. 본 세 finding 은 Adaptive Sampling 의 update path 가 multi-table only design intent 를 가정하고 만들어진 결과이며, 본 연구의 측정 단계에서는 `vector.update_sample_size = off` GUC 로 update 경로를 차단하고 sampling method 자체의 효과만 분리 측정하는 방식으로 회피했다. 자세한 narrative 는 `experiments/results/rq1_motivation/direction_pivot_rationale.md` 에 187 줄로 정리되어 있다.

### 4.4 Pivot A + Pivot C 병합 노선 확정 (4월 14일 17:35 KST)

위 finding 들을 근거로 본 팀은 4 월 14 일 17:35 KST 에 **Pivot A + Pivot C 병합 노선** 을 확정했다. 4 월 3 일 합의의 큰 골격은 그대로 유지되며, 다음 두 차원에서 정교화가 일어났다.

**시나리오 좁힘**. 본선 시나리오를 multi-table join with vector range filter 에서 단일 테이블 vector range query 사각지대로 좁힌다. 좁힘의 비용은 multi-table 벤치마크와의 직접 비교 불가능이며, 대응은 (i) 본 연구 motivation 자체가 사각지대를 드러내는 것이므로 multi-table 비교가 필요 없고, (ii) 단일 테이블 시나리오의 실무적 중요성이 본 연구의 외적 타당성을 강화한다는 것이다.

**측정 도구의 교체**. Layer 정의를 query-side feature 에서 data-side partition 으로 이전한다. Phase 5 의 8 지표 negative result 가 query-side feature 의 사전 식별 불가능성을 보였으므로, 본 팀은 데이터 자체에 대한 numpy mini-batch k-means K=20 (seed=42) 학습으로 stratum 을 정의하고 각 행에 `stratum_id smallint` 컬럼을 사전 부여해 query 시점의 overhead 를 0 으로 만든다.

본 두 정교화 위에서 두 sanitize 가 정의된다. **Pivot A** 는 `vector.c` L889 의 `TABLESAMPLE SYSTEM(%f)` 을 `TABLESAMPLE BERNOULLI(%f)` 로 한 줄 교체하는 단순 변경이며, Exqutor 가 사용하는 block sampling 의 row-correlation bias 를 제거하는 *fair baseline* 도구다. **Pivot C** 는 `vector.c` 에 +228 줄의 stratified sampling 분기를 추가하여 GUC `vector.sampling_method = 'stratified'` 활성화 시 per-stratum `ORDER BY random() LIMIT sample_size/K` 형태의 SPI SQL 로 층별 균등 sample 을 추출하고 Horvitz-Thompson 가중 카디널리티 추정식 `est = Σ (n_i × cnt_i / s_i)` 을 native 에서 계산하는 본 연구의 핵심 본선 구현이다. 두 Pivot 은 직교적이므로 SYSTEM/BERNOULLI/STRATIFIED × dataset × selectivity 의 ablation matrix 로 각 개선의 기여를 분리 측정할 수 있다.

Phase 4 의 native 수치는 §4.2 의 Python counterfactual (+3.8~9.1%) 과 같은 order of magnitude 로 방향이 일치한다. 자세한 산출물은 `experiments/results/rq1_motivation/phase4_*.parquet` + `phase4_compare.json`.

### 4.6 Phase 6 Step 4 — Pivot C KM20 Native 구현과 정상 selectivity 검증 (4월 14일 22:00 KST)

Phase 6 Step 1~3 (Python counterfactual) 와 Step 3' (4 layer 비교: bernoulli / pca_decile / kmeans_k10 / kmeans_k20) 위에서 KM20 = best layer 가 확정되었으며, 본 Step 4 는 그 KM20 stratified 를 native 로 직접 구현한 단계다. 본 팀은 `vector.c` 에 +228 줄의 stratified 분기를 추가하고 (GUC 3 개 + stratum_sizes 캐시 + estimate 함수), `partsupp_deep_10_subset_1m` 에 `stratum_id smallint` 컬럼 + 인덱스를 부여한 후 (data-side ALTER TABLE 옵션 B), 100 query × 6 selectivity × 1 seed × 2 mode = 1200 query 를 native 경로에서 측정했다. q-error 는 EXPLAIN 의 plan_rows 와 서버 로그의 hook estimate 에서 양쪽으로 추출해 일치성을 검증했다.

3 selectivity 구간 (s=0.050, 0.100, 0.500) 에서 STRAT 가 BERN 대비 paired Wilcoxon p < 0.05 우위. **최강 신호는 s=0.500 에서 p = 4.01e-05** 로 본 연구 RQ2 본선의 한 anchor 가 된다. 작은 selectivity 영역 (s=0.001) 에서는 두 모드가 동률 (median 2.5806) 이었는데, 이는 sample 385 안에서 매칭이 0~1 개로 떨어져 BERN 의 cnt-clamp `cnt=0 → 1` 와 STRAT 의 `cnt_total=0 → est_total=total/budget` fallback 이 같은 값 (993541/385 ≈ 2.581) 을 반환하는 구조적 동치성의 결과다. 본 영역은 어떤 stratification 도 개선이 어렵다는 것이 본 시점의 진단이었으나, §4.7 의 Phase 7 8M 측정에서 같은 영역이 다른 결과를 보이게 된다.

### 4.7 Phase 7 — 외적 타당성 확장 시도와 artifact 발견 (4월 15일 08:31 KST)

Phase 6 Step 4 직후의 결과는 *1M subset × 96d DEEP 단일 dataset × 100 query × 1 seed* 라는 좁은 조건에 한정되어 있어 외적 타당성이 부족했다. 본 팀은 4 월 15 일 오전에 두 가지 외적 타당성 확장을 시도했다.

**Phase 7-1 sf10 8M 재현** (`partsupp_deep_10_phase7_8m_subset`, 옵션 B 안전 경로). 원본 `partsupp_deep_10` 8M 행을 별도 테이블로 COPY 후 (보존) numpy mini-batch k-means K=20 (seed=42) 으로 8M 전체에 stratum_id 를 학습·UPDATE 하고 인덱스 + VACUUM ANALYZE 를 적용했다. setup 17 분 + measurement 23 분, 100 query × s=0.500 D_target × 2 mode = 200 query 측정.

**Phase 7-2 sift 128d 확장** (`customer_sift_10_phase7_noidx_subset`). vanilla PG 55435 의 `customer_sift_10` (1.5M, 128d, HNSW 있음) 에서 c_custkey + c_embedding 만 Exqutor PG 55436 으로 minimal transfer 한 후 (838 MB, 2 분 33 초), HNSW 없이 별도 테이블에 KM20 stratum_id 를 부여했다. setup 3 분 + measurement 7 분, 100 query × s=0.500 D_target × 2 mode = 200 query 측정.

본 두 실험에서 의도한 selectivity 0.500 은 1M subset 에서 derive 된 D_target 을 8M / 128d 에 그대로 적용했기 때문에 actual selectivity 가 약 0.0001 영역으로 이동했다 (1M 과 8M, 96d 와 128d 의 거리 분포 차이). 이 극극소 selectivity 영역에서 BERN 의 `cnt=0 → 1` clamp fallback 과 STRAT 의 stratum 균등 추출이 모두 fallback 경로로 진입한다.

**초기 분석의 오류와 artifact 발견**. 본 팀은 최초에 EXPLAIN ANALYZE plan tree 의 `plan_rows` 값을 q-error 산출에 사용했으며, 이로부터 BERN median q-error 20810 vs STRAT 9.60 (8M, ratio 2168×) 및 BERN 3875 vs STRAT 9.48 (sift, ratio 409×) 이라는 극단적 개선율을 산출했다. 그러나 심층 검증 결과, STRAT 측의 `plan_rows` 가 100/100 row 에서 **정확히 20** (min=max=20, std=0) 으로 고정되어 있음이 확인되었다. 이 값은 stratified estimator 의 추정 출력이 아니라 plan tree `Aggregate → Append → [Subquery Scan × 20]` 구조에서 `find_scan_node` 가 반환한 **stratum LIMIT 상수** 였다. q-error 9.60 은 true_card 193 / plan_rows 20 = 9.65 의 산술적 결과일 뿐이다.

Phase 6 Step 4 에서 확립한 측정 원칙 — `find_scan_node` 가 첫 Subquery Scan 의 plan_rows 를 반환하면 garbage 이므로 hook 이 `elog` 로 서버 로그에 기록한 `hook_est` 를 authoritative metric 으로 사용한다 — 에 따라 `hook_est` 기반으로 재분석한 결과는 **완전히 반전**되었다.

| 단계 | 데이터셋 | metric | BERN median | STRAT median | diff | n_better | p_less |
|---|---|---|---|---|---|---|---|
| Phase 7-1 | deep 96d 8M | hook_est | 16,687 | 21,111 | **STRAT −26.5%** | 26/100 | 0.9999 |
| Phase 7-2 | sift 128d 1.5M | hook_est | 3,968 | 16,867 | **STRAT −325%** | 37/100 | 0.9999 |

두 데이터셋의 plan_rows 기반 paired Wilcoxon p 가 정확히 `1.948279922547955e-18` 로 identical 한 것도 scipy `wilcoxon` 의 `w_stat=0` saturation floor 에 의한 artifact 임이 확인되었다.

**Phase 7 의 학술적 함의 — negative finding 으로의 재framing**. 본 결과는 Phase 4 의 s=0.001 tie 패턴 (sample 안 매칭 0~1 개로 두 모드 동치) 및 Phase 6 Step 4 의 s=0.001 동률 (median 2.5806) 과 일관된다. 극극소 selectivity 영역 (actual ≈ 0.0001) 에서는 어떤 stratification 전략도 cnt-clamp fallback 을 벗어나지 못하며, KM20 의 stratum 균등 추출이 오히려 BERN 대비 불리한 분배를 만든다. 이는 Pivot C 의 효과가 **정상 selectivity 영역에 한정**된다는 경계 조건을 정량적으로 확인한 negative finding 이다. 본 팀은 후속 실험에서 8M / sift 데이터셋의 D_target 을 재계산하여 actual selectivity ≈ 0.5 로 재진입한 뒤 Pivot C 효과를 재측정할 계획이며, 이를 통해 Phase 7 의 외적 타당성 결손을 해소한다. 상세한 검증 과정과 증거는 `experiments/results/rq1_motivation/phase7_artifact_verification_20260415.md` 에 공식 기록되어 있다.

본 Phase 7 측정 진행 중 발견한 다섯 가지 기술 이슈 — psycopg3 copy iterator 의 memoryview chunk yield, Adaptive update path snapshot 부재 에러, Exqutor stratified hook 의 normal SELECT 와의 plan tree 충돌, Postgres log file 의 UTC date rotation, EXPLAIN ANALYZE hook call 횟수 align 어려움 — 은 모두 본 보고서 작성 시점까지 fix 완료되어 위 정량 결과를 확보했다. 본 finding 들은 RQ1 motivation 의 Exqutor design constraint 목록에 추가되지 않으며, 본 팀의 측정 코드 안정화 작업으로 분류된다.

### 5.2 본 시점의 한계 (honest report)

본 중간 보고서 시점의 RQ1/RQ2 결과는 다음 네 가지 한계를 인지하고 기록한다.

**(a) 단일 dataset family 에 대한 제한된 외적 타당성**. Phase 7 까지의 측정은 deep 96d (1M, 8M) + sift 128d (1.5M) 의 두 데이터셋 family 에서 수행되었으며, 차원 96~128 의 좁은 영역만 커버한다. 768 차원 wiki 데이터셋 (`part_wiki_10`) 은 최종발표 W5 에 검증한다.

**(b) 작은 query × seed 표본**. 100 query × 1 seed 의 측정은 paired Wilcoxon test 의 통계적 power 측면에서 충분하지만, 효과 크기의 신뢰구간이 좁아 보일 위험이 있다. 최종발표 W6 의 전면 ablation 은 500 query × 10 seed 로 표본을 확대한다.

**(c) Phase 7 외적 확장의 artifact 와 negative finding**. Phase 7 의 8M / sift 128d 확장에서 D_target 을 재계산하지 않아 actual selectivity 가 약 0.0001 로 이동했으며, 초기 분석의 plan_rows 기반 q-error (2168× / 409×) 는 stratum LIMIT 상수 artifact 로 확정되어 철회되었다. hook_est 기반 재분석에서 STRAT 가 BERN 대비 오히려 나쁜 결과를 보였으며 (8M: −26.5%, sift: −325%), 이는 극극소 selectivity 영역에서 KM20 stratification 의 효과가 없다는 boundary negative finding 으로 재분류되었다. 후속 실험에서 D_target 재계산 후 actual sel ≈ 0.5 에서 재측정할 계획이다.

**(d) `vector.c` 의 단일 테이블 hook 우회 수정의 reviewer 관점 위험**. 본 팀의 측정은 `vector.c` line 243 의 `if (table_count > 2)` 를 `if (table_count >= 1)` 로 한 줄 수정한 상태에서 수행되었으며, 변경된 binary 와 원본 백업을 모두 보존해 검증 가능하게 만들어두었다. 그러나 이 변경 자체가 Exqutor 의 design intent 를 임의로 patch 한 것으로 보일 위험이 있어, 본 팀은 멘토 자문 이메일에서 이를 직접 질의하고 narrative 톤 조정 권고를 요청했다.

본 네 가지 한계 외에 본 연구의 측정 자체가 가진 정량적 약점은 §4 의 각 절에서 honest 하게 기록되었으며, Phase 5 의 8 지표 negative result 는 부정 결과로서 motivation 의 한 축으로 직접 편입되었다.

## 8. 결론

본 중간보고서는 4 월 14 일 ~ 15 일의 RQ1 Motivation + RQ2 본선 (Phase 1~7) 의 정량 결과를 종합한다. 4 월 3 일 합의의 큰 골격 (Exqutor Adaptive Sampling 의 정확도 한계를 데이터로 드러내고 두 트랙으로 sanitize 한다) 은 그대로 유지된 채, RQ1 의 측정 정의가 8 지표 negative result + 5 design constraint finding 으로 정교화되었고, RQ2 의 본선이 Pivot A (BERNOULLI 한 줄 교체) + Pivot C (data-side KM20 stratified native 구현) 의 직교 병합 노선으로 재정의되었다. Phase 4 의 native 측정에서 selectivity 4 구간 모두 paired Wilcoxon p < 0.001 로 Pivot A 의 효과가 확인되었으며, Phase 6 Step 4 의 native 측정에서 s=0.500 에서 +1.81% (p=4.01e-05) 로 Pivot C 의 정상 selectivity 영역 효과가 확인되었다. Phase 7 의 외적 타당성 확장 시도에서는 D_target 재계산 부재로 actual selectivity 가 약 0.0001 로 이동했으며, 초기 분석의 plan_rows 기반 극단적 개선율 (2168× / 409×) 은 stratum LIMIT 상수 artifact 로 판명되어 철회되었다. hook_est 기반 재분석에서 STRAT 가 BERN 대비 나쁜 결과를 보였으며 (8M: −26.5%, sift: −325%), 이는 극극소 selectivity 영역에서 KM20 stratification 의 효과가 없다는 boundary negative finding 으로 재분류되었다.

본 결과는 Pivot C 의 효과가 정상 selectivity 영역에 한정된다는 경계 조건을 정량적으로 확인한 것이며, Phase 4 s=0.001 tie 패턴 + Phase 6 Step 4 s=0.001 동률과 일관된다. RQ2 본선의 유효 anchor 는 **Phase 6 Step 4 의 s=0.500 +1.81% p=4.01e-05 단일**이며, 후속 실험에서 multi-seed 재측정으로 효과 크기 신뢰구간을 확보하고 8M / sift 데이터셋의 D_target 재계산 후 정상 selectivity 에서의 외적 재현을 시도한다. 본 중간보고서 시점의 한계는 단일 dataset family + 작은 query × seed 표본 + Phase 7 외적 확장의 artifact 판명 + `vector.c` 우회 수정의 reviewer 관점 위험이며, 4 가지 모두 최종보고서 (6/11) 까지의 W5~W8 로드맵에서 해소된다. RQ3 (1D distance KDE + quantile 경계) 는 W7 에 진입하며, Pivot C 의 자연스러운 확장 경로 — 분포를 알 때 사용한 stratum 정의를 분포를 모를 때 query 시점의 1D 거리 분포로 대체 — 로 합류한다.

본 연구의 학술적 명제는 다음과 같이 좁고 정확하다.

> 본 연구는 Exqutor 가 자신의 multi-table only design intent 로 배제한 단일 테이블 vector range query 사각지대를 두 단계로 분석하고 개선한다. 첫째 단계는 finding 제시 (Hook trigger 사각지대 + plan replacement 부작용 + query feature 사전 식별 불가능성) 이며, 둘째 단계는 개입 측정 (`TABLESAMPLE SYSTEM` 의 block bias 를 BERNOULLI 한 줄 교체로 sanitize, naive uniform sampling 을 data-side k-means K=20 stratified 로 sanitize) 이다. 두 sanitize 의 정확도 이득은 직교 ablation 으로 분리 측정되며, 본 중간 보고서 시점에서 Phase 4 (4 구간 p<0.001) + Phase 6 Step 4 (s=0.500 p=4.01e-05) 의 유효 anchor 를 확보했다. Phase 7 의 외적 확장 시도는 D_target 재계산 부재에 의한 selectivity 이동과 plan tree artifact 로 인해 negative finding 으로 재분류되었으며, 이는 Pivot C 의 효과 경계를 정량적으로 확인한 학술적 가치를 가진다.
